# 项目身份：文件夹决定是哪个项目，名字只是显示

状态：**方案**（未实施；接口和地址的现状见 [project-folders.md](./project-folders.md)，命令行见 [cli.md](./cli.md)）。

## 1. 要解决的问题

项目的名字目前同时是三件事：人看到的名字、`?p=` 和 `/api/projects/:p/…` 里的地址、登记表（`.links.json`）和分组（`.groups.json`）的键。这是"所有项目都放在一个全局项目目录里"留下来的：一个目录下的子文件夹天然不重名，所以名字可以当唯一键。

现在项目可以在任何地方（`new` 默认建在当前目录），两个不同位置的项目叫同一个名字是常态。名字不该再要求唯一，更不该因为"全局已有同名"而拒绝创建。身份应该是它所在的文件夹。

## 2. 名字今天被当键的地方

- 地址：编辑器 `?p=`、宿主消息、约 28 个服务端接口的 `:p`、SSE 事件、日志。
- 登记与整理：`.links.json`（名字 → 路径）、`.groups.json`（名字 → 分组）。
- 项目之间的引用：设计系统的安装（`designSystems`）、从别的画布导入的画板（`imports`）记的是别的项目的名字；zip 档案里项目文件夹并排放。
- 运行状态：每个项目一份的 Claude Code 会话、对话记录、`activeDelegates`、文件监听。
- 命令行：`open|check|export|prompt|history` 把名字解析成文件夹。

## 3. 考虑过的办法

| 办法 | 好处 | 问题 |
|---|---|---|
| A. 地址直接用绝对路径（`?p=/Users/me/site`） | 身份和地址一致，不需要登记表里的名字 | URL 带本机路径；上面所有按名字存的东西要改；project-folders.md 当时因此没选 |
| B. 地址用一个由路径生成的稳定短 id，名字纯显示 | 身份是路径，名字可重复，URL 短 | 同样要改所有存名字的地方；短 id 要稳定（文件夹挪走怎么办） |
| C. 保留"短名"当地址，但它只是句柄：由文件夹名生成、撞了加后缀，身份记在登记里（句柄 → 路径），命令行不再把名字当唯一键 | 约 47 个文件里的 `?p=`、接口、引用都不用动；已有项目和链接继续有效 | 句柄 `x-2` 仍会出现在地址栏；同名项目靠路径区分，不靠名字 |

## 4. 决定（建议，待确认）

先做 C，再看要不要走到 B。句柄是地址，不是名字：

- **显示用文件夹名或标题，不要求唯一。** 启动页同名的两张卡片并排显示路径（卡片已经写真实路径），不显示句柄。
- **创建永远不因重名拒绝**（`--global` 要占项目目录里的子文件夹，那是文件系统上的冲突，照旧拒绝）。
- **命令行接收路径、句柄或文件夹名。** 文件夹名只有一个项目叫它时直接用；多个时不猜，列出每个的路径让人选，退出码 1。`list` 总是带路径。
- **引用别的项目，仍记句柄，档案出入时翻译。** 项目 zip 里是并排的文件夹，导入时句柄本来就要重新生成；把引用重写成新句柄属于导入的职责（见 [project-archive.md](./project-archive.md)）。

## 5. 没定的

- 句柄要不要换成由路径生成的稳定 id（B）：好处是跨机器、跨登记表重建时不漂移，代价是地址不再可读。
- 文件夹被挪走后，登记是悬空还是跟着重新指定。
- 两个同名项目互相引用（一个安装了另一个同名设计系统）时，句柄在界面里怎么说清；目前只在设计系统的安装列表里出现。
