# 实时编辑指针：谁在改，改到哪里

状态：**已实施**（画布、幻灯片、动效、文档）；设计系统和看板有意不做（见 §5）；§7 是还开着的问题。画板见自身设计稿 `projects/tingly-design-ui-canvas` 的 `Live pointers` 板（`LivePointers.dc.html`）。

## 1. 问题

Claude Code、快速 AI、终端或另一个窗口改了一个文件，打开着的编辑器原地更新（[external_edit](../e2e/external_edit.py)），但人看不出**改的是哪一块**：要自己对比前后，或者去翻变更记录。改动越多、页面越大，越像"东西在自己变"。人想要的是协作里最基本的那一句：**谁在改、改到哪里**。

同时这件事是多人、多 agent 协作的第一块：以后一个项目里可能同时有 Claude Code、另一个 agent 和另一个人，每个都要能被分开看出来。只认"Claude"一个的设计以后要推倒重来。

## 2. 考虑过的做法

| 做法 | 问题 |
|---|---|
| 改动处闪一下高亮，没有"谁" | 看得到哪里变了，看不到谁改的；两个参与者同时改时分不开 |
| 在变更记录（journal）里列出改动 | 还是要人去找；记录说的是文件和摘要，不是页面上的那一块 |
| 自动把视图滚到 / 切到被改的地方（跟随） | 抢视图：人正在别处看或改，被拽走（ux-principles 第 12 条，副作用限定在当前表面）；跟随应该是人选的，不是默认 |
| 共享光标 + CRDT（Figma / Yjs 那一路） | 要把文件变成持久的协作文档，和"文件就是事实"、git、外部改动、写回引擎全面冲突（`.research/baoyu-design-collaboration.md` 的结论）；而且 agent 根本没有"光标"，只有写下的改动 |
| **每个参与者一个指针：从它写下的改动推出位置，也可以先声明位置；颜色和名字分开它们；不动就淡出** | 采用 |

## 3. 决定

### 3.1 看到的样子

- 被改的元素（画板、幻灯片、动效场景）或顶层块（文档）外面一圈参与者颜色的细框、极淡的同色底，左上角上方一个名签（"Claude Code"、"快速 AI"、"编辑器外"、"其他人"，或参与者自己的名字）。上面没有地方时名签放进框内顶部。
- 同一个参与者下一次改到同一页的别处，指针**滑过去**（位置和大小 0.35 秒过渡），而不是消失再出现，所以看得出"它在往哪里走"。换到另一页 / 另一块画板时在新位置淡入。
- **不挡编辑**：`pointer-events: none`，不改选中、不滚动、不抢焦点；画在选中框下面；导出（PNG、PDF 快照）里没有它，和选中框一样。
- 停下 `POINTER_IDLE_MS`（4 秒）不动就在 `POINTER_FADE_MS`（1.2 秒）里淡出并移除。指针表示"正在"，不是记录；记录是 journal 的事。
- 没有开关（ux-principles 第 6 条）：只有在别的参与者改动时才出现，几秒后自己消失，平时页面上什么都没有。

### 3.2 参与者

core 的 `Participant { id, actor, name?, color? }`。一个参与者同时只在一个地方：同一个 id 的新位置替换旧位置。

| 来源 | id | 名签 | 颜色 |
|---|---|---|---|
| Claude Code 运行中写盘（服务端监视器标成 `claude`） | `claude` | Claude Code | `#7c3aed` |
| 运行之外的写盘（终端、git、别的程序） | `external` | 编辑器外 | `#db2777` |
| 本窗口快速 AI 的回复（`enqueueResult` 的 `fast-edit`） | `fast-edit` | 快速 AI | `#0d9488` |
| 另一个编辑器窗口保存（文件事件带它的 `by`） | `client:<by>` | 其他人（按它的 actor） | 人：按 id 在 `PEOPLE_COLORS` 里取 |
| 声明位置的参与者（`POST …/pointer`） | 自己给的 id | 自己给的 `name` | 自己给的 `color`，否则按 actor |

颜色是写死的具体值，不是主题令牌：它代表"谁"，亮暗两种外观里应该是同一个颜色；选色避开编辑器自己在页面上画的选中蓝 `#2f6fed` 和批阅针脚的琥珀 `#d97706`。

**本窗口自己的手改不出指针**：你知道自己在改哪里。编辑器每个窗口带一个 `x-dc-client` 头（`api.ts` 的 `CLIENT_ID`，每次打开页面一个），服务端把它作为 `by` 放进 `PUT file` 的文件事件；`participantOf(actor, by, me)` 对自己的回声、以及来源不明的 `human` 写（服务端替编辑器做的改名、设计系统重算等）返回 null。

### 3.3 改到了哪里

编辑器收到文件事件时手里同时有改前（自己确认过的版本）和改后的内容，所以位置在客户端推出，服务端不用懂格式：

- **元素文件**（`*.dc.html`、`slides/*.html`、`scenes/*.html`，`isElementFile`）：`changedSpan` 取两段文本的共同开头和结尾，得到改后文本里变了的区间；纯插入时同一段文字可能有几种读法（`<p>b</p>` 插在 `</div>` 前，和后面共享一个 `<`），取从标签开始、到标签结束的那种读法，区间就是新元素本身。`pointerTid` 在 `parseDc` 的元素里找包住整个区间的最深的元素；落在页面不画的元素里（`helmet`、`style`、`script`、`sc-for` 这些）就往上找；落在所有元素之外（逻辑脚本、`data-props`、`<head>`）就指整块画板 / 整页。删除时区间是空的一点，指针落在被删东西的父元素上。
- **文档标签页**（`tabs/*.md`）：先记下改后的全文（`landing`），打开着的那个标签页在载入新内容时用 ProseMirror 的 `findDiffStart` 比较前后两棵树，第一个变了的顶层块就是位置（`placeLanding`）。比在 Markdown 上数块可靠：`splitBlocks` 的块和编辑器的顶层节点不总是一一对应。
- 一次写改了好几处时指向包住它们的共同祖先（画板）或第一个变了的块（文档）。

### 3.4 先声明再写：给多个参与者的接口

`POST /api/projects/:p/pointer`，body `{ participant: {id, name?, color?, actor?}, file, tid? | block? }`，`file: null` 收回指针。服务端检查参与者（`cleanParticipant`：id 只能是字母数字和 `: . @ _ -`，名字截到 40 字，颜色只收 `#rrggbb`）和路径，不写任何文件，只发一个 hub 的 `pointer` 事件给所有打开这个项目的编辑器。用途：另一个 agent 说"我在改这一块"，脚本标出它要动的位置，以后的访客发出自己的选中——都不必等写盘。

## 4. 实现

- core `pointer.ts`：`Participant`、`PointerTarget`、`pointerColor`、`participantOf`、`changedSpan`、`pointerTid`、`cleanParticipant`、计时常量；`protocol.ts` 的 `RuntimePointer` 和 `{ dc: 'pointers' }` 消息。纯函数，单元测试在 `packages/core/test/pointer.test.ts`。
- 服务端：`hub.ts` 的 `pointer` 事件和文件事件的 `by`；`app.ts` 的 `POST …/pointer`，`PUT file` 从 `x-dc-client` 取 `by`。
- 编辑器 `pointers.ts`：一个独立的小 zustand store（`usePointers`），不放进大 store，指针一秒变几次不该让整个编辑器重算；`showPointer`（替换同一参与者的位置、排好淡出和移除的计时）、`pointChange`（从前后文本推位置）、`useRuntimePointers(file)`。`store.ts` 的 `onEvent` 在把新内容交给视图**之前**调用 `pointChange`，文档标签页载入时才找得到等着它的指针。
- 画：画板（`Board.tsx`）、幻灯片和动效舞台（`SlideFrame.tsx` 的 `stage`）把这个文件的指针发给 runtime，`unit` 和批阅针脚一样让名签在任何缩放下大小不变；runtime 每个参与者一个常驻节点（不是每帧重写 `innerHTML`），所以 CSS 过渡能做出滑动和淡出。文档是 `docs/DocPointers.tsx`：页面文字顶上一个零高度锚点，指针按块的位置相对它摆，随文字滚动；有指针时每帧量一次，跟着正在重排的文字走。

### 为什么放在 core，不单独成包

模型只有一百多行，定位要用 core 的 `parseDc` 和 `rootElement`，而 core 已经是编辑器、服务端、runtime 都依赖的纯包。单独一个 `packages/pointer` 要么依赖 core（多一层只为放一个文件），要么把解析器的接口复制一份；`.dependency-cruiser.cjs` 和架构文档的依赖表也要多一行。以后如果做真正的网络 presence（心跳、在线列表、断线续传、访客身份），那是一层有自己传输和状态的东西，那时单独成包，并依赖这里的 `Participant`。

## 5. 各类型

| 类型 | 指向 | 说明 |
|---|---|---|
| 画布 | 改到的元素 | 每块画板的 iframe 里画 |
| 幻灯片 | 舞台上那一页里改到的元素 | 不在舞台上的页不提示 |
| 动效 | 舞台上停着的那个场景里改到的元素 | 隐藏的播放器 iframe 不画 |
| 文档 | 改到的第一个顶层块 | 只在打开着的那个标签页；文档里快速 AI 的段落改写不出指针（人就在那一段上） |
| 设计系统 | ✗ | 页面从 `tokens.json` 等生成，被改的文件位置对不上页面上的一块；以后可以把指针落在色板 / 字体那一行 |
| 看板 | ✗ | 页面由脚本画，改动在 HTML 源码或数据里，不是页面上的元素 |

## 6. 验证

`pnpm e2e pointer`（`e2e/pointer.py`）：画布、幻灯片、动效、文档各写一次盘，指针出现在改到的元素 / 块上、名签对、点击能穿过、几秒后消失；两个声明的参与者同时出两个各自颜色和名字的指针，一个收回后另一个还在；格式不对的声明被拒；另一个窗口保存时出"其他人"的指针；快速 AI 的回复处出指针，本窗口自己的保存不出。

## 7. 还开着的

- **视野外的改动**：不在舞台上的页、视野外的画板、没打开的标签页现在什么都不提示。可以在幻灯片条、画板边缘、标签页列表上放一个参与者颜色的小点，点一下跳过去（"跟随"由人发起）。
- **身份**：现在人只有"其他人"和一个按窗口的颜色；有了名字（调研里的第 1 阶段：身份写进 journal）之后，`Participant.name` 直接用上。
- **选中也是指针**：别的窗口里的人选中了什么，可以用同一个 `POST …/pointer` 发出来，就是共享的选中；要不要做、发得多频繁，等多人编辑真的有了再定。
- **命令行和 MCP**：还没有声明指针的命令（`commands.ts` 里加一条就能同时有 CLI 和 MCP 工具）；Claude Code 的指针现在只来自它写下的改动。
- **一次写改了很多处**：只指一处（共同祖先或第一个块）；可以按改动的几个片段各画一个淡框。
