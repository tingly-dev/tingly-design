# 图片生成：OpenAI 风格的 images 接口

状态：**已实施**（生成和改图的服务端路由；Claude Code、命令行 `image` 和 MCP `image` 三个入口；各类型 skill 里的说明；设置对话框里的"图片生成"一块）。编辑器里没有单独的按钮，见 §7。测试是 `packages/core/test/aiConfig.test.ts`（解析）和 `e2e/image_gen.py`（对话框、路由、改图、错误），外加 `e2e/mock_images.py` 作模拟网关。

## 1. 要解决的问题

编辑器里的图片只能是人带进来的（附件、导入、粘贴）。人想在项目里直接说一句"给封面加一张插图"，就得到一张，也想改一张已有的图。

接口用 OpenAI 的形状：`POST {base}/images/generations` 生成，`POST {base}/images/edits` 改图（multipart，原图加可选的蒙版）。OpenAI、xAI 等都是这个形状，Tingly Box 的网关也提供（`/tingly/imagegen/v1`，背后按它的规则转给各家），所以嵌在 Tingly Box 里时不用额外配置。

## 2. 图片是"材料"，不是一种新功能

这条决定了怎么接进各个类型。图片生成**不给任何一种类型加功能**，只是 `uploads/` 多了一种来源：之前是人带进来的（附件、导入、粘贴），现在也可以是模型做的。每种类型本来就会显示 `uploads/` 里的图，引用写法也现成（见 §5），所以类型这一侧不用改一行编辑器代码，要补的只是**告诉各路 agent 它能做这件事、做完怎么引用**。

产出图片的引擎只有一个：服务端的 `generateImage`（`apps/server/src/imagegen.ts`），按设置里的地址调 OpenAI 风格的接口，存进项目。它有三个入口，对应三种干活的方式：

| 谁在干活 | 入口 | 怎么知道能生成 |
|---|---|---|
| 编辑器里"交给 Claude Code" | `scripts/image-gen.mjs`，通过 `DC_SERVER_URL` 调 `POST /api/projects/:p/images` | `delegate.ts` 的系统提示和 `--allowedTools`，只在配好时才有 |
| 终端里或别的 agent（skill + 命令行的路线） | `tingly-design image <项目> "<描述>"` | 每种类型的 skill 里一小段"Pictures you make" |
| 说 MCP 的 agent | MCP 工具 `image`（一步：给描述，得路径） | 工具描述本身 |

三个入口走同一个引擎，所以限制和错误一致：没配好就明确失败并说原因，agent 不应该画一个替代品冒充。

**快速 AI 不自己生成。** 它的输出是一行行 jQuery 语句，在浏览器沙箱里同步执行，没有一个自然的位置放一次几秒到几十秒的异步调用；给执行器加一个异步语句要改它的整个流水线（逐行写回、撤销）。所以配好图片生成时，它的系统提示多一段，要新图就 `askClaude()`；画简单图标（内联 `<svg>`）仍是它的事。文档的段落改写不涉及图片。

这样"谁画图"对人是无感的：在请求栏说一句，结果出现在作品里，不需要选模式。

比较过的入口方案：

| 方案 | 取舍 |
|---|---|
| A. 模型判断需要图时自己去生成 | 不加按钮，没有模式要选（UX 原则 2）。代价是每一路 agent 都要有这个工具 |
| B. 单独的"生成图片"入口 | 好理解、好测，但生成和摆放分成两步，要决定摆到哪 |
| C. 两者都做 | 工作量最大 |

决定：先做 A（上表三个入口），引擎的接口就是将来 B 要用的那一层。

## 3. 生成的图放哪

**`uploads/`，按内容命名**（`<提示词的前 24 个字符>-<8 位哈希>.png`），和附件、导入的图一样：同一张图只存一份，每种类型现有的引用写法（画板、幻灯片、场景 `src="uploads/…"`，文档 `../uploads/…`）直接能用，六个技能不用加新的路径规则。

没有另开 `generated/`：能把"人带来的"和"模型做的"分开，但要改每个技能、每种类型的引用检查和导入逻辑，换来的区分用处不大。提示词不写进文件名以外的地方，只在服务端日志里记长度（日志从不记提示词本身）。

例外：**设计系统**的图片放它自己的 `assets/<组>/`（和导入一致），所以脚本有 `--dir assets/<组>`，路由只接受 `uploads` 或 `assets…` 这类能被 `assetRel` 校验通过的目录。**看板**只读 `data/`，不接图片生成（矩阵里写明）。

服务端按文件头识别格式（PNG / JPEG / WebP）来决定扩展名，不信网关给的 content-type；网关回 `b64_json` 或 `url` 都认；上限 25 MB。

## 4. 配置：第三个用途，挂在同一个连接上

沿用 [ai-settings.md](./ai-settings.md) 的规则：每一项"环境变量 > 已保存 > 默认"逐项比较，解析是 `packages/core/src/aiConfig.ts` 的纯函数 `resolveAi`，结果里多一个 `image`。

和前两个用途不一样的地方：**连接地址不能直接沿用**。连接是 Anthropic 兼容的入口（Tingly Box 是 `/tingly/anthropic`），图片走的是 OpenAI 兼容的 `/v1/images/*`，路径和协议都不同。所以图片有自己的地址，默认跟着连接走：

| 连接 | 图片地址 | 模型默认 | 密钥 |
|---|---|---|---|
| Tingly Box | 自动是 `http://localhost:12580/tingly/imagegen/v1`，界面只读 | `tingly`（由它的规则决定实际模型） | 连接的 |
| Anthropic | **没有**（Anthropic 没有图片接口）：这一块说明原因，不要求别的；图片生成保持关闭 | — | — |
| 其他地址 | 人自己填一个 OpenAI 兼容的地址（如 `https://api.openai.com/v1`） | `gpt-image-1` | 默认用连接的；填了单独的就用单独的 |

"准备好"（`image.ready`）= 有地址、有密钥、有模型名。没准备好时：路由回 501 和一句指向设置的话，Claude Code 没有这个脚本，快速 AI 的提示里没有这一段，`/api/health` 的 `imageGen` 为 `false`。

环境变量是宿主的覆盖：`DC_IMAGE_BASE_URL`、`DC_IMAGE_MODEL`、`DC_IMAGE_API_KEY`（不设就用连接的密钥）。宿主设了的值在对话框里显示为"由宿主设定"，只读。单独的图片密钥和连接的密钥一样，只存在服务端的文件里，接口只回"设了没有"和来源（`saved` / `env` / `connection`）。

## 5. 改图

`/images/edits` 随生成一起做了：路由的 `edit` 收一张项目里 `uploads/` 下的 PNG / JPEG / WebP 的路径（服务端自己读，不让调用者传任意路径），可选的 `mask` 同样；以 multipart 发给网关，结果是另一张新图，**原图不动**。Claude Code 通过 `--edit` 用它。

还没有的是"选中一张图再说'把背景换成夜景'"：要先有选中图片后的上下文，蒙版怎么画也没设计，见 §7。

## 6. 各类型怎么引用生成的图

| 类型 | 放哪 | 引用 | skill 里补了什么 |
|---|---|---|---|
| 画布 | `uploads/` | 画板 `<img src="uploads/…">`，画布上的图片项 `src` | 一段"Pictures you make" |
| 幻灯片 | `uploads/` | `src="uploads/…"` | 同上，在 `uploads/` 那一条下面 |
| 动效 | `uploads/` | 场景里 `src="uploads/…"` | 同上 |
| 文档 | `uploads/` | 标签页里 `../uploads/<文件>` | `uploads/` 那一行加一句 |
| 设计系统 | 它自己的 `assets/<组>/`（`--dir`） | 预览页相对路径 | 加一句，并提醒在组的 README 里补一行说明；**不要为品牌编造标志**，只为系统里要求的插画、摄影风格做图 |
| 看板 | 不接 | — | 看板只读 `data/`，图片只会是数据图表 |

编辑器里的"导入到这里""附件"这些界面不变：生成的图和带进来的图在项目里没有区别，所以也出现在已有的显示、替换刷新、导出里。

## 7. 没做的 / 待定

- **编辑器里的入口**。引擎已经是它要的那一层，缺的是形状。候选：① "导入到这里"里加一个"生成"页（提示词、尺寸，落进项目后像导入的图一样）；② 选中一个图片元素或占位，对话列里出现"为这里生成一张图"，生成后直接换掉它的 `src`（符合"把下一步要用的东西递到手边"，但要每种类型的选中上下文都认得图片）；③ 不加，只靠请求栏里说一句。目前走的是③，等人用过再定。
- **来历**：生成用的提示词现在只写在服务端日志的长度里，图片文件旁没有记录，所以"重新生成一张类似的"要靠人再说一遍。是否在 `uploads/` 旁放一个来历文件、是否记进改动记录，没定。
- **图片的 alt 文字**：由 agent 在引用处写，没有强制。
- **选中图片后改图、画蒙版**：编辑器里的选中上下文和蒙版绘制都还没有。
- **快速 AI 直接生成**：要给 jQuery 执行器加一个异步语句，同步沙箱里没有合适的位置；现在由它交给 Claude Code。
- **设置对话框里的"测试"**：快速 AI 的测试发一个很小的请求；生成图片每次都花钱，所以这一块没有测试按钮，只在填好后写"可以用了"。真正的错误由网关的原话在生成时回给人（`imageFailed`）。
- 张数（`n`）固定为 1；`response_format`、`output_format` 等不传，各家网关的默认就好。
