# 保存为图片：每种类型存一张 PNG

状态：**已实施**。入口现在是各类型栏里共用的导入 / 导出菜单（[export-menu.md](./export-menu.md)），这里讲图片怎么画；PPTX 还没有方案。

## 1. 问题

只有画布能存 PNG；幻灯片、文档、看板、设计系统、动效要图只能截屏，截出来还带着编辑器的界面。每种类型都要有一个"保存为图片"，存当下看到的样子。

## 2. 决定

- **默认 2 倍清晰度，不弹格式和倍率的选择**（幻灯片和动效按自身尺寸，已经很大）。文件名是作品名加页面或尺寸，成功一条提示，失败一条带原因的提示。
- **能在用户自己的浏览器里做，就在浏览器里做**，不依赖服务端和本机的 Chrome。画的办法是把一棵 DOM 放进 SVG foreignObject 让浏览器画（html-to-image），封装在独立的包 `@dc/export`（`rasterize`、`fontCss`、`download`、`canvasPng`），不依赖编辑器、服务端和 core。
- **入口是各类型栏里共用的导入 / 导出菜单**（[export-menu.md](./export-menu.md)）；画法、保存和提示共用 `apps/editor/src/imageExport.ts`（`nodeToPng`、`htmlToPng`、`saveImage`），不按类型复制。

## 3. 各类型怎么画

页面在哪，就在哪画：

| 类型 | 入口 | 画什么、在哪画 |
|---|---|---|
| 画布 | 导入 / 导出菜单（选中的画板 1×、2×，这一页的每个画板）和画板名称条的导出菜单 | 画板框架里 |
| 幻灯片 | 导入 / 导出菜单：这一页、每一页 | 一页一个离屏框架，用导出 HTML 同一份 `standalone` 标记（图片内联），1920×1080；"每一页"是依次触发的多次下载，不打 zip |
| 文档 | 导入 / 导出菜单：当前标签页 | 离屏框架里的 `docHtml`，宽度按文档设置，高度是页面自己的 |
| 看板 | 导入 / 导出菜单 | 看板的沙箱框架里，整页（`#dash-root` 的完整高度），主题、筛选和已加载的数据都是当时的样子 |
| 设计系统 | 导入 / 导出菜单 | 编辑器页面里当前这一页（`.dsview`），清掉 `margin: auto` 解析出的像素边距 |
| 动效 | 导入 / 导出菜单（播放头所在的帧） | 沙箱里 `seek` 到播放头再画舞台，字体由编辑器内联（沙箱没有网络）；画图的代码在单独的 `export.js`，第一次用才加载，播放器不变重 |

沙箱框架没有网络，所以网页字体要由编辑器先内联成 data URL（`fontCss`，只取用到的 unicode-range）；离屏框架和编辑器页面本身可以直接取。

## 4. 画不到的

foreignObject 画不到：`<x-embed>`（单独的框架）、`<video>` 层、WebGL 和 WebGPU 的 canvas、个别 CSS（backdrop-filter、少数混合模式）；设计系统的组件预览在各自的沙箱框架里，图片里是空白。没有像视频那样自动改走服务端，因为一张图的代价小、空白也一眼看得出来。
