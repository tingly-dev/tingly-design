# 对话放在右侧一栏：把左边留给类型自己的列表

状态：**未采纳**（保留取舍）。#465 曾选“对话在右侧、顶掉右侧面板”；用户判断那样会丢掉“对话和属性同屏”，最终改为 **对话固定最左、类型列表整体右移、右侧面板独立**，现行设计见 [chat-panel.md](./chat-panel.md)。位置菜单、外壳 `ChatShell`、`ListColumn` 都已删除；本文件里“右侧一栏”的部分只作为被否掉的方案保留。设计方案见 issue [#463](https://github.com/tingly-dev/tingly-design/issues/463)，板子在 `projects/tingly-design-ui-canvas` 的 “The conversation and the left side” 和 “The conversation pane”。

## 1. 问题

反馈只有一句：对话能放在左侧之后，产生了遮挡、挤压的问题。

在 1100 / 1200 / 1280 / 1440 / 1680 / 1920 六档、六种类型、`dc.barMode=left` 下实测：

- **没有 z 序上的遮挡**：没有元素盖住对话列，也没有 `position: fixed` 的东西落在列下面。
- 真正的三件事：
  1. **列占了类型自己在用的一侧**。幻灯片、文档、设计系统的左边本来就是页面 / 标签页 / 列表；左侧模式下它被折进“对话”页签，列表和对话永不同屏；没有请求在跑时，这一列大半是空的。
  2. **作品被两列夹住**。画布、幻灯片、动效还有右侧的属性，文档还有批注，看板还有数据来源；左侧的对话是第三列。
  3. **窄窗口时布局自己换**。窗口窄到 `280 + MIN_WORK` 以下，左列消失、底部卡片回到作品上方。1100 时画布、幻灯片、文档、看板、动效都这样；人选的布局不是拿到的布局，卡片还盖住作品的下半截。

对话在左侧时作品区的实测宽度（作品 = 舞台 / 文档页 / 主区，右侧面板按各类型平时的状态打开）：

| 类型 | 1280 | 1440 | 右边开着什么 |
|---|---|---|---|
| 画布 | 628 | 788 | 属性 312 |
| 幻灯片 | 628 | 788 | 属性 312；页面列表藏在页签里 |
| 文档 | 572 | 732 | 批注 320；标签页藏在页签里 |
| 设计系统 | 940 | 1100 | 没有右列；列表藏在页签里 |
| 看板 | 540 | 700 | 数据来源 400 |
| 动效 | 628 | 788 | 属性 312 |

1280 时 340 的对话 + 312 的属性，只剩 628 给舞台。对话不是唯一的代价，它是右侧那列之外多出来的一列。

原始需求里列的“左侧 tabs（项目文件、页面 / 标签页、图层、资源 / 组件、历史 / 阶段）”和这个代码库对不上：没有左侧 rail；文件面板、图层、历史 / 阶段都在右侧或弹层里。真正的左列只有三种：幻灯片页面（216 px）、文档标签页（220 px）、设计系统列表（220 px）。

## 2. 人的一次完整旅程

1. **默认**：请求栏在底部，浮在作品上、可以收起；作品拿到整个宽度。
2. **想一边看过程一边聊**：点顶栏的“对话”按钮，右侧打开对话一栏（记录 + 输入区）；左侧的页面 / 标签页 / 列表一直在，作品只让出右侧那一列。
3. **聊着聊着去改元素**：点“属性”（或批注 / 数据来源），对话收成记录留在这个项目里，请求栏回到作品底部，写到一半的字还在。再点“对话”，记录和草稿都回来。
4. **窗口变窄**：顶栏的“对话”灰掉，写“窗口再宽一点才能把对话放在旁边”；作品、左侧列表、底部栏都不动。窗口再宽回来，按钮恢复，但不会自己打开——开不开是人的选择。
5. **离开再回来**：每种类型记住自己最后开着哪个面板（`dc.pane.<kind>`），刷新、换窗口一样；记录本身仍由服务端的 `.transcript.jsonl` 提供（chat-panel.md §3.4）。

## 3. 决定

### 3.1 一个面板，一种位置

- 对话是**右侧的一个面板**，和属性 / 代码 / 微调、批注、数据来源、审查同级：同时最多一个。
- 每种类型都把 `chat` 加进 `KIND_PANE_IDS`（`panes.ts`），顶栏的 `PaneToggles` 因此自动多一个按钮。
- **底部仍是默认**：没打开对话面板时，请求栏在作品底部浮动、可折叠，和今天一样。打开对话面板时，输入区在面板底部（同一个 `RequestBar`），底部栏不画。
- **删掉位置菜单**：`PositionMenu`、`dc.barMode`、`ChatSlots.left`、外壳 `ChatShell` 的 `left` 状态、“左侧”这一处位置都不再有。对话在哪，由“对话面板开没开”决定，不再是一个单独的选择。
- **删掉外壳的包含块**：`.chat-work` 的 `transform` 和 `.chat-shell` 不再需要；每种的 `.app` 回到窗口坐标，`position: fixed` 的东西（顶栏、`.app`、请求栏）重新相对窗口。
- **顶栏回到整窗宽**：现在对话在左时顶栏从列右边开始（项目菜单和名字不在窗口最左角）；对话变成右栏后，顶栏从 x=0 开始，和底部模式一样。对话面板在顶栏下面，和属性面板从同一条线开始。
- **删除 `ListColumn`、`chatTab`、`chat-list` 槽和页签上的状态点**：类型不再把列表注册给外壳。
- **面板头**：`Conversation`（对话）+ 右侧关闭 ×，和属性面板的头同一高度、同一种排法。状态（运行中转圈、有新结果 / 失败一个小点）挪到顶栏的对话按钮上（`PaneToggles` 的 `Badge`，和批注数、审查数同一个机制），打开面板就清掉。

### 3.2 六种类型的列

| 类型 | 左边一直有的 | 右边原有的 | 对话面板打开时 | 1280 作品 | 1440 作品 |
|---|---|---|---|---|---|
| 画布 | 无（图层在右侧属性里） | 属性 / 文件 / 审查 | 对话顶掉右侧面板 | 940 | 1100 |
| 幻灯片 | 页面缩略图 216 | 属性 / 审查 | 对话顶掉属性；页面列表可见 | 724 | 884 |
| 文档 | 标签页 220 | 批注 | 对话顶掉批注；标签页可见 | 672（页 760 上限内） | 760（到上限） |
| 设计系统 | 列表 220 | 无 | 新增右侧一列 | 720 | 880 |
| 看板 | 无 | 数据来源 / 代码 400 | 对话顶掉数据来源 | 940 | 1100 |
| 动效 | 无 | 属性 / 审查 | 对话顶掉属性 | 940 | 1100 |

（“作品”是舞台 / 文档页 / 主区；数字是按 340 的对话宽度算的，设计系统按 220 的左列算，文档页按 760 的上限截断。）

设计系统是唯一变窄的一种：今天左列和对话共用一列（列表被藏起来），现在列表一直可见，对话再占 220。这是这套方案愿意付的代价；如果反馈说太窄，先看“打开问题”里的右列宽度和设计系统默认值。

### 3.3 宽度和窄窗口

- 对话面板宽度沿用 `--w-chat` / `dc.w.chat`：默认 340，280–560，拖动它**左**边缘调整（`SideResizer id="chat" edge="start"`；今天拖的是右边缘），双击恢复，方向键微调，做法同 [side-columns.md](./side-columns.md)。
- 每个面板记自己的宽度（属性 312、批注 320、数据来源 400、对话 340）；换面板时列宽会跳一下，这是各列原本就有的行为。要不要合成一个“右列宽”见 §6。
- 作品下限重估（`MIN_WORK`）：对话顶掉了右侧面板，不再两列叠加，所以比今天的值低：

  | 类型 | 画布 | 幻灯片 | 文档 | 设计系统 | 看板 | 动效 |
  |---|---|---|---|---|---|---|
  | 作品下限 | 780 | 620 | 560 | 600 | 720 | 780 |
  | 最窄可钉窗口 | 1060 | 1116 | 1060 | 1100 | 1000 | 1060 |

  “最窄可钉窗口”= 左侧列（0 / 216 / 220）+ 对话最小 280 + 作品下限，按本机记住的左侧列宽算；窗口更窄时顶栏的“对话”按钮灰掉，写“窗口再宽一点才能把对话放在旁边”。**不自动换位置、不盖住作品**；偏好不改，窗口变宽按钮自己恢复。
- 窗口刚够时，面板先从默认宽度收窄到 280，再不够才禁用（和今天的列一样）：`width: min(var(--w-chat), max(280px, calc(100vw - <左列宽> - var(--chat-need))))`。
- 1100 时只有设计系统能钉（220 + 280 + 600 = 1100）；其余五种保持底部，作品和左侧列表都拿到原本的宽度。这正是今天最容易出问题的那一档。
- 放映（幻灯片）、画布的非编辑模式、全窗查看都不画面板；导出和截图里没有面板。
- 面板关掉时右列是 `auto` 网格列，不占宽，没有空槽；动效底部栏的 `.mprompt` 槽位规则可以删掉。

### 3.4 输入区

- 仍然是同一个 `RequestBar`：作用范围、快速 AI / Claude Code、附件、输入、发送 / 停止、上下文标记都不变，只是容器从“底部卡片 / 左列脚下”换成“右栏脚下”。
- 对话面板里不出现历史按钮和折叠按钮：记录本身就是历史；折叠只属于底部卡片。
- **切面板不丢草稿**：草稿放进 store（或 portal 同一个输入框，不重建），底部 ↔ 面板来回时没发出的字还在。这条和 [#258](https://github.com/tingly-dev/tingly-design/issues/258) 的“换位置丢字”一起做；面板开合比原来的位置菜单更常发生，不能再留着。
- `⌘/Ctrl+J` 在两种位置都把光标放进输入框；面板关着时先展开底部卡片。
- 从命令行、MCP 发来的运行不抢面板：按钮上亮一个点；人打开面板才读。

### 3.5 从左侧迁过来

- `dc.barMode` 不再读；`left` 和更早的 `auto` 都失效。
- 一次性迁移：如果 `dc.barMode === 'left'`，下一次打开项目时打开对话面板（清掉 `dc.barMode`），让原来选了左侧的人落在“对话在旁边”的状态；之后按各类型记的 `dc.pane.<kind>` 走。迁移一次还是每种类型一次，见 §6。
- 底部的位置、折叠、历史、⌘J、运行卡片都不变。

### 3.6 怎么放进六种类型

- 每种类型在自己的右列里画 `<ChatPane>`：
  - 画布（`App.tsx` 的 `CanvasApp`）、幻灯片、动效：现在画 `RightPanel` / `.panel` 的位置；
  - 文档：`with-rail` 的第三列（`comments` 和 `chat` 共用一个槽，二选一）；
  - 看板：`with-side`（`sources` / `code` / `chat` 共用一个槽）；
  - 设计系统：新增第三列 `var(--w-chat)`，`KIND_PANE_IDS` 从 `[]` 变成 `['chat']`。
- 只留一个提供上下文的 `ChatSlots` provider 包住 app（没有 DOM、没有 transform）；`RequestBar` 把输入 portal 到面板的槽；类型不再注册列表，也不再需要 `ListColumn`。
- `PANE_DEF` 加 `chat`：Tabler 的对话图标（加进 `icons.tsx`；文档批注的 `Message` 不动）、名字 `Conversation` / `对话`、`ChatBadge`（运行中 / 新结果 / 失败）。
- `initialPane`：设计系统的 `ids[0]` 不能当“主面板”（它默认没有面板）；加一张 `MAIN_PANE: Record<ProjectKind, PaneId | null>` 表（画布 / 幻灯片 / 动效：属性；文档：批注；看板：数据来源；设计系统：null），`initialPane` 读它而不是 `ids[0]`。
- i18n：删 `prompt.position.*`；加 `common.pane.chat`、`common.pane.chatHint`、`common.pane.chatNarrow`（中英同写）。
- 测试：`e2e/chat_panel.py` 重写为面板模型（六种类型里列表与对话同屏、窄窗口按钮禁用、草稿跨开合、迁移、状态点、拖动左边缘、关闭后到底部）；`e2e/side_resize.py` 加对话面板；`baseline.py` 里“请求栏挪到左侧对话列”的那一批改成右侧面板；`e2e/coverage.json` 与 `.design/project-kinds.md` 第 55、57 行同步；“请求栏面板”一行改成“对话面板（右侧一栏）”，位置写“底部（默认）/ 右侧面板”。
- 文档：`docs/*/development.md` 的 `chat_panel` / `baseline` 说明、`docs/*/guide` 里“左侧对话列”的说法同步；`chat-panel.md` 标为已并入本文件。

## 4. 考虑过、没选的

- **A. 左侧 rail + 互斥面板**：左缘一条 48 px 图标栏（页面 / 标签页 / 列表、对话），一次开一个面板。列表和对话都能找到，但不占额外宽度；代价是列表和对话仍不能同屏，作品仍被两列夹住，四种类型多出“rail + 面板”两级界面而每种只有两三项，1100 的自动替换也没解决。
- **C. 把类型自己的列搬走**：页面变底部胶片条、标签页变顶部标签栏、设计系统列表进右侧或顶部菜单，左侧留给对话。三者都可见，但要做三套新布局和三套窄窗口规则；仍然是第三列，挤压不变（文档、看板更差），列表也离开了它列的东西。
- **保留左侧作为第三处位置**（底部 / 左侧 / 右侧）：位置三处，对话摆在哪不统一；左侧那套问题也还在。
- **对话和属性各占一条右列**：宽屏上可以（1680 的画布 1028 的舞台），但要新增“两条右列都开”的状态、顺序和宽度规则，两个面板挤在一起；先不做，见 §6。
- **右侧自动隐藏 / 浮动面板**：试过又去掉（agent-panel.md §3）；“有时在有时不在”的状态，先不做。
- **默认就开对话面板**：新用户第一次打开作品就让出一列；最常见的是“改一改、发一句”，默认底部。
- **对话做成属性面板里的一个页签**：不占额外宽度，但对话和属性不能同屏，且每次都要先打开属性；和面板模型是同一种“一次一个”，却少了一个顶栏入口。

## 5. 对照 ux-principles

| # | 判断 |
|---|---|
| 1 围绕问题组织 | “它做了什么 / 说了什么”是一个面板；“作品旁边有什么”由顶栏的面板按钮回答，不再由位置菜单回答 |
| 2 消除模式选择 | 去掉“位置”这个轴；开不开对话面板就是那个选择，和属性 / 批注 / 数据来源同一种操作 |
| 3 一个词一个意思 | “对话”仍是这段对话；面板的标题、顶栏按钮、记录里都是同一个词 |
| 4 轴要分开 | 面板（内容）一个轴，宽度一个拖动；范围、交给谁、上下文仍各是各的控件 |
| 5 具体值 | 记录里的文件名、请求原文、真实步骤不变 |
| 6 智能默认 | 默认底部；每种类型记住最后的面板；窄窗口禁用而不是自动换；发送后面板里就是这一轮 |
| 7 诊断走真实路径 | 记录仍由服务端在真实运行事件上写；面板只是读它 |
| 8 教育在产品里 | 对话按钮在每个类型的顶栏都在；灰掉时写明“窗口再宽一点”；面板头就是对话 |
| 9 少视觉噪声 | 去掉一个位置菜单、页签、列表槽、外壳；顶栏只多一个图标按钮；作品不再被三列夹 |
| 10 完成 ≠ 锁死 | 面板关掉记录还在；草稿跨开合；刷新、换窗口一样 |
| 11 把下一步交到手上 | 文件名片定位、撤销最新一轮、放回输入框、关闭面板回到作品，都在 |
| 12 副作用限在当前界面 | 面板不盖作品（占一列），开合不动类型自己的列表和底部栏，状态点不抢切换 |

## 6. 还开着的问题

- **输入区在面板脚下，还是永远在底部？** 现在选的是脚下（和今天的对话列一致）；另一种是底部永远有输入，右栏只读记录，好处是切面板不动输入，坏处是“输入”和“记录”分离。先按脚下做，看反馈。
- **宽屏要不要允许对话 + 属性两条右列？** 1680 以上画布能放下（1028 舞台）；需要新的状态、顺序和宽度规则，先不做。
- **设计系统变窄 220 px**：1280 时作品 940 → 720。列表变可见是收益；如果太窄，先考虑设计系统的右列默认更窄，或让它的列表可折叠，而不是回到“藏列表”。
- **一个右列宽，还是各面板各自宽？** 现在是各自宽（属性 312、对话 340），切面板跳一下；合成一个会让每个面板都记同一个数。
- **迁移一次还是每种类型一次**：全局一次简单，但只对第一个打开的项目生效；每种类型一次更照顾习惯，要多一个迁移标记。
- **面板关掉时底部卡片的折叠状态**：沿用原来的 `barCollapsed`，还是关面板时总是展开？倾向沿用，⌘J 随时展开。
- **设计系统的空状态**：默认没有面板；要不要在空的作品区提一句“可以打开对话”？先不加，避免噪声。
- **记录里“手改”仍不进记录**（chat-panel.md §7）不变；多窗口、更早轮次的撤销等也不变。
