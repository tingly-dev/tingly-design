# 画板里模板文字和模板颜色的编辑

状态：**已实施**（画布类型）。§7 是还没定的问题。

## 1. 要解决的问题

画板是模板：文字里有 `{{name}}` 这样的洞，样式里也有（`color:{{accent}}`）。值从两处来：`data-props` 里声明的默认值（Tweaks），和脚本 `renderVals()` 返回的数据。一个人在画板上能不能"直接改"，原来取决于文字是不是纯字面量：

| 画板里写的 | 以前 | 问题 |
|---|---|---|
| `Hello` | 双击原地改 | — |
| `{{heading}}`，`heading` 是文字 tweak | 原地改，改的是 tweak 的默认值 | 已解决 |
| `Hello {{name}}!` | 双击没有反应 | 一半是字面量、一半是 tweak，哪一半都改不了，也不说为什么 |
| `<sc-for>` 里的 `{{plan.name}} — {{plan.price}}` | 双击没有反应 | 循环里的项，列表在脚本里 |
| 样式 `color:{{accent}}` | 右侧"属性"里文字颜色一栏直接写着 `{{accent}}`，对比度按这串字符算成"过低" | 面板读的是源码里的字面串，不是画板上真正的颜色；改颜色又会在洞后面追加一条字面量，把模板绑定盖掉 |

共同的毛病：模板管着的值，在画板上看起来和普通内容一样，点下去却是死的，而且不告诉人原因。

## 2. 原则

1. **能改的地方都原地改，改的是真正的来源。** 洞来自 tweak，就改 tweak 的默认值；字面量，就改模板文字。人不需要知道它是哪一种。
2. **模板的洞保持不动。** 原地改的结果永远是"洞还在"。想把洞换成字面量，是另一个动作，不是改字时顺带发生的。
3. **改不了就当场说为什么，并指一条路。** 不再静默无反应。
4. **面板显示画板上真正的值。** 源码里的 `{{accent}}` 是模板的写法，面板要显示它此刻算出来的颜色，对比度也按算出来的颜色。

## 3. 文字

### 3.1 把一段文字拆成"字面量段"和"洞"

一个只含文字的元素，其模板文字按洞切成段：`Hello {{name}}!` 是 `Hello `、`{{name}}`、`!` 三段。每个洞按来源分三类：

- **tweak 洞**：`{{name}}`，`name` 在 `data-props` 里声明，是文字 tweak（没写 `editor` 或 `"text"`，默认值是字符串或没写）。可改，改默认值。
- **列表项洞**：`{{plan.name}}`，所在的 `<sc-for list="{{plans}}" as="plan">` 的列表 `plans` 也在 `data-props` 里声明，默认值是对象数组。可改，改的是 `plans[i].name`；`i` 是这一行的序号。
- **数据洞**：其余的（来自脚本的值、表达式）。不可改。

### 3.2 改完以后怎么对回去

原地改发生在渲染出来的文字上，人看不到段。办法是把"编辑前渲染出的文字"和"编辑后的文字"比一下，得到被改动的那一小段区间，再看它落在哪一段里：

- 落在一个 tweak 洞或列表项洞里：把这个洞的值改成新值。
- 落在一个字面量段里：改模板里这一段字面量，洞原样保留。
- 横跨了好几段，或落在数据洞里：不改，告诉人为什么（§3.4）。
- 光标在两段交界处插入字符时（"Hello Ann!" 在 Ann 后面接着打）归洞，因为洞是人在改的东西，字面量的"Hello"很少是在末尾续写的。

比较前先把空白折叠成一个空格，两边一致。拆段用的是"模板按洞切成正则、去匹配编辑前渲染的文字"：字面量段原样匹配，tweak 洞按它此刻的默认值匹配，其余洞用任意文字匹配。匹配不上（比如样式把文字转成了大写，渲染出来和模板对不上）就不改并说明，宁可不动也不乱写。

### 3.3 循环里的字面量

`<sc-for>` 里的字面量文字（"每月"）本来就能改，改的是模板，所有项一起变；这一点属性面板已经用"重复 N 次"的提示说过。列表项洞的改动只改这一行的数据，不影响别的行。

### 3.4 改不了的时候

在双击时就判断，不等人打完字再拒绝：整段都是数据洞的文字，双击只弹一条提示，不进入编辑。提示（两种说法，中英同写）：

- 数据洞：这段文字来自画板脚本里的数据，不能在这里改；告诉 Claude 要改什么，或在代码里改。
- 跨段：这段文字混着模板里的值，一次只改其中一部分，或在 Tweaks 里改值。

打完字才发现跨段（比如全选重打）：撤回画面上的改动，同样提示。

### 3.5 要不要让脚本里的列表也能原地改

不做。脚本里的数据在 JavaScript 里，没有可靠的办法从模板一侧改回去，硬做就是在改人的代码。取而代之的是一个写法约定：**要让人在画板上改的列表，声明在 `data-props` 里**（`"plans":{"default":[{"name":"Solo","price":"$9"}]}`），`renderVals()` 返回 `this.props.plans`。画布 skill 和用户文档都写了这条，Claude 生成画板时就会这样写。

## 4. 颜色

属性面板里，样式值整个就是一个洞（`color:{{accent}}`、`background:{{surface}}`）时：

- 颜色一栏显示它**算出来的颜色**（色块和十六进制），不显示 `{{accent}}`。对比度按这个颜色算。
- 栏里带一个小标签 `accent`，说明这个颜色由同名 tweak 管着；悬停说明"改这里改的是 tweak，画板上所有用它的地方一起变"。
- 在这一栏取色或输入，改 tweak 的默认值（`setPropDefault`），洞原样保留，撤销、改动记录与 Tweaks 一致。
- 洞不是一个 tweak（来自脚本），或者 tweak 不是颜色：显示算出来的颜色，标签写洞的名字，悬停说明"来自画板脚本"；改它的时候照旧在洞后追加一条字面量覆盖，这是原来的行为，属性面板里其他非颜色的洞也一样（字号、间距等显示算出来的值，不显示 `{{size}}`）。

不为每种样式属性做"改写回 tweak"：颜色是唯一一个 tweak 的值和样式值一一对应的类型；数字常带单位、枚举要映射，一对一的假设不成立。

## 5. Tweaks 里的列表

`data-props` 里默认值是数组或对象的项（§3.5 的约定）也要在 Tweaks 和画布的模板值里看得到，否则"看不全所有模板字段"的问题换了个样子。它们显示为一行只读的摘要（"3 项"）并说明在画板上双击文字来改。这一行不是输入框：把数组当文字改会把列表写坏。

## 6. 跨类型

只做画布。幻灯片和动效的文字没有洞（闭合的 HTML 子集）；设计系统、看板、文档没有模板。在 [project-kinds.md](./project-kinds.md) 的矩阵里记为有意只做画布。

## 7. 没定的

1. 全选重打一整段混合文字时，现在是拒绝并提示。也可以改成"把洞换成人打的字面量"（带确认）。倾向先观察，因为这是一个会丢模板的动作。
2. 嵌套循环里的列表项洞（外层循环的项作为内层的列表）不支持；只认最近一层 `<sc-for>` 直接引用声明过的数组。
3. 列表项里有 tweak 以外的类型（数字、布尔）时，原地改只处理文字。
4. 要不要给 Tweaks 里的列表一个表格编辑器。等有人真的在画板外改列表再看。

## 8. 验证

- core 单测：拆段与匹配（字面量、tweak 洞、列表项洞、数据洞；大小写变化匹配不上）；落点判断（洞里、字面量里、交界、跨段）；模板改写保留洞；列表项按序号写回。
- e2e（`e2e/tweak_text.py`）：混合文字改洞、改字面量、跨段被拒并提示；循环里的字面量改动影响所有项；列表项洞改一行；数据洞双击只提示；属性面板的颜色显示算出的值、对比度正确、改色写回 tweak 且洞保留、撤销。
- 自身设计稿 `projects/tingly-design-ui-canvas` 的画布板画出颜色一栏的绑定标签和双击提示。
