# 跨类型交互一致性：哪些概念被六种类型各写了一遍，怎么收拢

状态：**方案，分期实施中**（P1–P6b 已实施；§6 的产品取向按建议推进，随时可调）。读这份之前先读 [project-kinds.md](./project-kinds.md)（登记清单和跨类型功能矩阵）和 [kind-registry.md](./kind-registry.md)（按类型的穷尽表）；这份接着它们往交互层走。

## 1. 问题

矩阵里的功能（请求栏、顶栏、导出菜单、图层树、尺寸……）已经是共用部件，新类型接上就有。剩下的割裂不在"功能有没有"，而在**同一个概念在每种类型里长得不一样**：

- 幻灯片的页、动效的场景、文档的标签页、画布的画板和页面，都是"这件作品由哪些有序的东西组成，我可以加、复制、挪、改名、删"。四种各写了一套行、菜单、确认和日志。
- 删一个东西，有的弹浏览器的 `confirm()`，有的直接删，有的提示撤销。
- 打开一个旁边的面板（检查器、批注、数据来源、代码），状态记在三个地方，按钮摆法不同。
- 同一个"分段选择"画了四种标记。

这违反 [ux-principles.md](./ux-principles.md) 里的"一个词一个意思"和"在当前界面范围内处理副作用"：人在幻灯片里学会的"右键一页"，到了动效和文档要重新学一遍，而且重新学的结果还不一样。

不是要把六种类型做成一个样子。画布有自由位置，文档有层级，幻灯片有分节，这些差别是内容决定的，要留。要收的是**内容不决定、纯属各写各的**那一层。

## 2. 已经统一的，不动

下列在前几轮整理里做完了，这份计划建立在它们上面，不重做：

| 概念 | 共用部件 | 说明 |
|---|---|---|
| 顶栏、项目名改名、同步状态、"更多" | `TopBar`、`ProjectTitle`、`BarButton` | 六种同一条栏，面板开关作为 `panel` 参数 |
| 导入 / 导出入口 | `FileMenu` + 各类型交出的 `ExportItem` | 菜单共用，条目列表各类型自带（见 §3.7 的残余） |
| 请求栏 | `RequestBar`，`PromptBar` / `AskClaude` 是它的两种配置 | 见 §3.8 的残余 |
| 模态框 | `Dialog` | 遮罩、焦点、Tab、Esc 统一 |
| 边栏宽度 | `SideResizer`、`sideWidth.ts` | 八处列都在用 |
| 图层树 | `panel/LayerTree.tsx` | 画布、幻灯片、动效同一棵树 |
| 尺寸 | `BoardSizePicker`、`SizeRows`、核心 `boardSizes.ts`、`adaptSize` | 新建、画布面板、幻灯片面板、动效"添加尺寸"同一套 |
| 元素尺寸钩子、偏好读写、下载 | `hooks.ts` 的 `useElementSize`、`local.ts` | 取代了各文件私有的版本 |
| 左列 | `ChatShell` / `ListColumn` | 各类型的列表成为对话列的第一个页签 |
| 按类型的穷尽表 | 核心 `OUTLINE` `CHECK` `CARD`，服务端 `STARTER` `DELEGATE` `KIND_CLI`，编辑器 `KIND_APP` `PREVIEW` `KIND_NEW` | 新类型漏登记编译不过 |

## 3. 盘点：还割裂的概念

标记：**重复** = 同一件事多份实现；**分歧** = 同一概念行为不同；**有意** = 内容决定的差别，保留并写明。

### 3.1 有序条目的集合（最大的一块）

"作品由哪些条目组成"在每种类型里：

| | 条目 | 行的画法 | 加 | 复制 | 挪 | 改名 | 删 | 最后一个 |
|---|---|---|---|---|---|---|---|---|
| 幻灯片 | 页（可分节） | 缩略图 + 右键 `Menu` | 列底 `btn outline` + 菜单"在后面加" | 有 | 拖放 | 不改（标题取自内容）；节名双击 | 菜单，**不确认** | 提示"最后一页" |
| 动效 | 场景 | 时间轴上的块 + 右键 `Menu` | 列旁 `btn ghost sm` + 菜单 | 有 | 菜单"前移/后移" | 无 | 菜单，**不确认** | 提示"最后一个场景" |
| 文档 | 标签页（一层子页） | 列表行 + 自画的 `.tabmenu`（鼠标移出才关，没有键盘） | 列底 `btn ghost` + 菜单"加子页" | **无** | 菜单"上移/下移" | 双击或菜单，行内输入 | 菜单，**`confirm()`** | 无限制 |
| 画布 | 画板（自由位置）、页面 | 画板条上的标题 + 页面菜单 | 工具、菜单 | 有（选中复制） | 拖到任意位置 | 双击标题；页面是菜单里再点一次 | 选中 Delete，**`confirm()`**（有开关） | 无限制 |
| 设计系统 | 视图（固定六个） | 导航按钮 | — | — | — | — | — | — |
| 看板 | 数据来源 | 来源面板里的行 | 面板内 | — | — | — | 面板内 | — |

重复和分歧：

- **行内改名的输入**（Enter 提交、Esc 取消、失焦提交、`stopPropagation` 吃掉快捷键）复制了至少 6 份：`ProjectTitle`、幻灯片节名、文档标签页、画板标题、画布页面、设计系统令牌文本。每份对"空值""没变"的处理略有出入。
- **条目菜单**：幻灯片、动效用共用 `Menu`；文档自画；画板页面是 `Menu` 里嵌输入。同一个"加在后面 / 复制 / 前后挪 / 删"，条目、顺序、危险色、禁用态各不相同。
- **条目的增删复制挪**在 `slides.ts`、`motion.ts`、`docs.ts`、`actions.ts` 各有一套：都是"改 order 数组 + 写日志文字 + 保证最后一个不删 + 选中邻居"，只是索引文件不同（`deck.json` / `motion.json` / `doc.json` / `canvas.json`）。
- **拖放换序**只有幻灯片有；动效和文档用 ±1 菜单。
- **文档没有"复制标签页"**，其余三种有。这是漏，不是选择。
- **"当前条目"**记在四处：`store.slide`、动效的当前场景、`useDocs` 的当前标签页、画布的选择。RunFeed 的"定位到改动"（`onOpen`）、转录里的跳转、命令行的 `pick`，都要各类型自己写一遍"这个文件对应哪个条目、怎么打开"。

### 3.2 删除的规矩

| 做法 | 在哪 |
|---|---|
| 浏览器 `confirm()` | 文档标签页和批注、画板、设计系统素材、动效尺寸（带覆盖时） |
| 直接删，靠撤销 | 幻灯片、动效场景 |
| 删完一个 toast 带"撤销" | 动效尺寸、启动页取消登记 |

`confirm()` 是阻塞的原生框：不能按主题画，不能翻译措辞以外地调整，无头模式要特殊处理，也是最后一个没走 `Dialog` 的模态。整个编辑引擎本来就有撤销栈和日志，对**能撤销**的删除，确认框是多余的一步；对**撤销不回来**的（比如删文件后还有别的连带）才该确认。现在两种混着用，同一动作在不同类型里结果不同。

### 3.3 旁边的面板

| 面板 | 打开状态（原） | 开关按钮（原） | 拖宽 |
|---|---|---|---|
| 检查器（画布、幻灯片、动效） | `store.panelOpen` | `TopBar` 的 `panel` 参数 | ✓ |
| 数据来源、代码（看板） | `useDash.side` | 看板自己放 `BarButton` | ✓ |
| 批注（文档） | `useDocs.rail` | 文档自己放 `BarButton` | ✓ |
| 设计系统 | 没有侧面板 | — | — |

三份状态、三套摆法。后果：Esc、记住上次是否打开、外部命令（`pick`、宿主消息）想"打开某个面板"，都得逐类型处理；`RunFeed` 点看板的文件要懂 `useDash.side`。现在（P4）只剩一个 `store.pane`，开关由 `TopBar` 按 `KIND_PANE_IDS` 统一画，见 §4.4。

"整件作品的设置放哪"也分歧：画布是什么都没选时的检查器，幻灯片是页面面板，动效是 `MotionPanel`，文档是顶栏里的 `popmenu`，设计系统在令牌视图里，看板的主题是顶栏一个太阳/月亮按钮。

### 3.4 分段选择和页签

`seg`（分段按钮组）有四处标记不同：`AiSettings`、`PromptBar`、文档设置、`panel/fields.tsx`；`role="tablist"` 有五处写法不同（启动页分类、尺寸分类、`LookPicker`、对话列、检查器）；设计系统导航用 `aria-current` 的按钮。样式靠各自的 CSS 类，焦点和键盘（左右键）行为不一致。

### 3.5 作品自己的外观 ≠ 编辑器的外观

看板顶栏一个太阳/月亮（切看板页面的明暗）、设计系统导航脚一个主题下拉（切预览用的主题）、文档的字体和宽度。三者都是"预览/作品的外观"，而"更多"菜单里的外观是**编辑器**的外观。同一个词指两件事，位置又各不相同（[ux-principles.md](./ux-principles.md) 的"一个词一个意思"）。

### 3.6 快捷键和教育

`shortcuts.ts` 里按 `kind` 分支（`slideKey`、动效一段），文档、看板、设计系统的键各自写在自己的组件里（比如看板的 Esc）。可见的快捷键清单只出现在画布的"什么都没选"检查器里（`panel.canvas.shortcutList`），其余类型的人没有地方看。Esc 的层级顺序（菜单 → 放映 → 工具 → 选择）只对画布成文。

### 3.7 导出条目

`FileMenu` 共用，但每个类型的 `ExportItem` 数组是在 `*App.tsx` 里内联写的；"保存为 PNG / 复制为 PNG"这一对在画布、幻灯片、设计系统、看板、文档、动效里各写了一对 `run` 闭包，只有取哪个节点、怎么命名不同。导出过程的反馈也分三个：`PptxExportDialog`、`VideoExportDialog` / `ExportProgress`、其余的 toast。

### 3.8 请求栏的接线

`RequestBar` 共用，但每个类型给 `AskClaude` / `PromptBar` 传的是临时拼的一包：`context` 闭包（看板那段最长）、`onOpen`（定位到改动）、`placeholder`、`file`。这是 §3.1 "当前条目"没有统一出口的后果。

### 3.9 检查结果（"这件作品哪里有问题"）

幻灯片的页上标红（`Stage`、`SlidePanel`）、动效在 `MotionSidePanes`、设计系统一个"问题"视图、看板一个顶栏徽标，画布主要靠命令行 `check`。每处是自己的列表和徽标，没有共用的"问题行"，也没有统一的入口。

### 3.10 有意保留的差别（写下来，免得被当成漏）

- 画布的自由位置、缩放、模板值、原地改模板文字（[canvas-template-values.md](./canvas-template-values.md)）：只有画布有"画板是模板"。
- 幻灯片的分节、放映；动效的时间轴、关键帧、播放器；文档的层级与批注钉在文字上。
- 设计系统、看板没有元素树，所以没有图层树和缩放手柄；看板的数据来源不是"条目"。
- 批注 / 备注 / 便签 / 评论是四个词，其中便签是画布上的东西、备注是演讲者看的、评论钉在文字上，**意思确实不同**，不合并；但词要在界面里用对（见 §5.4）。
- 放映 / 播放三种各自实现（矩阵里已写）：内容不同；共用外壳是可选的，排在最后。

## 4. 方案

三层，自下而上，每层独立可交付：

### 4.1 第一层：交互原语（小、无风险、先做）

补齐已有的 `Menu` / `Dialog` / `SideResizer` 那一级，各一个文件，替换重复的写法，**界面不变**（除了把 `.tabmenu` 的缺陷补上）：

- **`InlineRename`**：行内改名的输入（Enter / Esc / 失焦、空值与未改动的处理、吃掉快捷键）。替换 6 份。`ProjectTitle` 建在它上面。
- **`Segmented`**：分段选择，统一标记（`role="radiogroup"`、`aria-checked`）和左右键；**`Tabs`** 同理。样式留在各区域的 CSS 里，类名收成一个。
- **`RowMenu`**：条目菜单的外壳（一个 ⋯ 按钮 + 右键，同一个 `Menu`，条目顺序固定：加 / 复制 / 前后挪 / 其他 / 分隔 / 删除）。文档的 `.tabmenu` 去掉。
- **`confirmDestructive` / `removeWithUndo`**：见 §4.3。
- **`imageExportItems({ node, name, background })`**：产出"保存 PNG + 复制为 PNG"一对 `ExportItem`；各类型只给节点和名字。
- 共用的**问题行**（`IssueRow`）：一行 = 级别图标 + 文字 + "定位"。

怎么借现成的库：**不引入整套 UI 库**（现有 `Menu` / `Dialog` 已按本项目的焦点与 Esc 先后定制，换库的收益小于改写成本）。唯一值得评估的是拖放排序：幻灯片现用原生 HTML5 拖放，没有键盘和触屏。若 §4.2 要把拖放推到文档和动效，再评估 `@dnd-kit/sortable`（带键盘与读屏支持）；不需要就不引入，保持菜单里的"前移 / 后移"作为键盘可达的路径。

### 4.2 第二层：条目的动词和"定位"

最初设想一张 `Record<ProjectKind, KindItems>` 的表，连条目列表的行也一起画（`ItemList`）。落到代码时收窄了：

- **行不共用。** 幻灯片画缩略图，文档画标题加子页缩进，动效画时间轴上的块，三者的行内容、拖放和选中方式都由内容决定；硬抽成一个 `ItemList` 要塞满插槽，得不偿失。真正重复的是**菜单和动词**，以及"改动的文件在界面里怎么找到"。
- **`ItemMenuItems`**：一份菜单内容，各类型的条目菜单（幻灯片右键、动效场景右键、文档标签页的 ⋯）都用它。顺序固定：加 / 复制 / 前后挪 / 本类型特有的 / 改名 / 分隔 / 删除。类型不会的动词不传就不出现，这一项对这个条目不可用（第一页不能前移）就传 `null` 变灰。竖排的列表说上移 / 下移，时间轴说前移 / 后移。词条在 `common.item`。
- **`LOCATE`**：`Record<ProjectKind, (file) => boolean>`，一个被改的文件在该类型里怎么显示（画布聚焦画板、幻灯片跳到那一页、文档切标签页、动效把播放头挪到场景、看板打开数据来源或代码；设计系统只列文件，不跳）。请求栏、运行反馈和对话记录都经过它，类型不再各自给 `onOpen`。动效的播放器在 `MotionApp` 里，由它挂载时登记一个定位函数。命令行 `pick` 仍在 `KIND_CLI`，两者目前不共用数据源，需要时再并。
- 由此补上了漏：文档得到"复制标签页"，幻灯片得到键盘能走到的"上移 / 下移"。动效场景的拖放换序仍待做（时间轴块的拖动要和现有的拖动手势协调，另议）。
- **没有统一的"当前条目"接口。** `list` / `current` / `open` 只在 RunFeed 定位和命令行 `pick` 时需要，而 `LOCATE` 已经覆盖前者；`SHOW_VIEW` 只做"按名字显示"，没有列出条目的接口，因为没有第二个使用者。

设计系统的六个视图和看板的数据来源不进条目模型（固定集合 / 不是有序作品组成部分）。

### 4.3 删除的规矩

**能撤销的删除直接做，toast 带"撤销"；撤销不回来的才问，而且用编辑器自己的对话框，不用浏览器的 `confirm()`。**

- 原来的情况比盘点时以为的更糟：幻灯片、场景删了是不可撤销、也不问（索引和文件都按 `undoable: false` 写，编辑器的撤销栈碰不到文件的删除）；文档标签页和画板倒是问了，但问完同样回不来。
- 做法：删除前把被删条目的文字留在内存里，删完发一条"已删除“X”"的 toast，带"撤销"（几秒内有效）；撤销是把文件原样写回、把条目放回索引原来的位置（`undoRemove.ts` 的 `offerUndo` / `putFiles`，各类型自己负责怎么放回索引：幻灯片还原封面和分节的起点，文档标签页连子页一起、按原位置放回）。批注线程同样。动效的尺寸本来就是这样。
- 为什么不用编辑引擎的撤销栈：删文件是服务端动作，栈里存的是"某个文件前后的文本"，装不下"这个文件整个没了"；且这个撤销应该在删除之后立刻能点到，不依赖焦点在哪。代价是撤销只在 toast 存在的几秒内有效，超过之后只能靠 git 或备份找回，和原来的"问一下"相比，是把"事前一道确认"换成"事后一次反悔"；对能反悔的东西这更快，也不打断。
- 只有设计系统的素材（图片、字体，二进制）没有内存里的副本可还原，所以删它们仍然问一次，用 `ConfirmDialog`（`askConfirm`），说明"删除后无法撤销"。
- 画布删画板的确认开关（`confirmBoards`）和所有 `confirm()` 一并去掉。剪切不另外处理：剪切一个画板会同样出现"撤销"，这是可以接受的。
- 还有一处浏览器原生框没有收：设计系统素材"新建分组"用 `prompt()`，留待后面的一期。

### 4.4 第三层：面板与"当前视图"的统一

- **`SidePanes`**：每种类型声明自己有哪些侧面板（`{ id, label, icon, badge?, render }`），一个状态切片 `store.pane`（`null | id`，`panes.ts`）替代 `panelOpen` / `useDash.side` / `useDocs.rail`。`TopBar` 的 `PaneToggles` 按 `KIND_PANE_IDS` 画开关（同一位置同一顺序，角标由各面板自带），`pane` 按类型记住上次（本机，`dc.pane.<kind>`；旧的 `dc.panelOpen` 作回退）。同一时刻只开一个面板，所以看板的"来源"与"代码"互相替换；`openPane(id)` 是外部命令和文件定位的统一入口。Esc 不关面板（输入框里的 Esc 另有含义）。宽度仍是 `SideResizer`。外部命令"打开代码面板"有了统一的口。
- **作品设置的家**：见 §6-2，先定产品取向，再决定是把画布空选检查器 / 页面面板 / `MotionPanel` / 文档设置 / 看板主题统一成"检查器里的'作品'一节"，还是各留各的。
- **外观**：见 §6-3。
- **当前视图**："显示作品的某一部分"是 `SHOW_VIEW`（`views.ts`）一张 `Record<ProjectKind, …>` 表，而不是给每个 `FileMenu` 传一个 `pick`；设计系统的页面状态在 `useDsView`。看板的明暗 / 数据模式和文档的弹层不是"作品的某一部分"，不进这张表。
- **快捷键**：`shortcuts.ts` 里的 `kind` 分支改成 `Record<ProjectKind, KeyHandler>`，同时每种类型提供一份"可见的快捷键表"，放在统一的位置（帮助菜单 / 检查器空态），不再只有画布有。

## 5. 分期与优先级

## 6. 产品问题与现在的取向

1. **删除**：同意"能撤销的直接删 + 撤销 toast，撤销不回来的才确认"，从而去掉所有 `confirm()` 和画布的 `confirmBoards` 开关吗？（取向：同意。）
2. **作品设置的家**：画布（空选检查器）、幻灯片（页面面板）、动效（`MotionPanel`）、文档（顶栏弹出）、看板（顶栏按钮）、设计系统（令牌视图）六处。统一进检查器的"作品"一节，文档和看板新增检查器？还是只统一"位置的规矩"（都在顶栏的同一个"外观与设置"弹出里）？这决定看板和文档要不要有检查器。（取向：不为统一而造检查器；只统一位置规矩，作品设置都在顶栏同一个按钮的弹出里，各类型自己的检查器照旧。P5 落地时细化为：设置已经各有顺手的家（顶栏弹层或检查器），不再合并成一个新弹层，只守"不再新增第三种位置"。）
3. **"作品的外观"和"编辑器的外观"**：把预览用的明暗 / 主题（看板、设计系统）、文档字体和宽度，统一叫"预览为…"并放在同一处，与"更多"里的编辑器外观分开命名，可以吗？（已定并实施：预览明暗 / 主题统一为顶栏的"预览为"菜单；文档的字体和宽度是文档自己的版式设置，留在"版式"弹层，不叫预览。）
4. **文档要不要加拖放换序和"复制标签页"**：本篇认为是漏，建议补。（取向：补，随 P2。）
5. **幻灯片 / 动效 / 画布要不要共用缩放**：现在只有画布能缩放，幻灯片和动效是自适应。要不要给幻灯片舞台加缩放？（不影响 P1–P4。取向：暂不做。）

## 7. 不做什么

- 不把六种类型做成同一个编辑器；§3.10 的差别保留。
- 不引入整套 UI 库；`Menu` / `Dialog` / `SideResizer` 已按本项目的焦点和 Esc 规矩定制。
- 不重写已统一的部分（§2）。
- 不动文件格式和服务端；这是纯编辑器层的整理（`locate` 的 `pick` 数据源除外，在 `KIND_CLI` 那张表里）。
