# 边栏的宽度：每一个都能横向拖动调整

状态：**已实施**。编辑器里每一列边栏的宽度由人定：拖它的边、用方向键，或双击恢复；各列分别记在本机。

## 1. 问题

边栏的宽度原来是 CSS 里写死的数：检查器 312、幻灯片缩略图列 216、文档标签页 220、批注 320、设计系统导航 220、看板数据来源 400。内容放得下放不下取决于人在看什么：长的图层名、宽的缩略图、长的批注，都被一个固定的数卡住。对话面板（[chat-panel.md](./chat-panel.md)）又多了一列，更需要让人自己定。

## 2. 决定

- **每一列边栏**：右侧检查器（画布、幻灯片、动效）、幻灯片的缩略图列、文档的标签页和批注、设计系统的导航、看板的数据来源与代码、对话列。人拖列的内侧边，宽度跟着变；方向键每次动 16 px（Shift 48 px）；双击回到这一列自己的宽度。
- **记在本机，各列各一份**（`dc.w.<列>`），一个类型里调的宽度不影响另一个类型。数值有上下限（每列在 `sideWidth.ts` 的 `SIDES` 里），拖出界就停在边上；窗口比较窄时对话列先收窄，再不够退回底部（[chat-panel.md](./chat-panel.md) §3.5）。
- **一件东西一个控件**：边本身就是控件，没有设置页、没有"宽 / 窄"开关（ux-principles 第 2、6 条）。鼠标移上去边亮一条线，光标变成左右箭头；这是它唯一的提示，不加按钮和图标（第 9 条）。
- **对话列里的列没有自己的边**：幻灯片、文档、设计系统的列在对话列的页签里时，宽度就是对话列的，它们自己的边不画（`InChatList`）。

## 3. 怎么做

- 宽度是页面根上的 CSS 变量 `--w-<列>`，每列的样式读它，旧的数字做回退（`var(--w-strip, 216px)`）。没拖过的列不写变量，样式还是它原来的样子，所以没有"忘了迁移某一列"的风险。
- 边是 `SideResizer`（`components/SideResizer.tsx`）：一个 `role="separator"` 的细条，指针捕获拖动、键盘和双击都在它上面。它按这一列的宽度变量定位到 `.app` 里（`panel.css` 的 `data-side` 规则），不放进会滚动的列内部，免得跟着内容滚走或被裁掉。
- 拖动时给 `body` 加 `resizing-side`：作品里的 iframe 不再接收指针，否则指针移进画板就丢了拖动。
- 拖动过程只改页面上的变量，松手才写进本机；e2e 见 `e2e/side_resize.py`。

## 4. 考虑过、没选的

- **只给对话列做**：问题是同一个：一个固定的数卡住内容。分开做，人要记哪几列能拖。
- **设置里给一个"边栏宽度"滑块**：离开手上的事去设置里调，也没法一边看一边调。边上直接拖。
- **按窗口宽度自动算**：窗口大就宽一点，听起来省事，但人要看长图层名还是要缩略图大一点，窗口说不出来。自动的只留在"放不下就退回底部"这一件事上。
- **拖到极窄就折叠这一列**：折叠是另一种状态（要有展开的办法），先不做；下限保证列始终可用。

## 5. 还开着的问题

- **拖动改变内容的排版**：缩略图固定宽度，列拉宽后右边留空；检查器里的控件拉宽后会跟着变宽。哪些应该跟着列走，等有人觉得别扭再逐个看。
- **触屏**：边只有 9 px 宽，手指不好点；编辑器目前不面向触屏。

## 6. 底部的条：高度也由人定，且不随内容跳

边栏的宽度是人定的；有内容的横条（目前只有动效时间轴的元素行）同理，高度也由人定，并且**固定**：条的高度不取决于里面此刻放着什么。原来的做法是“内容多少就多高，到上限为止”，播放头在有 2 行动画的场景和有 50 行的场景之间移动，整个时间轴和上面的舞台就跟着上下跳。

- **一条一个高度，固定而不是上限**：默认值在 `bandHeight.ts` 的 `BANDS` 里（动效元素行 132 px，下限 44，上限 360）；内容少就留空，没有内容就一行说明，内容多在条内滚动。
- **控件是条的底边**：`BandResizer`，和 `SideResizer` 一样是 `role="separator"`，上下拖、↑ ↓ 微调（Shift 更大步）、双击恢复默认；高度是页面根上的变量 `--h-<条>`，样式读它并带默认值回退，记在本机（`dc.h.<条>`）。
- **折叠是另一件事**：是否展开元素行是时间轴顶行的一个开关（默认折叠，同样记在本机）；折叠时整条不占高度，这是人主动选的那一次变化，不是随内容的跳动。
- **其他 kind**：逐个看过，目前没有同类的“随内容变高的横条”：画布和幻灯片的缩略图列是侧栏（已可拖宽），文档、设计系统、看板的区域占满剩余空间，请求栏按输入内容增高但有自己的上限。以后哪一个 kind 加了底部的条，就加进 `BANDS`，用 `BandResizer`，不要各写各的。

还开着的问题：触屏同样不适用；请求栏（输入多行）的高度是否也让人拖，等有人提出再看。
