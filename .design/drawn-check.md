# 看板画出来的样子自查

状态：已实施。

## 问题

Claude Code 写完或改完一个看板，今天能自己发现的是“标注的数字和数据对不上”和“脚本抛了错”（`.runs.json` 的 `marks` 和 `errors`）。但页面代码没报错、标注也对得上的时候，图可能还是画坏了：数字显示成 `NaN`（日期没解析、字段名写错）、图表容器里什么也没有（数据是空的，或脚本在画之前就返回了）、坐标轴标签叠在一起或被图的边缘裁掉。这些只有人看一眼才知道，于是“做完了”后面常跟着一轮“这张图是空的”。原版 Dashboard 最新一版加了同类的输出检查。

## 决定

**检查真实画出来的页面，不猜源码。** 浏览器排出来的版面才知道标签有没有压在一起，所以在页面所在的框架里跑，用 `getBoundingClientRect` 和计算样式，不分析脚本文本。

**一段代码，两处运行。** `packages/core/src/drawnCheck.ts` 的 `DRAWN_CHECK` 是一段自包含的 JavaScript 字符串（和 `layoutProbe.ts` 一样，不走打包，免得构建工具往函数里插东西后在框架里跑不起来）：

- 打开着的看板页面（沙箱的 `dash.ts`）在数据到齐、没有来源在加载或刷新时跑它，结果进 `DashReport.drawn`，由编辑器写进 `.runs.json` 的 `drawn`，也列在“数据来源 → 问题”里。这是 Claude Code 改完之后读的那条路。
- `check --snapshots` 的版面探针把它并进每个框架的结果，报成 `layout` 警告。没开编辑器、在终端或云端跑的 agent 走这条路。

**核心不带措辞。** 一条发现是规则 id 加它说的是什么：`{ rule, element, source?, text?, other?, more? }`。`element` 是 `<div#id.class>`，`source` 是最近一个 `data-source` 的数据集，让修的人能定位到图和数据。措辞由命令行（`cli.layoutRules`）和编辑器（`dash.problems.drawn`）各自用词条说；`.runs.json` 里是结构化数据，skill 里写明每个字段的意思。

## 规则

| 规则 | 什么时候报 | 为什么这样定 |
|---|---|---|
| `nan` | 可见元素自己的文字里有 `NaN`、`Infinity`、`undefined` 这样的整词；或 SVG 里 `d`、`width`、`cx`、`transform` 等绘图属性的值含 `NaN` / `Infinity` | 日期或数字没解析、字段名写错，d3 不抛错，只画出坏值。属性里的 `NaN` 看不到字但图是坏的 |
| `empty` | 带 `data-source`、没有 `data-field` / `data-row` / `data-where` 的容器（图表或表格）：里面的 `<svg>` 没有图形，或表格没有行，或什么也没有；数据在加载或出错的不报 | 只有坐标轴（`.tick`、`.domain`）的图什么也没说。单个数字的“空”状态已有 `data-dash-source-state=empty`，这里只管容器 |
| `labelOverlap` | 同一个 `<svg>` 里两个文字标签的框重叠，重叠面积不小于较小者的 25% | 25% 排除字距和描边的擦边，又抓得到刻度挤在一起。标签超过 400 个的（热力图）不判 |
| `labelClipped` | `<svg>` 的 `overflow` 不是 visible，而标签的框超出它的边缘 1.5 像素以上 | 轴标签留的边距不够，被图的边缘切掉一半 |

同一个元素的同一条规则只列一处，其余记在 `more`，免得一个坏掉的比例尺列出几十条。每个框架最多 30 条。都是警告：一个有意压住的标注可能是设计，检查器分不出来。

## 误报的取舍

- **看得见才算。** 元素自己或任何祖先是 `display: none`、`visibility: hidden` 或完全透明（没激活的标签页、藏起来的提示框），一律不查：读者看不到的东西没有对错。用 `checkVisibility`，没有时逐级往上看计算样式。
- **`undefined` 只在像值的地方报。** 散文里写“变量是 undefined”不是错；只有整段文字就是它，或紧挨着 `%`、货币符号时才算一个没算出来的值。`NaN` 和 `Infinity` 不限。
- **纯 CSS 画的图不算空。** 没有文字也没有 SVG、画布、图片的容器，要里面一个都没有画出颜色或边框才报；用一个带背景色的 div 当进度条是正当的。
- **画到一半不量。** 打开着的页面里，页面一有改动（含 d3 过渡每一帧改属性）就重新安排一次报告，安静下来才量，所以不会在动画中途报标签重叠或空图；读者自己点开一个标签页画出的坏图也会补报。
- **嵌套的 `<svg>` 各管各的**：外层不数里层的标签，避免同一个标签在两个元素下各报一次。

## 和别的检查的分工

- 标注核对（`marks`）管“显示的数和数据对不上”；这里管“显示的东西本身就是坏的”。
- 版面探针的 `clipped` 管 HTML 文字被框裁掉；`labelClipped` 管 SVG 文字，因为 SVG 的裁切不是 `overflow` 样式能量出来的。
- 这四条不分类型，在画板和幻灯片里也查（`NaN` 在哪里都是错）；`empty` 靠 `data-source`，只有看板会触发。

## 没定的

- 画布（`<canvas>`）画的图看不见里面的图形，只能说容器里有画布；要查要读像素，暂时不做。
- 把 `drawn` 里的条目在编辑器里点一下就在页面上高亮那个元素：现在只写元素名。
