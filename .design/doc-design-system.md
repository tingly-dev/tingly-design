# 文档穿上设计系统

状态：**已实施**（文档：顶栏“主题”、编辑器的页面、HTML / PDF / PNG 导出、微信公众号；内置的“WeChat”风格，带一套完整的文档词汇）。Word 导出、对比度提示是没做的，见 §7。起因是微信公众号导出（[wechat-export.md](./wechat-export.md)）里“所见即所得”这条原则：文档只有字体和宽度两项外观，没有地方说“这份文档按我们的品牌画”。

## 1. 要解决的问题

画布和幻灯片可以套设计系统的主题（[project-theme.md](./project-theme.md)）；文档不行。人想要的是：这份文档的颜色、字体、圆角跟着一套设计系统走，**编辑器里看到的就是导出的**（HTML、PDF、PNG、粘贴进公众号）。公众号的第一版导出曾经自己加上了“公众号常见的样子”（绿条、灰底），文档没有的东西凭空多出来，这破坏了所见即所得；改成默认画文档自己的样子之后，“公众号的样子”该住在哪？答案是它本来就是一种设计系统。

## 2. 前提：文档的文件里没有颜色

画布和幻灯片的主题是**把文件里的值换掉**（文件里存的是普通值，没有 `var()`）。文档的文件是 Markdown，没有颜色可换，也不该有：写进去就不再是一份能到处用的纯文本，Claude Code 也没有约束。所以文档走另一条路：**文件只存选择，画的时候才从 tokens 解出值**。

## 3. 决定

**数据：** `doc.json` 里两个键，和画布、幻灯片同名同形：

- `designSystems`：装入的系统，`DsRecord` 的列表；它的副本在 `ds/<名字>/tokens.json`（装入走和画布、幻灯片同一个 `POST /design-systems`，服务端按类型选索引文件，文档用 `doc.json`）。
- `theme`：`{ system, theme }`，穿着哪个系统的哪个主题。没有这个键就是文档自己的样子；不需要 `theme.base`（去掉记录就回去了，不用记原样）。

**一份取值，所有出口读它：** core 的 `docLook.ts`。`DocLook` 是一张取值表（页面色、文字、标题、次要文字、链接、线、代码和表头的底色、引用的竖线、高亮、标题字号、两套字体、圆角、文字颜色名的值）。两个来源：`docOwnLook`（编辑器一直画的样子，也是 HTML 导出的样子）和 `docLookFromSystem`（一套系统的一个主题）。后者用 `colourRoles`（画布和幻灯片主题已经在用的“角色”读法：页面、卡片、文字、次要、弱、线、强调）和 `dsGlance` 里的标题字体和正文字体、圆角里的第二个值；一个角色系统里没有就退回文档自己的值。系统的页面色偏黑时 `dark` 为真：文字颜色名（红橙绿蓝紫灰）用深色页上的值，高亮改半透明。设计系统一开始是为幻灯片和画布定的：十几个通用的颜色角色、一组按 1920px 幻灯片定的文字样式、组件和封面，没有“一段文字怎么排”的概念，所以文档穿上系统，大部分元素（引用、代码、表头、高亮、段距、列表缩进、小标题）系统根本没法说话，只能从通用角色硬推或用文档自己的。解决办法是给设计系统一套**文档词汇**（core 的 `docRoles.ts`，`DOC_ROLES`）：全是系统自己 `tokens.json` 里的普通 token，名字以 `doc-` 开头，不增加任何新语法，手写、Claude Code 写、从风格生成的系统都一样带得上。

| 种类 | 名字 | 说什么 |
|---|---|---|
| 颜色（按主题） | `doc-heading` `doc-link` `doc-quote-bar` `doc-quote-bg` `doc-code-bg` `doc-code-ink` `doc-table-head` `doc-mark` `doc-rule` | 标题字、链接、引用的竖线与底、代码的底与字、表头的底、高亮、线 |
| 文字样式 | `doc-h1`…`doc-h4` `doc-body` `doc-code` | 字号（px/rem）、行距（倍数或长度）、字重；`doc-h1` 的字重和行距管所有标题，`doc-h4` 的字号管 h4–h6，`doc-code` 管代码块（行内代码大 1px） |
| 间距 | `doc-column` `doc-gap` `doc-indent` | 正文栏宽、段距、列表缩进（px） |

**值之外：元素的装饰（`doc` 族）。** 上面是“值”。一套文档设计语言还会给元素加**装饰**：标题旁一道色条、图片外一圈相纸边框、分割线换成虚线。这些不是值，用值表达不出来（给每个元素的每种装饰都起一个 token 名会爆炸），所以 `tokens.json` 里有一个 `doc` 族：每个 token 以元素命名（`h1`…`h6`、`p`、`quote`、`code`、`pre`、`img`、`hr`、`table`、`th`、`td`、`a`、`ul`、`ol`、`li`、`mark`、`strong`），值是一串 CSS 声明，里面的 `{名字}` 是系统自己的颜色或长度 token（沿用 tokens.json 里别名的写法），按文档穿着的主题填成值，所以装饰跟着主题、不写 `var()`。`docDecor.ts` 管这一族：只认编辑器页面、导出和公众号编辑器**都保留**的属性（颜色、背景色、边框、圆角、内外边距、字号字重、字距、行距、对齐、缩进、装饰线、宽度、display 三个值、列表符号），阴影、定位、浮动、flex、grid、transform、`url()`、`var()`、`!important` 一律拒绝并在“问题”页说出原因，和别的读不了的 token 一样。它解析成 `DsTokens.docStyles`（不进 `others`，因为它不是谁会当值读的 token，所以生成 CSS、README 附录的数量、间距页都不用动）；`docLookFromSystem` 填成 `DocLook.decor`，编辑器页面（`docDecorCss`，作用域在 `.docbody` 下）、HTML / PDF / PNG（`docLookCss` 末尾）、公众号（`wechatStyles` 写在每个标签自己的值之后，所以优先）读同一份。**文档只读 `tokens.json`**：系统里 `components/bundle.css` 的类（比如 `wx-h1`）是给组件和幻灯片的，对文档没有作用，这一点写进了 design-system 的 skill。设计系统的“文档”页把系统写了的装饰也列在角色清单里，README 附录也列出来。

没写的角色：颜色从通用角色推（标题 ← 文字，链接和引用线 ← 强调，代码底和表头 ← 卡片，线 ← 线），其余用文档自己的值；读不到或越界（字号 10–72、正文 10–28、代码 9–24、行距 1–3、栏宽 280–1200、段距 0–48、缩进 8–64）也退回。系统里**别的**文字样式（幻灯片的标题 72px）一概不读，所以那 36 个 html-ppt 风格没有 `doc-*`，字号仍是文档的。`docRoleReport` 给每个角色报出“系统给的 / 推出来的”和最后画出来的值，设计系统的“文档”页用它（[design-system-guide.md](./design-system-guide.md)）。内置的 WeChat 风格带着除 `doc-code-ink` 和 `doc-mark` 以外的全部（那两项留着当“推出来的”示例）。

**谁读它，各是一个小函数：**

| 出口 | 怎么读 |
|---|---|
| 编辑器的页面 | `docLookVars` 写成自定义属性（`--look-*`，文字颜色名的 `--doc-*`）放在 `.docpage` 上；`.app.docs[data-wears]` 下的一组规则用它们（`docs.css` 末尾）。只作用在文档页，编辑器的外壳、菜单和评论栏仍是编辑器的主题 |
| HTML、PDF、PNG | `docLookCss` 生成整张样式表（页面色放在 `html,body`），字体用 `lookFontCss`（托管字体 `@import` 放最前，字体文件 `@font-face` 指向项目里的副本） |
| 微信公众号 | `wechatStyles(look)` 把同一份取值写成每个标签的内联样式；页面色带在文章最外一层的 `background-color` 里，所以深色系统贴出去还是它的样子 |
| Word | 暂不跟（§7） |

字号、行距和栏宽的去处：编辑器页读 `--look-h1…h3`、`--look-size`、`--look-line`、`--look-column`（页宽 = 栏宽 + 左右内边距，文档设成“宽”时仍然宽）；HTML / PDF / PNG 的 `body` 字体和页宽；公众号的 `wechatStyles`。系统没有栏宽就由文档自己的宽度设置决定。

**交互：顶栏的“主题”（调色板图标）。** 位置：画布和幻灯片的“主题”在右侧面板，文档没有右侧面板，所以是顶栏弹层；同一个词、同一批卡片（`th-card`）。弹层里：“文档自己的样子”一张卡，每个已装入系统的每个主题一张卡（用它自己的页面色、文字色、强调色和字体画一个小样），一句现在穿着什么，最后一节“设计系统”（`DsInstall`：装入、更新、移除，内置风格按组展开）。

- **点一下就换，没有预览态**：一步撤销（`editDoc`），回去的路是再点“文档自己的样子”或撤销。
- **装入即穿上**：第一次装入一套系统就穿它的第一个主题（等它的 tokens 到了编辑器再写 `theme`）；更新已装入的不改穿着。移除正在穿的系统，服务端同时删掉 `theme`，文档回到自己的样子。
- **对 Claude Code**：`settingsProject` 里文档带 `designSystems` 和 `theme`；换主题走 `recordChange` 的 `theme`（文档没有“没跟着变的颜色”，不会提议）；装入不发 `designSystem` 的提议，那条的话是“让 Claude 把现有内容重画成这套系统”，文档没有内容可画。

**微信：内置的“WeChat”风格，不是导出里的特例。** 风格的列表（`LOOKS`）多了一组“发布平台”（`platform`），手写的一项 `wechat`：白页、#333 文字、平台的绿 #07c160 作强调、浅灰的卡片和线、PingFang / 微软雅黑字体、圆角 4/6/8，文字样式 `doc-h1…h3` 24/20/18、`doc-body` 16px 行距 1.8，栏宽 `doc-column` 677px（取自平台阅读器和自己的插件的默认值）。它和 36 个 html-ppt 风格一样装入、一样选（名字不翻译，沿用 `ds.look.*` 的规则）。装入后文档在编辑器里就是那个样子，引用的竖线和链接是绿的，贴出去也是。它自带一份**说明**（`starter.lookDescription.wechat`，英文和中文各一；任何内置风格在这个组里有了自己的 id 就有说明，没有硬写“平台风格”）：颜色各自的用途、字体与形状、为平台写时编辑器留下什么（只留标签上的 `style`、正文栏约 677 px、外链改成文末编号、图片小于 1 MB）、怎么以它为底做另一个风格。设计系统本来就能带描述（README），所以说明和 tokens 放在一起，给以后用 agent 生成新风格的人读：用它新建设计系统时它就是 README（html-ppt 的风格则是署名那一份，`lookReadme` / `lookDescription`），装入文档时写在副本旁边的 `ds/look-wechat/README.md`；有没有说明由 `hasLookDescription(id)` 说了算，类型就是 i18n 里那个组的键，新加一个风格的说明要中英文都写才编译得过。预览里的“用微信的样子”走 `applyLook(CHANNEL_LOOK.wechat)`：发布渠道到它推荐的风格是一张表，以后加渠道是加一行。预览不再有自己的样式选择，只说跟着哪个主题，并给“更换…”（打开这里的主题）和没穿系统时的“用微信的样子”（一步装入并穿上）。

## 4. 考虑过没选的

| 方案 | 为什么不 |
|---|---|
| 像画布那样把值写进文件 | 文档的文件是 Markdown，没有值可换；写进去就不是一份纯文本了 |
| 每个导出各自选样式（公众号里选“微信绿”，PDF 里选别的） | 多出一条和文档自己的样子无关的轴；所见即所得要求编辑器里看到的就是导出的 |
| 用全局 CSS 把编辑器的 token（`--ink`、`--panel`…）整个换掉 | 会把编辑器的外壳、菜单、评论栏一起染上；只让文档页穿 |
| 在预览里选系统 | 预览里改的会悄悄改了文档（副作用越过当前这一处）；改成只读加一个“更换…” |
| 系统里有文字样式就用它的字号 | 现有 36 个风格的类型样式是为 1920px 的幻灯片定的 |

## 5. 对照 UX 原则

- 一词一义（3）：这里的“主题”和画布、幻灯片的“主题”是同一个词、同一批卡片；编辑器自己的外观仍叫“外观”，在“更多”里。
- 轴要分开（4）：文档穿哪个系统、哪个主题，是一条轴，写在文档里；输出渠道（公众号、PDF）是另一条，不各带一份样式。
- 聪明的默认（6）：不穿系统是默认，装入即穿上，不多一步“再去选”。
- 完成不等于锁死（10）：撤销、再点“文档自己的样子”、移除系统，三条路都回得去。
- 把下一步的东西交到手上（11）：预览里“用微信的样子”一步到位；装好之后文章就是它的样子。
- 副作用限于当前这一处（12）：不碰 `ds/` 以外的文件，不碰别的项目；预览不改文档，要改走主题。

## 6. 每种类型

只有文档用这个办法（画布、幻灯片用 [project-theme.md](./project-theme.md) 的办法，设计系统是来源，看板和动效不装设计系统）。

## 7. 还没做 / 还开着

- **Word 导出**不跟：它用自己的字体和颜色表（[docs-docx.md](./docs-docx.md)），之后可以读同一份 `DocLook`。
- **36 个 html-ppt 风格没有 `doc-*`**：它们的文档字号仍是文档的；要不要为它们各推一套文档用的字号，还没定。
- **词汇的边界**：现在 18 个值角色加一个装饰族；代码的语法颜色、表格斑马纹、任务项的勾选色、h5 / h6 各自的字号、标题上下间距，先看有没有人需要。
- **对比度**：画布的主题页会列文字放在底色上的对比度；文档还没有，系统的 `ink` 在它的 `surface` 上多半没问题，但“强调色的链接在页面色上”可能不够。
- **按标签页覆盖**：一份文档一个主题；一个标签页换一套样子没有人要过。
- **公式和图示的图**：Mermaid 和公式画成图片，仍是白底浅色，不跟深色页（公众号导出里）。
- **命令行**：`export --as wechat` 用文档穿着的系统（读 `doc.json` 的 `theme`）这一条还没在命令行端到端跑过（命令行的 Chrome 在容器里起不来）；穿上系统本身还没有命令行或 MCP 的入口。
