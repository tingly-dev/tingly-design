# 请求栏的外形：一张卡，三行

状态：**已实施**。请求栏（`RequestBar`，画布、幻灯片、动效的 `PromptBar` 和其余类型的 `AskClaude` 共用）原来把八样东西挤在一条窄带里：目标、Fast AI / Claude Code 切换、历史、位置、折叠、回形针、输入框、发送，选项行再挂在下面。人看到的是一排大小不一、对不齐的控件，哪个是这次请求的设置、哪个是整个栏的工具，分不出来。本篇是它的取舍，位置和对话列见 agent-panel.md、chat-panel.md，图像生成见 image-generation.md。画板是 `projects/tingly-design-ui` 的 Composer。

## 1. 决定的形状

一张圆角 16 的卡，三行，每行回答一个问题：

| 行 | 内容 | 回答 |
|---|---|---|
| 头 | 左：这次请求针对什么（整张画板、第 3 页、选中的元素）；右：历史、位置、折叠三个安静的图标 | 我在对什么说话，栏本身怎么摆 |
| 输入 | 附件缩略图（有才出现）和输入框 | 我要说什么 |
| 工具条 | 左：回形针，这次请求的设置（"新对话 / 接着：…"、ImageGen）；右：谁来回答（Fast AI｜Claude Code），圆形的发送 | 这次请求怎么发、谁来做 |

规则：

- 设置是药丸，开着是强调色，关着是灰色加删除线，只读的（"每次都是新的"）是不能点的灰；整栏的工具是图标，不画框。两类东西长得不同，才分得清。
- 谁来回答是一个中性的分段控件，放在发送旁边，因为它决定发送去哪。选中的那段是白底（暗色下是面板色）加轻影，不用强调色，强调色留给"可以发送"。
- 发送是圆形图标按钮：输入为空是灰的，有内容是强调色，运行中变成描边方块（停止）。名字仍是"发送 / 停止"，读屏和 e2e 按名字找。
- Fast AI 目标下没有 ImageGen（只有 Claude Code 有这个工具），工具条左边只剩"每次都是新的"。仪表盘和设计系统本来就没有 ImageGen。
- 历史、位置、折叠仍是头行右边的三个图标；备选是收进一个 ⋯ 菜单，现在这三个都是高频或需要看见状态（历史有未读，折叠有状态），留在外面。

## 2. 左侧对话列（窄）

列只有 360px 左右，工具条放不下所有东西。做法是让设置药丸**独占工具条的上一行**，下一行是回形针、分段控件、发送。没有选"药丸只留图标"：图标省下的宽度不多，却让"新对话"这类有意义的词消失。

## 3. 折叠

折叠成一粒药丸（`BarPill`，"Claude Code 在运行 · 4 步"）没有变。

## 4. 命名

图像生成的名字统一叫 **ImageGen**，中英文都不翻译，设置里的区块、药丸、提示和错误都用它。一个词在整个产品里只有一个意思，也不再有"图像生成"与"生图"并存。`project-kinds.md` 矩阵里那一行的键是文档里的概念名，没有跟着改，免得 `e2e/coverage.json` 一起动。

## 5. 没做的

- 窄列里的分段控件仍是两段，不是一个下拉；再窄的列（拖到最小宽度）会让它换行。
- 运行中的卡片（`RunFeed`）只换了外框的圆角，内容没动。
