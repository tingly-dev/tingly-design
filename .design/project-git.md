# 项目和 git：提交到哪、没有仓库时怎么办

状态：**已实施**。测试是 `e2e/git.py`。

## 1. 要解决的问题

项目可以放在任何文件夹里（[project-folders.md](./project-folders.md)），提交却原先写死在项目文件夹所在的仓库里跑，而且只有画布的改动记录里有一个提交按钮，用浏览器的 `prompt()` 问一句说明，不说会提交到哪里。由此带出三个问题：

- 项目不在任何仓库里（npm 安装后的 `~/.tingly-design/projects`、随手新建的文件夹）时，只会报“不在 git 仓库里”，没有下一步。
- 项目在别人的代码仓库里时，提交落在那个仓库的当前分支上，点之前看不出来。
- 六种类型的入口不一致。

## 2. 选过的办法

| 问题 | 选项 | 结论 |
|---|---|---|
| 没有仓库 | A 只提示；B 给这个项目建一个它自己的仓库；C 在数据目录建一个大仓库装所有项目 | **B**。一个项目一个仓库，搬走、分享、删掉都只牵动它自己；C 把不相干的项目绑进同一段历史 |
| B 什么时候建 | 单独一个“建仓库”按钮；第一次提交时顺带建；新建项目时建 | **第一次提交时**是默认：确认框里说“会在 `<文件夹>` 新建一个，只给这个项目用”，确认一次就建好并提交，不多一步。**新建项目时**是给想一开始就有仓库的人的可选项（起步选项里一个勾选，默认不勾） |
| 用哪个仓库 | 固定某处；离项目最近的那个 | **最近的那个**：git 自己往上找。想把仓库建在更上层的人自己 `git init` 就行，不需要设置 |

## 3. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 提交什么 | 只提交这个项目的文件夹（`git add -A -- .`、`git commit -- .`，都在项目文件夹里跑）；同一个仓库里别处已暂存或没暂存的改动都不碰 | 项目在别人的代码仓库里时，不能把人家写到一半的代码一起提交 |
| 本机文件 | 改动记录 `.journal.jsonl`、看板运行记录 `.runs.json`、Claude Code 对话的会话号 `.claude-session.json`、渲染出的视频 `renders/` 从不提交；新建仓库时顺手写一个列出它们的 `.gitignore` | 它们只属于这台机器上的这个服务；写进 `.gitignore`，在终端里提交也会跳过 |
| 提交前说清楚 | 提交对话框先问服务端（`GET /api/projects/:p/git`）：有仓库时写“提交到 `<仓库>`，分支 `<分支>`”和改了几个文件；没有改动时提交按钮不可点并说明；没有仓库时写会在哪里新建，按钮变成“新建仓库并提交” | 第 7 条：诊断走真实路径。问的就是会被用到的那个仓库 |
| 不经同意不建 | `POST …/commit` 不带 `init` 时，没有仓库就只返回说明；只有对话框里确认过才带 `init` | 建仓库是对人的文件夹做的改动 |
| 新建时可选 | 新建对话框“起步选项（可跳过）”里“同时创建 git 仓库”，默认不勾，只在目标文件夹不在任何仓库里时出现（`/api/folder` 的 `repo`、`/api/health` 的 `projectsInRepo`）；勾了就建仓库并做第一次提交 | 第 6 条：默认够用（第一次提交会建），想要的人一勾就有；已经在仓库里的位置不显示一个没有意义的选项 |
| 入口 | 共用顶栏的同步状态（历史图标）打开改动记录，里面是“提交到 git”；六种类型是同一个 `JournalPopover`，对话框挂在 `<body>` 上 | 跨类型功能做一次 |
| 提交说明 | 默认 `design(<项目名>): update`，可改 | 不按类型拼标题（原先用的是画布标题，别的类型拿不到） |
| git 身份 | 不替人设置 `user.name` / `user.email`；没有配置时把 git 的原话显示出来 | 提交以谁的名义是人自己的事 |

## 4. 没定的

- 没有推送（push）和拉取，也没有分支切换：编辑器只做“存一个快照”。
- 提交后改动记录不会标出“这里提交过”。
- 不在任何仓库里的项目，仓库建在项目文件夹里；从别处打开的项目如果事后被搬进了一个仓库，会改用那个仓库，旧的 `.git` 不会被清理。
