# 按目录管理：打开一个文件夹作为分组，项目引用其他项目或文件夹给 Claude 看

状态：**已实施**（命令行和 MCP 还没有入口，见 §6）。测试是 `e2e/folder_groups.py`。

## 1. 要解决的问题

一批相关的作品常常放在同一个文件夹里：同一个品牌的设计系统、官网画布、介绍幻灯片、动效；或者一个仓库的 `design/` 下面一排子文件夹。现在要在 Tingly Design 里用它们，得一个一个"打开文件夹"（[project-folders.md](./project-folders.md)）；新建在那里的项目也不会自己出现。

第二个问题是 Claude Code 只看得到当前项目的文件夹。改官网画布时想让它对照同一批里的设计系统，只能把内容复制过来，或者在提示里写路径、再祈祷它被允许去读。两边都应该是一个动作：把这一批文件夹打开一次；在项目里说"改这个的时候可以看那些"。

## 2. 用词

启动页已经有"分组"（[launcher.md](./launcher.md) §3：单层标签，一个项目至多一个，磁盘上仍是平的）。这次不再造第二个词（ux-principles 第 3 条）：

- **打开的文件夹**：人的说法仍是"打开文件夹"，它里面的项目在启动页里列在以这个文件夹命名的分组下。分组还是那个分组，只是名字和成员来自磁盘，不是人手填的。
- **引用**：一个项目可以"引用其他内容"，让 Claude 在改它时去读。没有"工作区""集合""依赖"这类新词。

## 3. 选过的办法

### 3.1 文件夹分组怎么存

| 办法 | 好处 | 问题 |
|---|---|---|
| A. 打开时把每个子项目都登记进 `.links.json` | 零新机制 | 之后在文件夹里新建或删除的项目不会跟着变；单个移除又会和"整个文件夹"打架；`.links.json` 里混进了本来就能从磁盘上读出来的东西 |
| B. 另起一个"工作区"概念，带自己的页面和设置 | 能放更多东西（共享的引用、设置） | 人要先想清楚"工作区"是什么才能用；和分组两套并存（第 2、3 条）；六种类型都要接 |
| C. **登记文件夹本身**（`.folders.json`，`{ id: 路径 }`），成员是看一眼磁盘得到的 | 新建、删除、改名在磁盘上发生就跟着变；登记只有一行；成员走和别处项目同一条路（`links` 表和 `projectDir`），其余服务端一行不改 | 成员不稳定地出现，要在列表和按名字找不到时重新看一次 |

选 C。成员只在内存里进入 `links`，用 `memberNames` 标出，写 `.links.json` 时跳过：文件里仍只有人亲手打开的项目。名字还是 `idFor(路径)`，所以一个项目无论是单独打开还是在打开的文件夹里，名字相同，日志、会话、分组的键不变。

### 3.2 什么算"一个文件夹的项目"

只看直接子文件夹，一层，不递归；点开头的文件夹不算；符号链接指向文件夹算。递归会在大仓库里扫很久，也让"这个文件夹是什么"变得不确定；一层刚好对应"一批并排放的项目"。文件夹本身是项目时按项目打开，不当分组（接口返回 409，对话框里直接是项目）。

### 3.3 和人手填的分组怎么共处

人填的分组（`.groups.json`）优先于文件夹名：把成员"移到分组"就进了那个分组，"移出分组"回到文件夹名下。卡片带 `folderGroup { id, path, derived }`，`derived` 说明现在显示的分组是不是文件夹给的；是的话菜单里不出现"移出分组"（那是个什么都做不了的按钮，第 9 条）。成员的 ⋯ 没有"从列表移除"：它在列表里是因为文件夹开着，单独移掉会在下一次扫描回来；要移就关文件夹（分组标题上的按钮，吐司里有撤销）。

### 3.4 引用存哪、引用什么

| 问题 | 决定 | 为什么 |
|---|---|---|
| 存在哪 | 项目自己的 `.references.json`（`{ paths: [绝对路径] }`），本机状态：不进 zip，不进提交（`git.ts` 的 `LOCAL`），和 `.image.json` 同类 | 路径是这台机器的，换一台就是错的；它是"这个作品这台机器上让 Claude 看哪里"，不是作品的内容 |
| 用路径还是名字 | 路径 | 项目的身份就是文件夹（[project-identity.md](./project-identity.md)）；名字是可重复的句柄，登记变了会变 |
| 引用什么 | 一个项目，或者一个装着项目的文件夹（不要求已打开） | 两种都是人会说的"参考那个设计系统""参考那一批"。任意文件夹（比如代码仓库）这次不做：它不是 Tingly Design 的东西，界面上也没法说清它是什么；见 §6 |
| 怎么选 | 项目菜单里"引用其他内容…"，一个对话框：已打开的文件夹和其他项目各一组，每行一个复选框，点一下就存，没有"保存"按钮 | 第 6、10 条：改了就生效，也随时可以改回来。不是模式选择，不先问"引用哪种" |
| 引用的东西不见了 | 留在列表里标"找不到"，请求里略去 | 文件夹可能在没挂上的盘上；和 `.links.json` 悬空一样不忘掉 |
| 不能引用自己 | 服务端拒绝（`refSelf`） | 一个项目的文件夹本来就给 Claude 了 |

### 3.5 Claude Code 怎么拿到引用

每次请求（编辑器、`prompt` 命令、MCP 都经 `startDelegate`）：

- 引用的文件夹各加一个 `--add-dir`，Claude 才被允许读；
- **只读靠权限规则，不靠提示词**：引用里的每个项目文件夹（文件夹引用则是其中每个项目）加 `--disallowedTools Edit(//绝对路径/**)`，Edit 规则同样管 Write；当前项目本身即使在被引用的文件夹里也不在其中，所以"引用整批、而自己就在这一批里"可行；
- 用户消息里加一段"Reference folders"，说是别的作品、只读，每个项目是哪一种（引用文件夹则列出里面的项目和种类）。提示词是给 Claude 看的说明，不是防线。

没有选"以只读方式 --add-dir"：Claude Code 没有这样的开关，`acceptEdits` 对加进来的文件夹同样放行编辑，所以用拒绝规则补上。文件夹引用的拒绝规则是启动时数出来的项目：之后新建的项目这一次请求里没有被拒绝，但提示词仍说只读；下一次请求就覆盖了。

## 4. 六种类型

打开文件夹、成员、引用都发生在 `projectDir` 和 `startDelegate` 之下，和类型无关；`DELEGATE` 表给每种类型一个说法（"canvas / deck / design system / dashboard / doc / motion"），用在引用说明里，新类型缺了会编译不过。`e2e/folder_groups.py` 的文件夹里放着六种各一个，逐个设引用、逐个发请求、检查参数。矩阵见 [project-kinds.md](./project-kinds.md) §3。

引用没有放进 `settingsProject`（[config-awareness.md](./config-awareness.md)）：那一张表是"项目文件里的设置"，会让 Claude 在下一次请求里知道"人手改了什么"；引用不是从项目文件读出的值，每次请求本来就带着，没有"改了以后要告诉它"的步骤，所以也不出现跟进条（`followUp`）。

## 5. 界面

- 启动页"新建项目"菜单的"打开文件夹…"：里面是一批项目时，状态行说"这个文件夹里有 N 个项目：a、b、c …，打开后它们会一起列在『文件夹名』下"，按钮还是"打开"。同一个对话框，不多一个入口（第 2 条）。
- 分组标题：文件夹名、数量、文件夹路径（等宽，真实值），最右一个"关闭文件夹"，只去掉登记，吐司里有撤销。
- 请求栏：和图像开关并排的一个常显的"引用 N"小块，点开就是引用对话框。引用是对 Claude 说话时用的，入口就放在说话的地方；最初只放在项目菜单里，人找不到（第 8 条：教育放在产品里）。
- 项目菜单（每种类型的顶栏最左，所以六种自带）："引用其他内容（N）…"，同一个对话框的第二个入口。

## 6. 没定的

- **命令行和 MCP 还没有入口**：`tingly-design prompt` 和 MCP 的 prompt 工具已经带着引用（同一个 `startDelegate`），但引用的增删、`open` 一个文件夹作为分组只能在编辑器里做。要加的话是 `commands.ts` 里的一个 `refs` 命令和 `open` 认得出文件夹。
- 引用任意文件夹（代码仓库、素材文件夹）：对"让 Claude 照着代码改设计"很有用，但界面上没有好的方式说出"这是什么"。要做的话，对话框里加"添加路径…"，状态行用 `GET /api/folder` 说它是什么。
- 一个文件夹分组自己带引用（"这一批都参考 brand"）：现在每个项目各设一次；成员多了会烦，但会引出"组的设置存在哪"（文件夹里放一个点文件，还是 `.folders.json` 里）。
- 嵌套：文件夹里的文件夹里的项目不算成员。真有人这样放，再考虑可选的深度。
- 文件夹分组里同名（文件夹名相同）的两个分组会在启动页合成一段；卡片上有各自的真实路径，没有额外处理。
- 文件夹被挪走：成员暂时消失，登记还在，没有"重新指定"（和 [project-folders.md](./project-folders.md) 的文件夹一样）。
