# 动效的手艺：把"好不好看"写进 skill 和检查器

状态：**方案**（未实施）。调研见 [`.research/opendesign.md`](../.research/opendesign.md)；这里只留下决定要做的那一小部分。

## 1. 问题

动效的 skill 和检查器回答的都是"能不能放"：文件格式、时间属性、能否导出、文字有没有来得及读。模型写出来的动效常见的毛病却在"好不好"：元素挤在同一时刻进场，进场快到看不清或慢到拖沓，所有东西都在动、没有一个主角，没有停顿让人读完。这些不是格式错误，所以现在没人提醒，模型也没有可参照的标尺。

## 2. 别人怎么做

OpenDesign 的动效 skill 和 motion-anything 的规格各写了一份"品味"：先写节拍表，一个主动作、其余配合；按动作类型给时长区间；缓动按用途选；同屏进场数量有预算；每条都写 reduced-motion 兜底。它们是写给 agent 的文字，没有任何检查。

## 3. 方案

### 3.1 写进 skill（主要的价值）

在 `.claude/skills/motion/SKILL.md` 加一小节，`delegate.ts` 里动效的系统提示和快速 AI 的 `FAST_EDIT_MOTION` 同步一句话指向它。内容只保留对"逐帧渲染的视频"成立的部分，控制在二十几行内（skill 每次任务都会被读，随 npm 包发布）：

- **节拍**：先想每个场景一句话要观众记住什么，谁是主角；一个场景一个主动作，其余动作配合它。
- **时长区间**（写在 `data-in` / `data-keys` 里的数字的起点，不是上限）：小点缀 120–220 ms，主要元素进场 350–650，形状变化 600–1200，大揭示或镜头移动 900–1800。
- **缓动按用途**：进场 ease-out，退场 ease-in，镜头 in-out，机械感匀速；精确的东西默认不弹。
- **停顿**：动作和静止交替，最重要的那一下前面留静；文字至少停够读完（检查器已有）。
- **毛病对照**：像幻灯片 → 让一个对象贯穿变形；挤 → 选主角、其余延后或删；没分量 → 调时长和缓动；忙而空 → 删装饰、留因果。

### 3.2 检查器（只给警告，不给错误）

`planScene` 已经为每个元素算出了进出场区间，并有 `warning` 一档（文字不够读、embed 缺 `data-seek`）。再加两条，同样走"问题"列表和 `tingly-design check`：

| 规则 | 何时警告 | 为什么 |
|---|---|---|
| 进场时长离谱 | `data-in` 的时长小于 100 ms 或大于 2 s（`slam` 本来就快，不算） | 前者看不见，后者拖沓；都多半是写错单位 |
| 同时进场太多 | 一个场景里任一时刻正在进场的元素超过 4 个 | 观众没有主角可看；默认的错开（0.15 s）下四五个短元素就会达到，所以阈值要用示例校准 |

两条都是启发式，措辞写成"可能"，不拦导出。

### 3.3 不做的

- **reduced-motion、只动 transform/opacity、60 fps**：这些是网页 UI 动效的规则。我们的产物是逐帧渲染的视频，这三条不适用。`<x-embed>` 里的交互另论，不在这里。
- **整屏"克制预算"当硬规则**：同屏一个庆祝、一个环境循环这类说法没有属性可检查，只放进 skill 的文字里。
- **"微妙…电影感"档位拨盘**：是模式选择器；要的话应该是设计系统里一组具名的节奏 token（见 [rhythm-tokens-plan](../.research/opendesign.md) 提到的计划），不是一个开关。

### 3.4 校准

阈值定得不对，警告就会变成噪音，模型和人都会学会无视。验收标准：新建的起手场景和 `projects/` 里所有动效示例**零新警告**；再用一个故意写差的场景覆盖两条规则，写成 `packages/core` 的单元测试。

### 3.5 各类型

只涉及动效，没有新的跨类型功能，`project-kinds.md` 的矩阵不变。幻灯片的构建动画有自己的时长写法，是否套用同一份标尺，先不动。

## 4. 还没定

- 节奏 token 做出来之后，3.1 的区间换成具名 token 的默认值，文字里的数字退场。
