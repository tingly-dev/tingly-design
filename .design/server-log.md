# 服务端日志与改动记录的说明

已实施。

## 问题

快速 AI 和 Claude Code 的调用只在编辑器里看得到结果。出了问题（超时、没有密钥、CLI 报错、跑了很久）时，开发者和宿主没有地方看"服务端到底发生了什么"。另一头，改动记录（journal）里的"提交到 git"让人以为它和撤销是一回事。

## 日志

- 一个事件一行，写 stderr（stdout 留给宿主解析的 `TINGLY_DESIGN_READY`）。人读的是 `时间 级别 事件 key=value`，`DC_LOG_FORMAT=json` 时每行一个对象，方便宿主收集。
- 事件名是稳定的 `对象.动作`（`fast.start/done/aborted/error`、`delegate.start/step/finish`），字段在 `docs/*/development.md` 里列全。
- 级别用 `DC_LOG_LEVEL`（`error|warn|info|debug|silent`，默认 info）。info 只记一次调用的开始和结果（耗时、字符数、token 数、步数）；每个工具步骤是 debug，避免一次长运行刷屏。
- 提示词和回复不进日志，只记长度：里面可能有用户的文件内容和附件。
- 没有引入日志库：只有一个小模块 `apps/server/src/log.ts`，宿主要接自己的日志系统时读 JSON 行即可。

## 改动记录的解释

三个常被混淆的东西放在改动记录弹层顶部一段说明里，并写进画布指南：

- 撤销 / 重做：撤回自己的改动，按上下文定位，只在本次会话（最多 100 步）；Claude Code 的一次运行可整体撤销。
- 记录里的一行：一次保存到文件的改动，是记录，不是可以回去的快照。
- 提交到 git：真正的快照，撤销不改它，提交也不清撤销。

选择把说明直接放在弹层里（education inside the product），而不是只放文档或者做成提示气泡：用户在看记录的当下正好有这个疑问。

## 未决

- 记录行还不能"回到这一步"；若要做，需要把 journal 持久化，并和撤销的上下文定位合并考虑。
- 日志还没有按请求 id 贯穿一次快速 AI 与它触发的文件写入。
