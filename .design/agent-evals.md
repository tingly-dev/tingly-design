# 评测：agent 用 skill 或 MCP 能不能把设计做完

已实施（运行器、两条路线、打分、汇总、两个任务）；不接进 CI，约每周手动跑一次。

## 问题

e2e 管编辑器的交互，单元测试管格式和写回，`check --snapshots` 管作品有没有画坏。没有东西量的是**另一头**：一个 agent 拿到我们的 skill 或 MCP，能不能从一句话做出可用的设计、自己检查、改好、导出。skill 写得对不对、检查器漏了什么、工具的顺序顺不顺，过去只能靠人偶尔试一次。

一次对照实验（两个子 agent，同一个题目，一个走 skill 加命令行，一个只走 MCP）说明这是一个值钱的反馈回路：两边都做出了合格的页面，成本几乎一样，却撞上了同一批缺口，和走哪条路无关。所以要把这件事留下来，能重复跑、能比较、不依赖编辑器内部。

## 决定

**黑盒，独立于仓库其余部分。** `evals/` 只通过 Tingly Design 对外的三个面说话：命令行、MCP 服务、skill。不 import 仓库里的代码，不读源码。命令行从哪来由 `--cli` 决定：默认是仓库里的源码，也可以是 bundle 或 npm 装好的包，所以同一套评测能量一个已发布的版本。

**驱动是无头的 Claude Code**（`claude -p`），每条路线一个干净的工作区：

| 路线 | agent 拿到什么 | 不给什么 |
|---|---|---|
| `skill` | 命令行；格式说明用 `skills add` 装进工作区的 `.claude/skills`，就是产品发给别的仓库的那一份 | MCP |
| `mcp` | MCP 服务（`--strict-mcp-config`，只有它）；格式说明从资源和提示来 | skill、命令行的说明 |

两边都只读项目设置（`--setting-sources project`），不受这台机器上用户设置的影响。路线是不是守住了也记下来：`mcp` 路线里 agent 在 shell 里敲了我们的命令行就记成越界，`skill` 路线里用了 MCP 工具同理。

**题目是闭环，不是单步。** 一个任务（`evals/tasks/*.json`）是一句话的题目，要求做出来、用工具检查、看图、改、导出，加上期望（项目里各类条目的个数）、必须出现的词和一份给图像评审用的评分表。量的是整个循环，因为实验里真正的缺口（板子高度猜错、检查说"没问题"）都出在"看图改"这一步。先有两个：画布的定价页、四页的幻灯片；别的类型按需要加。

**打分分三层，只有第一层决定过不过：**

1. **确定性检查**，通过命令行读 agent 留下的项目：项目在、条目数对、任务点名的词都在、`check` 没有错误、画得出来（`check --snapshots`）、要求的导出文件在。警告只记录，不判失败：设计里的警告可能是有意的。
2. **过程指标**：工具调用数、`check` 和 `look` 的轮数、看了几张图、回合数、费用、用时、token、有没有越界。两条路线放在一张表里比。
3. **图像评审**（`--judge`，可选）：另一次 Claude 读最终的图，按评分表打 1–5，附一句最大的毛病。只作参考，不进通过与否，因为模型打分会漂。

**不进 PR、`pnpm test` 和 CI，约每周手动跑一次。** 每次真实运行要花钱、要几分钟、要登录的 `claude`，定时跑也没有必要：要看的是 skill、检查器、MCP 改动后有没有变差，一周一次、改了这几处之后再跑一次就够。进 `pnpm test` 的只有纯函数（读 transcript、打分）的单元测试，用固定的样本，不花钱。

## 考虑过、没选的

- 并进 `e2e/` 的 Python 套件：语言不同，而且 e2e 起的是源码里的编辑器，这里要能评测已发布的包。
- 用 mock 模型：要量的就是真实模型会不会用这套工具，mock 没有意义。
- 打分只靠评审模型：不稳定、贵，也给不出"没导出"这种硬事实。
- 自己用模型 SDK 写 agent 循环：要重做一遍工具集，偏离真实的 Claude Code 体验。

## 没定的

- 一次一条路线一个样本只能看趋势；要看方差用 `--runs N`。差多少算回退还没定。
- 结果往哪放：现在写在本地的 `evals/out/`，不进仓库；每周跑一次的结论写进相关的 `.research/` 或 issue。
- 更多类型的任务（看板、文档、动效；动效要 ffmpeg）。
- 只覆盖了 Claude Code 这一种客户端；Claude Desktop、IDE 连 MCP 的行为可能不同。
- 评审模型要不要校准（拿几张人看过的图对一遍）。

## 第一次实验带来的修改

实验里两边撞上的问题，已经在产品里补上：

- 画布板子比内容高很多，检查却说"没问题"：版面探针加了一条 `gap`，只对画布板子（从上读到下的页面）报，幻灯片的留白是有意的，不问。
- 板子的尺寸写在根元素、`canvas.json` 和 `$preview` 三处：根元素和 `canvas.json` 不一致本来就是错误；现在 `$preview` 不一致报警告，skill 把三处和"高度要按内容定"写明了。
- `check --snapshots` 只说"1 张图"：现在列出文件。
- `look` 的结果已经包含 `check` 的全部问题，说明里写明，避免白白多调一次。
- skill 的"不要编数字"遇上本来就是虚构的题目：写明虚构的品牌或演示可以写具体的数，并在回复里说明是编的。
