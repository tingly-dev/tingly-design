# 项目放在哪：项目文件夹之外的项目和默认数据目录

状态：**已实施**。测试是 `e2e/folders.py`。

## 1. 要解决的问题

项目原先只能是项目文件夹（源码里的 `projects/`，或宿主给的 `DC_PROJECTS`）下面的一层子文件夹。设计稿常常属于别处：和它描述的代码放在同一个仓库里、在另一个仓库、在共享盘上。想在 Tingly Design 里打开它，只能把文件夹搬进 `projects/` 或者做符号链接，搬了以后它就离开了自己的仓库，也离开了那边的 git 历史。新建项目同样只能建在 `projects/` 里。

另一个相关的问题：从 npm 装的包没有 `DC_PROJECTS` 时，项目和 AI 设置（含密钥）写在包自己的目录里（`node_modules/.../tingly-design/projects`），升级时整个目录被替换，项目跟着没了。

## 2. 选过的办法

| 办法 | 好处 | 问题 |
|---|---|---|
| A. 项目按绝对路径寻址（`?p=/Users/me/site`） | 不需要登记 | `?p=`、宿主的 `tingly-design:open`、日志、委托给 Claude Code 的路径、分组文件、`activeDelegates` 全是按"平的项目名"设计的，要改一遍；URL 里带出本机路径；名字和路径两种地址并存，处处要分支 |
| B. 换一个更大的工作区根目录（扫描任意深度） | 一个设置 | 还是要求项目在同一棵树下；扫描一个大目录很慢；"工作区"是一个人们要先想清楚再配置的东西（第 6 条） |
| C. **登记**：外面的文件夹以一个名字记进项目文件夹旁边的 `.links.json` | 其余一切照旧按名字走，`projectDir(name)` 一处查表；文件夹不动 | 多一个小文件；文件夹被挪走后，登记会悬空 |
| D. 符号链接放进 `projects/` | 零代码 | 跨平台差（Windows 要权限）；`seedSamples`、监听和 git 对链接的处理各不相同；用户看不到它是链接 |

选 C。和分组（`.groups.json`）同理：这是"我怎么整理我的工作区"，不是项目本身的属性，放在项目文件夹旁边、项目之外。

## 3. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 登记存在哪 | `<项目文件夹>/.links.json`：`{ 名字: 绝对路径 }`，服务端启动时读进内存，增删时原子写回 | 和 `.groups.json` 同一个位置；内存表让 `projectDir` 保持同步调用 |
| 名字从哪来 | 文件夹自己的名字转成合法项目名，和已有的名字（项目文件夹里的子目录、已登记的）加上由路径算出的 6 位短码（`site-3f9a1c`），不管有没有撞名都这样，同一个文件夹总是得到同一个名字，不取决于谁先登记。登记文件里旧的名字（手起的、按先后加 `-2` 的）读进来时保留成别名，仍能解析，第一次启动时文件整份改写成路径生成的名字 | 和新建对话框"文件夹名跟着标题走"同一个规则；人不用为一个内部名字想办法 |
| 打开的入口 | 启动页"新建项目"菜单的最后一项"打开文件夹…"：一个路径输入框，边输边告诉你那里是什么（哪种项目 / 已经在列表里 / 还没有项目 / 有别的文件 / 是文件） | 浏览器给不出本地文件夹的路径，只能输入；但输入时要立刻看到结果，不是点了"打开"才报错（第 7 条：诊断走真实路径，这里问的就是服务端） |
| 文件夹里还没有项目 | 同一个对话框的按钮变成"在这里新建"，打开新建对话框，位置已经填好 | 打开和新建是同一个问题"我要在这个文件夹里工作"的两种答案，不让人先判断该点哪个入口 |
| 新建到任意位置 | 新建对话框原来的"改文件夹"输入框同时接受名字和完整路径：写名字放进 `projects/`，写 `~/…` 或 `/…` 就建在那里（`projects/` 前缀随之消失，下面一行写出会建在哪）；那里必须不存在或是空的 | 不加第二个"位置"控件（第 2 条）；名字和路径一眼分得开，不会误解 |
| 卡片上怎么显示 | 写出真实路径（家目录下写成 `~/…`），放不下时省略前面、保留文件夹自己的名字 | 第 5 条：具体的值。路径的末尾才是认得出的部分 |
| 从列表里拿掉 | 卡片 ⋯ 菜单里"从列表移除"（只对登记来的项目出现），只删登记，文件夹不动；提示条上有撤销 | 不在这里做"删除项目"（launcher.md §3 已说明删除要回收站）；"移除"和"删除"是两个词（第 3 条） |
| 文件夹不见了 | 登记还在，卡片不出现（`kindOf` 认不出就跳过）；文件夹回来后又出现 | 文件夹可能在没挂上的盘上，不该因此忘掉它 |
| 宿主 | `DC_LINKS=0` 关掉：入口不显示，相关接口返回 403 | 宿主可能要求项目只在它自己的数据目录里；`/api/health` 的 `links` 告诉编辑器 |
| 服务端其余部分 | 都经过 `projectDir(name)`，不需要知道项目在哪；监听器为每个登记的文件夹加一个监听路径；提交在项目自己的文件夹里跑 git（它可能在另一个仓库里）；委托给 Claude Code 时给项目文件夹之外的登记加 `--add-dir`；`scripts/dash-query.mjs` 也认登记的看板 | 一处查表，其余不分支 |
| 默认数据目录 | 从源码跑：仍是仓库里的 `projects/`。从打好的包跑（npm 安装）且没有 `DC_PROJECTS`：项目在 `~/.tingly-design/projects`，AI 设置在 `~/.tingly-design/ai.json`。宿主设了 `DC_PROJECTS`（和 `DC_CONFIG`）就照宿主的 | 包目录随升级替换，人的数据不能放在里面 |

接口：`GET /api/folder?path=` 说明某个路径是什么；`POST /api/links { path }` 打开（返回名字）；`DELETE /api/links/:p` 移除登记；`POST /api/projects` 收 `path` 时在那里新建并登记，返回名字。命令行和别的工具可以直接用这几个接口。

## 4. 六种类型

登记发生在 `projectDir` 之下，和类型无关：六种类型都能从外部打开、新建到外部、编辑、同步外部改动、交给 Claude Code，`e2e/folders.py` 逐一打开了六种。矩阵见 [project-kinds.md](./project-kinds.md) §3。

## 5. 没定的

- 编辑器里的 `ProjectMenu` 还没有"打开文件夹"；目前只在启动页。
- 没有文件夹选择器：浏览器拿不到本地路径。桌面壳或 Tingly Box 宿主将来可以用系统对话框把路径交进来。
- 登记的文件夹嵌在另一个登记的文件夹里时，监听事件归第一个匹配的登记；没有专门处理。
- 文件夹被挪走后，没有"找不到了，重新指定"的提示，只是暂时不出现。
