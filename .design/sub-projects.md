# 子项目：项目里面的项目

状态：**已实施（第一期）**。测试是 `e2e/nested.py`。嵌入只做到"当作来源导入"（§6），活的引用见 §7。

## 1. 要解决的问题

一件作品常常由几件小作品组成：官网画布里的 logo、一组图标、一份介绍文档、一个动效。把它们都建成顶层项目，启动页上就是一排互不相干的卡片，看不出谁属于谁；把它们塞进同一个画布，又失去各自的编辑器、检查、导出和对话（一个设计系统不能是画布的一部分）。人想要的是：**在一个项目里面单独画一件东西，让它自己是个完整的项目，再把它当作品拿到别处用**。

## 2. 词和范围

"子项目"（sub-project）：文件夹**直接**位于另一个项目文件夹里面的项目，任何类型都可以（画布、幻灯片、文档、动效、看板、设计系统）。外面的叫它的"父项目"。子项目自己还可以有子项目。没有新的类型、新的索引文件、新的"工作区"概念：子项目就是项目。

和已有的东西的界线：

| | 是什么 | 和子项目的关系 |
|---|---|---|
| 启动页分组（[launcher.md](./launcher.md) §3） | 人填的标签，磁盘上平的 | 子项目是磁盘上的包含关系，不是标签；子项目跟着父项目所在的分组 |
| 打开的文件夹（[folder-groups.md](./folder-groups.md)） | 一个**不是项目**的文件夹，里面并排放着项目 | 子项目的"文件夹"本身是项目 |
| 引用（同上 §3.4） | 让 Claude 读别的项目，不复制 | 引用是路径，不要求包含关系；子项目不需要引用也在父项目文件夹里，Claude 本来就看得到 |
| 从项目导入（[import-from-project.md](./import-from-project.md)） | 把一个画布的画板复制进来并记下出处 | 子项目是它的来源之一（§6） |
| #53（项目之间互相链接） | 幻灯片带动效、画布当图、文档引用看板，活的链接 | 子项目是它的一种来源，链接本身仍是 #53 的事（§7） |

## 3. 考虑过的办法

### 3.1 子项目的地址（名字）

| 办法 | 好处 | 问题 |
|---|---|---|
| A. 名字带斜线：`parent/sub` | 一眼看出层级 | `?p=`、约 28 个 `/api/projects/:p/…` 路由、事件流、日志、会话、`activeDelegates`、journal 的键全是"一个路径段"；每处都要改，还会和 `…/files/a/b` 的路径混 |
| B. 另造一个地址空间（`?p=parent&sub=logo`） | 层级明确 | 名字和路径两种地址并存，处处分支（[project-identity.md](./project-identity.md) §3 已经否决过同类做法） |
| C. **用文件夹路径生成的稳定句柄**（`logo-3f9a1c`），和 `.links.json` 里的项目一样（采用） | 其余一切照旧按名字走；`projectDir(name)` 一处查表；同一文件夹总是同一个名字 | 句柄里没有层级，层级放在卡片的 `parent` 字段里 |

### 3.2 子项目怎么被登记

| 办法 | 好处 | 问题 |
|---|---|---|
| A. 新建时写进 `.links.json` | 零新机制 | 手工放进去或 Claude Code 在里面建的子项目不出现；父项目被挪走后登记悬空；磁盘上能读出来的东西又存了一遍 |
| B. **看磁盘**（采用）：每个项目的直接子文件夹里有索引文件的，就是它的子项目；像打开的文件夹的成员一样进内存里的 `links` 表（`nestedNames` 标出，写 `.links.json` 时跳过），`parentOf` 记它在谁下面 | 手工放的、Claude Code 建的、解压出来的都自己出现；删了就走；不存任何东西；旧的平的项目一个字节也不动 | 要在列表生成时、名字查不到时、监听到索引文件出现或消失时再看一遍（`refreshNested`） |

决定：只看**直接**子文件夹，递归（子项目的子项目），深度到 4 为止。不看更深的任意位置：那会在大仓库里扫很久，也让"这个文件夹是什么"变得不确定（同 folder-groups.md §3.2）。项目自己放东西的文件夹（`uploads`、`ds`、`data`、`assets`、`fonts`、`slides`、`scenes`、`tabs`、`datasets`、`files`、`renders`、`node_modules`）和点开头的文件夹从不看；新建时取这些名字会被拒绝（`subReserved`），不会建出一个看不见的项目。已经单独打开（`.links.json`）的项目保持原样，不因为恰好在别的项目里面就改成子项目。

### 3.3 父项目的文件里要不要有子项目的文件

不要。`walk()`（项目的受控文件列表，大纲、检查、导出、卡片数量、委托给 Claude 的文件、回收站都读它）遇到本身是项目的子文件夹就跳过。这是必须的，不是整洁：画布的画板文件允许在子文件夹里（`isBoardFile` 接受 `sub/Board.dc.html`），不跳过的话子画布的画板会变成父画布的画板。

其他按"项目的文件夹"工作的地方各自处理：

| 地方 | 决定 |
|---|---|
| 文件监听 | 一个文件属于**最深**的那个项目文件夹，不是列表里第一个匹配的；子项目里的外部改动记在子项目的改动记录里；索引文件出现或消失时重新看子项目（`serve.ts`） |
| git 状态、提交、阶段、跳回 | 父项目的 `git add` / `status` / `log` / `commit` 带 `:(exclude)<子项目>`，阶段的文件列表过滤掉子项目前缀：父项目的提交不带子项目的文件，跳回也不会覆盖它们；子项目自己在"最近的仓库"里提交，行为不变（`git.ts`） |
| zip | **子项目自己的 zip 只有它自己**；**父项目的 zip 带着它的子项目**（它们在父项目的文件夹里，一份包要能整个搬走再整个回来）。导入 zip 时子项目随文件夹落位，被看磁盘找到 |
| 文件面板 | 把子项目的文件夹当作普通文件夹列出（它确实在磁盘上），不做特殊处理 |
| 委托给 Claude Code | 请求里加一段 "Sub-projects"：这些文件夹是独立的项目，别当成这个项目的文件、别检查或修改，除非请求讲的就是它们（`delegate.ts` 的 `subNote`） |
| 回收站 | 子项目也移进 `.trash/`，元数据里记下它原来的父文件夹和自己的名字；恢复时放回原处（同名位置空着、父项目还在时），否则作为顶层项目恢复。删除父项目时子项目随文件夹一起走；父项目或任一子项目有 Claude Code 在跑就拒绝 |

### 3.4 新建、显示

**新建**不加新对话框，也不加模式选择器：项目菜单（编辑器）和卡片 ⋯（启动页）里的"新建子项目…"打开同一个新建对话框，位置字段预填为父项目的文件夹（对话框原来就收完整路径），一行说明"这是『X』的子项目：独立的项目，放在那个项目的文件夹里"。服务端：`POST /api/projects` 带 `path` 时，`linkFolder` 发现这个文件夹直接在一个项目里面，就不登记链接，只在内存里记下（以后由看磁盘找到）。命令行 `new <kind> ./sub` 在项目文件夹里执行同样成立。人也可以直接在磁盘上建。`DC_LINKS=0` 的宿主不接受任意路径，所以也不提供入口。

**显示**：

- 启动页：顶层只列没有父项目的项目；有子项目的卡片/行在 ⋯ 左边有一个很小的计数钮，点开把子项目紧接着列在父项目下面（卡片带一圈各自类型颜色的轮廓和一行“↳ 在『父项目』里”，列表行缩进），再点收起；展开状态记在浏览器里（`dc:launcher-open-subs`）。默认收起：没有子项目的人看不到任何变化，有子项目的人在卡片上就能看到数量。
- 筛选和搜索不能让子项目消失：搜索时拉平列出，类型标签页里父项目不在时子项目自己列出，并写"在『父项目』里"。
- 分组：子项目跟着最上面那个父项目的分组，自己没有"移到分组"。
- 子项目的 ⋯ 有重命名、新建子项目、导出、移到回收站；没有"从列表移除"（它不是登记来的）。
- 编辑器：项目菜单在子项目里第一行是"属于『父项目』"，在父项目里有"这个项目里的"一段（子项目，一层），再是"新建子项目…"。
- 命令行：`list --json` 的每一项带 `parent`。

### 3.5 兼容

没有迁移。平的项目不变；原来就放在别的项目里面的项目文件夹（如手工放的）下次看磁盘时开始显示为子项目，它们的名字是由路径算出来的句柄，和以前单独打开时一样（链接过的保持链接）。`projectDir` 看不到名字时，名字以 `-` 加六位十六进制结尾就再看一次磁盘，所以直接打开 `?p=logo-3f9a1c` 的书签在服务重启后也有效。

## 4. 六种类型

登记、`walk`、监听、git、回收站都在 `projectDir` 和 `store.ts` 之下，和类型无关；`e2e/nested.py` 六种类型都做过子项目。矩阵见 [project-kinds.md](./project-kinds.md) §3。

## 6. 嵌入：这一期做到哪

子项目是已有的"从项目导入"（[import-from-project.md](./import-from-project.md)）的来源：选择器按"父项目 / 子项目"命名，当前项目的子项目排在最前面；设计系统子项目和别的设计系统一样可以安装进画布和幻灯片。语义不变：复制并记出处，嵌入块指向副本，所以导出和单独发给别人不会断。

## 7. 没做的

- **活的引用**（#53）：子项目改了，用它的地方自己跟着变。现在要手动"从原画板更新"。
- 来源只有画布的画板、去处只有幻灯片和动效的限制没有变；文档里嵌入子项目、看板的图表当来源等等都没做。
- 在界面里把子项目挪到别的父项目（现在是在磁盘上挪文件夹，句柄随路径变）；子项目改名只改标题，不改文件夹。
- 子项目的子项目在启动页卡片上缩进到第 3 层；更深的情况没有特别设计。
- 一个已经单独打开的项目又恰好在别的项目里面时，保持顶层；没有"变成子项目"的动作。
- 命令行 `list` 只带 `parent` 字段，没有树形输出。
