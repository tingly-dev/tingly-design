# 子项目：项目里面的项目

状态：**隔离和 Claude Code 新建已实施**，**显示和自动发现是方案**（另开 issue #488）。测试是 `e2e/nested.py`。把子项目的成果嵌进别处（#53 一类）由另一份设计负责，这里只留接缝（§6）。

## 1. 要解决的问题

一件作品常常由几件小作品组成：官网画布里的 logo、一组图标、一份介绍文档、一个动效。把它们都建成顶层项目，启动页上就是一排互不相干的卡片；把它们塞进同一个画布，又失去各自的编辑器、检查、导出和对话（一个设计系统不能是画布的一部分）。人想要的是：**在一个项目里面单独画一件东西，让它自己是个完整的项目**，之后才好把它当作品拿到别处用（那一步见 §6）。

## 2. 它本来就能做到什么，缺什么

"子项目"（sub-project）：文件夹**直接**位于另一个项目文件夹里面的项目，任何类型都可以。没有新的类型、新的索引文件、新的"工作区"概念：子项目就是项目。

项目本来就可以放在任何路径（[project-folders.md](./project-folders.md)）：新建对话框的"位置"收完整路径，登记进 `.links.json`，得到由路径算出的句柄，之后按名字走一切。所以**在项目 A 的文件夹里建项目 B，本来就能建、能打开、能编辑、能被引用**，不需要"子项目"这个新机制；"统一访问"也已经成立：引用（`.references.json`）和"从项目导入"都按路径或名字找项目，和项目放在哪无关。

放进另一个项目的文件夹之后真正会坏的，只有"外面那个项目把里面的当成自己的文件"这一件事，它在三处发生：

| 地方 | 坏在哪 |
|---|---|
| `walk()`（项目的受控文件列表：大纲、检查、导出、卡片数量、委托给 Claude 的文件都读它） | 画布的画板允许在子文件夹里（`isBoardFile` 接受 `sub/Board.dc.html`），子画布的画板会变成父画布的画板 |
| 文件监听 | 取"第一个包含这个路径的项目文件夹"，子项目里的外部改动记到了父项目的改动记录里 |
| git 状态、提交、阶段跳回 | 父项目的 `git add -A -- .` 带上子项目的文件，阶段跳回会把子项目的文件当作"父项目里多出来的"并覆盖 |

## 3. 这一份做的：隔离

**规则**：一个项目文件夹直接位于另一个项目文件夹里（嵌套可以多层），外面的项目不把它当自己的文件。项目自己放东西的文件夹（`uploads`、`ds`、`data`、`assets`、`fonts`、`slides`、`scenes`、`tabs`、`datasets`、`files`、`renders`、`node_modules`）和点开头的文件夹不算（`isSubSkipped`）；新建项目时取这些名字会被拒绝（`subReserved`），免得建出一个被当成外面项目文件的"项目"。判断只看磁盘上有没有索引文件（`kindOfSync`），**不要求登记**：手工放进去、解压出来的项目文件夹也不属于外面的项目。

| 地方 | 决定 |
|---|---|
| 文件列表 `walk()` | 遇到本身是项目的子文件夹就跳过（`isNestedProject`）；卡片数量、大纲、检查、导出、回收站、委托给 Claude 的文件都跟着干净 |
| 文件监听（`serve.ts`） | 一个文件属于**最深**的那个登记的项目文件夹；没登记的子项目里的文件（`inNestedProject`）谁的都不是，不进父项目的改动记录 |
| git（`git.ts`） | 父项目的 `status` / `add` / `log` / `commit` 带 `:(exclude)<子项目>`，阶段的文件列表过滤掉子项目前缀：父项目的提交不带子项目的文件，跳回也不会覆盖它们；子项目自己在"最近的仓库"里提交，行为不变 |
| 委托给 Claude Code | 请求里加一段 "Sub-projects"，列出里面的子项目、说它们不是这个项目的文件、别检查或修改，除非请求讲的就是它们（`delegate.ts` 的 `subNote`）。Claude 用 Glob 和 Grep 在父项目文件夹里找文件，不告诉它就会搜进去 |
| zip | 子项目自己的 zip 只有它自己；父项目的 zip 是它的整个文件夹，**带着**里面的子项目（一份包要能整个搬走再整个回来）。没有改 `archive.ts` |
| 回收站 | 不改：项目建在项目文件夹里是登记来的项目，卡片菜单里是"从列表移除"，不是"移到回收站"（`project-trash.md`）；父项目移进回收站时它的文件夹连同里面的子项目文件夹一起走 |

**入口**：项目菜单（编辑器）和卡片 ⋯（启动页）里的"新建子项目…"打开**同一个**新建对话框，位置预填为这个项目的文件夹，一行说明"这是『X』的子项目：独立的项目，放在那个项目的文件夹里"。没有新对话框，也没有模式选择器；位置字段原来就收完整路径。`DC_LINKS=0` 的宿主不接受任意路径，所以也没有这个入口。命令行 `new <kind> ./sub` 在项目文件夹里执行同样成立。

**登记**：这样建出来的是一个**登记过的平项目**（`.links.json` 里一行），在启动页顶层和别的项目并排列着，卡片上写着自己的真实路径。这正是"显示另开"的意思（§5）。

## 4. 六种类型

隔离在 `walk`、监听、git 之下，和类型无关；`e2e/nested.py` 里画布、文档、设计系统各做过子项目，并检查了手工放进去的画布文件夹。矩阵见 [project-kinds.md](./project-kinds.md) §3。

## 5. 没做的（显示和自动发现，#488）

这一份之后，子项目在启动页里是个平的卡片，看不出属于谁。要做成"放在当前项目下面"，需要下面这些，它们已经设计过也做过一版（本地分支 `tp/sub-projects-display`），因为只有显示、没有隔离那样的正确性问题，拆出去单独合：

- **看磁盘发现**（`refreshNested`）：项目的直接子文件夹里有索引文件的，就是它的子项目，不写 `.links.json`，像打开的文件夹的成员一样进内存里的 `links` 表（`nestedNames`、`parentOf`），名字仍是由路径算出的句柄；手工放的、Claude Code 建的、解压出来的都自己出现，删了就走。深度到 4 层。要在列表生成时、名字查不到时、监听到索引文件出现或消失时再看一遍；新建时要给还没写出来的文件夹一个名字（`pendingNested`），免得中途再看一遍把它丢了。
- **`ProjectCard.parent`** 和启动页的树：父项目的 ⋯ 左边一个计数钮，点开把子项目紧接着列在下面；筛选和搜索不让子项目消失（写"在『父项目』里"）；分组跟着父项目。
- 编辑器的项目菜单写出"属于『父项目』"和"这个项目里的"。
- 回收站把子项目恢复到父项目下面。
- 父项目的 zip 导入后，子项目随副本落位并出现在列表里（现在是落进副本的文件夹但不在列表里，要"打开文件夹…"才出现）。
- 开放问题：已经单独登记的项目又恰好在别的项目里面时，是否改成子项目（现在登记优先）；在界面里把子项目挪到别的父项目。

## 6. 和嵌入的接缝

这一份不做嵌入。给做嵌入的人留的事实：

- 子项目是列表里的普通项目：按名字读它的文件、`projectDir(name)`、`/raw/` 都和别的项目一样；"从项目导入"来源选择器（只看 `kind` 和名字）不改也能列出它们。
- 来源记录里写的是子项目的句柄（由路径算出）。父项目被挪走或改了文件夹名，句柄会变；要做"跟着源走"的链接，应该记路径或相对父项目的文件夹名，而不是句柄。
- 父项目的文件列表不含子项目的文件，所以父项目里的页面引用子项目的文件要通过嵌入那边自己的机制（复制到 `uploads/` 再引用，或按名字取），不能指望 `walk()` 把它们列进来。
- agent 建完子项目后怎么用它（放回父项目的页面里）是嵌入那一半，§7 只负责建出来。
- 父项目的 zip 带着子项目，所以"嵌进来的是子项目本身"的作品搬走时不会断；复制进 `uploads/` 的副本则本来就自足。

## 7. Claude Code 新建子项目

人能做的，agent 也要能做：做一个工作的时候开子项目画点额外的东西（一张图、一份文档）。

| 问题 | 决定 | 为什么 |
|---|---|---|
| 给 agent 什么能力 | 一个小脚本 `scripts/new-sub-project.mjs <项目> <类型> <文件夹名> ["标题"] [--size WxH] [--look id]`，经服务端的 `POST /api/projects/:p/sub-projects` 建（`createSubProject`）；委托的 `--allowedTools` 只加 `Bash(node scripts/new-sub-project.mjs:*)` | 和 `image-gen.mjs` 同一个办法：能力是一个命令，不是整个 Bash；服务端用和新建对话框同一套起步文件，所以建出来的和人建的一样 |
| 建出来是什么 | 和人在新建对话框里按路径建的一样：登记过的平项目（`createSubProject` 经 `linkFolder`），所以立刻出现在列表里，不需要看磁盘发现；需要 `DC_LINKS` 开着，`DC_LINKS=0` 的宿主拒绝 | 不另开一条登记路径；发现是 #488 的事 |
| 为什么不让它手写索引文件 | 提示和技能都写"别手写子项目的索引文件" | 手写会漏起步内容，也绕过名字检查（保留的文件夹名、已有的文件夹），而且手写出来的不会被登记，列表里看不到 |
| 怎么告诉它 | 每个请求的 "Sub-projects" 一段：什么时候该建（请求要一个单独的成果，或不建就做不成；普通修改不建）、怎么建、建完读那种类型的技能再用 Edit/Write 写它的文件、子项目的文件不是这个项目的文件；已有的子项目列在后面。六个技能各有一段同样的 "Sub-projects" | 提示词给每个请求带着，技能是它要写别种类型时读的参考 |
| 建完怎么放回父项目里 | 不做：技能让它"说出子项目在哪里，不要链接到它的文件" | 嵌入是另一份设计（§6） |
| 拒绝 | 保留的文件夹名、已存在的文件夹、未知类型、不存在的项目都回明确的错误，脚本退出码非 0；白名单之外的命令不放行 | 失败要让 agent 看得见，而不是悄悄建出一个看不见的项目 |

测试是 `e2e/agent_subproject.py`：用假的 `claude`（它按 `--allowedTools` 检查命令）在委托请求里运行脚本，六种类型各建一个，查列表里有它、磁盘上在父项目文件夹里、父项目自己的文件列表不变、请求里有说明、子项目可以再建子项目、各种拒绝。没有用真的模型跑过：模型会不会在合适的时候主动开子项目，是提示词的效果，要用起来才知道。
