# 请求栏与 agent 执行反馈

状态：**已实施**（运行卡片、步骤、计时、停止、改动文件、撤销整次运行、忙时保留输入、jQuery 移到“代码”面板）。"还开着的问题"一节是没做的。

## 1. 问题

请求栏（画布、幻灯片、动效的 `PromptBar`，设计系统、看板、文档的 `AskClaude`）把请求交给快速 AI 或 Claude Code。交出去以后，用户脑子里有四个问题，原来一个都答不好：

| 用户在问 | 原来的样子 |
|---|---|
| 我刚才说了什么？ | 发送后输入框立即清空，请求只在一行紫色小字"正在处理：…"里出现，完成后连这行也没了 |
| 它还在干活吗，在干什么？ | 快速 AI 有逐行的 jQuery；Claude Code 只有最后几行原始工具名和绝对路径（`Read /…/projects/box-console/canvas.json`），没有时间，长时间没有新行时看不出是在想还是卡死 |
| 改了什么？ | Claude Code 完成后只剩一句话，不知道动了哪些文件；快速 AI 显示"已保存" |
| 不满意怎么办？ | Claude Code 跑起来停不下；改完不能整体撤销；失败后请求已经被清掉，得重打 |

输入本身也别扭：输入框固定一行不会长高；Claude Code 正在跑时再按 Enter 什么也不发生、也不说为什么；发送按钮在 Claude Code 运行时仍然是"发送"；Claude Code 没启动成功时请求已经丢了。另外，"用户正在看什么"（看板上点的数据、文档里选的字、动效停在哪个场景）是拼在请求前面一起发的，于是回显出来的是一段机器上下文，不是用户写的话。

## 2. 决定：一张运行卡片，所有类型、两种 agent 共用

`RunFeed`（`apps/editor/src/components/RunFeed.tsx`）放在请求栏里、输入框上方，像对话里的上一轮。它按上面四个问题分区（ux-principles 第 1 条）：

1. **你说的**：右对齐的气泡，原样显示发出的请求（最多三行，悬停看全文）。手写的 jQuery 用等宽字体。上下文不进气泡：它作为单独的 `context` 字段交给服务端，服务端放在 `Request:` 之前告诉 Claude Code。
2. **现在在干什么**：状态图标 + 一个词的状态（"正在处理"/"完成"/"没能完成"/"已停止"）+ 计时（运行中"已 12 秒"，结束后"用时 1 分 05 秒"）。下面是步骤列表：
   - Claude Code 的每个工具调用由 `describeTool`（`packages/core/src/activity.ts`）翻译成一句中文：读格式说明、读 `deck.json`、搜索"title"、改 `slides/cover.html`、查询数据。路径一律相对项目目录（第 5 条：展示用户认得的具体值，而不是机器路径）；技能文件统称"格式说明"。
   - Claude Code 说的话单独成行（对话气泡图标），和步骤分开。
   - 最后一步带转圈；最后一条是"说话"或超过 8 秒没有新动作时，多一行"在想下一步（N 秒没有新动作）"，让用户分得清"在想"和"卡住"。
   - 快速 AI 继续逐行显示 jQuery 语句（它本身就是要执行的具体值），重试之间的分隔行保留。
3. **改了什么**：Claude Code 改过的文件列成文件名片（来源有两个：`Edit`/`Write` 步骤的路径，和服务端以 `claude` 身份推送的文件变化）。画布点名片会定位画板，幻灯片切到那一页，文档切标签页，动效跳到那个场景，看板打开数据来源或代码面板；设计系统只列不跳。运行中画布上被改的画板显示"Claude Code 正在改"徽标（快速 AI 的徽标改成"快速 AI 正在改"，同一个词只指一件事）。
4. **下一步**（第 11 条：把下一步的物件交到手上）：
   - 快速 AI：保存后给"撤销"，只在撤销栈顶就是这次改动时出现，免得撤掉别的。
   - Claude Code：给"撤销这次改动"，把这次运行碰过的每个文件恢复到运行前（运行新建的文件删掉）。恢复走普通的编辑队列和 `rebaseSwap`，所以运行之后的手改不会被冲掉。
   - 失败或停止：给"放回输入框"，把请求放回去改一改再发。
   - 结束后步骤收起成"N 步 ›"，点开还能看（第 10 条：完成不等于锁死）；卡片右上角可以关掉。

一次只显示一张卡片：最新开始的那次运行。快速 AI 判断要交给 Claude Code（`askClaude()`）时，卡片接着显示那次 Claude Code 运行，并注明"快速 AI 判断……交给了 Claude Code"。

## 3. 输入

- 输入框随内容长高（`useAutoGrow`，上限沿用 CSS 的 180px）；有换行时提示"Enter 发送，Shift + Enter 换行"，平时不显示（第 9 条）。
- 发送后请求立即进卡片、输入框清空；Claude Code 没能启动时，请求放回输入框，附件也留着，同时给出错误提示。
- 正在运行时，发送按钮变成"停止"，停的是当前这个 agent 的那次运行。运行中按 Enter 不再静默：输入框下面出现一行"还在处理上一条。等它完成或先停止；你写的这条会留在这里。"，文字留在框里。
- 停止 Claude Code：`DELETE /api/projects/:p/delegate/:id` 结束进程，事件状态为 `stopped`，卡片写明"停止前写下的改动还在，可以撤销"。快速 AI 的停止仍是中断流，结果是"已停止，没有保存任何改动"。

## 4. 手写 jQuery：高级入口，放在“代码”里

快速 AI 的输出就是 jQuery 语句，所以执行器本来就能直接跑手写的语句，不需要模型和 API key。它曾经是请求栏上和快速 AI、Claude Code 并列的第三个选项，问题是：

- 会写 jQuery 选择器、还知道编辑器给元素编的 `#dcN` 的人很少；放在请求栏上，所有人每次都要越过它（ux-principles 第 2 条：消解模式选择）。
- 它不是"交给谁"的问题：快速 AI 和 Claude Code 是两个 agent，jQuery 是用户自己动手。并列放会让人以为它是第三个 AI。

所以请求栏只剩快速 AI / Claude Code 两项，jQuery 放进右侧面板的"代码"标签，在源文件下面（`panel/JQueryBox.tsx`）：

- 位置理由：想写 jQuery 的人正是会看源码的人；源码就在上面，选择器照着写。选中元素时提示它的句柄（`#id` 或 `#dcN`），占位示例也用这个句柄。
- 画布（元素和画板）、幻灯片、动效都有；幻灯片和动效没选中东西时，"代码"显示舞台上那一页 / 那个场景的源码和 jQuery，不用先去点。设计系统、看板、文档不走 jQuery 执行器（文档的快速 AI 改的是段落文字），也就没有这个入口。
- 执行走同一条路径（`runJQuery`），结果出现在请求栏上方同一张运行卡片里，撤销也一样。⌘/Ctrl + Enter 执行，Enter 换行（多条语句是常态）。
- 快速 AI 跑完后，展开"N 条语句"可以点"在 jQuery 里改"：把留下的语句放进这个框、打开"代码"，改一两处再执行。这样高级入口是从结果里自然走到的，而不是一开始就要选。
- 草稿（`jqDraft`）放在 store 里，切换选中、切换标签不会丢。

## 5. 协议

服务端事件 `{type: 'delegate'}` 的变化：

- `start` 带 `at`（开始时间），计时从服务端时间算。
- `progress` 带 `step: AgentStep`（`kind`、`text`、改动文件的 `changed`）；没有 `step` 的 `progress` 是 Claude Code 说的话。`text` 仍然有，旧客户端照常显示。
- 新状态 `stopped`。
- 正在跑的运行，事件按顺序留在 hub 里；编辑器打开或刷新时先回放，所以中途打开的编辑器也能看到已经做了哪些步骤。运行结束就丢掉。

`describeTool` 放在 core 而不是编辑器，是因为路径相对化需要服务端知道的项目绝对路径和 Claude Code 的工作目录；放在 core 方便单测。

## 6. 考虑过、没选的

- **把步骤放进日志（journal）**：日志回答"谁改了哪个文件"，是事后的记录；运行卡片回答"现在在干什么"。混在一起，日志会被读文件、搜索之类不改东西的步骤淹没。保持分开，日志仍以文件改动为单位。
- **常驻的对话历史面板**：多轮历史需要一个固定区域，会和画布、幻灯片的舞台抢空间；这里的请求大多是一次性的指令，不是来回对话。先只保留最近一次运行；要不要历史见下面。
- **完成时只弹 toast**：toast 几秒就消失，而且和请求不在一个地方。现在请求栏在屏幕上时不弹 toast，结果留在卡片里；只有请求栏不在（例如画布放映模式）时才用 toast。
- **在卡片标题旁再放一个"停止"**：和输入框右边的"停止"重复，两个按钮做同一件事是视觉噪声，只保留输入框旁那一个（和发送按钮同一个位置，用户的手已经在那里）。

## 7. 跨类型

六种类型都通过 `PromptBar` 或 `AskClaude` 拿到同一张卡片，矩阵见 [project-kinds.md](./project-kinds.md) 的"运行反馈"一行。差别只在点文件名片能跳到哪里（§2.3）。设计系统没有可定位的单一视图，名片只列不跳。

## 8. 还开着的问题

- **二选一的"交给谁"**（快速 AI / Claude Code）仍在画布、幻灯片和动效的请求栏上，和 ux-principles 第 2 条（消解模式选择）相冲。快速 AI 已经能自己 `askClaude()`，理想是默认只有一个入口，由它判断交给谁。这会改变快速 AI 的提示词和判断边界，单独做。jQuery 已经不在这里（§4）。
- **历史**：只显示最近一次运行。要不要能翻看之前几次（日志里已有文件级记录）还没定。
- **Claude Code 的撤销基于编辑器收到的文件内容**：编辑器没打开时 Claude Code 改的文件，没有"运行前"的版本可恢复；二进制文件（图片、字体）不进这条路径，撤销不了。
- **进度百分比**：Claude Code 不报告总步数，没法给进度条；现在用计时 + 步骤 + 静默提示代替。
