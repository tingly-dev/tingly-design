# 批阅：在页面上写批注，一次交给 Claude Code

状态：**已实施**（画布、幻灯片、动效）；§6 是还开着的问题。画板见自身设计稿 `projects/tingly-design-ui-canvas` 的 `Review` 板。

## 1. 问题

现在对一处不满意，只有一条路：选中它，在请求栏里写一句，发出去，等一次运行。看完一页有十处要改，就是十次运行；或者写一大段"第二个按钮""标题下面那行"，让 Claude Code 在文字里猜指的是哪个元素。人真正的动作是**审阅**：一遍看下来，指到哪写到哪，看完了一起交出去。一起交还有一个好处：Claude Code 能看到全部意见，自己权衡冲突，做一遍连贯的修改，也只有一次撤销。

## 2. 考虑过的做法

| 做法 | 问题 |
|---|---|
| 请求栏里连续选、连续写，攒成一条长请求 | 请求栏是一个输入框，选中又会改掉"这条请求针对谁"；十处意见在一个框里没法逐条改、逐条删，也看不出哪句对着哪个元素 |
| 先发一条，等它跑完再发下一条（现状） | 十次运行、十次对话轮次；后一条可能推翻前一条 |
| 在页面上放便签（画布的便签项） | 便签是**作品的一部分**，写进文件、会被导出；批阅意见是给 AI 的临时话，不该留在作品里 |
| 像文档那样的评论串（`comments.json`） | 评论是一场对话（每串有回复、可解决、Claude 也回在串里），写进文件、进 git；批阅是单向的一次性交付 |
| **一个"批阅"面板：点一下留一条批注，针脚钉在元素上，面板里列出全部，一个按钮一起发** | 采用 |

## 3. 决定

### 3.1 进入和离开：面板就是模式

顶栏里画布、幻灯片、动效多一个"批阅"按钮，和属性面板在同一处（`KIND_PANE_IDS` 里的 `review`，`PaneToggles` 画按钮）。打开它，右栏换成批阅面板，页面上的点击改成"留批注"；关掉它（面板的 ×，或再点顶栏按钮）回到属性面板。**不做模式选择器**（ux-principles 第 2 条）：没有"先选批阅模式再开始"，状态只有一个值，右栏现在是什么。

- 进入时清掉选中：点击不选中，拖动、缩放、双击改字都关闭（runtime 里 `review.on`），右键菜单不出现。页面上的 Delete 键因此没有对象可删。
- 项目重新打开时不在批阅里（`rememberPane` 把 `review` 记成 `inspector`）：点击的含义变了，不该因为上次忘了关而让一个人点不出选中。
- 顶栏按钮上带还没发的批注条数（和文档的评论按钮同一种角标）：离开批阅后也看得到手里还有东西。

### 3.2 一条批注

点页面上的元素：在它的左上角钉一个**编号针脚**，面板里多一张卡片，输入框已经有键盘。点页面空白处（文件的最外层元素）是给**整页**写。再点一个已经有针脚的元素，回到它的批注，不会多出第二条：一个元素一条。

- 针脚是琥珀色（`--warn`），选中和悬停是蓝色：选中和批注从来不会看起来一样（第 4 条：两条轴分开）。聚焦的批注，针脚带蓝环。针脚在页面里由沙箱运行时画（`drawPins`，随缩放保持屏幕上的大小：编辑器按 `1 / zoom` 给 `unit`），所以画布缩放、幻灯片舞台缩放下都对得上。
- 卡片显示的是具体的东西（第 5 条）：句柄 `#hero-title`（没有 id 时编辑器给的 `#dc16`）、标签、元素自己的字，再下面是画板 / 幻灯片 / 场景的名字。点卡片的这一块会把页面带到那里（`LOCATE`，和运行卡片的文件名片同一张表）。
- × 删除，toast 的撤销放回原来的位置；"清空"同样可撤销（`offerUndo`，不询问）。
- 没写字的批注不发，留在面板里（"N 条批注没写字，留在这里"）。

### 3.3 一起发

面板底部只有一个主按钮："把 N 条批注交给 Claude Code"（N 是写了字的条数）。它是**一个请求**，走和请求栏同一条路（`delegateToClaude`）：接着项目的对话、一次运行、一次"撤销这次改动"。

- 对话里显示的是人自己的话，按编号列出（`Review remarks (3), to handle together:` 加每条 `1. #hero-title on Pricing: …`，给模型的提示本来就是英文），请求栏的气泡照常最多三行、悬停看全文。
- 结构化的部分作为**上下文**走，不回显（和"指着的元素"同一条路）：每条的文件、元素、**当前**的源码片段，以及怎么看这些话——这是人对设计的意见，改文件，不当成对机器的指令；一次做完，冲突时说明采纳哪条，最后逐条回答。
- 发出去，这些批注就离开页面和面板（对话里有它们，撤销是一整次运行）；启动不了（没有 Claude Code、服务出错）时它们留着，面板底部给原因。Claude Code 正在跑时按钮不可点，写明原因（和请求栏一致，一次只一个运行）。
- 只给 Claude Code，不给快速 AI：快速 AI 一次只改一个文件，一批批注可以跨文件。

### 3.4 批注钉在哪、改了文件之后怎么办

批注不写进作品文件，存在这台机器的浏览器里（`dc.review.<项目>`，`store/review.ts`），刷新后还在，直到发出。它不进 git、不进 `.zip`、不进文件历史。

元素在文件里的位置（`tid`）是顺序号，别处插入一个元素就变了。所以每条批注同时记着它的**锚点**（core `review.ts` 的 `RemarkAnchor`）：标签加 id，没有 id 就加元素自己的字，和当时的源码片段。每次画针脚、每次发送都按锚点重新找（`resolveRemark`）：

1. 原位置还是它 → 不动；
2. 文件别处有同样的锚点 → 跟过去（取离原来最近的）；
3. 它的字被人原地改了（同位置、同标签、同有无 id）→ 仍认为是它；
4. 找不到了 → 针脚不画，卡片灰色虚线，写明"这个元素变了。你写的话还在"；发送时仍然带上，说明元素已不在原处并附上最后记得的源码，让 Claude Code 按字去找。

不去猜：宁可说"找不到"，也不把针脚钉到别的元素上。

### 3.5 哪些类型

画布、幻灯片、动效共用同一个沙箱运行时，点击、针脚、关编辑手势只写了一遍，三种类型一起有。画布的批注可以分在好几块画板上，一次发出；幻灯片、动效是舞台上那一页 / 那个场景（切换页面时批注仍在，针脚只画在对应的页上）。

不做的类型，原因写在 [project-kinds.md](./project-kinds.md) 的矩阵里：设计系统没有"点元素"的舞台；看板的页面是脚本画的，点选给的是数据来源；文档已有评论串（它是对话，不是一次性交付）。

## 4. 词

- **批阅**（Review）：这个模式，也是它的面板。
- **批注**（remark）：一条意见。不叫 note：画布已有便签（note），幻灯片和动效有备注（speaker notes），一个词一个意思（ux-principles 第 3 条）。文档的"评论"是另一回事。

## 6. 还开着的问题

- **词**："批注 / remark" 是否合适，还是更想要别的（比如"意见"）？
- **一个元素一条**：够不够？同一个元素要写两件互不相干的事时，现在写在一条里。
- **发出的一批不留**：面板里不保留"上一批"，也没有"放回来"；对话里有原文。要不要保留，等有人要。
- **框选一块区域**写批注（拖一个矩形，不对应单个元素）：没设计。
- **文档**：把"所有未解决的评论一次交给 Claude Code"做成评论栏的一个按钮，是同一个想法在评论串上的版本，还没做。
- **命令行和 MCP**：批阅是编辑器里的交互，命令行的 `prompt` 一次一条请求，没有对应物。
- **键盘**：没有专门的快捷键进出批阅（点顶栏按钮）；`Esc` 只让批注的输入框失焦。
