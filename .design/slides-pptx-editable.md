# Slides: PPTX that people can edit in PowerPoint and Keynote

已实施（块级文本框与原生项目符号/编号、标题占位符、分节、主题配色与字体、图片替代文字、对象命名与 txBox、超链接、半透明表格分隔线；导入方向读回分节与标题）。验证见 §6：python-pptx 读回、真实 Chrome 浏览器回归、`pnpm e2e pptx_edit` 的结构断言与重新导入图像对比；**真实 PowerPoint / Keynote 打开、编辑与渲染未验收**。

导出整体的契约（捕获、图片化、资源边界、writer 校验）仍以 [slides-pptx.md](./slides-pptx.md) 为准；本篇只讲“导出的文字和结构在 Office 里好不好改”。

## 1. 问题

导出一直以“看起来对”为第一目标：`pptxDom.ts` 用 DOM Range 逐字测量，每换一行、每换一个 run 就输出一个 `wrap="none"` 的文本框。位置很准，但收件人在 PowerPoint 里改一个词后面不会重排；改标题要改三个框；列表符号是单独的“•”文本框；大纲视图、辅助功能检查、“重用幻灯片”都看不到标题；主题是 Office 默认的。

基线（七页测试稿 `e2e/fixtures/pptx-edit`，编辑器菜单导出，`scripts/pptx-fidelity/readback.py` 用 python-pptx 读回）：

| 看什么 | 之前 | 之后 |
|---|---|---|
| 文本框（7 页） | 77，全部 `wrap="none"` | 29，只有 `white-space:pre` 的代码块不换行 |
| 只装一个“•”/“3.”的文本框 | 8 | 0 |
| 原生项目符号/编号的段落 | 0 | 8 |
| 标题占位符 | 0/7 | 7/7 |
| 分节 | 无 | 4 节，与 `deck.json` 一致 |
| 主题字体 / 颜色 | Calibri、Office 配色 | 幻灯片自己的字体与颜色 |
| 图片替代文字 | 内部文件名 `dc-asset-0.png` | `alt` |
| 默认样式的 `<table>` | 不是原生表格（表头 4 张图片 + 17 个文本框） | 原生表格 |

表格那一行是这次顺带发现的：幻灯片基础样式给 `th/td` 的分隔线是半透明的（`rgba(127,127,127,.35)`），原生表格路径拒绝半透明边框，于是**所有用默认样式的表格**都退回逐元素路径。

## 2. 已定方案

### 2.1 一个文本块一个文本框

“文本块”按幻灯片子集本来的语义认：

- 只含文字和行内元素的块：`h1–h3`、`p`、`li`、只含文字的 `div`。行内元素（`b i u a span code`……）成为 run，`<br>` 成为段内换行（`<a:br/>`）。
- `ul` / `ol`：一个文本框，每项一段，带原生 `buChar`（disc/circle/square/单字符 `list-style-type`）或 `buAutoNum`（decimal、alpha、roman，`start` 作 `startAt`）。项目符号挂在列表的内边距里（`marL` = 该项文字起点到文本框左边的距离，`indent` 为其负值），这是 PowerPoint 的标准悬挂缩进，与 Chrome 的 `::marker` 位置略有不同。
- `div data-text`：子集里本来就叫“一个文本框”，里面的 `p`、`ul`、`ol` 进同一个文本框；块与块的间距按实测（后一块的上边减前一块的下边）写成段前距。

段落属性都取实测或计算值：对齐、行高（CSS `line-height` 为 px 时写精确行距）、字号字体颜色等 run 属性沿用原来的 `styleText`。`white-space:pre/pre-wrap` 的换行变成段落，`pre`/`nowrap` 的文本框不换行。

**几何与换行**：文本框取元素的内容框（去掉边框和内边距；元素自己的底色/边框仍是单独的形状），开启换行，`fit:none`（不自动缩放）。宽度在实测宽度上加一点余量（1%，至少 4px，至多一个字号），向对齐方向的反侧长、不超出页面。余量有上限 `room()`：逐行测出每行宽度和下一行第一个词（CJK 为第一个字）的宽度，余量永远小于“让上一行能多装下下一行首词”所需的宽度。于是**字体相同时**，PowerPoint 的折行与编辑器一致（重新导入的图像对比证实了这一点，见 §6）；字体略宽时，余量吸收一部分差异；字体差得多时，折行会不同——这是开启换行的代价，已接受（§4）。

### 2.2 标题、分节、主题、替代文字、命名

- **标题**：每页**第一个显示出来的 `h1` 或 `h2`**，且它能成为一个文本块时，进 `title` 占位符（每页最多一个）。位置和文字都在该页自己身上；母版和版式各加一个标题占位符（位置取第一个标题），供 PowerPoint 的“重置”使用。没有标题的页没有占位符。
- **分节**：`deck.json` 的 `sections` 映射到导出的可见页上：每页属于在它之前（含它）开始的最后一节；第一节之前的页归入一个以 deck 标题命名的节；不含导出页的节省略。写成 `p14:sectionLst`。
- **主题**：`pptxTheme(deck)` 从画出来的东西推导：标题的字体（没有标题就用最大的字）作 major，字数最多的字体作 minor；最常见的页面底色按明暗进 `lt1`/`dk1`，它上面最常用的文字色作另一个；次一个明/暗色作 `lt2`/`dk2`；按面积和字数排序、色度足够、彼此不相近的颜色作 accent1–6，accent1 兼作超链接色；推不出的槽位保留 Office 的。**对象仍写具体颜色和字体**（“值，不是变量”的规则不变）：主题只决定 PowerPoint/Keynote 的取色器和新加内容的默认值，不改变已有内容的样子。
- **替代文字**：`img` 的 `alt`、`svg` 的 `aria-label` 写进 `descr`；整棵图片化的元素也带上它的 alt/aria-label。
- **命名**：按 PowerPoint 自己的习惯 `Title 1`、`TextBox 2`、`Picture 1`、`Table 1`、`Rectangle 3`；非标题文本框写 `txBox="1"`。
- **超链接**：`a href` 为 http/https/mailto 时，run 带原生超链接。

### 2.3 回退顺序

一个元素按下面顺序找到第一种能用的表达，失败不影响兄弟元素：

1. 块级文本框（上面的规则）。
2. 逐行原生文字（原来的路径：每行每 run 一个 `wrap="none"` 文本框，列表符号作文字）。块里出现子集之外或 PowerPoint 段落表达不了的东西时走这里：带底色/边框/内边距的行内元素、定位或浮动的子元素、`vertical-align` 非 baseline、`text-overflow:ellipsis`、行数截断、单项改了编号的 `li value`、`list-style-position:inside`、图片符号、旋转子树里的列表和 data-text 框。
3. 该元素的图片（原来的逐元素图片化）。

列表整体不能成块时，每个能成块的 `li` 仍各自成一个带原生符号的文本框，只有出问题的那一项退回第 2 步。

### 2.4 写包

`writePptx` 的 DTO 增加：段落 `bullet`/`indentPx`，run `breakBefore`/`href`，文本 `role:'title'`/`name`，图片 `altText`/`name`，deck `sections`/`theme`；全部严格校验。PptxGenJS 4.0.1 能写的直接写（`bullet`、`softBreakBefore`、`hyperlink`、`objectName`、`isTextBox`、`altText`、`theme` 字体）；它写不了的由 `normalizePptx401` 按固定结构补：标题占位符（按对象名找到该形状，在 `nvPr` 里加 `<p:ph type="title"/>`）、母版/版式的标题占位符、`p14:sectionLst`、主题 `clrScheme`。结构不符一律失败（错误里带是哪一步），仍不是通用 OOXML 修复。4.0.1 遇到带 bullet 的 run 会另起一段，所以只有段落的第一个 run 带 bullet；同段其余 run 的段落属性只在项目符号上不同，normalize 只保留第一个。

### 2.5 导入方向

导出写了的东西，导入要读回来，否则往返会丢：

- `p14:sectionLst` → `deck.json` 的 `sections`（每节从它第一张导入成功的页开始）。之前导入总是写空的 `sections`。
- `title` 占位符的段落写成 `h2`，`ctrTitle` 写成 `h1`（带 `font-weight` 以免基础样式把非粗体标题加粗），于是导入后再导出，标题仍是标题。
- 列表本来就读成 `ul`/`ol`（含 `start`），现在导出写的是真列表，往返后仍是列表；之前往返得到的是一堆单独的“•”。

## 3. 幻灯片内部的有限调整

用户允许为导出在幻灯片模型或渲染里做“有限但合理”的调整。结论是：**子集本来就是块语义**（`data-text` 是一个文本框，`span` 只带颜色，列表是 `ul`/`ol`），不需要改模型；需要的是把已有约定明确下来，以及一处只在导出里做的处理。

| 调整 | 理由 | 影响范围 | 状态 |
|---|---|---|---|
| “每页第一个 `h1`/`h2` 是这页的标题”成为明确约定，不新增属性 | 标题占位符需要知道哪段是标题；子集里本来就这样写标题，加属性等于让人和 AI 多记一件事 | 导出、导入、slides skill 一句话；文件格式不变 | 已实施 |
| 半透明的默认表格分隔线：编辑器照旧画半透明，导出时把它混合到它下面的实色背景上，写成实色边框 | 半透明让同一条线在深浅底上都合适，改成实色会改变深色页的外观；PowerPoint 表格边框不支持透明度（PptxGenJS 不写），混合后的 1px 线看起来一样 | 只改导出；底色本身半透明时仍退回逐元素 | 已实施 |
| 提醒“列表用 `ul`/`ol`，不要在 `p` 里手打 • 或 1.；标题写在每页第一个 `h1`/`h2`；行内高亮（`span` 带底色）会让那一段退回逐行” | 这些写法在编辑器里看不出差别，在 PowerPoint 里差很多 | slides skill 的 PowerPoint 段落 | 已实施（文字） |
| `check` 增加“手打的项目符号”“这一段在 PowerPoint 里会逐行导出”的警告 | 让 Claude Code 和人在导出前就看到 | core 的 deck 检查 | 提案，未实施 |
| 字体栈：现在只写第一个 family；可按栈选一个 Office 自带的后备 | 收件人缺字体时由 PowerPoint 自选替代，换行差异更大 | 导出 | 提案，未实施（要先定写主字体还是后备字体） |
| 首行基线：PowerPoint 精确行距下首行基线比 CSS 半行距低约 0.1em | 视觉上整段略下移 | 导出 | 开放问题，未调 |

## 4. 已接受的取舍

- **开启换行**：收件人缺少 deck 的字体时，PowerPoint 用替代字体排，折行会和编辑器不同，文字可能多出一行。不加“逐行精确 / 可编辑”模式开关（[ux-principles](./ux-principles.md)：消除模式选择），导出结果对话框说明这一点（`slides.pptx.metrics`）。需要逐行精确的人仍可以在 PowerPoint 里看到同样的位置，只是要装好字体。
- 不嵌入字体、不回写原 OOXML、不引入第二套编辑模型、不依赖 Office/LibreOffice（[slides-pptx.md](./slides-pptx.md) §4）不变。
- 主题是推导出来的，可能把某个只出现一次的颜色排进 accent；这只影响取色器，不影响已有内容。

## 5. 不做 / 以后

- 每页版式库（“标题和内容”“两栏”……）与正文占位符：我们没有母版模型，正文文本框保持普通文本框。
- 原生图表：slides 子集还没有带数据的图表元素（见调研 `research-pptx-skill.md` 的第 4 名）。
- 多级列表：子集只有一级列表，嵌套列表退回逐行。
