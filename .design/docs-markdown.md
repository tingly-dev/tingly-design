# 文档导出为 Markdown

状态：**已实施**。入口在 [export-menu.md](./export-menu.md) 的文档一行；幻灯片的同类导出见同文件 §3.1，那边的取舍（确定性、不调模型）这里沿用。

## 1. 问题

文档本来就是 Markdown 文件，导出 Markdown 看起来不用做什么。但“把标签页源文件原样拼起来”给出的不是一份能单独拿去用的文件：

- 文档标题不在文件里；各标签页每个都带自己的 `# 标题`，拼在一起只有 `---` 隔开，层级是平的，读的人分不出哪个是章、哪个是节。
- 图片写的是 `../assets/x.png`（相对 `tabs/`），文件一离开项目目录就全断。
- 编辑器的 `==高亮==` 不是 Markdown，别处会原样显示成等号。

发出去读、放进仓库或知识库、交给别的模型继续整理，要的是一份结构正确、引用不断的文本。

## 2. 决定

由核心的 `docToMarkdown`（`packages/core/src/docMarkdown.ts`）把文档确定性地转成一份 Markdown，不调用模型；整个文档和单个标签页走同一个函数。

- **结构**：文档标题是唯一的 `#`；每个标签页是 `##` 一节，子标签页 `###`；标签页自己的标题（开头的 `# 标题`）就是节标题，不重复，没有就用目录里的标题；正文里的标题顺着往下推，最深到 `######`。第一个标签页开头的标题和文档同名（常见：首页标签页写的就是文档标题）时，它是文档的导语，不再另起一节，免得同一个标题出现两次。单个标签页导出时，标签页标题是 `#`，自成一篇。
- **图片**：本地图片（`assets/`、`uploads/`）的路径去掉 `../`，成为相对这份 .md 自己所在目录的路径；远程图片原样。
- **高亮**：`==x==` 写成 `<mark>x</mark>`（CommonMark 允许行内 HTML，多数渲染器认；不认的也只是多一对标签，文字还在）。行内代码和围栏代码块里的内容一律不动，标题推移和图片改写也不进代码块。
- **其余原样**：列表符号、表格对齐、换行写法都是作者写的样子，不重排。
- **评论不导出**：评论是别人对文档的意见，不是文档的文字；放进去会让一份“给人读的文档”里夹着没有上下文的对话。要看评论的人看 `comments.json`。

## 3. 图片怎么跟着走

菜单里只有一个 Markdown 项，不让人先选“要不要图片”（智能默认，不做开关）：文档里没有本地图片就存 `<名称>.md`；有就存 `<名称>.zip`，里面是 `<名称>.md` 加上图片文件，放在文本里写的那些路径上（`assets/x.png`）。解压后文本和图片的相对关系就是对的，Typora、Obsidian、GitHub 都能直接用。菜单项的说明里写明“有图片时是带图片的 .zip”，不让文件类型成为意外。读不到的图片（文件已被删）不让整次导出失败：zip 照出，提示里说有几张没放进去。

命令行 `tingly-design export <文档> --as md [--tab …]` 跑的是菜单的同一项，所以同样得到 .md 或 .zip。

没选的：
- 把图片内嵌成 `data:` 地址：单文件，但体积大几倍，GitHub 等不渲染，编辑也不可读。
- 总是出 zip：没图片的文档也要解压才能看，白多一步。
- 两个菜单项（“Markdown”和“Markdown + 图片”）：同一个词两个意思，让人先判断自己的文档有没有图。

## 4. 没做 / 还开着

- 评论是否可选导出（比如作为文末脚注）：没人要过，先不做。
- 嵌套深度只有两级（标签页、子标签页），和文档本身的限制一致。
- 一个很长的 .md 按 `##` 拆成多个标签页：导入一个文件仍是一个标签页（和导入文件夹里的多个文件一致）。导出再导入因此得到一个大标签页，不是原来的几个；要拆成几个，人自己在编辑器里分，或交给 Claude Code。

## 4b. 会自己画的代码块

不新增节点类型，也不引入文件格式：围栏的语言决定画什么，文件里永远是普通围栏，所以 Markdown 导出、git diff、Claude Code 读写都不变。`mermaid` 画图（Mermaid），`latex`/`tex`/`math` 画公式（KaTeX），`csv`/`tsv` 画表格（核心的 `parseDataFile`）。三者都沿用现成的库，按需动态加载。光标不在块里时只显示画出来的结果，光标进来（或点一下）显示源码；画不出来时显示原因并保留源码。上游 Claude Docs 的图表是脚本模块，导出即丢；这里选的是更便宜的方案（见 `.research/claude-docs-diagrams.md` 的 A–D），可编辑标签的 SVG 块仍开着。实现在 `apps/editor/src/components/docs/richCode.ts`。

## 5. 导入：导出的 .zip 原路回来

导入本来就能收 Markdown 文件和文件夹（每个文件一个标签页，图片留在 `uploads/`，链接改过去）。要补的是导出的产物自己：带图片的导出是 .zip，回来时不能让人先解压。所以“导入 Markdown…”也收 .zip：拖进来、从文件选择器选都行，里面的文件当作一个文件夹导入，之后和导入文件夹完全一样。只有文档的导入这样做（只有它收 Markdown）；整个项目的 .zip（带 `tingly-design.json`）不展开，仍从首页打开。`<mark>x</mark>` 读回编辑器的 `==x==`，是导出的逆过程；代码里的不动。

## 6. 文字颜色

给几个词上色（警告、状态、关键数字），不用离开编辑器也不写 HTML。选中文字后的菜单里有“文字颜色”，展开六个色板（红、橙、绿、蓝、紫、灰）和一个清除。

- **文件里存名字，不存色值**：`<span data-color="red">词</span>`（`packages/core/src/docColors.ts` 是名字表，编辑器的 `textColor.ts` 读写）。色值由读的一方决定：编辑器用主题 token（`--doc-red` 等，浅色深色各一套），所以同一份文件在深色下不会刺眼，换主题也不用改文件。独立导出（HTML、PDF、PNG）用名字表里的浅色值，因为那些页面是浅底。没选的：存 `style="color:#c62828"`，深色下读不清，Claude Code 写色值也没有约束。
- **色板固定，不跟文档的字体外观走**：文档的“look”只管字体和宽度，不是配色；另做一套按外观派生的色板，是一个没人要的配置面。要加色，往名字表里加，编辑器、导出和 skill 一起跟。
- **是 §2 里唯一读回编辑器的原始 HTML**：别的标签仍不可编辑（skill 里照旧要求避免）；名字不在表里的 `<span data-color>` 不认，原样当文字，不丢字。
- **Markdown 导出**：span 原样保留（CommonMark 允许行内 HTML），不认的渲染器只是少了颜色，字还在，和 `<mark>` 同一个取舍。
- **只有文档有**：这是行内文字的标记；画布、幻灯片、动效的文字颜色是各自属性面板里的样式，不是这个。
