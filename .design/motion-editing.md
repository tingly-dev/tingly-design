# 动效的细粒度编辑：舞台点选、时间轴、关键帧

状态：**第一期已实施**，第二到四期是方案。实施了什么、和方案有哪些出入见 §8；§3–§7 是完整的设计，其中没做的部分仍是方案。这份说明场景原来为什么点不动，以及让它像幻灯片一样逐个元素编辑的交互和实现。版面和播放 / 暂停时两个画面怎么切换的示意图在 [motion-editing.pencil.md](./motion-editing.pencil.md)，两份冲突时以本文为准。

格式本身（`data-in` / `data-out` / `data-keys` / `data-<format>` / `data-only`）不变，见 [motion.md](./motion.md) §5；本文只讲编辑器怎么改这些属性。

## 1. 为什么原来点不动

场景文件就是幻灯片子集加时间属性，按理说幻灯片能做的点选、改字、拖动，场景都应该能做。点不动不是哪里坏了，而是播放器和幻灯片舞台走的是两条完全不同的路（下表是第一期之前的情况，播放器这一列至今仍是播放器的样子）：

| | 幻灯片舞台（`SlideFrame` → `runtime.tsx`） | 动效播放器（`MotionFrame` → `sandbox/src/motion.ts`） |
|---|---|---|
| 怎么画 | 用 core 的解析器把源码解析成元素树，React 逐个渲染，每个 DOM 节点带 `data-dc-tid`，指回源码里的那段字符 | 把源码塞进 `<template>.innerHTML`，再按尺寸改写属性（`data-tall` 合进 `style`）、展开 `<x-shape>`；DOM 和源码之间没有任何对应关系 |
| 和编辑器说什么 | `select` / `hover` / `inspect` / `text` / `move` / `dragout` / `contextmenu`…，编辑器据此走 `editElement` 写回 | 只有 `load` / `seek` / `play` / `pause` 进，`loaded` / `time` / `ended` 出；没有任何指针事件 |
| 一次改动的代价 | 只重渲染这一页，React 增量更新 | 整个作品重新 `mount`：所有场景重建、字体重新加载、嵌入等就绪（最多 3 秒） |
| 编辑器外壳 | 选择状态、属性面板、图层、提示栏、撤销 | `MotionApp` 都没接；服务端的快速 AI 对动效直接拒绝 |

除了"没接"，还有三处是动效特有的难点，决定了不能简单把幻灯片舞台搬过来：

1. **画面上的样子不是源码里的样子。** 在时刻 t，一个元素的位置、透明度、缩放是 `style` 加上入场 / 出场 / 关键帧动画的结果。点到一个正在上升的标题，拖它，该改 `style`、改 `data-in`，还是加一个关键帧？
2. **看不见的元素也在 DOM 里。** 还没入场的元素透明度为 0，但照样接收点击，会挡住下面看得见的东西。
3. **同一个文件，几种尺寸。** 在 9:16 里看到的样式是 `style` 合并 `data-tall` 的结果；在 9:16 里改了字号，该写到哪一个属性里？

所以要做的是三件事：让舞台能把点击对回源码（§4），定下"在时刻 t 改东西"的规则（§3.3–3.5），定下"在某个尺寸里改东西"的规则（§3.6）。

## 2. 编辑动效时，人在问什么

改一段动效的问题分在两条互相独立的轴上（UX 原则 4，正交的轴分开放）：

- **空间：这个东西长什么样。** 这行字写错了，标题再大一点，卡片挪到右边，按钮换个颜色。这和改一页幻灯片完全一样，答案也应该一样：点它，改它。
- **时间：它什么时候、怎么出现。** 标题晚一点进来，这个场景短一点，三张卡片依次弹出，光标在 2 秒时移到按钮上。

空间问题在舞台和属性面板里回答，时间问题在时间轴和属性面板的"动画"一节里回答。两者共用一个选择：在舞台、图层、时间轴任何一处选中一个元素，三处同时高亮。

## 3. 交互设计

### 3.1 版面

和幻灯片编辑器同一套骨架，换掉左侧的缩略图条：

- **顶栏**：作品名、插入（文字、图片、形状 / 图标，和幻灯片一样）、尺寸切换（16:9 · 9:16）、速度、封面、检查、记录、属性面板开关。
- **舞台**：当前场景在播放头时刻的画面，可以直接点、拖、双击改字。
- **时间轴（舞台下方）**：最上一行是刻度和播放头；第二行是场景条（现在播放器里已有的那一行，按时长等比）；下面是当前场景里每个有动画的元素一行，一条时间条。
- **右侧属性面板**：复用幻灯片的 `RightPanel`（图层、样式、代码），多一节"动画"。
- **提示栏**：和其他类型一样的 `PromptBar`，快速 AI 和交给 Claude Code 在同一处。

场景顺序本身就是时间，放在时间轴里比放在左侧竖条里更直接；左侧不再有缩略图条，舞台更宽。

### 3.2 播放和编辑没有模式之分

不设"编辑模式 / 预览模式"开关（UX 原则 2）。规则只有一条：**暂停时可以改，播放时只看。**

- 暂停时，舞台显示播放头所在场景在该时刻的画面，可以点选、拖动、改字。
- 播放时点舞台任何地方：暂停，回到编辑画面。（理想是同时选中点到的元素；播放画面是独立的框架，点击拿不到元素，这一半没做，见 §7。）
- 改动立刻生效在舞台上；从暂停处再按播放，看到的就是改后的成片。
- 只想看片时，播放按钮旁的"全屏播放"收起时间轴、面板和提示栏，只留画面和进度条，按 Esc 回到编辑。这是视图的切换，不是一种编辑模式：回来时选择和播放头都还在。
- 播放器和编辑共用一个界面：现在播放器里的尺寸切换、速度、封面、检查、场景条都保留，场景条并进时间轴。

### 3.3 点选：在时刻 t 点到的是什么

- **只能点到此刻看得见的元素。** 还没入场、已经出场、或此刻透明度为 0 的元素不接收点击，点击穿过它落到下面的元素上。
- **看不见的元素从图层或时间轴选。** 图层面板里，此刻不在画面上的元素显示为淡色，并标出它出现的时间（"0.8 s 入场"）。从图层或时间轴选中一个此刻看不见的元素时，播放头跳到它落定的时刻（入场结束那一刻），因为人选它就是要看它。
- **场景开头是落定页。** 播放头停在场景第 0 秒（点场景条就停在这里）时，整个场景按落定的样子画出，所有元素都能点，像一页幻灯片。离开开头，回到时刻 t 的真实画面和上面两条规则。理由见 §8。
- **场景本身**：点舞台空白处选中整个场景（`<section>`），属性面板显示背景、版式、时长、转场。

### 3.4 改样式：改的是落定状态

一个元素在源码里的 `style` 是它**落定**时的样子：入场动画从某个偏移量走到它，出场动画从它走开。入场结束到出场开始之间，画面上看到的就是 `style`（有关键帧的除外，见下）。所以：

- **拖动、缩放、改面板里的数值，写的都是 `style`。**
- **选中即落定。** 选中一个正在动的元素（播放头停在它入场的半途），舞台把**这一个元素**画在落定状态，周围画一圈虚线，角上一个小标签"显示落定位置"；其他元素仍停在时刻 t。这样拖到哪里就落在哪里，不会出现"拖完一放，元素又跳开"。取消选择，它回到时刻 t 的样子。

考虑过的另外两种：

- 选中时把播放头跳到它落定的时刻。会把整个画面带走，人正在对照的上下文没了；只在"选中一个此刻看不见的元素"时这样做（§3.3）。
- 改此刻画面上的值，自动换算成动画参数。一次拖动可以对应改 `style`、改入场偏移、加关键帧好几种写法，人猜不到写了什么。不做。

**有关键帧的属性例外。** 一个元素的某个属性（`x`、`y`、`scale`、`rotate`、`opacity`）已经有 `data-keys` 轨道时，这个属性在此刻的值就是轨道算出来的，没有"落定"可言。这时改它写的是**播放头处的关键帧**：播放头正好在一个关键帧上（半帧以内），就改那一帧；不在，就在播放头处加一帧。面板里这一行带一个 ◆ 标记和"关键帧 @2.0 s"，人看得到写到了哪里。没有轨道的属性，面板每行右侧有一个空心 ◇，点一下就在播放头处开始一条轨道。是否有关键帧由源码决定，不是一个需要来回切换的开关（UX 原则 6）。

**改字**：双击进入文字编辑，和幻灯片一样。编辑时暂停、该元素落定显示。`type`（逐字打出）和 `count`（数字滚动）改的是最终的文字。

### 3.5 改时间：时间轴和"动画"一节

**时间轴里的一个元素一行。** 时间条从入场开始到出场结束（没有出场就到场景结尾）；条的头部一段是入场动画，尾部一段是出场动画，段上写预设名。

| 拖什么 | 改什么 |
|---|---|
| 时间条中段 | 入场和出场的 `@start` 一起平移 |
| 入场段的左沿 / 右沿 | 入场的 `@start` / 时长 |
| 出场段的左沿 / 右沿 | 出场的 `@start` / 时长 |
| 场景条上一个场景的右沿 | 该场景 `<section>` 的 `data-duration` |
| 两个场景之间的转场标记 | 点开选 `cut` / `fade` / `push` / `magic` 和时长，写 `data-transition` |
| 关键帧菱形（展开元素行后） | 那一帧的时间 |

- 拖动吸附到：播放头、场景边界、同场景其他元素的入场开始 / 结束、整 0.1 秒。按住 Alt 不吸附。
- **自动排的时间要可见。** 没写 `@start` 的入场按源码顺序自动错开（200 ms 起，每个 150 ms）。时间条照实画在自动算出的位置上，起点画成虚线，面板写"@0.35 s（自动）"；一旦拖了，就写成具体的 `@0.35s`，虚线变实线。原则 5：显示具体值，不显示别名。
- 刻度用**写进文件的时间**（作品速度之前），因为拖出来的数字就是文件里的数字；刻度末端写成片时长（"成片 24.3 s · 1.5×"）。

**属性面板的"动画"一节**（选中元素时出现，紧跟样式之后）：

```
入场  [rise ▾]  500 ms  @0.2 s  [ease-out ▾]
出场  [fade ▾]  300 ms  @5.4 s  [ease-in  ▾]    或  [＋ 出场]
关键帧  x ◆ 3 帧   scale ◆ 2 帧                 或  在播放头处加 ◇
```

每个值都是可以直接改的具体数字，改完写回同一个属性。预设下拉里每一项旁边有一个小预览（鼠标移上去在舞台上播放一遍该元素的这个预设），省得人去记 `slam` 和 `pop` 的区别（原则 8，教育放在产品里）。

### 3.6 多尺寸：改动写到哪

尺寸切换就在顶栏。改动落在哪里跟着人此刻所在的尺寸走（原则 12，副作用限定在当前界面），并且写在明处：

- **在第一个尺寸（主尺寸）里改样式**，写共享的 `style`，所有尺寸都变。
- **在其他尺寸里改样式**，写这个尺寸的覆盖属性（`data-tall`），只合并有差异的声明。
- 属性面板顶部一行写清楚"改动写到：所有尺寸"或"改动写到：仅 tall（1080×1920）"。在其他尺寸里，被单独设过的属性旁边有一个标记和"用共享值"，点了就删掉这条覆盖。
- **文字和时间永远共享。** 一个尺寸只该在版式上不同，台词和节奏不该分叉；`data-in-tall` 这类覆盖仍然认，但编辑器只在元素已经有它时才写它。
- **只在某些尺寸出现的元素**（`data-only`）：在不显示它的尺寸里，图层面板列出它，淡色，标"只在 wide"；面板里可以改 `data-only`。

### 3.7 亲手设定尺寸

尺寸不该只能靠描述给 AI。这里的"尺寸"有两层，都要能在界面上直接、精确地设：

**元素的尺寸：舞台上的缩放手柄。** 选中元素后四角四边八个手柄，拖动时旁边实时显示 `W × H`。

- 写回：`width` / `height`（px）；固定定位的元素从左、上两边拖时同时写 `left` / `top`。在弹性布局里的元素，一拖就从"填充 / 适应内容"变成固定值，面板里的宽高模式随之显示"固定"。
- Shift 保持比例，Alt 以中心缩放；吸附到同场景其他元素的边和中线、场景的边和中线，吸附时画出参考线。
- 面板里现有的宽、高、最小 / 最大宽高字段不变，手柄和字段改的是同一个属性。
- 动效特有：缩放的是落定状态（§3.4），带 `scale` 动画的元素按未缩放的尺寸算；在非主尺寸里拖，写进该尺寸的覆盖（§3.6）。
- 手柄做在共用的编辑运行时里（§4.2），所以画布画板里的元素和幻灯片里的元素同时得到它（现在三者都只能拖动位置、在面板里填数）。

**作品的尺寸：管理 `formats`。** 顶栏的尺寸切换旁边一个"＋"，什么都没选中时属性面板显示"作品"一节：

```
尺寸   wide   1920 × 1080   主尺寸
       tall   1080 × 1920            [删除]
       ＋ 添加尺寸 ▾   16:9 · 9:16 · 1:1 · 4:5 · 自定义 W × H
帧率   30 fps
```

- 宽、高、名字都是可以直接改的字段，写 `motion.json` 的 `formats`。
- 新加的尺寸没有任何覆盖，靠弹性布局和 `%` 自己适配；加完立刻切到它，检查把超出画面的元素列出来，点一条就选中那个元素，接着在这个尺寸里调（写进它的覆盖）。
- 删除一个尺寸同时删掉所有场景里它的 `data-<name>` 覆盖，删除前说清有多少处。
- 第一个尺寸是主尺寸，共享的 `style` 就是它的样子。换主尺寸意味着把所有覆盖换个方向重写，暂不提供（§7）。

**画布已有的和要补的。** 画板尺寸已经能直接设：面板里有宽高字段和预设，画板角上可拖。缺的是画板里元素的缩放手柄，由上面的共用手柄补上。

**其他类型（待讨论）：** 幻灯片的页面固定 1920×1080，这是子集的前提，元素手柄随共用运行时一起得到；看板页面随窗口自适应，元素尺寸多由网格决定，手柄的意义要再看；文档只有图片宽度一项值得做。

### 3.8 场景

在时间轴的场景条上操作，右键菜单和幻灯片缩略图的一样：在后面新建一个场景、复制、删除、设为封面。拖动场景块换顺序（写 `motion.json` 的 `order`）。封面场景显示为场景条最前面一个单独的块，选中它时舞台显示封面，没有时间条。

### 3.9 插入

（图片和 SVG 的插入已随导入实施，见 §8；文字和形状的插入仍是方案。）


插入的文字、图片、形状和幻灯片一样落在舞台中央，并且**从播放头开始入场**：新元素带 `data-in="fade 300ms @<播放头>"`。人一般是停在"这里要多一个东西"的时刻才去插入，这比让它从场景开头就在更符合意图（原则 6，聪明的默认值）。

### 3.10 AI

- **快速 AI 开放给动效。** 现在服务端拒绝，是因为没有舞台、没有选择，模型不知道人在说哪个元素。有了选择以后，和幻灯片一样走 jQuery 写回：上下文带当前场景文件、选中元素、播放头时刻、当前尺寸和这个场景的时间表（每个元素的入场、出场、关键帧）。"标题晚半秒进来"变成 `$('#dc7').attr('data-in', 'rise 500ms @0.7s')`；"竖版标题大一点"变成写 `data-tall`。越出子集或时间检查报错的改动，像幻灯片一样撤回并说明。
- **交给 Claude Code** 不变，附上的场景从"播放头所在场景"扩展为"选中元素所在场景 + 选中元素"。

## 4. 实现：舞台用哪个运行时

### 4.1 三种做法

| | A. 给动效运行时补上编辑能力 | B. 舞台用幻灯片的编辑运行时，加上"在时刻 t" | C. 一个运行时同时服务编辑、播放和导出 |
|---|---|---|---|
| 做法 | 在 `sandbox/src/motion.ts` 里给每个元素记上 tid，再写一遍点选、拖动、改字、悬停、检查 | `runtime.tsx` 多一种渲染方式：只渲染当前场景，渲染后把这个场景的动画计划（core 的 `planScene`）套到带 tid 的 DOM 上并停在 t | 播放器和渲染器也改成 `runtime.tsx` 渲染，`motion.ts` 只剩时钟 |
| 能复用 | 只有动画部分 | 点选、拖动、改字、悬停、右键菜单、`inspect`、图层、属性面板、`editElement`、撤销、409 重放全部现成 | 同 B，且只有一条渲染路径 |
| 新写 | 约一千行编辑交互，与 `runtime.tsx` 平行维护 | 动画计划从 `motion.ts` 抽成共用函数；按尺寸改写属性放到渲染时；`seek` 消息；不可见元素不接点击；选中元素落定 | 渲染器要加载 React 运行时；转场、多场景叠放要搬进 `runtime.tsx`；`--verify` 全部重测 |
| 风险 | 两套编辑交互慢慢分叉 | 编辑画面和播放画面由两份代码画，可能走样（见 §4.5） | 改动面最大，导出路径刚刚稳定，没必要现在动 |

**选 B。** 它把"场景能不能像幻灯片一样改"变成"幻灯片舞台能不能停在一个时刻"，而后者需要的新东西很少。C 是可以走向的终点，但不是现在的前提；B 里抽出来的共用动画函数正是 C 将来要的那一块。

### 4.2 运行时

- **共用的场景动画函数。** 把 `sandbox/src/motion.ts` 里"给一个 `<section>` 生成 Web Animations 并停在 t"的部分抽成一个函数（输入：场景根节点、元素列表、场景时间窗、尺寸；输出：动画、计数器、检查结果），播放器和编辑舞台都调它。布局 CSS 两边都用 `sceneBaseCss`。
- **`runtime.tsx` 的动效渲染方式**：渲染消息多带 `{ format, formats, size, t }`。渲染每个元素时先用 `attrsForFormat` 合并当前尺寸的覆盖，tid 不变；被 `data-only` 排除的元素不渲染。React 提交后调用共用函数，`currentTime = t`。改字、拖动后重渲染的只是这一个场景。
- **新消息 `seek`**：暂停时拖播放头，只改 `currentTime`，不重渲染。
- **不可见不接点击**：每次 seek 后，给此刻不可见的元素加 `pointer-events: none`。
- **缩放手柄**：选中元素的八个手柄、实时尺寸标签、吸附参考线，结束时发一条 `resize`（要写和要删的声明），编辑器照常走 `editElement`。画布和幻灯片共用。
- **选中即落定**：被选中元素的入场 / 出场动画暂停在落定时刻；有关键帧的属性仍按 t 算。选择框按落定位置画。
- 嵌入（`<x-embed data-seek>`）在编辑舞台里和幻灯片一样只能整块选中，内部不接点击；`seek` 时一并转发给它。

### 4.3 编辑器

- **两个画面叠放**：播放用现在的 `MotionFrame`（整条时间线、转场、所有场景）；暂停时显示编辑画面（当前场景，停在 t）。两个都常驻，编辑画面在显示前先 seek 好，切换不跳。播放画面不再跟着每次按键重载：源码变了只记一个"过期"，下次按播放时才重新 `load`。
- **播放头落在转场里**时，编辑的是进来的那个场景（和现在场景条的高亮规则一致）。
- `MotionApp` 接上 store 的选择状态（`selection` 的 `file` 就是 `scenes/<id>.html`）、`RightPanel`、`PromptBar`、`ContextMenu`；`store.ts` 里给动效加当前场景（类似幻灯片的 `slide`）。
- `RightPanel` 里现在按 `kind === 'slides'` 分支的地方，动效走同样的分支（场景就是子集），再加"动画"一节；幻灯片的 `BuildRow` 是"动画"一节的样板。
- 服务端去掉对动效快速 AI 的拒绝，加 `FAST_EDIT_MOTION`；检查用幻灯片子集检查加 `planScene` 的时间检查。

### 4.4 每个操作写回什么

全部是一个属性或一处文字的改动，走同一个编辑队列、409 重放和撤销。

| 操作 | 写回 |
|---|---|
| 改字 | 元素文字 |
| 拖动、缩放手柄、面板改样式（主尺寸） | `style` 的相应声明（缩放手柄写 `width` / `height`，必要时 `left` / `top`） |
| 同上（其他尺寸） | `data-<format>`，只写与共享值不同的声明 |
| "用共享值" | 从 `data-<format>` 删掉那条声明 |
| 有关键帧的属性 | `data-keys` 里播放头处的那一帧 |
| 拖时间条 / 面板改入场出场 | `data-in` / `data-out` |
| 拖场景右沿 | `<section data-duration>` |
| 转场 | `<section data-transition>` |
| 添加、改、删除作品尺寸 | `motion.json` 的 `formats`；删除时连同各场景里的 `data-<name>` |
| 场景新建、复制、删除、排序 | `scenes/<id>.html` 的新建 / 删除，`motion.json` 的 `order` |
| 插入 | 新元素，带 `data-in="fade 300ms @<t>"` |

### 4.5 不让编辑画面和成片走样

B 的代价是同一帧有两份代码画（编辑舞台和播放器）。三道防线：

1. 时间部分只有一份：动画计划来自 core 的 `planScene`，套用来自 §4.2 的共用函数，两边都调。
2. 布局部分只有一份：`sceneBaseCss` 和子集基础样式；`<x-shape>` 等由 core 的 `slideArt` 画。
3. 端到端测试对示例项目的每个场景取几个时刻，编辑舞台和播放器各截一张，逐像素比较（容差同 `--verify`），走样就失败。

## 8. 实施状态

第一期已实施。和上面的方案一致的部分不再重复，这里只记落地时定下的细节和出入。

**共用的场景动画。** `packages/sandbox/src/sceneAnim.ts` 的 `animateScene(元素, 场景起点, 时长)` 把 `planScene` 的计划套成暂停的 Web Animations，返回 `setTime(t, 落定集合)` 和 `clear()`。播放器（`motion.ts`）每个场景调一次，编辑舞台（`runtime.tsx`）只对当前场景调一次。可 seek 的嵌入在两边都附上同一段 `SEEK_BRIDGE`。

**舞台。** `SlideFrame` 多一个 `scene` 参数：文件是 `scenes/<id>.html`，尺寸、字体和渲染消息里的 `motion`（尺寸名、全部尺寸、画面大小、t）都来自作品。运行时渲染每个元素前先合并当前尺寸的覆盖，被 `data-only` 排除的不渲染；提交后套动画并停在 t。此刻不在画面上的元素带 `data-dc-off`（不接点击），选中的元素带 `data-dc-rest`，入场和出场停在落定状态，关键帧仍随 t。

**两个画面。** 播放器和编辑舞台叠在同一处。暂停时编辑舞台在上；播放时换成播放器，编辑舞台保留暂停那一刻的画面，不随每帧重渲染。播放器的源码去抖 600 ms 后在后台重新加载，所以连续改字不会让它反复重载。播放时点画面暂停回到编辑。没有做"全屏播放"。

**一条时间轴。** 舞台下方是一块时间轴面板：顶行是播放按钮、时间和"播放头在哪个场景"；下面是刻度尺（带秒数标注，标注间距按面板宽度在 1 s 到 10 min 之间取，至少约 64 px）和场景轨道，场景片段写场景名和时长，播放头带一个落在刻度尺上的手柄。刻度尺、场景轨道和播放头画在同一条轴上，宽度相同，起点相同。场景块的左沿是场景的开始时刻，右沿是下一个场景开始的时刻（最后一个到作品结尾），不是场景自己的时长：有转场时相邻两个场景的窗口重叠，按时长等比排开的话，块的总宽超出作品时长，越往后越偏离播放头。按"下一个场景接手"划分，正好对应舞台编辑的规则（转场里编辑进来的那个场景），点块里任何位置和播放头停在那里，高亮的是同一个场景。转场重叠段现在不单独画，等做转场标记时再画。刻度尺本身是原生的 range 输入，保留键盘和读屏；滑块宽度设为 0，值才能对上整条轴的宽度（默认滑块会让两端各缩进半个滑块）。

**定位和落定页。** 点场景条跳到场景开头。场景是一页，人选中一个场景来改，期待播放头在这一页的起点。但第 0 秒的真实画面往往是空的，元素都还没入场。所以播放头正好停在场景开头时，舞台把整个场景画成落定的样子：每个元素入场已完成、出场未开始、计数显示终值，全部可点。时间轴下的标签写"落定"。往后走一帧或拖动播放头，就回到那一刻的真实画面。考虑过的另两种做法：一是跳到"都到位"的时刻（`sceneVisibility` 的 `settled`），可以点，但播放头落在场景中段，和"选中这一页"的直觉不符；二是停在开头并画真实帧，舞台是空的，只能从图层里选。落定页的代价是，同一位置先后出现的元素会叠在一起；这正是改版面时需要看到的。编辑的是播放头所在的场景，封面打开时是封面场景。

**尺寸。** 在非主尺寸里的样式改动由 store 的 `editElement` 统一改写成 `data-<format>` 的属性改动（core 的 `editsForFormat`），面板、手柄和快速 AI 走的都是这一处。面板读样式时用 `styleInFormat` 合并覆盖。删除尺寸时一并删掉 `data-<name>`、`data-(in|out|keys|duration|transition)-<name>`，并把它从 `data-only` 里去掉。尺寸改名不提供：改名要改所有覆盖属性的名字，和删了重加没有区别。

**面板。** 什么都没选时是作品（标题、帧率、尺寸）；选中场景根节点时是场景（id、时长、转场、背景、文字色，以及 `checkScene` 的问题）；选中元素时是"改动写到"一行加普通样式面板。图层里此刻不在画面上的元素淡色，标出"x 入场 / 已离场 / 不在 tall"。没有 Tweaks 页。

**快速 AI。** 服务端的系统提示是幻灯片的提示加 `FAST_EDIT_MOTION`（时间属性、覆盖写法、只改属性不改结构）。给模型的大纲写明作品尺寸、主尺寸、播放头（停在开头时说明画面是落定的）和场景列表；写回后的检查用 `checkScene`（幻灯片子集检查去掉幻灯片的转场规则，换成动效的转场和时间检查）。

**还没做（第一期范围之外，或推后的）。** 场景的新建、复制、删除和排序（编辑器里提示交给 Claude Code）；元素时间条和"动画"一节；关键帧；在播放头插入；导出和装入设计系统。

**导入。** 动效接在各类型共用的导入路径上（[import-into-project.md](./import-into-project.md)）：图片和 SVG 拖进来、粘贴或用顶栏按钮，放到播放头所在的场景上，从播放头入场，原文件在 `uploads/`。场景里的相对路径原来只有编辑舞台会解析；现在播放器按项目地址解析，命令行渲染把它们内联成 data: URL。
