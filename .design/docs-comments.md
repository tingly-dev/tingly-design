# 文档评论：表情回应，和刻意不做的

状态：**已实施**（表情回应）；草稿、@提及、多人光标 **不做**（理由见 §3）。评论的文件格式和定位见 [docs-markdown.md](./docs-markdown.md) 与 `.claude/skills/docs/SKILL.md`。

## 1. 问题

一条讨论里常有只需要“收到”的回复：人看完 Claude 的答复，或同事看完一条意见，只想表示“看到了”“同意”“做完了”。现在只能再写一条评论，讨论串被一句“好的”拉长，Claude Code 下次读讨论时也多读一条没有信息的话。

## 2. 决定

- 每条评论可以带 `reactions`：`{"👍": ["我", "Claude"]}`，表情对应点过的人，按点的先后。存在 `comments.json` 里，和评论一起被 git、zip、Claude Code 读到。
- **提供的表情是固定的六个**（👍 ✅ ❤️ 🎉 😄 👀；手写进文件的别的表情照样显示），不开表情选择器：固定的几个在每台机器上长一样，意思也不会各人各样；Claude 回应时也只有这几个可选，skill 里写明 👍 是“读过了”，✅ 是“做完了”。要更多表情有人要了再说。
- **点哪里**：打开的讨论里，每条评论下面有一个“添加表情回应”小按钮，点开就地展开六个表情（不弹浮层，也就不用处理点外面关闭）；已有的表情是小胶囊（表情 + 人数），点一下加上或收回自己的，自己点过的高亮，悬停显示是谁。没打开的讨论只显示已有的胶囊，不多出按钮，右栏不变吵。
- **谁是“我”**：设置过的名字（`dc.author`），没设置就写固定的 `me`，显示时才换成界面语言的“我”。不写界面语言的字，是因为换语言后“我”的字不同，同一个人会被当成两个人、收不回自己点的那个。
- **回应不是请求**：skill 告诉 Claude 把它当作确认，改讨论时保留，不把 👍 当成“照做”的指令。
- 回应的改动走普通的评论写回（不进撤销栈，和别的评论操作一致）。

## 3. 没做

- **草稿 / 提案（Insert as draft）**：上游把一处修改先显示成待接受的草稿。这里改文档是写文件，人和 Claude 同时在改，加一层“待接受”要有第二份文本和合并规则；而价值（改动落地前先看一眼）已经被历史版本与恢复（[docs-history.md](./docs-history.md)）覆盖：改坏了一键回去。等有人明确要“先看后落”再设计。
- **@提及、多人光标**：本地单人工具，一个服务上没有第二个人；没有受众的功能不做。
- **按人筛选 / 右栏筛选表情**：量不到需要。
