# 画布和幻灯片的主题：一键换成设计系统的某个主题

状态：**已实施**（画布、幻灯片）。§7 是还没定的问题。

## 1. 要解决的问题

装入一套设计系统（或内置的一个风格）之后，人想看到"整个画布 / 整套幻灯片穿上它的亮色或暗色是什么样"，满意就留下，不满意就回去。现在只能一个元素一个元素地用颜色框的 ◆ 去选令牌，十几块画板、几十页幻灯片等于没法比较。

原版 Claude Design 和 Slides 在最近一次发布里都加了"主题"页：选设计系统和它的主题，按角色分组看颜色，并检查文字和底色的对比度，幻灯片还有"应用到所有页"。我们要的是同样的"一眼比较、一键换"，但要守住几条：

- 不能变成又一个要先选的模式：点一下就换，不再有"预览 / 应用"两步。
- 必须能撤销，而且"原样"随时能回去。
- 幻灯片的范围（这一页还是所有页）要说出来，不能靠猜。
- 写进文件的是普通值（Claude Code、git、导出都看得见），不是只有编辑器认得的状态。

## 2. 前提：文件里存的是什么

装入的设计系统只把 `tokens.json` 复制到项目里（`ds/<名字>/`），颜色框选一个令牌写下去的是**它的值**（`#f7f7f4`），不是 `var(--paper)`：幻灯片的子集没有 `var()`，画板里也没有 `tokens.css` 的位置。所以"换主题"不是改一个全局开关，而是把文件里代表某个角色的值换成另一个主题里同一角色的值。

## 3. 考虑过的方案

位置：

| 方案 | 好处 | 问题 |
|---|---|---|
| A. 右侧面板第四个页签"主题" | 位置固定；选中任何东西都能用；和原版的页签一致 | [画布的模板值](./canvas-template-values.md) 当时否决过加页签，理由是页签是"看同一个选中对象的几种方式"，再加一个范围不同的会混 |
| B. 什么都没选时，面板里多一节 | 范围一致（没选 = 整个作品） | 选着元素时要先取消选择；这一节已经有画布名、模板值、设计系统装入、快捷键，再加卡片和色板就太长 |
| C. 顶栏的弹出 | 和"作品设置统一进顶栏"的方向一致（[cross-kind-consistency.md](./cross-kind-consistency.md) §6-2） | 那个决定还没落地；色板和对比度要的空间比弹出多 |

换法：

| 方案 | 问题 |
|---|---|
| 把文件里的颜色改成 `var(--令牌)`，主题只是 `data-theme` 切换 | 幻灯片子集没有 `var()`；画板、导出、PPTX 都要认；要改写所有已有作品的格式 |
| 让 Claude Code 重画 | 慢、要钱、不确定；"看看暗色是什么样"不该花一次模型调用 |
| **按角色把值换掉**（选这个） | 对已经用着系统颜色的作品很准；对从没用过系统的作品只能换最有代表性的几种 |

## 4. 决定

**位置：A，右侧面板的"主题"页签，只给画布和幻灯片。** 理由：主题是整个作品的事，不是选中对象的事，但又必须在选着元素时也能换（看了暗色发现某个元素不对，要能直接去点它）。所以页签是**不随选择变化**的那一个：选了什么它都显示同一份内容，打开它时图层树收起来让位。它和模板值那条理由不矛盾：模板值是"还有什么没选时才有意义的信息"，主题是"一个动作"。位置以后跟着 P5（作品设置的家）走，见 §7。

**卡片：每个已装入系统的每个主题一张，最前面一张"原样"。** 一张卡画这个主题自己的页面色、文字色、强调色和正文字体。点一下就换；亮着的那张是现在这个作品穿着的主题。没有"预览"状态，Undo 的 toast 和"原样"就是回去的路。单主题的系统（内置风格）只显示系统名。

**怎么知道作品现在穿着什么：从文件读，不信记录，而且一个文件一个文件地读。** 把每个主题的令牌值集合和这个文件里的颜色用量比：要至少两种不同的令牌色、并且占全部颜色用量的四成以上，用量最多的那个（系统、主题）才算它穿的；否则就是原样（白底页面上几个白色按钮，不能算穿了某个系统的 `surface`）。一套幻灯片可以一半亮一半暗，所以每个文件按它自己穿的主题换；卡片上亮的是整体最多的那个，点已经亮着的卡片会把剩下的也拉齐。`canvas.json` / `deck.json` 里的 `theme` 记录只用来在平手时选，并保存"原样"。这样人用颜色框手改了一半、Claude Code 改过、撤销过，都不会和记录不一致。

**怎么换（core `theme.ts`）：**

1. 已经穿着某个主题：把它的令牌和目标主题的令牌**按角色**配对（页面、卡片、文字、次要文字、弱文字、线、强调），角色没有的再按同名配对。不能只按名字：Tingly 的页面叫 `paper`、卡片叫 `surface`，内置风格的页面叫 `surface`、卡片叫 `surface-raised`，同名不同义。配对之后文件里等于旧值的颜色换成新值；别名令牌（`accent = {brand}`）按它指向的值算。
2. 原样（没有用过任何系统）：只取**三种定义这个作品的颜色**：每个文件根元素的背景（页面）、用得最多的 `color`（文字）、用得最多的有色相的颜色（强调），当成这三个角色。其余颜色不动。页面色只在 `background` / `fill` 这类属性里换，文字色只在 `color` / `fill` / `stroke` / 边框这类属性里换：白底页面上“蓝按钮里的白字”不是页面，不能跟着变成暗色页面色。
3. 这三个原来的值记在 `theme.base`（按角色，不按令牌名，所以之后亮暗来回换都不丢；之后新加的文件再换一次，已有的 `base` 优先，不会被覆盖）。"原样"把现在穿着的令牌值（同样按属性）换回 `base`，并删掉记录。只换这一页时不写 `base`：那一页的“原样”靠 Undo。
4. 字体族只在幻灯片里换（幻灯片有 `faces`，装入时已经装好了字体；画板没有加载系统字体的地方），同样按键（sans、display）配对，原样记在 `base.fonts`。文字样式的大小、行高不动：那是这个作品的版式，不是主题的。
5. 只改声明的值：行内 `style`、`<style>` 里的声明、`fill` / `stroke` 这类颜色属性；`<script>` 里的、`url(#id)`、`href="#add"` 一律不碰。

**为什么只换三种而不是全部：** 全部要给每一个旧颜色猜一个令牌，猜错一个就是人要逐个找回来的错。三种是任何设计都有、而且换了就一眼看出"换了"的；其余的颜色保持原样，卡片下面那一行说有几种没动，并且在请求栏下面提议"让 Claude 换掉其余的"（还剩 3 种以上才提；一两个杂色不值得一次请求）。“没动的颜色”只数不属于任何已装入系统的颜色，同一系统里没配上对的令牌色不算。

**撤销：**

- 一次换动很多文件，在撤销栈里是**一步**（编辑引擎的 `group`）：⌘Z 一次全退，⇧⌘Z 一次全做，`theme` 记录跟着。不这样的话，⌘Z 会默默撤掉人之前的另一处修改。
- 换完的 toast 带 Undo：栈顶还是这一步就等于 ⌘Z；之后又做了别的，就按换之前的内容把还保持着换完样子的文件写回（之后又被改过的不动，并说一声）。
- "原样"在没有东西可回去时（作品打开时颜色就已经是某个系统的）是灰的，并说明原因；这时来回切换亮暗仍然是可逆的。

**范围：** 画布永远是所有画板。幻灯片有一个"应用到：所有幻灯片 | 这一页"的选择，默认所有页；"这一页"只改当前页，不写 `theme` 记录（这一页和整套可以穿不同的主题，记录说的是整套）。

**让 AI 知道：** 换主题通过 `recordChange` 告诉 Claude Code（[config-awareness.md](./config-awareness.md)）：`describeChange` 一句话说换成了什么、哪些没动；`settingsProject` 里带着现在的 `theme`；`.claude/skills` 里写明 `theme` 键是编辑器维护的，别删。

**对比度：** 每个主题列出文字令牌放在它所画的底色上的对比度（正文 4.5:1，弱文字和强调色 3:1），不够的只标出来，不拦着。

## 5. 对照 UX 原则

- 按人的问题组织（1）：卡片回答"这个作品穿上哪个好看"，下面回答"现在穿的是什么、哪些没跟着变、读得清吗"。
- 消解模式（2）：点卡片就换，没有"预览 / 应用"；范围是一个看得见的选择，不是隐藏的模式。
- 一词一义（3）：这里的"主题"只指设计系统的主题（亮 / 暗）；编辑器自己的外观叫"外观"，在顶栏的"更多"里。
- 轴要分开（4）：哪个设计系统和它的哪个主题是两条轴，卡片上写成"系统 · 主题"两行；范围（所有页 / 这一页）是第三条，单独一行。
- 具体的值（5）：色板显示真实的颜色和名字，对比度显示真实的比值。
- 完成不等于锁死（10）：Undo、"原样"、再点一张卡，三条路都能回去。
- 把下一步交到手上（11）：没动的颜色数量和"让 Claude 换掉其余的"就在卡片下面和请求栏下面。
- 副作用限于当前这一处（12）：不碰 `ds/`、不碰别的项目；`theme` 记录只写在这个作品自己的索引里。

## 6. 每种类型

| 类型 | 结论 |
|---|---|
| 画布 | ✓ 所有画板 |
| 幻灯片 | ✓ 所有页或这一页，另外换字体 |
| 设计系统 | — 它本身就是主题的来源；它页面上已有"预览为…"的主题切换 |
| 看板 | — 颜色来自图表的调色板和数据，不是装入的设计系统；服务端不允许装入 |
| 文档 | — 文档有自己的外观设置（字体、宽度），不装设计系统 |
| 动效 | — 服务端不允许装入设计系统；动效的颜色在场景里写死 |

## 7. 还没定的问题

- **位置**：作品设置的家（[cross-kind-consistency.md](./cross-kind-consistency.md) P5）定下来之后，页签可能要搬进那里。
- **画布的字体**：画板没有地方加载系统字体，所以画布只换颜色，字体和文字样式交给"让 Claude 换掉其余的"。要做的话得先让画板能带字体。
- **更多角色**：现在"原样"只换三种。可以再加卡片底色（第二多的背景）和线，代价是更容易猜错；先看有没有人需要。
- **模板洞里的颜色**：`data-props` 的默认值、`{{accent}}` 这样由洞决定的颜色不是文件里的字面值，换主题不会碰它们，也不计入“没动的颜色”；这样的画板要靠 Tweaks 或让 Claude 处理。
- **只换这一页的原样**：现在靠 Undo。要有的话，`base` 得按幻灯片记。
- **逐元素的例外**：人手动给某个元素换过的颜色，如果碰巧等于某个令牌值，也会跟着换；没有"这个别动"的标记。
- **命令行和 MCP**：换主题现在只有编辑器里有。`tingly-design theme <p> <system> <theme>` 的数据（`planTheme` / `applyThemePlan`）已经在 core 里，要加只是接线；等有人在终端里需要。
