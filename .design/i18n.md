# 界面语言（i18n）

状态：**已实施**（英文、简体中文）。§6 是还开着的问题。

## 1. 问题

编辑器的界面文字原来直接写在代码里，默认是中文，但并不统一：右侧面板的 "Tweaks"、各处零散的英文按钮和中文混在一起；Claude Code 运行反馈的步骤（"读 canvas.json"）在 core 里拼成中文，服务端的报错有中有英；新建项目写进文件的占位文案只有中文。示例项目和用户自己的作品又多是英文，于是同一屏上中英交错，哪种语言都不完整。

编辑器还要嵌进 Tingly Box。Tingly Box 的控制台默认英文、跟随浏览器、可以切到中文和俄文；编辑器自己固定中文，嵌进去就和宿主对不上。

要解决的是两件事：界面只说一种语言，并且这种语言可以由人、由宿主来定。

## 2. 词条放在哪

| 方案 | 好处 | 问题 |
|---|---|---|
| 每个应用各放一份（编辑器一份、服务端一份） | 各管各的 | 服务端报错、core 的步骤文字和编辑器是同一批句子，分开放必然漂移 |
| 放进 `packages/core` | 已经是共享包 | core 是格式和写回逻辑，不依赖任何 UI 库；一千多条界面文字放进去喧宾夺主 |
| **单独一个 `packages/i18n`（`@dc/i18n`）** | 编辑器、服务端、导入器共用一份；core 保持无关语言 | 多一个包 |

选了第三种。包里按区域分文件（`locales/<lang>/<area>.ts`：`common`、`prompt`、`canvas`、`panel`、`slides`、`motion`、`ds`、`docs`、`dash`、`launcher`、`importer`、`importReport`、`starter`、`errors`……），文件名就是键的第一段（`slides.toast.copied`）。区域按"谁在用"划分，多数对应一种项目类型或一个共用部件，改一个类型只碰它自己的两份文件。

core 不再产出任何给人看的句子，改成给结构化的结果，由显示的一方去措辞：

- Claude Code 的步骤是 `{ kind, op, target, within }`，编辑器用 `prompt.step.<op>` 说出来。同一个运行可能有两个人在看，各自看到自己的语言。
- 用时是 `elapsed(ms) → { m, s }`，编辑器用 `prompt.elapsed.*` 拼。
- 撤销时定位失败抛 `RebaseConflict`（`code: 'rebase-conflict'`），编辑器显示 `errors.rebaseConflict`。
- 日志里的"谁改的"在编辑器显示 `app.actor.<actor>`；给模型看的版本在 core 里用固定的英文（`ACTOR_NAME`），提示词不跟界面语言变。

## 3. 用什么库

| 方案 | 好处 | 问题 |
|---|---|---|
| **i18next + react-i18next（和 Tingly Box 相同）** | 同一套键的写法（嵌套键、`{{name}}`、`_one` / `_other` 复数）、同一种语言检测思路；服务端和导入器用同一个库，不用 React | 体积几十 KB |
| 自己写一个 `t()` | 零依赖、键可以天然有类型 | 复数、插值、回退都要自己维护；和 Tingly Box 两套写法 |

选了 i18next，在它上面补上类型：

- `CustomTypeOptions` 把英文词条声明为资源类型，`t('不存在的键')` 是类型错误。
- 其他语言的文件写成 `satisfies Locale<typeof en>`：少一个键、拼错一个键都是类型错误，而不是悄悄回退成英文。`Locale` 允许中文省掉它用不到的复数形式（`x_one`）。
- `packages/i18n/test` 再查三件事：两种语言的键完全一致、译文保留了原文的占位符、代码里每个字面量键都存在；另外扫一遍编辑器、服务端、core、导入器和沙箱的代码，**注释以外不许出现汉字**，少数是数据不是文案的（文档字数统计的 CJK 区间、看板读数据时的"万 / 亿"、沙箱里的两条内置提示）列在白名单里并写明原因。最后这条是防止回到"写死一句中文"的老路。

## 4. 语言从哪来

和主题（`theme.ts`）用同一套优先级，嵌入方只需要学一种模式：

1. `?lang=`（链接带的，存进 sessionStorage，只管这个标签页）；
2. 人在语言按钮里选的（localStorage `dc.lang`）；
3. 服务端的 `DC_LANG`；
4. 浏览器的语言列表里第一个我们有的（`zh-CN`、`zh-TW` → `zh`）；
5. 英文。

启动后最新的一次生效：语言按钮、`window.tinglyDesign.setLanguage()`、宿主发来的 `tingly-design:set-language`。语言变了，编辑器把 `<html lang>` 改掉，并告诉宿主 `tingly-design:language-changed`；`ready` 消息也带上当前语言。这些是新增字段和消息，旧宿主可以忽略，所以协议号不变（见 [embedding](../docs/zh/embedding.md)）。

默认英文、跟随浏览器，和 Tingly Box 一致。浏览器是中文的人照旧看到中文。

只做英文和中文，不跟 Tingly Box 一起做俄文：编辑器的用户是这两种语言，多一种语言就多一份每次改文案都要同步的译文。宿主传来别的语言（如 `ru`）时编辑器认不出，保持原来的语言。真要加，是 `SUPPORTED_LANGUAGES` 一行加一个 `locales/<code>/` 目录，类型会逼着把每个键都译出来。

存储键用自己的 `dc.lang`，不读 Tingly Box 的 `i18nextLng`：嵌入时两者同源，共用一个键看起来省事，但宿主改了存储方式编辑器就会悄悄坏掉；宿主要传语言就走 URL 或消息，明明白白。

语言选择有自己的按钮，在外观按钮旁边，按钮上直接写着当前语言（English、中文）。原先它藏在外观菜单的第二段里，按钮是个太阳或月亮，想换语言的人没有理由去点它；而主题和语言是两件事，不该共用一个入口。两者都是编辑器自己的设置，不属于某个项目。每种语言用它自己的名字列出，看不懂当前语言的人也能找到自己的那一项。

## 5. 界面以外的文字

| 文字 | 用哪种语言 | 怎么做 |
|---|---|---|
| 服务端的报错 | 请求者的界面语言 | 编辑器每个请求带 `x-dc-lang`；服务端 `HttpError` 只带键和参数，统一在错误处理里用请求的语言措辞，并附 `code` 方便程序判断；没有这个头时看 `Accept-Language`、`DC_LANG`，再退回英文 |
| 新建项目写进文件的占位文案 | 新建者的界面语言 | `starter.*`；core 的模板函数（`newBoardSource`、`newSlideSource`、`newMotion`、`DASH_STARTER_PAGE`）只接收文案，不自带语言 |
| 编辑器写进文件的东西（导入报告便签、新幻灯片和文字工具的占位、文档里插入的日期） | 写的那一刻的界面语言 | 写进去就是作品的一部分，之后切换语言不会改它 |
| 日志摘要 | 见 §6 | 多数仍是英文短句（`artboard created`），幻灯片和动效已按界面语言写 |
| 模型的回复和它新写的文案 | 跟请求的语言走，拿不准时用界面语言 | 快速 AI 和 Claude Code 的提示里各加一句界面语言（`replyLanguage`）；系统提示本身保持英文 |
| 沙箱里的出错提示 | 跟画板页面的 `lang`，再看浏览器 | 沙箱是单独打包的 IIFE，跑在不透明源的 iframe 里，不引入 i18next；`sandboxDoc` 把编辑器的语言写进框架的 `<html lang>`，`packages/sandbox/src/msg.ts` 内置两条中英对照 |
| 导入器的报告和报错 | 编辑器里跟界面语言；命令行看 `DC_LANG`、`LANG` | `toCanvas`、`describeReport` 接收 `t`，默认英文；`readSvg` 也跑在浏览器里的 IIFE 中，不带 i18next，只返回结构化的字段和带 `code` 的 `ImportError`，由调用方措辞 |
| 示例项目 | 不变 | 示例是作品，不是界面；它们本来就用英文写成 |

## 6. 还开着的

- **语言和外观**：启动页有语言按钮和外观菜单；编辑器里在共用顶栏最右的"更多"（⋯）菜单里（[top-bar.md](./top-bar.md)）。
- **英文文案的打磨**：原有的界面文字是中文写成的，英文是逐条翻译过来的，还需要一次以英文为母语的通读。
- **日志摘要**：journal 的 `summary` 是自由文本，既给人在日志里看，也作为最近改动发给模型。现在多数是英文短句，幻灯片和动效按界面语言写，两种混在同一份日志里。要彻底统一，应该像运行步骤一样把摘要改成结构化（动作 + 对象），显示时再措辞，发给模型时用英文；这牵涉日志格式，留到单独做。
- **Claude Code 技能文件**（`.claude/skills/*/SKILL.md`）是给模型看的，保持英文，不随界面语言变。
