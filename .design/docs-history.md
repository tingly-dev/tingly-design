# 文档的历史版本

已实施。

## 1. 问题

文档是 Markdown 文件，人、快速模型和 Claude Code 都会改它。改错、被 Claude Code 改多了，只有撤销（本次会话内）和 git（要先提交）能救。上游 Claude Docs 有“版本历史、可恢复”，这里一直没有（`docs/*/comparison.md`）。

## 2. 决定

- 在写盘的唯一入口（`writeAtomic`）里，覆盖 `tabs/<id>.md` 之前把被覆盖的旧文本存到 `.history/<文件>/<时间>.md`：同一文件一分钟内最多一份，最多留 40 份，内容与上一份相同就不存。
- `.history/` 是本机状态，和 `.journal.jsonl` 一样不进 zip（点开头的目录本来就不进）、不进提交（`git.ts` 的 LOCAL，仓库 `.gitignore`）。
- 读取接口：`GET /api/projects/:p/history?path=` 列表，`…/history/item?path=&id=` 取文本。恢复只多一个“先存当前文本”的 `POST …/history`：编辑器把取到的文本交给 `saveTab`，和人手改一样走块级合并和日志；恢复前先无条件存一份当前文本（不受一分钟限制），所以恢复本身也能被恢复回来。恢复不进编辑器的撤销栈。
- 顶栏一个“历史版本”按钮，弹层是时间列表、所选版本的原文或它与当前文本的块级差异（“原文 / 改动”一排选择），和“恢复这个版本”。比较按标签页（历史本来就是每个标签页一份），用写回同一套块含义（`blockKey`）对齐：core 的 `diffBlocks` 给出 `same` / `old`（这版有、现在没有）/ `new`（现在有、这版没有）三种块，编辑器把 `old` 染成危险色、`new` 染成成功色。
- 删除标签页也走这套：删除前先把每个被删文本无条件存一份（删除不是覆盖写，`writeAtomic` 拦不到，所以编辑器在删文件前调 `POST …/history`），再在 `.history/<文件>/.deleted.json` 里记住标签页组（含子页，doc.json 里的原样条目和原来的位置）。左侧标签页列表有“已删除的标签页”菜单（只在有被删标签页时出现）：一项把标签页、子页和最新一份文本放回原位，然后删掉记号；标签页回来了记号就不再列出。提示气泡里的 Undo 和这个菜单走同一条恢复路径（`restoreTabGroup`）。

## 3. 为什么不用 git

沿用 git 最省事，但很多项目目录不在仓库里，也没人每次编辑都提交；而这里要的是“刚才那一段还在”。所以只在没有更好来源时才自己存，并且只存文本、只管文档。提交仍然用已有的提交流程。

## 4. 没做 / 还开着

- Claude Code 在编辑器之外直接改文件时不会存快照，它改之前的内容要等下一次从编辑器写入才会留下。
- 只管 `tabs/*.md`；`doc.json`、评论没有历史。
