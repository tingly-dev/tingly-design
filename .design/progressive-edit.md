# AI 编辑的渐进可视化：一次改动怎么一路走到画布上

状态：**已实施**（画布、幻灯片、动效、文档本就是逐笔更新；看板页面帧和设计系统组件预览改为双帧交接，不再每笔写入白屏一次；委托系统提示要求大改动分几笔落盘，best effort）。

## 问题

“Claude 编辑时要逐步看得见”不是加一个开关，而是一条链路上不许有攒批：模型的一次工具调用 → 文件写入 → 文件监听 → SSE → 编辑器状态 → 沙箱渲染。任何一环把几笔合成一笔、或趁机整页重建，人在屏幕上看到的就是“等完了才刷”。

## 链路里已经是渐进的（这次没动，说清楚是契约）

- **快速 AI**：回复一行一条流式执行（`FastEditSession`），画板立刻显示草稿（虚线边）。
- **Claude Code**：每次 Edit / Write 是一次文件写入；chokidar（`awaitWriteFinish` 60ms 稳定阈值）→ hub 的 `file` 事件 → SSE → 编辑器 `onEvent` 更新文件 → 画板 / 幻灯片 / 场景的沙箱帧收到 `dc:render` 重渲染（React 重建，不重载 iframe）。逐笔上屏；运行结束没有“最后一次整体刷新”，运行中的画板只多一个“Claude 编辑中”的角标。
- **文档**：Markdown 在编辑器进程里渲染，`file` 事件到即重渲染。
- **看板的数据**：数据文件改动只重载读到它的数据集（`dataChanged`），不重载页面。
- **运行卡片**：每个工具步骤实时进 `delegates` 的日志（`describeTool`）。

## 这次补上的三处

1. **看板页面帧双帧交接**（`DashApp.tsx` 的 `PageFrame`）。原来 `files/` 一变就 bump `pageKey` 换 key 重建 iframe：页面白一下，Claude 改几笔就白几次。现在两个帧轮流：台上的留着，下一版页面在隐藏的孪生帧里启动（每次都是全新帧，页面脚本的 window 环境干净，不会叠监听器），等它 `dash-declared`（页面挂载完）再交换位置；5 秒兜底，页面挂不完也接管。两个约定使数据不断：
   - 页面在挂载途中（`dash-declared` 之前）就会 `dash-want` 要数据，所以“我们对哪一帧说话”（`frameWin`）在孪生帧 `ready` 时就切过去，答复由缓存供给（`asked` 跨重载不清）；`dash-want` 两个帧都听。
   - 除此之外只有台上的帧说话算数（`dash-refresh`、`dash-report`、`dash-pick`……都按发送帧过滤），后台那帧的定时器说了不算。交换时清空旧页面的报告（`.runs.json` 由新页面重画后重新报告）。
2. **设计系统组件预览双帧**（`ComponentViews.tsx` 的 `Preview`）。bundle.js / bundle.css / tokens.json 每笔写入原来都让每个预览 iframe 重载一遍。同样两帧轮流，孪生帧 `onLoad` 后接管、旧帧退场；高度消息只听台上帧，免得启动中的帧把卡片高度顶来顶去。两处共用的教训：两帧的 React key 必须带槽位名，否则第 2 次启动时两帧同号，React 调和错元素。
3. **委托系统提示的“分笔落盘”**（`delegate.ts` 的 `STEPWISE`，六种类型共用一句）。一次 Edit / Write 对编辑器是一个原子事件，事件内部无法再流式；所以对模型提要求：大改动尽量分几笔写，每笔都让作品完整地显示（一节、一张卡、页面的一部分），除非改动必须整体成立（改名、重排到一半会坏的那类）。best effort：是否分、分多细由模型按改动性质权衡——每多一笔就是一次模型往返，不把“渐进”做成固定的耗时开销。

## 到不了的地方（为什么维持现状）

- **一次写入的内部**：内容在模型一侧就完整了，写入前无从流式；机制上保证“逐元素”只能拆多次工具调用（见第 3 条，劝而不强制）。
- **沙箱画板的整树重建**（`runtime.tsx` 的 `key={current.source}`）：组件类是从源码现编译的（页面脚本 `class Component extends DCLogic`），源码一变类型就变，React 必然整树卸载重建。要按 tid 做跨版本的 DOM 调和等于重写模板渲染器，脚本状态、嵌入、就地改字都要重新论证，风险大于收益。现状通常不可见（图片走缓存）；画板里嵌入的 iframe 会跟着重载，是已知代价。
- **看板页面的脚本**：页面脚本自己画 DOM（d3 等），换一段 HTML 是没有意义的，重跑脚本就是契约；双帧做的是把“重跑时白屏”藏掉，而不是少跑。
