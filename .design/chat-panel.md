# 对话面板：对话在最左边，类型自己的列表往右让

状态：**已实施**（§7 是没做的）。请求栏默认在底部；对话也可以钉成**最左边的一栏**，类型自己的列表（幻灯片页面、文档标签页、设计系统列表）整体往右让，右侧的属性 / 批注 / 数据来源照旧留在右边——**对话和右侧面板可以同时开着**。面板里是一份能回头读的对话记录，取代"最近一次运行的卡片 + 只有请求的历史"。位置菜单、`dc.barMode`、外壳 `ChatShell`、`ListColumn`、把类型列表做成页签都不在了；旧的 `left`（和更早的 `auto`）在下一次打开项目时迁移一次，落在对话栏打开的状态。

**方案的历史**：#463 / PR #465 的 `chat-pane.md` 选的是"对话在右侧、顶掉右侧面板"；用户判断那样会丢掉"对话和属性同屏"，改成现在这份：对话固定最左，列表右移，右面板独立（`chat-pane.md` 只保留取舍，不再是现行设计）。

## 1. 问题

反馈只有一句：钉住的对话面板，能让人更好地看懂 agent 做了什么。

拆开看，是四个现有设计留下的缺口（agent-panel.md §3 和 §5 已经点过其中几个）：

| 人在问 | 现在的样子 |
|---|---|
| 它这一路做了什么？ | 运行卡片只留最近一次，步骤默认折成一行；下一次运行一开始，上一次的步骤和回答就没了 |
| 它上次说了什么？我当时怎么要求的？ | 历史列表只有请求原文、状态和时间，没有回答、步骤和改了哪些文件；刷新、换项目后清空 |
| 我一边看画面一边读它的过程，行不行？ | 底部的卡片盖住刚改完的位置；右侧的面板是临时盖上去的，鼠标移开就收。两种都没有"一直在那里"的选择 |
| 命令行、MCP 发的请求，编辑器里看得到吗？ | 看不到过程。接着的会话号虽然在服务端，但哪一轮做了什么没有记录 |

已经试过又去掉的东西要记住：右侧自动隐藏（临时盖在舞台上，鼠标移开就收）、把类型列表和对话合成一列用页签（列表和对话永不同屏）。这次的区别是两点：对话固定最左，类型列表整体右移，两者同屏；右侧面板独立，对话和属性可以同时开着。

## 2. 人的一次完整旅程

1. **默认**：请求栏在底部，浮在作品上、可以收起；作品拿到整个宽度。
2. **一边看过程一边聊**：点顶栏的"对话"按钮，最左边打开对话一栏（记录 + 输入区）；类型自己的列表（页面 / 标签页 / 列表）整体往右让，右侧属性 / 批注 / 数据来源留在原处。
3. **聊着聊着去改元素**：对话和属性可以同时开着；不用在两者之间切。点顶栏的"对话"关掉它，底部栏回来，写到一半的字还在。
4. **窗口变窄**：顶栏的"对话"灰掉，写"窗口再宽一点，或关掉右侧面板…"；已经打开的那一栏不会自己关、也不会自己换位置，由人拖窄或关掉。窗口再宽回来，按钮恢复，但不会自己打开。
5. **离开再回来**：刷新、换窗口、重开项目，记录还在；在终端里 `tingly-design prompt` 或 MCP 发的请求也出现在记录里，标明来自命令行。对话栏开没开是六种类型共用的一个设置（`dc.chat`）。
6. **在幻灯片、文档、设计系统里**：最左边是对话，接着是页面 / 标签页 / 列表，然后作品，最后是右侧面板；两条左列都能拖。正在跑或有新结果时，顶栏的对话按钮上有一个状态点，打开就读。
7. **不想要了**：点对话栏头的 ×，或再点一次顶栏的对话按钮；底部栏回来。

## 3. 决定

### 3.1 一条独立的最左列

对话不是右侧的"面板之一"，而是最左边的一条独立栏：

| 状态 | 位置 | 与右侧面板的关系 |
|---|---|---|
| 底部（默认） | 浮在作品下沿 | 无关；底部栏和右侧面板各管各的 |
| **对话栏打开** | **最左边，类型列表在它右边** | **同时开着**；对话不顶掉属性 / 批注 / 数据来源 |

- 顶栏的 `PaneToggles` 先画对话按钮（每种类型都有，`chatOpen`），再画类型自己的右侧面板按钮（`KIND_PANE_IDS`）。
- 对话开合只影响左列：`<ChatPane>` 是 `.app` 网格的第一格，类型的列表顺次右移；右侧列不动。
- 对话栏和类型列表各自记住宽度（`dc.w.chat`、`dc.w.<列>`），互不影响。
- 状态（运行中转圈、有新结果 / 失败一个小点）在顶栏的对话按钮上（`PaneToggles` 的 `Badge`），打开就清掉。
- **窄窗口**：放不下时按钮灰掉并说明（可以关掉右侧面板腾地方），**不自动换位置、不自动关闭、不盖住作品**；已经开着的栏由人决定（§3.5）。

### 3.2 面板里是一份对话记录

对话栏打开时，栏里就是对话本身，不再有"运行卡片"和"历史列表"两个东西：记录就是历史。

- **一轮**由 `RunFeed` 画（仍然是同一个部件，它改成画一轮记录，运行中的那轮和已结束的那轮用同一份渲染）：
  1. 你说的（右对齐的气泡，原样；附件缩略图）；
  2. 过程：运行中显示最新一步 + 计时 + 停止；结束后折成"N 步 ›"，点开是全部步骤（读了什么、改了什么），每一轮各自展开，互不影响；
  3. 回答：Claude Code 的话按 Markdown 读（段落、标题、列表、表格、引用，代码块带语言和复制，链接只开 http/https/mailto，图片不加载；见 conversation-markdown.md），可选中复制；快速 AI 的注记和失败、停止的说明仍是纯文本；它执行的 jQuery 折叠显示（带"在 jQuery 里改"）；
  4. 改了什么：文件名片，点一下在作品里定位（画布选中画板、幻灯片切页、文档切标签页、动效跳场景、看板打开来源，设计系统只列不跳，和 agent-feedback.md 一致）；
  5. 下一步：最新一轮有"撤销这次改动"（更早的轮次不给，因为恢复到那一轮之前会冲掉后面的改动；给"放回输入框"）；失败或停止的轮次给"放回输入框"。
- **分隔线**：每次"新对话"（栏头的上下文标记决定）在记录里画一条分隔线，写"新对话"；"接着"的轮次直接接在上一轮后面。记录因此回答"它记得多少"：分隔线以上它不记得。
- **滚动**：默认跟到最新一轮；人往上滚就停止跟随，并出现"回到最新"。新一轮结束但人不在底部时，只在"回到最新"上点一个小点，不抢滚动位置。
- **面板头**：名字"对话"和关闭 ×。**历史按钮在面板里不出现**，因为记录本身就是历史；底部它还在，列表读的就是同一份记录（所以刷新后不再清空，每一行能展开回答和步骤）。运行状态在顶栏的对话按钮上，不在面板头。
- **输入区**：就是 `RequestBar` 的输入部分（作用范围、快速 AI / Claude Code 的切换、附件、输入框、发送 / 停止），放在面板底部。底部栏和面板里是同一个部件，只是容器不同；没发出的草稿在 store 里（`draft`），换容器不丢。

### 3.3 已有左列的类型：两条左列并排

幻灯片（页面缩略图 216 px）、文档（标签页 220 px）、设计系统（列表 220 px）左边本来就有一列。对话打开时**不碰它、也不藏它**：对话在最左，列表整体右移一格，两者同屏，各自可拖。

原来"列表和对话合成一列、两个页签"的做法（`ListColumn`、`chatTab`、`chat-list` 槽）保留为已删除，不再回来。代价是作品要同时让出两条左列（见 §3.5 的数值）；换来的是列表永远可见、对话和右侧属性可以同屏。

### 3.4 记录存在服务端，不在页面里

问题：运行卡片的内容活在编辑器页面的内存里，所以刷新就没了，命令行和 MCP 发的请求页面也不知道。

决定：每个项目一份对话记录 `.transcript.jsonl`，在项目文件夹里，和 `.claude-session.json`、`.runs.json`、`.journal.jsonl` 一样属于这台机器：不提交、不进 .zip、写回引擎不当作作品文件。

- 每行是一轮：`{ id, agent, prompt, at, source, state, continued, steps, answer, files, startedAt, endedAt }`。`source` 是 `editor | cli | mcp`。运行中同一轮追加更新，结束时定稿；读取时同一个 `id` 取最后一条。
- Claude Code 的轮次由服务端在 `delegate.ts` 里写（它已经在处理 `start / progress / done / stopped / error` 事件），所以命令行和 MCP 的请求也在里面，编辑器不必在场。快速 AI 在浏览器里执行，轮次由编辑器在结束时提交给服务端。
- 编辑器打开项目时读最近一段（一百轮），之后由已有的 SSE 事件更新；不新增第二条推送通道。
- **有上限**：保留最近 200 轮；每轮最多 300 步，更长的把中间折成一条"省略了 N 步"；回答和请求各截到几千字。上限在服务端，超过就从最旧的开始丢，整份重写。
- 删除：不提供"清空记录"按钮。人想重新开始，就是"新对话"的分隔线；真要删，是删项目里的 `.transcript.jsonl`。（"完成 ≠ 锁死"，记录也不该一个手滑就没，ux-principles 第 10 条。）
- 隐私：记录里有请求原文和 Claude 的回答，和 Claude Code 自己机器上存的会话同级；因为属于本机状态，不进 .zip，分享项目时不会带出去。实施时把它加进 `project-archive.md` 的"不进 zip"清单。

### 3.5 宽度和窄窗口

两条左列和右侧面板都可能同时存在，所以有一条明确的预算（`panes.ts` 的 `MIN_WORK` / `chatNeed` / `chatFits`）：

- 对话默认 340 px（280–560，拖它的**右**边缘，`SideResizer id="chat" edge="end"`）；类型列表和右侧面板各用原来的宽度和范围。
- 对话的宽度 = `min(记住的宽度, max(280, 窗口 − 类型列表 − 当前右面板 − MIN_WORK))`：窗口宽时用记住的宽度；变窄时先收窄对话，再窄就不开。
- **能不能开**：`窗口 ≥ 对话最小 280 + 类型列表 + 当前右面板 + MIN_WORK`。右面板关着时不占这项，所以窄窗口里关掉属性 / 数据来源可以腾出位置。MIN_WORK：画布 480、幻灯片 420、文档 420、设计系统 480、看板 440、动效 480。
- 关掉右面板后的最窄可开窗口：画布 760、幻灯片 700、文档 700、设计系统 760、看板 720、动效 760。
- 默认右面板开着时的最窄可开窗口：画布 1072、幻灯片 1228、文档 1240、设计系统 980、看板 1120、动效 1072。1280 px 下六种类型都开得起来；1100 px 下画布、设计系统、动效可以，幻灯片 / 文档 / 看板要么加宽，要么关掉右面板。
- 低于这条线，对话按钮**灰掉并写**"窗口再宽一点，或关掉右侧面板…"；已经打开的那一栏**不会自己关**，也不会换位置。窗口再宽回来按钮恢复，但不会自己打开。
- 放映（幻灯片）和画布的非编辑模式不画对话栏，作品得到整个窗口。
- 对话栏打开时：底部栏不渲染；`.mprompt`（动效为底部栏留的槽位）不占高度（`.mprompt.in-pane`）；"请求栏在屏幕上就不弹 toast"的规则继续成立。

### 3.6 怎么放进六种类型

只有一个提供上下文的 `ChatSlotsProvider` 包住 `App`（没有 DOM、没有 `transform`）：它拿着输入框要 portal 进去的槽和记录用的 `bridge`。每种类型把 `<ChatPane>` 画在自己 `.app` 网格的第一格，并加上 `with-chat`：

- 画布：`auto 1fr auto`（对话、作品、右面板）；
- 幻灯片：`auto var(--w-strip) 1fr auto`（对话、页面、舞台、右面板）；
- 文档：`auto var(--w-doctabs) 1fr`，批注开着时再加 `var(--w-docrail)`；
- 看板：`auto 1fr`，数据来源 / 代码开着时再加 `var(--w-dashside)`；
- 设计系统：`auto var(--w-dsnav) 1fr`；
- 动效：`auto 1fr auto`，属性开着时右格就是它。

`PANE_DEF` 不包含对话；`PaneToggles` 单独先画 `CHAT_DEF`（Tabler 对话图标 `icons.tsx` 的 `Conversation`，文档批注的 `Message` 不动）、`ChatBadge`，点它调 `toggleChat`。`initialPane` 只读右侧面板的 `MAIN_PANE`；对话开没开由 `initialChatOpen` / `rememberChat` 管。

## 4. 考虑过、没选的

- **左侧自动隐藏、钉住、窄带（前一版的做法）**：不占宽度，也能钉住，但面板"有时在有时不在"：要给它做小标签、探出的时机、点哪里收回、和左缘已有的东西抢位置。这一版先去掉，只留一直打开的一列；等有人说"想要整个舞台"再加。
- **右侧钉住一栏**：曾经选过一版（#465），宽度被拿走的同时它顶掉了属性 / 批注 / 数据来源，对话和属性不能同屏；改成最左一栏后两者可以同时开着。
- **右侧自动隐藏继续留着**：面板"有时在有时不在"，要做小标签、探出的时机、点哪里收回，还要和检查器抢边缘；统一成一个开关的面板。
- **检查器里的一个页签（属性 / 代码 / 微调 / 对话）**：不占额外宽度，但对话和属性不能同屏，设计系统、文档、看板的右侧又各不相同，要想办法补；人要的"一边看过程一边改"做不到。
- **已有左列的类型把列表和对话合成一列用页签**（上一版的做法）：作品被右侧检查器和左边那一列夹住，列表和对话永不同屏，没有请求在跑时那列大半是空的，窄窗口还会自己换位置。
- **默认就打开对话面板**：新用户的第一个请求就让出一列宽度，而最常见的用法是发一句、看一眼。默认保持底部，要长对话的人自己开（智能默认，不是开关，第 6 条）。
- **每个类型的布局里各写一份面板**：六份实现、六份样式。面板和槽位是共用的（`ChatPane.tsx`、`ChatSlotsProvider`），类型只决定左列放在网格的哪里。
- **用 Claude Code 自己的会话文件当记录**：它只有 Claude Code 的轮次，没有快速 AI；格式是别人的，会变；用户清理 Claude Code 的会话后，记录就没了而项目还在。我们自己存一份很小的。
- **记录放浏览器 localStorage**：换窗口、命令行和 MCP 发的请求都看不到，和 agent-panel.md 里会话号上服务端是同一个理由。
- **记录放进改动日志（journal）**：日志回答"谁改了哪个文件"，是事后的记录；记录回答"它说了什么、做了什么"。混在一起，日志会被读文件、搜索之类不改东西的步骤淹没（agent-feedback.md §6）。
- **清空记录的按钮**：见 3.4。
- **把记录做成可以分叉、重发、重新生成**：对话产品常见，但这里一个项目一段对话（agent-panel.md），先把"读得到"做对；"放回输入框"已经够重发一条。

## 5. 对照 ux-principles

| # | 判断 |
|---|---|
| 1 围绕问题组织 | 面板回答"它做了什么、说了什么"，不是"它在做什么"一个问题 |
| 2 消除模式选择 | 去掉"位置"这个轴；开不开对话栏就是那个选择；没有"隐藏 / 钉住 / 窄带"这类型状态 |
| 3 一个词一个意思 | "对话"= 一个项目里 Claude Code 的那一段；记录里的分隔线就是它的边界；快速 AI 的轮次也在记录里，但标明"每次从头开始"；面板的标题、顶栏按钮、记录里都是同一个词 |
| 4 轴要分开 | 面板（内容）一个轴，宽度一个拖动；范围、上下文、交给谁各自仍是各自的控件 |
| 5 具体值 | 文件名、请求原文、真实步骤 |
| 6 智能默认 | 默认底部；对话开没开全局记住一个；右侧面板每种类型各记各的；记录默认跟到最新；步骤默认折叠；窄窗口禁用而不是自动换 |
| 7 诊断走真实路径 | 记录由服务端在真实运行事件上写，不是页面自己拼的 |
| 8 教育在产品里 | 对话按钮每种类型的顶栏都有；灰掉时写明"窗口再宽一点，或关掉右侧面板"；栏头就是对话 |
| 9 少视觉噪声 | 去掉一个位置菜单、页签、列表槽、外壳；顶栏只多一个图标按钮；对话和列表各自一条，不叠页签 |
| 10 完成 ≠ 锁死 | 回答和步骤留着、刷新还在、每轮可展开、可放回输入框；草稿跨开合 |
| 11 把下一步交到手上 | 文件名片定位、最新一轮撤销、放回输入框、关闭对话栏回到作品 |
| 12 副作用限在当前界面 | 面板不盖作品（占一列）；开合不动右侧面板；类型列表只是右移，不被藏；状态点不抢切换 |

## 6. 跨类型

六种类型都经同一个 `ChatPane` 拿到对话栏，`ChatSlotsProvider` 只提供槽位。差别：

| 类型 | 左边一直有的 | 右边原有的 | 对话打开时 |
|---|---|---|---|
| 画布 | 无（图层树在右侧属性里） | 属性 / 文件 / 审查 | 对话在最左，右侧面板照旧 |
| 幻灯片 | 页面缩略图 216 px | 属性 / 审查 | 对话、页面、舞台、属性四列；放映不画对话 |
| 设计系统 | 列表 220 px | 无 | 对话、列表、作品三列 |
| 看板 | 无 | 数据来源 / 代码 | 对话、作品、右侧面板三列 |
| 文档 | 标签页 220 px | 批注 | 对话、标签页、正文、批注四列 |
| 动效 | 无 | 属性 / 审查 | 对话、作品、属性三列；`.mprompt` 不占高度 |

矩阵的"对话面板"一行是"底部（默认）/ 最左一栏，类型列表右移，右面板独立"，每个 ✓ 对应各自的 e2e 套件；"对话记录"和"边栏宽度可拖"也同步。

## 7. 还开着的问题

- **更早轮次的撤销**：现在只给最新一轮。要给更早的，需要"这一轮之后没人再碰过这些文件"的判断，和 journal 的 `rebaseSwap` 能不能做到有关，等有人要再做。刷新后最新一轮也不能撤销（记录里没有改动前后的内容，只有文件名）。
- **记录里放不放"手改"**：现在只有请求和 agent 的轮次；人在画布上手动改的东西不进记录（那是 journal 的事）。如果人想在同一条时间线上看到"我改了什么、它改了什么"，要把两份合起来读，等有人提再说。
- **多窗口同时看同一个项目**：两个编辑器窗口靠 SSE 同步，不做冲突处理。
- **两条左列 + 右面板都开着时作品很窄**：1280 px 幻灯片 420、文档 420；已经用可拖宽度和"关掉右面板"缓解，是否要在某个宽度自动收起某一列，等真实反馈，不先做自动行为。
- **对话固定在左侧后，右侧只剩属性**：这是有意的；如果以后要"对话 + 批注 + 属性"三面同屏，需要新的右列规则。
- **一个左列宽，还是各列各自宽**：现在各自宽（对话 340、页面 216、文档标签 220），拖的时候各管各的。
- **和 Tingly Box 里 Projects 页面的对话视图共用**：Projects 的线程页已经有 transcript 部件；如果形状够像，值得把记录的一轮抽成共用的 UI 包（agent-panel.md §5 已经提过）。先做编辑器自己的，再看。
- **迁移一次还是每种类型一次**：现在是全局一次（`dc.barMode` 读过就清掉，`dc.chat` 全局一个）；每种类型一次更照顾习惯，要六个设置。

## 8. 实现里的几个事实

不是设计，是读代码前该知道的：

- **没有外壳**：`ChatSlotsProvider`（`ChatPane.tsx`）只是一个 context，包住 `App`，没有 DOM、没有 `transform`。每种类型把 `<ChatPane>` 放在自己 `.app` 网格的第一格；关着时不留空槽。
- **两条左列**：对话列是 `.app` 的第一个网格列（`auto`），类型自己的列表是下一列；右边是作品（`1fr`）和右面板（`auto`）。CSS 变量 `--chat-rest`（列表 + 当前右面板）和 `--chat-min`（`MIN_WORK`）给出对话的宽度。
- **槽位**：`ChatSlotsProvider` 拿着输入框的槽。`RequestBar` 在对话打开时把整条栏（只是输入的部分，不是卡片）portal 到对话脚下的槽；记录里点文件名、"放回输入框"经 provider 里的一个 ref（`bridge`）回到这个 `RequestBar`。
- **菜单**：请求栏自己用 `translateX(-50%)` 居中，所以它是里面 `position: fixed` 的包含块。`Menu` 因此 portal 到 `<body>`，调用方在哪个带 `transform` 的祖先里都按窗口坐标定位。菜单不在栏的 DOM 里，所以栏的“点外面放开输入框”和对话框的 Tab 陷阱都把 `[role=menu]` 当作自己的一部分。（`Dialog` 本身不走 portal。）
- **一轮的来源**：`turns.ts` 把服务端存的轮次和这个页面里的活动运行（`delegates`、`fast`）按 `id` 合并，活动的优先，但页面是跑到一半才打开的，则保留记录里更长的步骤。一轮结束时进 `store.turns`，快速 AI 的还 POST 给服务端（`api.keepTurn`）；快速 AI 交给 Claude Code 的那次只算 Claude Code 的一轮（`via: 'fast'`）。
- **服务端读到"还在跑"但进程已经没了**（重启、崩溃）：`GET …/transcript` 把超过 20 秒且 `children` 里没有它的 Claude Code 轮次改成失败并写"这次运行在结束前被中断了"，不改文件。
- **对话的记忆**：`dc.chat`（全局一个，`1` / `0`）；右侧面板仍是 `dc.pane.<kind>`。旧的 `dc.barMode` 和旧代码里 `dc.pane.<kind>='chat'` 只在 `panes.ts` 的迁移里读一次。
- **按钮上的点**：`store.chatNote`（`new` / `failed`），在结束的一轮且对话栏关着时设置，打开清掉；运行中一直显示转圈。
- **草稿**：`store.draft`，`RequestBar` 的输入框读它、写它，所以底部 ↔ 对话栏换容器不重建文字；打开另一个项目时清空（`agentReset`）。
- **回答可选中、可复制**：记录是普通的页面文字，拖选、双击、三击都不拦。拦的是键：编辑器窗口把每个 ⌘C / ⌘X 当作"复制 / 剪切选中的元素"并 `preventDefault`，浏览器的复制就没了。现在页面里有选中的文字时（`shortcuts.ts` 的 `textSelected`）这两个键留给浏览器；没有选中文字时仍是选中元素的。画板的 iframe 里点一下选中东西时（`leaveField`）会清掉页面上的文字选区，这样刚点中的元素的 ⌘C 立刻生效，而不是还复制旧的那段话。`e2e/chat_copy.py`。
- **回答按 Markdown 读**：Claude Code 完成后的回答由 `ChatMarkdown` 画（GFM + `breaks`、消毒后的 DOM、代码块的语言头和复制按钮、只认 http/https/mailto 的链接、不加载图片）；快速 AI 的注记与失败、停止的说明仍是纯文本。`conversation-markdown.md`；`e2e/run_feed.py`（Markdown 与复制断言）。
