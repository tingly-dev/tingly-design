# 对话面板：把请求栏钉在左侧，留下完整的对话记录

状态：**方案**（尚未实施）。它在 [agent-panel.md](./agent-panel.md) 的两处位置（底部、右侧自动隐藏）之外加第三处："钉在左侧"，并把"最近一次运行的卡片 + 只有请求的历史"换成一份能回头读的对话记录。确定后，结论并入 agent-panel.md 和 agent-feedback.md，这份保留取舍。

## 1. 问题

反馈只有一句：钉住的对话面板，能让人更好地看懂 agent 做了什么。

拆开看，是四个现有设计留下的缺口（agent-panel.md §3 和 §5 已经点过其中几个）：

| 人在问 | 现在的样子 |
|---|---|
| 它这一路做了什么？ | 运行卡片只留最近一次，步骤默认折成一行；下一次运行一开始，上一次的步骤和回答就没了 |
| 它上次说了什么？我当时怎么要求的？ | 历史列表只有请求原文、状态和时间，没有回答、步骤和改了哪些文件；刷新、换项目后清空 |
| 我一边看画面一边读它的过程，行不行？ | 底部的卡片盖住刚改完的位置；右侧的面板是临时盖上去的，鼠标移开就收。两种都不是"一直在那里" |
| 命令行、MCP 发的请求，编辑器里看得到吗？ | 看不到过程。接着的会话号虽然在服务端，但哪一轮做了什么没有记录 |

已经试过又去掉的东西要记住：右侧钉住的一栏（占舞台宽度，幻灯片和动效最需要宽度，且那时面板里仍然只有一张卡片，占了地方却没多给信息）。这次的区别是两点：钉住的位置是左侧，不和右侧的检查器抢；钉住之后面板里是一份真正的对话记录，值得那块宽度。

## 2. 人的一次完整旅程

1. **钉上**：在请求栏头的"位置"菜单里选"左侧"。面板在窗口最左边占一列，作品往右让；以后在本机一直保持这个位置，各类型一样。
2. **发请求、看它做**：在面板底部的输入框写请求，上面的记录里立刻出现这一轮：你说的、现在在做什么（最新一步 + 计时 + 停止）。作品就在旁边，同时看得见改动发生。
3. **读结果**：这一轮结束后留在记录里：回答（可选中、可复制）、改了哪些文件（点名片，作品里定位到那一处）、"撤销这次改动"（只对最新一轮）、"放回输入框"。下一轮接在下面，不覆盖上一轮。
4. **回头读**：往上滚，每一轮的请求、步骤、回答、改动都在。"新对话"在记录里是一条分隔线，不是清空。
5. **离开再回来**：刷新、换窗口、重开项目，记录还在；在终端里 `tingly-design prompt` 或 MCP 发的请求也出现在记录里，标明来自命令行。
6. **不想要了**：面板缩成左缘一条窄带（图标 + 有事时的小点），或者从"位置"菜单换回底部 / 右侧。

## 3. 决定

### 3.1 三处位置，一个菜单

位置现在有三处，都由人选，默认仍是底部（常见用法是发一句、看一眼，不该先让出一列宽度）：

| 位置 | 占宽度 | 面板里有什么 | 适合 |
|---|---|---|---|
| 底部（默认） | 否 | 输入框一直在；运行卡片平时一行 | 发一句看一眼 |
| 右侧，自动隐藏 | 否，临时盖上去 | 同一个面板，移到边缘才出现 | 要整个舞台，偶尔问一句 |
| **左侧，钉住（新）** | **是，一整列** | **对话记录 + 输入框** | **一轮接一轮地做，要看懂它的过程** |

栏头原来有两个互相替换的按钮（"移到右侧" / "移到底部"），再加第三个会让栏头更挤。改成一个"位置"按钮，图标显示当前位置，点开是三项单选，每项一行说明它的代价（例如"左侧：一直打开，作品让出一列"）。这是把一个轴（放哪里）收成一个控件，而不是三个并列的开关（ux-principles 第 4、9 条）。位置记在本机（`dc.barMode`），各类型共用。

为什么是左而不是右：右侧已经是检查器（属性 / 代码 / 微调）、文档的批注、看板的数据来源，对话和它们同屏是常见需求（边改元素边问）；左侧的列表（图层、幻灯片缩略图、文档标签页）窄且稳定。左→中→右的阅读顺序也自然：说了什么 → 作品 → 属性。

### 3.2 面板里是一份对话记录

钉住时，面板就是对话本身，不再有"运行卡片"和"历史列表"两个东西：记录就是历史。

- **一轮**由 `RunFeed` 画（仍然是同一个部件，它改成画一轮记录，运行中的那轮和已结束的那轮用同一份渲染）：
  1. 你说的（右对齐的气泡，原样；附件缩略图）；
  2. 过程：运行中显示最新一步 + 计时 + 停止；结束后折成"N 步 ›"，点开是全部步骤（读了什么、改了什么），每一轮各自展开，互不影响；
  3. 回答：Claude Code 的话，可选中复制；快速 AI 则是它执行的 jQuery（折叠，带"在 jQuery 里改"）；
  4. 改了什么：文件名片，点一下在作品里定位（画布选中画板、幻灯片切页、文档切标签页、动效跳场景、看板打开来源，设计系统只列不跳，和 agent-feedback.md 一致）；
  5. 下一步：最新一轮有"撤销这次改动"（更早的轮次不给，因为恢复到那一轮之前会冲掉后面的改动；给"放回输入框"）；失败或停止的轮次给"放回输入框"。
- **分隔线**：每次"新对话"（栏头的上下文标记决定）在记录里画一条分隔线，写"新对话"；"接着"的轮次直接接在上一轮后面。记录因此回答"它记得多少"：分隔线以上它不记得。
- **滚动**：默认跟到最新一轮；人往上滚就停止跟随，并出现"回到最新"。新一轮结束但人不在底部时，只在"回到最新"上点一个小点，不抢滚动位置。
- **栏头**：左边是名字和上下文标记（接着 / 新对话，沿用 agent-panel.md），右边是"位置"菜单和折成窄带的按钮。**历史按钮在钉住时不出现**，因为记录本身就是历史；底部和右侧两种位置里它还在，行为不变。
- **输入区**：就是 `RequestBar` 的输入部分（作用范围、快速 AI / Claude Code 的切换、附件、输入框、发送 / 停止），放在面板底部。三种位置里的输入是同一个部件，只是容器不同。

### 3.3 记录存在服务端，不在页面里

问题：运行卡片的内容活在编辑器页面的内存里，所以刷新就没了，命令行和 MCP 发的请求页面也不知道。

决定：每个项目一份对话记录 `.transcript.jsonl`，在项目文件夹里，和 `.claude-session.json`、`.runs.json`、`.journal.jsonl` 一样属于这台机器：不提交、不进 .zip、写回引擎不当作作品文件。

- 每行是一轮：`{ id, agent, prompt, at, source, state, continued, steps, answer, files, startedAt, endedAt }`。`source` 是 `editor | cli | mcp`。运行中同一轮追加更新，结束时定稿；读取时同一个 `id` 取最后一条。
- Claude Code 的轮次由服务端在 `delegate.ts` 里写（它已经在处理 `start / progress / done / stopped / error` 事件），所以命令行和 MCP 的请求也在里面，编辑器不必在场。快速 AI 在浏览器里执行，轮次由编辑器在结束时提交给服务端。
- 编辑器打开项目时读最近一段（一百轮），之后由已有的 SSE 事件更新；不新增第二条推送通道。
- **有上限**：保留最近 200 轮；每轮最多 300 步，更长的把中间折成一条"省略了 N 步"；回答和请求各截到几千字。上限在服务端，超过就从最旧的开始丢，整份重写。
- 删除：不提供"清空记录"按钮。人想重新开始，就是"新对话"的分隔线；真要删，是删项目里的 `.transcript.jsonl`。（"完成 ≠ 锁死"，但记录也不该一个手滑就没，ux-principles 第 10 条。）
- 隐私：记录里有请求原文和 Claude 的回答，和 Claude Code 自己机器上存的会话同级；因为属于本机状态，随 `.git` 之外、不进 .zip，分享项目时不会带出去。实施时把它加进 `project-archive.md` 的"不进 zip"清单。

### 3.4 宽度、让位和窄窗口

钉住的一列不能把作品挤坏。规则：

- 默认 340 px，可拖动改到 280–520 px，记在本机（`dc.chatWidth`）。
- 作品区至少要有自己能用的宽度（各类型有自己的下限：幻灯片和文档左边还有一列，看板和画布右边有检查器）。窗口不够时，面板先收窄到 280，再不够就**自动回到底部**（和右侧位置在窄窗口里的做法一样，不是人的选择，所以偏好不改，窗口变宽又回来）。数值在实施时按各类型的真实布局量出来，不在这里写死。
- 钉住时：底部栏和右侧栏都不渲染；`.mprompt`（动效为底部栏留的槽位）不占高度；卡片和 toast 的规则里"请求栏在屏幕上就不弹 toast"继续成立，面板算在屏幕上。
- 面板可以折成左缘 44 px 的窄带：显示运行状态图标（转圈 / 完成 / 失败）和"有新结果"的小点；点一下展开。窄带仍占那 44 px，不是盖上去，因为它是"钉住"的一种状态，不是自动隐藏。

### 3.5 怎么放进六种类型而不用写六遍

面板不放进任何类型自己的布局。`App` 外面包一层外壳，外壳是一行：[对话面板][当前类型的整个应用，含顶栏]。类型的 `grid`、顶栏、浮动工具栏都不改。要处理的是各类型里 `position: fixed` 的东西（现在 `.app` 是 `inset: var(--topbar-h) 0 0 0`）：外壳给类型这一列一个新的包含块（`transform`），让它们相对这一列而不是整个窗口定位。弹窗、菜单走 `<body>` 的 portal，仍相对整个窗口，不受影响。

顶栏在面板右边，所以项目菜单和名字不在窗口最左角。面板的栏头和顶栏等高、同一条分界线，看起来是一整条栏，不是两块。

这一点是风险最大的地方：浮在作品上的东西（画布的工具条、动效的播放条、幻灯片的放映）是否都跟着新包含块走，要每种类型实际点一遍，并加进 e2e。

## 4. 考虑过、没选的

- **右侧钉住一栏**：试过，去掉了（agent-panel.md §3）。宽度被拿走的同时面板里没有多出信息；这次换到左边，并且面板有了记录才值得。
- **检查器里的一个页签（属性 / 代码 / 微调 / 对话）**：不占额外宽度，但对话和属性不能同屏，设计系统、文档、看板的右侧又各不相同，要想办法补；人要的"一边看过程一边改"做不到。
- **左侧自动隐藏（像右侧那样）**：不占宽度，但这次要的就是"一直在那里"，隐藏的面板不能在作品旁边读。钉住和自动隐藏是两种需要，各留一个位置。
- **默认就钉住**：新用户的第一个请求就让出一列宽度，而最常见的用法是发一句、看一眼。默认保持底部，要长对话的人自己钉（智能默认，不是开关，第 6 条）。
- **每个类型的布局里各加一列**：六份实现、六份样式，之后每个新类型还得想一遍。外壳统一包一层，类型不知道它存在。
- **用 Claude Code 自己的会话文件当记录**：它只有 Claude Code 的轮次，没有快速 AI；格式是别人的，会变；用户清理 Claude Code 的会话后，记录就没了而项目还在。我们自己存一份很小的。
- **记录放浏览器 localStorage**：换窗口、命令行和 MCP 发的请求都看不到，和 agent-panel.md 里会话号上服务端是同一个理由。
- **记录放进改动日志（journal）**：日志回答"谁改了哪个文件"，是事后的记录；记录回答"它说了什么、做了什么"。混在一起，日志会被读文件、搜索之类不改东西的步骤淹没（agent-feedback.md §6）。
- **清空记录的按钮**：见 3.3。
- **把记录做成可以分叉、重发、重新生成**：对话产品常见，但这里一个项目一段对话（agent-panel.md），先把"读得到"做对；"放回输入框"已经够重发一条。

## 5. 对照 ux-principles

| # | 判断 |
|---|---|
| 1 围绕问题组织 | 钉住的面板回答"它做了什么、说了什么"，不是"它在做什么"一个问题 |
| 2 消除模式选择 | 位置是三项单选，不是三个开关；窄窗口的退回是自动的，不要人选 |
| 3 一个词一个意思 | "对话"= 一个项目里 Claude Code 的那一段；记录里的分隔线就是它的边界；快速 AI 的轮次也在记录里，但标明"每次从头开始" |
| 4 轴要分开 | 位置（放哪里）一个控件；范围、上下文、交给谁各自仍是各自的控件 |
| 5 具体值 | 文件名、请求原文、真实步骤 |
| 6 智能默认 | 默认底部；记录默认跟到最新；步骤默认折叠 |
| 7 诊断走真实路径 | 记录由服务端在真实运行事件上写，不是页面自己拼的 |
| 8 教育在产品里 | "位置"菜单每项一行代价说明；窄窗口退回时面板位置菜单里"左侧"灰掉并说明"窗口再宽一点才能钉住" |
| 9 少视觉噪声 | 栏头不加按钮（位置一个菜单代替两个按钮，钉住时去掉历史按钮）；步骤默认折叠 |
| 10 完成 ≠ 锁死 | 回答和步骤留着、刷新还在、每轮可展开、可放回输入框 |
| 11 把下一步交到手上 | 文件名片定位、最新一轮撤销、放回输入框 |
| 12 副作用限在当前界面 | 钉住的面板不盖住作品；运行结果不再借舞台的空间 |

## 6. 跨类型

六种类型都经 `RequestBar` 拿到面板，位置由外壳决定，类型本身不改。差别：

| 类型 | 左边已有 | 右边已有 | 钉住时要注意 |
|---|---|---|---|
| 画布 | 无固定列（图层树在检查器里） | 检查器（约 310 px） | 作品区被两边夹，窄窗口最先退回 |
| 幻灯片 | 页面缩略图 216 px | 检查器 | 左边会有两列（对话 + 缩略图）；放映模式不显示面板 |
| 设计系统 | 列表 220 px | 无 | 只列不跳的名片不变 |
| 看板 | 无 | 数据来源 / 代码 400 px | 面板在最左，和数据来源不冲突 |
| 文档 | 标签页 220 px | 批注 320 px | 两边都有列，下限最高 |
| 动效 | 无 | 检查器 | 底部时间轴要宽度；`.mprompt` 槽位钉住时不占高度 |

矩阵的"请求栏面板"一行在实施时更新：位置列出三处，备注写"钉住时记录由服务端的 `.transcript.jsonl` 提供，命令行和 MCP 的请求也在里面"，并给每个 ✓ 对应的 e2e 套件；新增一行"对话记录"。

## 7. 还开着的问题

- **钉住是否取代右侧自动隐藏**：两种都留是现在的建议（自动隐藏是为"要整个舞台、偶尔问一句"做的，没人说它不好）。如果之后发现没人用右侧，再删一处位置，菜单从三项变两项。
- **数值**：作品区的各类型下限、面板的最小 / 默认 / 最大宽度，要按真实布局量。
- **窄窗口时折成窄带还是退回底部**：现在选退回底部（与右侧一致，少一种状态）；如果实际常在这个宽度下想看记录，改成"窄带 + 点开盖上去"。
- **更早轮次的撤销**：现在只给最新一轮。要给更早的，需要"这一轮之后没人再碰过这些文件"的判断，和 journal 的 `rebaseSwap` 能不能做到有关，等有人要再做。
- **记录里放不放"手改"**：现在只有请求和 agent 的轮次；人在画布上手动改的东西不进记录（那是 journal 的事）。如果人想在同一条时间线上看到"我改了什么、它改了什么"，要把两份合起来读，等有人提再说。
- **多窗口同时看同一个项目**：两个编辑器窗口都钉着，靠 SSE 同步，不做冲突处理。
- **和 Tingly Box 里 Projects 页面的对话视图共用**：Projects 的线程页已经有 transcript 部件；如果形状够像，值得把记录的一轮抽成共用的 UI 包（agent-panel.md §5 已经提过）。先做编辑器自己的，再看。
