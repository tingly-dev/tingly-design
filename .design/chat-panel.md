# 对话面板：请求栏放在左侧，留下完整的对话记录

状态：**已实施**（§7 是没做的）。请求栏的位置收成两处：底部（默认）和**左侧**。左侧是一列一直打开的对话面板，作品往右让；右侧自动隐藏的位置取消，也没有"自动隐藏"这件事了。面板里是一份能回头读的对话记录，取代"最近一次运行的卡片 + 只有请求的历史"。本来就有左列的类型（幻灯片、文档、设计系统），把自己的左列和对话做成同一列里的两个页签。确定后，结论并入 agent-panel.md 和 agent-feedback.md，这份保留取舍。

## 1. 问题

反馈只有一句：钉住的对话面板，能让人更好地看懂 agent 做了什么。

拆开看，是四个现有设计留下的缺口（agent-panel.md §3 和 §5 已经点过其中几个）：

| 人在问 | 现在的样子 |
|---|---|
| 它这一路做了什么？ | 运行卡片只留最近一次，步骤默认折成一行；下一次运行一开始，上一次的步骤和回答就没了 |
| 它上次说了什么？我当时怎么要求的？ | 历史列表只有请求原文、状态和时间，没有回答、步骤和改了哪些文件；刷新、换项目后清空 |
| 我一边看画面一边读它的过程，行不行？ | 底部的卡片盖住刚改完的位置；右侧的面板是临时盖上去的，鼠标移开就收。两种都没有"一直在那里"的选择 |
| 命令行、MCP 发的请求，编辑器里看得到吗？ | 看不到过程。接着的会话号虽然在服务端，但哪一轮做了什么没有记录 |

已经试过又去掉的东西要记住：右侧钉住的一栏（占舞台宽度，幻灯片和动效最需要宽度，且那时面板里仍然只有一张卡片，占了地方却没多给信息）。这次的区别是两点：位置在左，不和右侧的检查器抢；面板里是一份真正的对话记录，值得那块宽度。

## 2. 人的一次完整旅程

1. **换到左侧**：在请求栏头的"位置"菜单里选"左侧"。面板在窗口最左边占一列，作品往右让；以后在本机一直保持，各类型一样。
2. **发请求、看它做**：在面板底部的输入框写请求，上面的记录里立刻出现这一轮：你说的、现在在做什么（最新一步 + 计时 + 停止）。作品就在旁边，同时看得见改动发生。
3. **读结果**：这一轮结束后留在记录里：回答（可选中、可复制）、改了哪些文件（点名片，作品里定位到那一处）、"撤销这次改动"（只对最新一轮）、"放回输入框"。下一轮接在下面，不覆盖上一轮。
4. **回头读**：往上滚，每一轮的请求、步骤、回答、改动都在。"新对话"在记录里是一条分隔线，不是清空。
5. **离开再回来**：刷新、换窗口、重开项目，记录还在；在终端里 `tingly-design prompt` 或 MCP 发的请求也出现在记录里，标明来自命令行。
6. **在幻灯片、文档、设计系统里**：左列是"页面 / 标签页 / 列表 | 对话"两个页签。切到列表选页，切回对话继续聊；对话在跑或有新结果时，"对话"页签上有状态点，不用切过去也知道。
7. **不想要了**：从"位置"菜单换回底部，各类型原来的左列回到原处。

## 3. 决定

### 3.1 两处位置，一个菜单

位置由人选，默认仍是底部（常见用法是发一句、看一眼，不该先让出一列宽度）：

| 位置 | 占宽度 | 面板里有什么 | 适合 |
|---|---|---|---|
| 底部（默认） | 否 | 输入框一直在；运行卡片平时一行 | 发一句看一眼 |
| **左侧（新）** | **是，一整列，一直打开** | **对话记录 + 输入框** | **一轮接一轮地做，要看懂它的过程** |

原来的右侧自动隐藏取消，也不做左侧的自动隐藏、钉住或窄带：这些都是"面板有时在有时不在"的状态，先不做，有反馈再调。已经选了右侧的人，下次打开时迁到左侧。

栏头原来有两个互相替换的按钮（"移到右侧" / "移到底部"），换成一个"位置"按钮，图标显示当前位置，点开是两项单选，每项一行说明代价（"左侧：一直打开，作品让出一列"）。位置记在本机（`dc.barMode` 为 `float` 或 `left`），各类型共用；一个轴一个控件（ux-principles 第 4、9 条）。

为什么是左而不是右：右侧已经是检查器（属性 / 代码 / 微调）、文档的批注、看板的数据来源，对话和它们同屏是常见需求（边改元素边问）；左→中→右的阅读顺序也自然：说了什么 → 作品 → 属性；聊天界面通常也把对话放左边。

### 3.2 面板里是一份对话记录

左侧时，面板就是对话本身，不再有"运行卡片"和"历史列表"两个东西：记录就是历史。

- **一轮**由 `RunFeed` 画（仍然是同一个部件，它改成画一轮记录，运行中的那轮和已结束的那轮用同一份渲染）：
  1. 你说的（右对齐的气泡，原样；附件缩略图）；
  2. 过程：运行中显示最新一步 + 计时 + 停止；结束后折成"N 步 ›"，点开是全部步骤（读了什么、改了什么），每一轮各自展开，互不影响；
  3. 回答：Claude Code 的话，可选中复制；快速 AI 则是它执行的 jQuery（折叠，带"在 jQuery 里改"）；
  4. 改了什么：文件名片，点一下在作品里定位（画布选中画板、幻灯片切页、文档切标签页、动效跳场景、看板打开来源，设计系统只列不跳，和 agent-feedback.md 一致）；
  5. 下一步：最新一轮有"撤销这次改动"（更早的轮次不给，因为恢复到那一轮之前会冲掉后面的改动；给"放回输入框"）；失败或停止的轮次给"放回输入框"。
- **分隔线**：每次"新对话"（栏头的上下文标记决定）在记录里画一条分隔线，写"新对话"；"接着"的轮次直接接在上一轮后面。记录因此回答"它记得多少"：分隔线以上它不记得。
- **滚动**：默认跟到最新一轮；人往上滚就停止跟随，并出现"回到最新"。新一轮结束但人不在底部时，只在"回到最新"上点一个小点，不抢滚动位置。
- **栏头**：左边是名字和上下文标记（接着 / 新对话，沿用 agent-panel.md），右边是"位置"菜单。**历史按钮在左侧面板里不出现**，因为记录本身就是历史；底部它还在，列表读的就是同一份记录（所以刷新后不再清空，每一行能展开回答和步骤）。
- **输入区**：就是 `RequestBar` 的输入部分（作用范围、快速 AI / Claude Code 的切换、附件、输入框、发送 / 停止），放在面板底部。两种位置里的输入是同一个部件，只是容器不同。

### 3.3 已有左列的类型：同一列里的页签

幻灯片（页面缩略图 216 px）、文档（标签页 220 px）、设计系统（列表 220 px）左边本来就有一列。再并排放一列会让作品区过窄，所以合成一列、两个页签：

- 第一个页签是类型自己的列（"页面" / "标签页" / "列表"，沿用它现在的名字），第二个是"对话"。列宽用面板的宽度（见 3.5），原来的内容跟着拉宽（缩略图变大，列表变宽），不另做一套。
- 输入区在面板底部，两个页签都在：人在看页面列表时也能直接写请求；发送时自动切到"对话"页签，看到它开始做。
- "对话"页签上显示状态：跑着时转圈，结束且人没在看时一个小点，失败时一个红点；人切过去就清掉。从命令行发来的请求也一样，不抢切换，只亮点。
- 位置换回底部时，类型的列回到原处，页签消失。
- 没有左列的类型（画布、看板、动效）面板就是一整列对话，没有页签。画布的图层树在右侧检查器里，不受影响。

这一步要类型配合：这三种类型要把自己的列交给面板的第一个页签位，不能完全靠外壳统一包一层（见 3.5）。

### 3.4 记录存在服务端，不在页面里

问题：运行卡片的内容活在编辑器页面的内存里，所以刷新就没了，命令行和 MCP 发的请求页面也不知道。

决定：每个项目一份对话记录 `.transcript.jsonl`，在项目文件夹里，和 `.claude-session.json`、`.runs.json`、`.journal.jsonl` 一样属于这台机器：不提交、不进 .zip、写回引擎不当作作品文件。

- 每行是一轮：`{ id, agent, prompt, at, source, state, continued, steps, answer, files, startedAt, endedAt }`。`source` 是 `editor | cli | mcp`。运行中同一轮追加更新，结束时定稿；读取时同一个 `id` 取最后一条。
- Claude Code 的轮次由服务端在 `delegate.ts` 里写（它已经在处理 `start / progress / done / stopped / error` 事件），所以命令行和 MCP 的请求也在里面，编辑器不必在场。快速 AI 在浏览器里执行，轮次由编辑器在结束时提交给服务端。
- 编辑器打开项目时读最近一段（一百轮），之后由已有的 SSE 事件更新；不新增第二条推送通道。
- **有上限**：保留最近 200 轮；每轮最多 300 步，更长的把中间折成一条"省略了 N 步"；回答和请求各截到几千字。上限在服务端，超过就从最旧的开始丢，整份重写。
- 删除：不提供"清空记录"按钮。人想重新开始，就是"新对话"的分隔线；真要删，是删项目里的 `.transcript.jsonl`。（"完成 ≠ 锁死"，记录也不该一个手滑就没，ux-principles 第 10 条。）
- 隐私：记录里有请求原文和 Claude 的回答，和 Claude Code 自己机器上存的会话同级；因为属于本机状态，不进 .zip，分享项目时不会带出去。实施时把它加进 `project-archive.md` 的"不进 zip"清单。

### 3.5 宽度和窄窗口

一直打开的一列不能把作品挤坏。规则：

- 默认 340 px，可拖动改到 280–560 px，双击恢复，记在本机（`dc.w.chat`；拖动的做法和所有边栏一样，见 [side-columns.md](./side-columns.md)）。
- 作品区至少要有自己能用的宽度，各类型的下限（`MIN_WORK`，`ChatPanel.tsx`）：画布 860、动效 860、看板 840、文档 920（右边还有批注）、幻灯片 820、设计系统 600。窗口比"280 + 下限"窄时，列先从当前宽度收窄到 280，再不够就**自动回到底部**，类型的列也回到原处；这不是人的选择，所以位置偏好不改，窗口变宽又回到左侧。回到底部期间，位置菜单里"左侧"灰掉并写"窗口再宽一点才能放在左侧"。数值是按各类型右边的检查器、批注和数据来源的宽度估的，不是写死的规定；谁觉得挤，改这张表。
- 放映（幻灯片）和画布的非编辑模式不画列，作品得到整个窗口。
- 左侧时：底部栏不渲染；`.mprompt`（动效为底部栏留的槽位）不占高度；"请求栏在屏幕上就不弹 toast"的规则继续成立，列算在屏幕上。

### 3.6 怎么放进六种类型而不用写六遍

面板不放进每个类型自己的布局，而是在 `App` 外面包一层外壳，外壳是一行：[对话面板][当前类型的整个应用，含顶栏]。类型的 `grid`、顶栏、浮动工具栏都不改。要处理的是各类型里 `position: fixed` 的东西（现在 `.app` 是 `inset: var(--topbar-h) 0 0 0`）：外壳给类型这一列一个新的包含块（`transform`），让它们相对这一列而不是整个窗口定位。弹窗、菜单走 `<body>` 的 portal，仍相对整个窗口，不受影响。

唯一要类型配合的是 3.3 的三种：它们把自己的左列注册给外壳（页签名 + 内容），左侧位置时由外壳放进面板的第一个页签，底部位置时照原样画在自己的布局里。同一份列的组件，只换容器。

顶栏在面板右边，所以项目菜单和名字不在窗口最左角。面板的栏头和顶栏等高、同一条分界线，看起来是一整条栏，不是两块。

风险最大的是外壳的包含块：浮在作品上的东西（画布的工具条、动效的播放条、幻灯片的放映）是否都跟着新包含块走，要每种类型实际点一遍，并加进 e2e。

## 4. 考虑过、没选的

- **左侧自动隐藏、钉住、窄带（前一版的做法）**：不占宽度，也能钉住，但面板"有时在有时不在"：要给它做小标签、探出的时机、点哪里收回、和左缘已有的东西抢位置。这一版先去掉，只留一直打开的一列；等有人说"想要整个舞台"再加。
- **右侧钉住一栏**：试过，去掉了（agent-panel.md §3）。宽度被拿走的同时面板里没有多出信息；这次换到左边，并且面板有了记录才值得。
- **右侧自动隐藏继续留着**：位置变三处，对话摆在哪不统一，还要和检查器抢边缘。统一到左。
- **检查器里的一个页签（属性 / 代码 / 微调 / 对话）**：不占额外宽度，但对话和属性不能同屏，设计系统、文档、看板的右侧又各不相同，要想办法补；人要的"一边看过程一边改"做不到。
- **已有左列的类型并排放两列**：作品区被左右两列和检查器夹到过窄；合成一列用页签，代价是看列表和看对话不能同屏，可以接受，因为输入框两个页签里都在。
- **默认就放左侧**：新用户的第一个请求就让出一列宽度，而最常见的用法是发一句、看一眼。默认保持底部，要长对话的人自己换（智能默认，不是开关，第 6 条）。
- **每个类型的布局里各加一列**：六份实现、六份样式，之后每个新类型还得想一遍。外壳统一包一层，类型只注册自己的列。
- **用 Claude Code 自己的会话文件当记录**：它只有 Claude Code 的轮次，没有快速 AI；格式是别人的，会变；用户清理 Claude Code 的会话后，记录就没了而项目还在。我们自己存一份很小的。
- **记录放浏览器 localStorage**：换窗口、命令行和 MCP 发的请求都看不到，和 agent-panel.md 里会话号上服务端是同一个理由。
- **记录放进改动日志（journal）**：日志回答"谁改了哪个文件"，是事后的记录；记录回答"它说了什么、做了什么"。混在一起，日志会被读文件、搜索之类不改东西的步骤淹没（agent-feedback.md §6）。
- **清空记录的按钮**：见 3.4。
- **把记录做成可以分叉、重发、重新生成**：对话产品常见，但这里一个项目一段对话（agent-panel.md），先把"读得到"做对；"放回输入框"已经够重发一条。

## 5. 对照 ux-principles

| # | 判断 |
|---|---|
| 1 围绕问题组织 | 面板回答"它做了什么、说了什么"，不是"它在做什么"一个问题 |
| 2 消除模式选择 | 位置是两项单选；没有"隐藏 / 钉住 / 窄带"这类状态要人管；窄窗口的退回是自动的 |
| 3 一个词一个意思 | "对话"= 一个项目里 Claude Code 的那一段；记录里的分隔线就是它的边界；快速 AI 的轮次也在记录里，但标明"每次从头开始"；"对话"页签和这段对话是同一个词 |
| 4 轴要分开 | 位置（放哪里）一个控件；范围、上下文、交给谁各自仍是各自的控件 |
| 5 具体值 | 文件名、请求原文、真实步骤 |
| 6 智能默认 | 默认底部；记录默认跟到最新；步骤默认折叠；发送自动切到"对话"页签 |
| 7 诊断走真实路径 | 记录由服务端在真实运行事件上写，不是页面自己拼的 |
| 8 教育在产品里 | "位置"菜单每项一行代价说明；窗口放不下左侧时"左侧"灰掉并说明"窗口再宽一点才能放在左侧" |
| 9 少视觉噪声 | 栏头不加按钮（一个菜单代替两个移动按钮，左侧去掉历史按钮）；步骤默认折叠；没有小标签、窄带 |
| 10 完成 ≠ 锁死 | 回答和步骤留着、刷新还在、每轮可展开、可放回输入框 |
| 11 把下一步交到手上 | 文件名片定位、最新一轮撤销、放回输入框 |
| 12 副作用限在当前界面 | 面板不盖住作品；运行结果不再借舞台的空间；页签上的点不抢切换 |

## 6. 跨类型

六种类型都经 `RequestBar` 拿到面板，位置由外壳决定。差别：

| 类型 | 左边本来有 | 右边已有 | 左侧位置时 |
|---|---|---|---|
| 画布 | 无（图层树在右侧检查器里） | 检查器（约 310 px） | 一整列对话；作品区被两边夹，窄窗口最先退回底部 |
| 幻灯片 | 页面缩略图 216 px | 检查器 | 页签："页面 / 对话"；放映模式不显示面板 |
| 设计系统 | 列表 220 px | 无 | 页签："列表 / 对话"；文件名片只列不跳 |
| 看板 | 无 | 数据来源 / 代码 400 px | 一整列对话 |
| 文档 | 标签页 220 px | 批注 320 px | 页签："标签页 / 对话"；两边都有列，下限最高 |
| 动效 | 无 | 检查器 | 一整列对话；`.mprompt` 槽位不占高度，底部时间轴照常 |

矩阵的"请求栏面板"一行在实施时更新：位置列出两处（底部、左侧），备注写"左侧时记录由服务端的 `.transcript.jsonl` 提供，命令行和 MCP 的请求也在里面；幻灯片、文档、设计系统的左列成为第一个页签"，并给每个 ✓ 对应的 e2e 套件；新增一行"对话记录"。

## 7. 还开着的问题

## 8. 实现里的几个事实

不是设计，是读代码前该知道的：

- **外壳**：`ChatShell`（`ChatPanel.tsx`）包住 `App`。关着时 `.chat-shell` 和 `.chat-work` 都是 `display: contents`，不影响任何布局；打开时 `.chat-work` 有 `transform`，里面 `position: fixed` 的东西（顶栏、`.app`）相对它而不是窗口。两种状态下树的形状一样，所以换位置、窗口变窄都不重建作品。
- **槽位**：列里有两个槽，输入框的和类型自己的列的。`RequestBar` 左侧时把输入部分 portal 到输入框槽；`ListColumn` 把幻灯片、文档、设计系统的列 portal 到第一个页签槽，并把页签名告诉外壳。记录里点文件名、"放回输入框"要回到输入框所在的 `RequestBar`，经外壳里的一个 ref（`bridge`）。
- **菜单**：请求栏自己用 `translateX(-50%)` 居中，所以它也是里面 `position: fixed` 的包含块。`Menu` 因此统一 portal 到 `<body>`（和上面说的弹窗、菜单一致），调用方在哪个带 `transform` 的祖先里都按窗口坐标定位；位置菜单曾因此在仪表盘里掉到窗口外，选不到“左侧”。
- **一轮的来源**：`turns.ts` 把服务端存的轮次和这个页面里的活动运行（`delegates`、`fast`）按 `id` 合并，活动的优先，但页面是跑到一半才打开的，则保留记录里更长的步骤。一轮结束时进 `store.turns`，快速 AI 的还 POST 给服务端（`api.keepTurn`）；快速 AI 交给 Claude Code 的那次只算 Claude Code 的一轮（`via: 'fast'`）。
- **服务端读到"还在跑"但进程已经没了**（重启、崩溃）：`GET …/transcript` 把超过 20 秒且 `children` 里没有它的 Claude Code 轮次改成失败并写"这次运行在结束前被中断了"，不改文件。
- **一个词的 key**：`dc.barMode` 是 `float` / `left`；旧值 `auto` 读作 `left`。
- **页签上的点**：`store.chatNote`（`new` / `failed`），在对话页签不在当前时由结束的一轮设置，切到对话页签清掉；发送从列里的输入框发出时自动切到对话页签，所以点只对从别处来的运行（命令行、MCP）亮。
