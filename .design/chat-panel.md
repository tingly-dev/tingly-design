# 对话面板：右侧的一栏，留下完整的对话记录

状态：**已实施**（§7 是没做的）。请求栏默认在底部；对话也可以是**右侧的一个面板**，和属性 / 批注 / 数据来源 / 审查同级，右侧同时最多一个面板。左边永远是类型自己的列表（幻灯片页面、文档标签页、设计系统列表）。面板里是一份能回头读的对话记录，取代"最近一次运行的卡片 + 只有请求的历史"。原来"把请求栏放到左侧的一列"已经删除（位置菜单、`dc.barMode`、外壳 `ChatShell`、`ListColumn`、把类型列表做成页签都不在了）；旧的 `left`（和更早的 `auto`）在下一次打开项目时迁移一次，落在对话面板打开的状态。方案与取舍见 issue [#463](https://github.com/tingly-dev/tingly-design/issues/463) 和 PR [#465](https://github.com/tingly-dev/tingly-design/pull/465) 的 `chat-pane.md`，采纳后并入这一份。

**方案 B 已实施**：[chat-pane.md](./chat-pane.md) 把对话放进右侧一栏、把左边还给类型自己的列表，并删掉位置菜单、外壳和 `ListColumn`；它已并入这一份（§3.1、§3.3、§3.6 就是它），不再是一份单独的提案。

## 1. 问题

反馈只有一句：钉住的对话面板，能让人更好地看懂 agent 做了什么。

拆开看，是四个现有设计留下的缺口（agent-panel.md §3 和 §5 已经点过其中几个）：

| 人在问 | 现在的样子 |
|---|---|
| 它这一路做了什么？ | 运行卡片只留最近一次，步骤默认折成一行；下一次运行一开始，上一次的步骤和回答就没了 |
| 它上次说了什么？我当时怎么要求的？ | 历史列表只有请求原文、状态和时间，没有回答、步骤和改了哪些文件；刷新、换项目后清空 |
| 我一边看画面一边读它的过程，行不行？ | 底部的卡片盖住刚改完的位置；右侧的面板是临时盖上去的，鼠标移开就收。两种都没有"一直在那里"的选择 |
| 命令行、MCP 发的请求，编辑器里看得到吗？ | 看不到过程。接着的会话号虽然在服务端，但哪一轮做了什么没有记录 |

已经试过又去掉的东西要记住：右侧自动隐藏（临时盖在舞台上，鼠标移开就收）、左侧一直打开的一列（把类型自己的列表藏进页签，作品被左右两列夹住，窄窗口还会自己换位置）。这次的区别是两点：对话和属性 / 批注 / 数据来源**同级**，只占本来就要有的那一条右列；面板里是一份真正的对话记录，值得那块宽度。

## 2. 人的一次完整旅程

1. **默认**：请求栏在底部，浮在作品上、可以收起；作品拿到整个宽度。
2. **一边看过程一边聊**：点顶栏的"对话"按钮，右侧打开对话一栏（记录 + 输入区）；左边类型自己的列表一直在，作品只让出右侧那一列。
3. **聊着聊着去改元素**：点"属性"（或批注 / 数据来源），对话收成记录留在这个项目里，请求栏回到作品底部，写到一半的字还在。再点"对话"，记录和草稿都回来。
4. **窗口变窄**：顶栏的"对话"灰掉，写"窗口再宽一点才能把对话放在作品旁边"；作品、左侧列表、底部栏都不动。窗口再宽回来，按钮恢复，但不会自己打开——开不开是人的选择。
5. **离开再回来**：刷新、换窗口、重开项目，记录还在；在终端里 `tingly-design prompt` 或 MCP 发的请求也出现在记录里，标明来自命令行。每种类型记住自己最后开着哪个面板（`dc.pane.<kind>`）。
6. **在幻灯片、文档、设计系统里**：左边一直是页面 / 标签页 / 列表；对话在右边，列表和对话同屏。正在跑或有新结果时，顶栏的对话按钮上有一个状态点，打开面板就读。
7. **不想要了**：点面板头的 ×，或再点一次顶栏的对话按钮；底部栏回来。

## 3. 决定

### 3.1 一个面板，一种位置

对话是右侧的一个面板，和其他面板一样由顶栏的按钮开关：

| 状态 | 占宽度 | 面板里有什么 | 适合 |
|---|---|---|---|
| 底部（默认，面板关着） | 否 | 输入框一直在；运行卡片平时一行 | 发一句看一眼 |
| **右侧面板** | **是，一条右列** | **对话记录 + 输入框** | **一轮接一轮地做，要看懂它的过程** |

- 每种类型把 `chat` 加进 `KIND_PANE_IDS`（`panes.ts`），顶栏的 `PaneToggles` 因此自动多一个按钮；右边同时最多一个面板，打开对话就顶掉属性 / 批注 / 数据来源。
- **删掉位置菜单**：`PositionMenu`、`dc.barMode`、`ChatSlots.left`、外壳 `ChatShell` 的 `left` 状态、"左侧"这一处位置都不再有。对话在哪，由"对话面板开没开"决定。
- **删掉外壳的包含块**：`.chat-work` 的 `transform` 和 `.chat-shell` 不再需要；顶栏回到整窗宽，`.app` 回到窗口坐标。
- **删除 `ListColumn`、`chatTab`、`chat-list` 槽和页签上的状态点**：类型不再把列表注册给外壳。
- **面板头**：`Conversation`（对话）+ 右侧关闭 ×，和属性面板的头同一高度。状态（运行中转圈、有新结果 / 失败一个小点）在顶栏的对话按钮上（`PaneToggles` 的 `Badge`），打开面板就清掉。
- **窄窗口**：放不下时按钮灰掉并说明，**不自动换位置、不盖住作品**；偏好不改，窗口变宽按钮自己恢复，但不会自己打开（§3.5）。

### 3.2 面板里是一份对话记录

对话面板打开时，面板就是对话本身，不再有"运行卡片"和"历史列表"两个东西：记录就是历史。

- **一轮**由 `RunFeed` 画（仍然是同一个部件，它改成画一轮记录，运行中的那轮和已结束的那轮用同一份渲染）：
  1. 你说的（右对齐的气泡，原样；附件缩略图）；
  2. 过程：运行中显示最新一步 + 计时 + 停止；结束后折成"N 步 ›"，点开是全部步骤（读了什么、改了什么），每一轮各自展开，互不影响；
  3. 回答：Claude Code 的话，可选中复制；快速 AI 则是它执行的 jQuery（折叠，带"在 jQuery 里改"）；
  4. 改了什么：文件名片，点一下在作品里定位（画布选中画板、幻灯片切页、文档切标签页、动效跳场景、看板打开来源，设计系统只列不跳，和 agent-feedback.md 一致）；
  5. 下一步：最新一轮有"撤销这次改动"（更早的轮次不给，因为恢复到那一轮之前会冲掉后面的改动；给"放回输入框"）；失败或停止的轮次给"放回输入框"。
- **分隔线**：每次"新对话"（栏头的上下文标记决定）在记录里画一条分隔线，写"新对话"；"接着"的轮次直接接在上一轮后面。记录因此回答"它记得多少"：分隔线以上它不记得。
- **滚动**：默认跟到最新一轮；人往上滚就停止跟随，并出现"回到最新"。新一轮结束但人不在底部时，只在"回到最新"上点一个小点，不抢滚动位置。
- **面板头**：名字"对话"和关闭 ×。**历史按钮在面板里不出现**，因为记录本身就是历史；底部它还在，列表读的就是同一份记录（所以刷新后不再清空，每一行能展开回答和步骤）。运行状态在顶栏的对话按钮上，不在面板头。
- **输入区**：就是 `RequestBar` 的输入部分（作用范围、快速 AI / Claude Code 的切换、附件、输入框、发送 / 停止），放在面板底部。底部栏和面板里是同一个部件，只是容器不同；没发出的草稿在 store 里（`draft`），换容器不丢。

### 3.3 左边一直是类型自己的列表

幻灯片（页面缩略图 216 px）、文档（标签页 220 px）、设计系统（列表 220 px）左边本来就有一列，对话面板**不碰它**：列表一直在，对话在右边，两者同屏。没有左列的类型（画布、看板、动效）左边就是空的，对话也只在右列；画布的图层树在右侧属性里，不受影响。

原来"列表和对话合成一列、两个页签"的做法删掉了（`ListColumn`、`chatTab`、`chat-list` 槽）。代价是设计系统打开对话时作品变窄 220 px（它原来没有右列），换来列表不再被藏起来。

### 3.4 记录存在服务端，不在页面里

问题：运行卡片的内容活在编辑器页面的内存里，所以刷新就没了，命令行和 MCP 发的请求页面也不知道。

决定：每个项目一份对话记录 `.transcript.jsonl`，在项目文件夹里，和 `.claude-session.json`、`.runs.json`、`.journal.jsonl` 一样属于这台机器：不提交、不进 .zip、写回引擎不当作作品文件。

- 每行是一轮：`{ id, agent, prompt, at, source, state, continued, steps, answer, files, startedAt, endedAt }`。`source` 是 `editor | cli | mcp`。运行中同一轮追加更新，结束时定稿；读取时同一个 `id` 取最后一条。
- Claude Code 的轮次由服务端在 `delegate.ts` 里写（它已经在处理 `start / progress / done / stopped / error` 事件），所以命令行和 MCP 的请求也在里面，编辑器不必在场。快速 AI 在浏览器里执行，轮次由编辑器在结束时提交给服务端。
- 编辑器打开项目时读最近一段（一百轮），之后由已有的 SSE 事件更新；不新增第二条推送通道。
- **有上限**：保留最近 200 轮；每轮最多 300 步，更长的把中间折成一条"省略了 N 步"；回答和请求各截到几千字。上限在服务端，超过就从最旧的开始丢，整份重写。
- 删除：不提供"清空记录"按钮。人想重新开始，就是"新对话"的分隔线；真要删，是删项目里的 `.transcript.jsonl`。（"完成 ≠ 锁死"，记录也不该一个手滑就没，ux-principles 第 10 条。）
- 隐私：记录里有请求原文和 Claude 的回答，和 Claude Code 自己机器上存的会话同级；因为属于本机状态，不进 .zip，分享项目时不会带出去。实施时把它加进 `project-archive.md` 的"不进 zip"清单。

### 3.5 宽度和窄窗口

右侧的一条面板不能把作品挤坏。规则（`panes.ts` 的 `MIN_WORK` / `chatNeed` / `chatFits`）：

- 默认 340 px，可拖动改到 280–560 px（拖它**左**边缘，`SideResizer id="chat" edge="start"`），双击恢复，记在本机（`dc.w.chat`；做法同 [side-columns.md](./side-columns.md)）。
- 作品区至少要有自己能用的宽度，各类型的下限：画布 780、幻灯片 620、文档 560、设计系统 600、看板 720、动效 780。窗口比"左列宽 + 280 + 下限"窄时，面板先从当前宽度收窄到 280；再窄，"对话"按钮灰掉并写"窗口再宽一点才能把对话放在作品旁边"，**不自动换位置、不盖住作品**。已经开着的面板在窗口变窄到放不下时会关掉，底部栏回来；窗口再宽回来按钮恢复，但不会自己打开。数值是按各类型剩下的宽度估的，不要挤时改这张表。
- 每种类型的最窄可钉窗口（左列 216 / 220 或 0）：画布 1060、幻灯片 1116、文档 1060、设计系统 1100、看板 1000、动效 1060。
- 放映（幻灯片）和画布的非编辑模式不画面板，作品得到整个窗口。
- 面板打开时：底部栏不渲染；`.mprompt`（动效为底部栏留的槽位）不占高度（`.mprompt.in-pane`）；"请求栏在屏幕上就不弹 toast"的规则继续成立，面板算在屏幕上。

### 3.6 怎么放进六种类型

只有一个提供上下文的 `ChatSlotsProvider` 包住 `App`（没有 DOM、没有 `transform`）：它拿着输入框要 portal 进去的槽和记录用的 `bridge`。每种类型在自己的右列里画 `<ChatPane>`：

- 画布、幻灯片、动效：现在画 `RightPanel` 的位置，`pane === 'chat'` 时换成对话面板；
- 文档：`with-chat` 的第三列，和批注二选一；
- 看板：`with-chat`（`sources` / `code` / `chat` 共用一个槽）；
- 设计系统：新增第三列 `var(--w-chat)`，`KIND_PANE_IDS` 从 `[]` 变成 `['chat']`。

`PANE_DEF` 加 `chat`：Tabler 的对话图标（`icons.tsx` 的 `Conversation`；文档批注的 `Message` 不动）、名字 `Conversation` / `对话`、`ChatBadge`（运行中 / 新结果 / 失败）。`initialPane` 读 `MAIN_PANE`（画布 / 幻灯片 / 动效：属性；文档：批注；看板：数据来源；设计系统：`null`），不再拿 `ids[0]` 当"主面板"。

## 4. 考虑过、没选的

- **左侧自动隐藏、钉住、窄带（前一版的做法）**：不占宽度，也能钉住，但面板"有时在有时不在"：要给它做小标签、探出的时机、点哪里收回、和左缘已有的东西抢位置。这一版先去掉，只留一直打开的一列；等有人说"想要整个舞台"再加。
- **右侧钉住一栏**：以前试过又去掉（agent-panel.md §3）：宽度被拿走的同时面板里只有一张卡片。现在面板里是一份真正的对话记录，而且它是"面板"之一、顶掉属性而不是多一列，才值得这块宽度。
- **右侧自动隐藏继续留着**：面板"有时在有时不在"，要做小标签、探出的时机、点哪里收回，还要和检查器抢边缘；统一成一个开关的面板。
- **检查器里的一个页签（属性 / 代码 / 微调 / 对话）**：不占额外宽度，但对话和属性不能同屏，设计系统、文档、看板的右侧又各不相同，要想办法补；人要的"一边看过程一边改"做不到。
- **已有左列的类型把列表和对话合成一列用页签**（上一版的做法）：作品被右侧检查器和左边那一列夹住，列表和对话永不同屏，没有请求在跑时那列大半是空的，窄窗口还会自己换位置。
- **默认就打开对话面板**：新用户的第一个请求就让出一列宽度，而最常见的用法是发一句、看一眼。默认保持底部，要长对话的人自己开（智能默认，不是开关，第 6 条）。
- **每个类型的布局里各写一份面板**：六份实现、六份样式。面板和槽位是共用的（`ChatPane.tsx`、`ChatSlotsProvider`），类型只决定画在右列哪里。
- **用 Claude Code 自己的会话文件当记录**：它只有 Claude Code 的轮次，没有快速 AI；格式是别人的，会变；用户清理 Claude Code 的会话后，记录就没了而项目还在。我们自己存一份很小的。
- **记录放浏览器 localStorage**：换窗口、命令行和 MCP 发的请求都看不到，和 agent-panel.md 里会话号上服务端是同一个理由。
- **记录放进改动日志（journal）**：日志回答"谁改了哪个文件"，是事后的记录；记录回答"它说了什么、做了什么"。混在一起，日志会被读文件、搜索之类不改东西的步骤淹没（agent-feedback.md §6）。
- **清空记录的按钮**：见 3.4。
- **把记录做成可以分叉、重发、重新生成**：对话产品常见，但这里一个项目一段对话（agent-panel.md），先把"读得到"做对；"放回输入框"已经够重发一条。

## 5. 对照 ux-principles

| # | 判断 |
|---|---|
| 1 围绕问题组织 | 面板回答"它做了什么、说了什么"，不是"它在做什么"一个问题 |
| 2 消除模式选择 | 去掉"位置"这个轴；开不开对话面板就是那个选择，和属性 / 批注 / 数据来源同一种操作；没有"隐藏 / 钉住 / 窄带"这类型状态 |
| 3 一个词一个意思 | "对话"= 一个项目里 Claude Code 的那一段；记录里的分隔线就是它的边界；快速 AI 的轮次也在记录里，但标明"每次从头开始"；面板的标题、顶栏按钮、记录里都是同一个词 |
| 4 轴要分开 | 面板（内容）一个轴，宽度一个拖动；范围、上下文、交给谁各自仍是各自的控件 |
| 5 具体值 | 文件名、请求原文、真实步骤 |
| 6 智能默认 | 默认底部；每种类型记住最后的面板；记录默认跟到最新；步骤默认折叠；窄窗口禁用而不是自动换 |
| 7 诊断走真实路径 | 记录由服务端在真实运行事件上写，不是页面自己拼的 |
| 8 教育在产品里 | 对话按钮每种类型的顶栏都有；灰掉时写明"窗口再宽一点"；面板头就是对话 |
| 9 少视觉噪声 | 去掉一个位置菜单、页签、列表槽、外壳；顶栏只多一个图标按钮；作品不再被三列夹 |
| 10 完成 ≠ 锁死 | 回答和步骤留着、刷新还在、每轮可展开、可放回输入框；草稿跨开合 |
| 11 把下一步交到手上 | 文件名片定位、最新一轮撤销、放回输入框、关闭面板回到作品 |
| 12 副作用限在当前界面 | 面板不盖作品（占一列）；开合不动类型自己的列表和底部栏；状态点不抢切换 |

## 6. 跨类型

六种类型都经同一个 `ChatPane` 拿到面板，`ChatSlotsProvider` 只提供槽位。差别：

| 类型 | 左边一直有的 | 右边原有的 | 对话面板打开时 |
|---|---|---|---|
| 画布 | 无（图层树在右侧属性里） | 属性 / 文件 / 审查 | 顶掉右侧面板 |
| 幻灯片 | 页面缩略图 216 px | 属性 / 审查 | 顶掉属性；页面列表可见；放映不画面板 |
| 设计系统 | 列表 220 px | 无 | 新增右侧一列 |
| 看板 | 无 | 数据来源 / 代码 | 顶掉数据来源 / 代码 |
| 文档 | 标签页 220 px | 批注 | 顶掉批注；标签页可见 |

## 7. 还开着的问题

- **更早轮次的撤销**：现在只给最新一轮。要给更早的，需要"这一轮之后没人再碰过这些文件"的判断，和 journal 的 `rebaseSwap` 能不能做到有关，等有人要再做。刷新后最新一轮也不能撤销（记录里没有改动前后的内容，只有文件名）。
- **记录里放不放"手改"**：现在只有请求和 agent 的轮次；人在画布上手动改的东西不进记录（那是 journal 的事）。如果人想在同一条时间线上看到"我改了什么、它改了什么"，要把两份合起来读，等有人提再说。
- **多窗口同时看同一个项目**：两个编辑器窗口靠 SSE 同步，不做冲突处理。
- **宽屏上对话和属性两条右列**：1680 以上画布放得下（约 1028 的舞台），但要新增"两条右列都开"的状态、顺序和宽度规则，先不做。
- **设计系统打开面板时变窄 220 px**：1280 时作品 940 → 720。列表变可见是收益；如果太窄，先考虑它的面板默认更窄，或让列表可折叠，而不是回到"藏列表"。
- **一个右列宽，还是各面板各自宽**：现在是各自宽（属性 312、对话 340），切面板跳一下；合成一个会让每个面板都记同一个数。
- **和 Tingly Box 里 Projects 页面的对话视图共用**：Projects 的线程页已经有 transcript 部件；如果形状够像，值得把记录的一轮抽成共用的 UI 包（agent-panel.md §5 已经提过）。先做编辑器自己的，再看。
- **迁移一次还是每种类型一次**：现在是全局一次（`dc.barMode` 读过就清掉），只对第一个打开的项目生效；每种类型一次更照顾习惯，要多一个迁移标记。

## 8. 实现里的几个事实

不是设计，是读代码前该知道的：

- **没有外壳**：`ChatSlotsProvider`（`ChatPane.tsx`）只是一个 context，包住 `App`，没有 DOM、没有 `transform`。每种类型自己在右列里画 `<ChatPane>`；关着时右列是 `auto` 网格列，不占宽，没有空槽。
- **槽位**：`ChatSlotsProvider` 拿着输入框的槽。`RequestBar` 在面板打开时把整条栏（只是输入的部分，不是卡片）portal 到面板脚下的槽；记录里点文件名、"放回输入框"经 provider 里的一个 ref（`bridge`）回到这个 `RequestBar`。
- **菜单**：请求栏自己用 `translateX(-50%)` 居中，所以它是里面 `position: fixed` 的包含块。`Menu` 因此 portal 到 `<body>`，调用方在哪个带 `transform` 的祖先里都按窗口坐标定位。菜单不在栏的 DOM 里，所以栏的“点外面放开输入框”和对话框的 Tab 陷阱都把 `[role=menu]` 当作自己的一部分。（`Dialog` 本身不走 portal。）
- **一轮的来源**：`turns.ts` 把服务端存的轮次和这个页面里的活动运行（`delegates`、`fast`）按 `id` 合并，活动的优先，但页面是跑到一半才打开的，则保留记录里更长的步骤。一轮结束时进 `store.turns`，快速 AI 的还 POST 给服务端（`api.keepTurn`）；快速 AI 交给 Claude Code 的那次只算 Claude Code 的一轮（`via: 'fast'`）。
- **服务端读到"还在跑"但进程已经没了**（重启、崩溃）：`GET …/transcript` 把超过 20 秒且 `children` 里没有它的 Claude Code 轮次改成失败并写"这次运行在结束前被中断了"，不改文件。
- **面板的记忆**：`dc.pane.<kind>`（`none` 表示关着）；主面板在 `MAIN_PANE`，设计系统没有主面板。旧的 `dc.barMode` 只在 `panes.ts` 的迁移里读一次。
- **按钮上的点**：`store.chatNote`（`new` / `failed`），在结束的一轮且对话面板不在当前时设置，打开面板清掉；运行中一直显示转圈。
- **草稿**：`store.draft`，`RequestBar` 的输入框读它、写它，所以底部 ↔ 面板换容器不重建文字；打开另一个项目时清空（`agentReset`）。
- **回答可选中、可复制**：记录是普通的页面文字，拖选、双击、三击都不拦。拦的是键：编辑器窗口把每个 ⌘C / ⌘X 当作"复制 / 剪切选中的元素"并 `preventDefault`，浏览器的复制就没了。现在页面里有选中的文字时（`shortcuts.ts` 的 `textSelected`）这两个键留给浏览器；没有选中文字时仍是选中元素的。画板的 iframe 里点一下选中东西时（`leaveField`）会清掉页面上的文字选区，这样刚点中的元素的 ⌘C 立刻生效，而不是还复制旧的那段话。`e2e/chat_copy.py`。
