# 动图（GIF）作为图片

状态：**已实施**（文档、幻灯片、动效；PPTX 里的动图是静帧，见 §6 还开着的问题）。

GIF 本来就能当图片存进项目：上传、`uploads/`、整项目 `.zip`、Word 导出都认 `.gif`。缺的是放进作品之后它的行为：在动效里它按浏览器自己的挂钟播放，和时间轴、拖动播放头、渲染出的视频都没有关系；文档收不到拖入或粘贴的图片；导出里的 GIF 画哪一帧没人说过。

## 1. 各类型的结论

| 类型 | GIF 是什么 | 编辑时 | 导出 |
|---|---|---|---|
| 动效 | 时间轴上的一段**片段**：元素入场时开始，某一时刻显示这一时刻该有的那一帧 | 拖动、播放、倍速都按时间轴 | 精确渲染、HTML 播放器、浏览器里的 MP4 / WebM / GIF 和"保存为 PNG"画的是同一帧，反复渲染逐帧一致 |
| 幻灯片 | 普通图片 | 编辑和放映时由浏览器播放 | PNG 是第一帧（e2e 钉住）；PDF 由服务器上的 Chrome 打印、PPTX 把元素画成图，都是静帧，具体哪一帧没有实测 |
| 文档 | 普通图片 | 浏览器播放 | Markdown `.zip` 和 Word 带原文件（e2e 钉住）；PNG 和 PDF 是静帧，未单独实测 |
| 画布 | 普通 `<img>`，浏览器播放 | 同左 | 静帧；画布没有时间轴，不接管 |
| 设计系统、看板 | 不适用（素材 / 数据页面） | — | — |

## 2. 动效：为什么是"片段"

动效的所有输出（编辑器的舞台、精确渲染器、HTML 播放器、浏览器导出）都靠同一件事成立：`seek(t)` 之后画面恰好是第 t 毫秒。`<img src="x.gif">` 不服从这条时钟：

- 编辑器和播放器里它从浏览器加载完的那一刻开始自己播，拖动播放头、改入场时间都不影响它；
- 渲染时每一帧是整页截图或把 DOM 画成 SVG 再栅格化，GIF 显示的是"碰巧到了哪一帧"（SVG 里的图片不会动，总是第一帧），两次渲染的结果不同，按正反序 seek 的检查也不一定过得了。

考虑过的做法：

1. **让浏览器的 GIF 保持自播，导出时画第一帧**：什么都不用做，但动效里的 GIF 没有意义，作品逐帧不确定。不选。
2. **把 GIF 转成视频或雪碧图再放进场景**：要新的文件格式和转换步骤，原 GIF 不再是作品里引用的那个文件，也改变了"文件原样放进 `uploads/`"的规矩。不选。
3. **运行时解码，按时间轴换帧（选定）**：文件和场景里的 `src` 一个字都不动，运行时读出每一帧，在 `seek(t)` 时把 `<img>` 画的内容换成第 t 毫秒的那一帧。所有出口共用 `animateScene`，所以一处实现、处处一致。

### 约定

- 起点：元素出现的时刻（`data-in` 的开始时间，没有就是场景开始），这个时刻之前显示第一帧。
- 帧：用文件里每一帧的延时；不到 20 ms 的延时按 100 ms（浏览器的老习惯，旧 GIF 速度不变）。
- 循环：照文件自己的循环次数——无限循环就一直播，没有循环块就播一遍停在最后一帧，写了次数就播那么多遍。作者可以在 `<img>` 上写 `data-gif="loop"` 或 `data-gif="once"` 盖过文件。
- 倍速：GIF 的时间就是作品的时间，所以随倍速一起变。
- 读不了（不是 GIF、被截断、太大、取不到）：这张图保持原样自己播，并在舞台的“检查”列表里出一条警告（e2e 钉住）。

### 实现要点

- 解码在 core 的 `gif.ts`：纯函数，不依赖 DOM。`parseGif` 读出尺寸、循环次数和每一帧的小块（补丁），`composeGif` 按处置方式（保留、清除、恢复）逐帧合成完整画面，`gifFrameAt` 回答"过了 ms 毫秒是第几帧"。不加依赖。
- 上限：画面不超过 1600 万像素，像素 × 帧数不超过 1.2 亿，不超过 1500 帧，防止一个超大 GIF 把页面撑爆；超过就走"读不了"。
- 运行时在 `sandbox/src/gifSync.ts`：取字节、合成每一帧、编成 PNG 地址放着（同一个地址只解一次，最近用过的 6 个留着，编辑时场景重画不重解）；`setTime(t)` 换 `src`，`settled()` 等页面把新帧解码完，所以 `seek(t)` 返回时一份 DOM 副本（导出用）画出的就是这一帧。`clear()` 把 `src` 还回去。
- 原 `src` 只在 DOM 里被换；编辑器读元素的地址、复制 / 保存原图、属性面板都读场景源文件，所以拿到的仍是原 GIF。

## 3. 文档

- 斜杠菜单的"图片"原本就能放 GIF（按原样存进 `uploads/`）。
- 新增：把图片（GIF 同）粘贴或拖到正文，落在光标 / 落点；"导入"里单独的图片放到当前标签页末尾（`docsImport` 现在收 `markdown` 和 `image`；和 Markdown 一起选的图片是那份 Markdown 自己的，仍随它保存）。

## 4. 幻灯片

不改显示：GIF 是普通图片，插入、导入、展开去编辑里的图片选择器（只列项目里的图片，GIF 在内）都已经认 `.gif`。PNG 导出画第一帧（SVG 里的图片不会动），由 e2e 钉住；PDF 和 PPTX 没有单独实测。

## 5. 附件

给模型的附件只读 GIF 的第一帧：5 MB 以内的 GIF 原样给；更大的把第一帧重编码后给，项目里仍留原 GIF（原先会直接拒绝，超过 20 MB 时还会把 GIF 字节标成 `.webp`）。

## 6. 还开着的问题

- **PPTX**：PowerPoint 能在放映时播放 GIF，但导出器（`@dc/export/pptx`）是严格的、受审计的，只收 PNG / JPEG / SVG；现在 GIF 作为"元素的图片"进去，是静帧。原生嵌入 GIF 是后续。
- **精确渲染器**（机器上的 Chrome + ffmpeg）和 HTML 播放器走的是同一个 `mount()`，GIF 用 `data:` 地址进页面，设计上同样成立；这台机器的 Chrome 起不来，所以这两条出口没有在本机实跑，由浏览器里的 GIF 导出和 PNG 帧导出间接覆盖。
- 画布里的 GIF 不接时间轴（没有时间轴）；被 `<x-embed>` 嵌入的画板里的 `<img>` 在嵌入里播放，不接动效的时钟。
- 内存：每一帧存成 PNG 地址，帧多、画面大的 GIF 会占几十 MB；要更省可以改成按需编码。
