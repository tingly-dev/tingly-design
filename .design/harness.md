# Harness：怎么确认一切都还好用

状态：统一入口 `pnpm e2e` 和三种节奏（巡检、发布前、PR 冒烟）已实施；快照的结构检查、编辑器截图基线、跨类型矩阵数据化是方案。调研和考虑过的方向在 `.research/harness.md`。

## 问题

产品大部分是交互和画面，不是模型调用。单元测试管格式和写回，30 个 e2e 套件管交互，但 e2e 各有各的启动方式（有的要 `pnpm dev` 加 mock 模型，有的要不配模型的 `pnpm dev`，有的先 `pnpm build` 自己起服务，`embed` 要 `pnpm bundle`），没人一次跑全，坏了也没人知道。画面"对不对"更是没有任何检查。

## 决定

**先只做不依赖外部的部分。** 不调真实模型、不依赖 Tingly Box：mock 模型（`e2e/mock_anthropic.py`）和假的 `claude` 已经能覆盖要测的故障路径。真实模型的评测、视觉模型打分、VModel 编排、对外的 `verify` 命令都先不做。

**一个入口，按组起环境。** `e2e/run.py`（`pnpm e2e`）里有一张 `SUITES` 表，写每个套件属于哪一组；每组先起好它要的东西，组内逐个跑，跑完停掉。结果从套件打印的 `PASS` / `FAIL` 行读，不信退出码（很多套件失败时也退出 0），没有任何检查行或异常退出算 error，超时单独算。汇总写到 `e2e/out/report.md` 和 `report.json`，每个套件的输出在 `e2e/out/logs/`。

- 套件会改示例项目再 `git checkout` 回去，所以 `projects/` 有未提交改动、或有一个只剩被忽略文件的文件夹（上一次留下的改动记录）时不开跑，`--force` 例外。不这样做，会悄悄丢掉人的改动，或者让"导入后取一个空闲的名字"这类检查拿到 `-3`。
- 每组用临时的 `DC_CONFIG`，不读这台机器上存的模型设置。
- `DC_CHROME` 没设时用 Playwright 的无头版（完整版 Chromium 无头时点缩放后的画板会点偏）。
- `delegate` 调真实的 `claude`，只在 `--real` 时跑。

**全量 e2e 不进每个 PR。** 整套大约十分钟，还要装浏览器、起几轮服务，每个 PR 都跑代价太大。分三种节奏（`.github/workflows/e2e.yml`）：

| 节奏 | 跑什么 | 红了怎样 |
|---|---|---|
| 巡检：每晚在 main 上，也可手动触发 | 全量 | 开一个 `e2e-patrol` 标签的 issue（已有就追加评论），转绿后自动关；不拦合并 |
| 发布前：`release.yml` 打包前调用 | 全量 | 拦住发布 |
| PR 冒烟：改了 `apps/`、`packages/`、`e2e/`、`projects/` 时 | `--smoke`：每种类型一个套件，加运行反馈 | PR 上一个红的检查 |

冒烟集合是 `run.py` 的 `SMOKE`，选的是"打开、编辑、写回"最直接的那个套件，加上 `run_feed`（请求栏在六种类型里都有一次运行）。

报告和日志作为 `e2e-report` 产物上传，`report.md` 也写进运行页的摘要。

## 方案（还没做）

1. **快照的结构检查。** `check --snapshots` 现在只能证明"画得出来"。在每个作品的框架里再查：文字被裁掉、元素跑出画板或幻灯片、文字和纯色背景的对比度不够、整块空白。只报警告，不设基线。
2. **编辑器界面截图基线。** 每种类型 × 明暗 × 中英，固定视口和浏览器，带容差比较；有差异时人看过再一条命令重录，不自动接受；只在巡检和发布前比。基线放旁路分支，不进主分支。
3. **跨类型矩阵变成数据。** `.design/project-kinds.md` 的矩阵每个 ✓ 格子要么列出覆盖它的套件，要么写明没测的原因；单元测试查格子和套件是否都对得上。

## 没定的

- PR 冒烟要不要设成必过检查（仓库设置，不在这里决定）。
- 冒烟集合的大小：等巡检跑出几次真实耗时再调。
