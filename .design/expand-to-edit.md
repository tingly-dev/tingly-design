# 展开非文字元素去编辑：图片、链接、卡片里有什么，就改什么

状态：**第一期已实施**（画布、幻灯片、动效共用同一个运行时和同一个表单）。§8 是还没做的，§9 是没定的。测试是 `e2e/expand.py` 和 `packages/core/test/expand.test.ts`。

## 1. 要解决的问题

画板、幻灯片页、动效场景里，手动能改的原来只有一种东西：纯文字。双击一个文字叶子可以原地改（模板里带洞的文字见 [template-text-editing.md](./template-text-editing.md)），属性面板能改盒子的样式（尺寸、布局、字体、填充、边框、阴影）。除此之外的元素，选得中、拖得动，却**改不了它自己的内容**，双击也不说一声：

| 元素 | 原来的情况 |
|---|---|
| `<img>` | 能选、能调样式；**`src` 和 `alt` 改不了**，换一张图只能让 Claude Code 去改文件 |
| `<a href>` | 标签只有在是纯文字叶子时才能原地改；**地址、新标签页改不了** |
| `<input placeholder>`、带图标的 `<button>` | 占位提示改不了；有子元素的按钮标签改不了 |
| 混排文字 `Save <b>20%</b> today`、`<h1>标题 <span>重点</span></h1>` | 带样式的词能改，**词旁边的文字改不了**：文本节点没有元素 id，整个段落因为含子元素不算"纯文字" |
| 卡片（标题 + 说明 + 图 + 按钮） | 双击卡片没有任何反应，人得知道去逐个点中里面的元素再双击 |
| 属性里的洞：`src="{{logo}}"` | 文字里的洞早有规则，属性里没有 |

共同的形状：**元素不是文字，但看着它的人知道自己想改什么**（换图、改链接、改这张卡片上的三行字）。系统没有一个通用的办法说"这个元素里有这些东西可以改"，于是每一种要么是一次性的面板（`BoardEmbedProps`，只管画板嵌入），要么什么都没有，而且没有任何提示。违背 [ux-principles.md](./ux-principles.md) 第 10 条（完成≠锁死：能进去的就该能再进去）和 template-text-editing 的第 3 条原则（改不了就当场说为什么）。

## 2. 考虑过的做法

| 做法 | 问题 |
|---|---|
| 每种元素一个属性面板（`ImageProps`、`LinkProps`…，像 `BoardEmbedProps`） | 面板是对的落点，但只有面板：舞台上双击没有反馈；每加一种元素加一个组件，卡片这种"好几样东西"的没有归处 |
| 右键菜单里加"替换图片…""编辑链接…" | 藏得最深，和 ux-principles 第 8 条（教育内嵌）相反；而且一个元素只有一个菜单项，卡片还是没有 |
| 整个容器 `contenteditable`，把 `innerHTML` 写回 | 浏览器会随手改结构（`<div>` 换成 `<br>`、吞掉元素），写回引擎要"最小改动"的承诺守不住 |
| Figma 式"进入组"模式：双击进入，其余变暗，每个部件原地有控件 | 对文字很自然，对图片要换的是一个选择器、对链接要一个地址输入，这些仍然需要一个浮出的表单；进入组可以靠已有的 Enter / Shift+Enter 选子级 / 父级（见 §4）。作为第二期 |
| **一张"可编辑字段"清单 + 一个表单，舞台上的气泡和属性面板的"内容"区各画一次**（采用） | — |

## 3. 模型：元素 → 一串字段

核心是 core 的 `expand.ts`，纯函数：

- **`editFields(doc, el)`** 把一个元素连同里面的东西读成**字段**清单，按阅读顺序：
  - `<img>`：来源（`src`）、替代文字（`alt`）；`<video>`：来源。
  - `<a>`：里面的每段文字（包括里面带样式的词）、地址（`href`）、"在新标签页打开"（`target=_blank`）。
  - `<input>`（文字类型）、`<textarea>`：占位提示（`placeholder`）。
  - 其它元素：它的**文本节点**，每段非空白的文字一个字段（`Save <b>20%</b> today` 是三个字段：`Save`、`20%`、`today`），然后进到子元素里。
  - 不进去的：锁定（`data-lock`）和隐藏（`data-hide`）的部分、`svg`、`x-embed` / `x-icon` / `x-shape` / `x-connector`、`dc-import`、`helmet`、脚本和样式。
- 每个字段带**来源**（`binding`）：
  - `literal`：文件里就这么写，直接改；
  - `tweak`：整个值恰好是 `{{name}}`，`name` 是文字类 tweak（`data-props` 里没写 `editor` 或写 `"text"`，默认值是字符串）：显示的是 tweak 的默认值，改的是 tweak 的默认值，洞原样保留（和 template-text-editing §3 一个规则）；
  - `readonly`：其它的洞（脚本给的数据 `data`，列表某一行的值 `row`）：显示洞原文，不能改，并**说出原因**和出路。
  - 字段还带 `repeated`（在 `<sc-for>` 里，每一行都画一次，改一处所有行跟着变）和 `owner`（它属于哪张图、哪个链接、哪个输入框；链接里带样式的词属于链接，所以一个链接的所有字段排在一个块里）。
- **`planField(field, value)`** 说这个字段怎么写回，仍然只用普通的编辑操作，**文件里不加任何新语法**：属性是 `attr` 操作；文字是新加的 **`textRun`** 操作（改元素的第 n 个文本节点，周围的元素和文件里的缩进、空白原样保留，`DesignCopy` 本来就按文本节点写回最小补丁）；tweak 是 `setPropDefault`。"在新标签页打开"一次写 `target="_blank"` 和 `rel="noopener"`，取消时两个一起去掉。空的 `alt` 保留为 `alt=""`（装饰图，不是没写）。
- `fieldNear` 在多个文字字段里找到**被双击的那一段**（运行时用 `caretPositionFromPoint` 取指针下文本节点的文字，由编辑器去匹配）。

这个清单不关心谁来画：舞台上的气泡、属性面板的"内容"区、以后的别的入口都用它。

## 4. 展开：双击和 Enter 做哪一件事

对选中的元素，按顺序只做一件：

1. **纯文字叶子**（`retypeKind` 是 literal / tweak / mixed）：原地改，和以前一样。**带地址的链接也是这样**：`<a>` 里只有文字时，双击还是改标签，地址在属性面板的"内容"区里（选中它就在那里），因为"改一个链接的字"远比"改地址"常见，不该为了后者让前者多一步。
2. **有可改字段**（一张图、一个输入框、带子元素的链接、一张卡片）：在元素下方（放不下就挪上来）开一个**气泡**，里面是这些字段的表单；光标落在被双击的那一段，没有就在第一个可写的字段上。
3. **什么都没有**：用一句话说（"这个元素里没有可以手动改的内容。外观可以在右侧面板里调，要换成别的就告诉 Claude。"），不再静默。
4. **已锁定**：同样说一句（以前文字被锁时也是静默的），不打开。

Enter 的含义早已是"进一层"（Enter 选第一个子元素，Shift+Enter 选父级）：**Enter 在没有子元素的选中项上改成"编辑它"**，文字就原地改，图片 / 输入框就开表单。这样"进到卡片里 → 选中图片 → Enter 换图"整条路都不用鼠标，也不加新快捷键。

Esc 关闭气泡（在表单里的任何输入框里按都行，没提交的输入丢掉）；选中别的元素、点气泡外面也会关。气泡属于它打开时的那个元素。

**气泡和面板是同一个表单**（`ContentForm`）：属性面板顶上多一个"内容"区，选中图片、链接、输入框、卡片时出现，同样的字段、同样的写回。气泡开着的时候面板不重复画同一份。面板区的好处：不用知道"要双击"也能找到；气泡的好处：眼睛不用离开元素。纯文字叶子不给"内容"区（那里本来就是原地改）；字段多的容器（整张画板的根）面板里只列前 8 个并说"还有 N 处"，气泡最多 24 个。

字段在表单里的样子：

- 文字：一个多行输入（长的最多四行），Enter 提交，本身就是自己的标签，不再写"文字"。
- 图片：缩略图、**照文件里写的来源**（具体值，不是别名）、"替换…"；展开是一个选择器：这个项目里所有的图片（`entries` 列表，新的在前）和"上传图片…"。选一张写它的路径，**不复制文件**（已经在项目里了）；上传走 `uploads/`（和别处导入一样，按内容命名）。
- 链接：标签、地址、"在新标签页打开"。输入框：占位提示。
- 悬停一个块，画板里对应的元素描出轮廓（和图层树悬停同一个机制）。

## 5. 写回、撤销、和 AI

- 每次提交是一次 `editElement`（或 tweak 的一次 `edit`），是**一步撤销**，进改动记录，被外部改动冲突时重放，和别的手动编辑完全一样；AI 之后读到的是改后的文件。没有新的配置项，所以不走 `recordChange`。
- 锁定（`data-lock`）：运行时不展开；面板的表单在已有的"整块禁用"的 fieldset 里。**锁对 AI 意味着什么**仍是 [#162](https://github.com/tingly-dev/tingly-design/issues/162) 的待定问题，本特性不改。
- 动效场景里，元素的编辑仍照 `editElement` 的老规则（关键帧、非主尺寸覆盖）：改的是 `src` / 文字，不是样式，所以这些规则不介入。

## 6. 防杂乱

1. 没有新的工具栏按钮，没有常驻的东西。入口是已有的手势（双击、Enter）和属性面板里一个按需出现的区。
2. 表单只列元素**真有**的字段；没有字段就不出现。
3. 一块屏幕上限：气泡最多 24 个字段、面板最多 8 个，再多就说"还有 N 处，选中其中一个"，不滚出一面墙。
4. 词汇不新造：标签是 Source / Alt text / Address / Placeholder，和浏览器、HTML 的叫法一致；"替换…"学图片菜单。
5. 不抢画板：气泡贴在元素下方，放不下挪到上方，不盖住被改的东西。

## 7. 各类型怎么接

| 类型 | 状态 |
|---|---|
| 画布 | ✓ 双击、Enter、面板"内容"区 |
| 幻灯片 | ✓ 同一个运行时，`SlideFrame` 收 `expand` 和 `noedit` 消息，面板同一个 `ElementProps` |
| 动效 | ✓ 同一个 `SlideFrame` 和面板（e2e 只测了幻灯片，见 `e2e/coverage.json` 的理由） |
| 设计系统 | — 没有元素选择：组件预览是整份源码，在代码里改 |
| 看板 | — 页面在沙箱框架里，靠"认领"而不是选择模型；先要把选择语义带进框架 |
| 文档 | — 文档是 ProseMirror 的块，不是带 `tid` 的元素；图片块的来源和 alt 另议（块角部栏的"图片"行，[block-corner-bar.md](./block-corner-bar.md) §4），那一页会复用 `ContentForm` 的图片行 |

幻灯片里 `x-icon`、`x-embed`、`x-shape`、`x-connector` 不收：它们的属性（图标名、嵌入的地址、形状类型）各是一张自己的小表单，不是"文字和一个地址"，见 §8。

## 8. 还没做的（第二期以后）

- **列表和表格的结构编辑**：一个列表 / 表格里增、删、挪一行（`duplicate` / `remove` / `move` 操作都已存在，现在只在右键菜单里对单个 `li` / `tr`）。设想：选中 `ul` / `table` 时，"内容"区在字段旁多一组"加一项、删一项、挪动"，在 `<sc-for>` 里对应 `data-props` 里那个列表的增删（`setListItemField` 已有）。
- **图标名**（`x-icon name`）：一个小选择器。
- **列表行里的值**（`src="{{item.photo}}"`）：现在标 `row` 只读。运行时知道被点的是第几行（`data-dc-item`），可以像文字那样改 `plans[i].photo`；表单里需要带上行号。
- **进入组模式**：双击进入一个容器，其余变暗，各部件在原处有控件；Tab / 方向键在部件间走。
- **文字的富编辑**：把一段混排文字里的一个词变粗、加链接。现在每段文字是纯文字，样式保留在它周围的元素上。
- **文档的图片**、**看板的部件**：见 §7。
- **舞台上展开前的提示**：悬停一张图时轻轻提示"双击编辑"（教育内嵌）。要和现有的悬停轮廓一起设计。

## 9. 还开着的问题

- 气泡和面板同时需要吗？现在气泡开着时面板不重复，关了再出现，面板内容会上下跳一次；另一个做法是双击时直接聚焦面板里的字段、不开气泡（少一层浮出物，但眼睛要离开元素）。
- 带地址的纯文字链接：双击改标签、地址在面板，是否应该双击就给表单？现在的取舍见 §4.1。
- 脚本给的值（`readonly`）只说原因；要不要给一个"让 Claude 改这个"的按钮，直接把请求写进请求栏（ux-principles 第 11 条）。
