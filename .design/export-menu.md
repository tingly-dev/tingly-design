# 导入 / 导出：一个菜单，各类型一样

状态：**已实施**（PDF 一键、视频选项、状态条）；§7 是没做的。导出的底层（编码、取图、字体）在 [export.md](./export.md) 和 [export-image.md](./export-image.md)，这里只讲入口、菜单里放什么、选项怎么收，以及为什么。

## 1. 问题

导入和导出原来是各类型各写各的，散在每个栏的角落里：画布是左栏末尾一个看不出意思的图标（导入）加每个画板名称条上的小下载图标（导出），幻灯片是一个下载图标，看板和文档是两个文字按钮，设计系统是一个图片按钮，动效是"保存帧"和"导出视频"两个按钮。想"把东西弄进来或弄出去"的人要在六种栏里各找一遍；每个类型能存什么也看不出来。

视频只有"导出"一个按钮：尺寸、帧率、格式、质量、范围一概不能选。PDF 是浏览器的打印窗口，多一步、还要人自己选"另存为 PDF"。

## 2. 决定

- **每种类型的栏里只有一个"导入 / 导出"按钮**，菜单分两段：导入（选文件、选文件夹、（幻灯片、动效）从项目导入）和导出（这种类型能存的格式）。**菜单里看得见的字只有一行名称**：导入项直接写它收什么（"导入 HTML、SVG、图片…"，不是"选择文件…"），详细的说明（每种素材会变成什么、拖进来或粘贴也行、PDF 会走打印窗口）放在行尾的信息图标上，悬停或键盘聚焦才出现。选项的图标始终和名称同一行，不再被多行说明撑得错位。共用部件 `FileMenu`，各类型只交出自己的导出项列表（`ExportItem`），菜单、措辞、失败怎么提示都一样。画布的列表跟着选中的画板变（打开菜单时才读）。
- **导出项按"想要什么"排**：PDF（需要时）最先，然后图片，然后 HTML、Markdown 等文本，用分隔线隔开。名称写格式，说明写内容和做法（"每页幻灯片占一页""这一页，每页一个文件"）。同名的格式靠说明区分，成批的写复数（"PNG 图片"）。
- **不可用的不藏起来，写原因**：没有 Chrome 的机器上 PDF 项的说明改成"……· 会打开打印窗口"，点了走原来的打印窗口。菜单在不知道时（还在问服务端）不作承诺。
- **画板名称条上的下载图标保留**：它是针对那一个画板的就地入口，菜单里的"选中的画板"项和它做同一件事。
- **命令行跑的是同一份列表**：`FileMenu` 把各类型交出的导出项登记给 `headless.ts`，`tingly-design export` 和 `check --snapshots` 在本机 Chrome 里打开编辑器、按 id 跑这些项（[cli.md](./cli.md) §4）。所以一种格式只在菜单里加一次，命令行就有了；各类型另交一个 `pick`（显示某个画板、幻灯片、标签页、视图），菜单里的人用不到它。编辑器里存文件一律走 `local.ts` 的 `download`，命令行才接得住。

选了而没选的：把导入和导出做成两个按钮（人想的是"文件进出"，不是两个动作）；在菜单里放"导出设置"（见 §4，选项只在选项真的多的地方出现，而且折起来）。

## 3. 各类型放什么

| 类型 | 导出项 | 说明 |
|---|---|---|
| 画布 | PNG、PNG @2x（选中的画板，没选中而这一页只有一个时就是它）；PNG 多张（这一页的每个画板）；源文件（`.dc.html`） | 画板在各自的框架里，PDF 要把框架合成一页，不做；见 [project-kinds.md](./project-kinds.md) |
| 幻灯片 | PDF；PNG（这一页）；PNG 多张（每一页）；HTML；Markdown；演讲者备注 | Markdown 见 §3.1 |
| 设计系统 | PNG（屏幕上的这个视图） | 没有适合分页的内容，不做 PDF |
| 看板 | PNG（页面现在的样子） | 页面在沙箱框架里，PDF 没做（页面是动态的，分页没有意义） |
| 文档 | PDF；Markdown（当前标签页、整篇）；HTML；PNG（当前标签页） | PDF 按 A4 排版；整篇和当前标签页各一项，名称分开写（“Markdown”“Markdown（当前标签页）”），不靠悬停说明区分；Markdown 见 [docs-markdown.md](./docs-markdown.md)（有图片时是带图片的 .zip） |
| 动效 | 视频…（打开选项对话框）；GIF…（同一个对话框，格式已选 GIF）；PNG（播放头所在的帧） | GIF 单独占一项：只在"更多选项"里的格式，用户找不到，会以为不支持 |

### 3.1 幻灯片的 Markdown：写成文档，不是缩小的幻灯片

问题：PDF 和 HTML 适合放映，不适合“把内容发给别人读”：版面是为 1920×1080 的台上观众排的，一页一个大字，复制不出结构，搜索和 diff 也不行。要的是一份**重新组织成文档**的文字。

决定：由 `packages/core/src/slidesMarkdown.ts` 的 `deckToMarkdown` 把牌组确定性地转成 Markdown，不调用模型。

- 文档标题是牌组标题；第一张（封面）的标题并入它，封面剩下的文字成为导语。
- 有分节说明的牌组：分节是二级标题，每页标题三级；没有分节：每页标题二级。页里的小标题（卡片标题）再低一级，直到六级。
- 页标题取编辑器大纲用的同一个规则（第一个 h1–h3，没有就第一段文字），不另立标准。
- 按源码顺序读（不是绘制顺序）：文字框、段落、列表、表格（GFM，第一行作表头）、图片（路径加 alt）、粗体 / 斜体 / 链接照原样。形状、图标、连接线、内联 SVG 和嵌入块在文字里没有意义，不输出。
- 每页都印的页脚、页码、标签行（如“某某 · 介绍 · 02”）是幻灯片的版面，不是内容：一行的短段落，去掉数字后在三页以上、且占一半以上的页里重复，就不输出。
- 演讲者备注跟在各自那页之后，作引用块，“备注：”由编辑器的词条提供（核心不带文案）；隐藏的页不输出。

没选的：用模型改写成“好读的文章”：结果不可重复、要钥匙和等待，而且改写了人写的字；这和导出菜单的“一次点击出文件”不合。需要改写的人可以把这份 Markdown 交给 Claude Code 继续整理。每页一个分隔线、把每页当 PDF 页缩小：读起来仍是幻灯片。

没解决：图片只带项目内的相对路径（`assets/…`、`uploads/…`），单独发这个 .md 时图片是断的，要和项目文件夹一起给；之后可以考虑“Markdown + 图片 zip”。命令行 `export --as md` 用同一份。

**整个项目。** 每种类型的导出项后面都有同样两项：整个项目（.zip）和仅项目文件（.zip）。它们存的是项目本身而不是成品，由 `FileMenu` 自己加，各类型不用交；见 [project-archive.md](./project-archive.md)。

**复制为 PNG（画布右键菜单）。** 导出菜单管“存成文件”，贴进别的应用（聊天、文档、设计稿）要的是剪贴板上的图，下载再拖进去多两步。所以画布的右键菜单在“复制”下面有“复制为 PNG”，对选中的元素和整块画板都能用（便签没有，它不在画板的框架里）。图和 PNG @2x 一样是 2 倍，画法也一样：沙箱收到带 `tid` 的 `export` 消息就画那一个元素（没带就画画板根）。写剪贴板时把画图的 promise 直接交给 `ClipboardItem`，这样写入在点击的手势里开始，Safari 才不会拒绝；浏览器不能往剪贴板放图（或权限被拒）时改为下载同一张 PNG，提示里说明改成了下载，而不是安静地什么都没发生。原来的“复制”仍只复制元素的 HTML 源码，用于在画布间粘贴。幻灯片、看板已有自己的 PNG 路径，复制为 PNG 暂时只做画布，等别的类型也要时再把“画好的图 → 剪贴板”抽成共用函数。

PPTX 仍是方案（先一页一图，见 [export.md](./export.md) §5），不在菜单里占位：菜单里没有的格式就是还没有。

## 4. 视频：默认一键，选项折起来

菜单里的"视频…"打开一个对话框，上面是**一行摘要**（"MP4 · 1920×1080 · 30 帧/秒 · 整段 · 36.4 秒"）和"导出"按钮：最常见的做法是按作品自己的尺寸和速度出文件，一次点击。"更多选项"默认折起来，展开后是：

| 选项 | 取值 | 默认 | 为什么 |
|---|---|---|---|
| 格式 | 自动（MP4，浏览器写不了时 WebM）、MP4、WebM、GIF | 自动 | 用户要的是"能到处播的文件"，不是编码器；写不了时由 `planVideo` 退到 WebM 并说明 |
| 尺寸 | 作品自己的，再加比它小的常见高度（2160、1440、1080、720、480、360） | 作品自己的 | 只往小了选：放大不会更清楚，只会更慢；比例不变，不会拉伸 |
| 帧率 | 24、30、60 和作品自己的；GIF 是 10、15、24 | 作品自己的 | |
| 质量 | 高、均衡、小文件 | 高 | 高保留细小文字的清晰，和原来一致 |
| 范围 | 整段、播放头所在的场景 | 整段 | 只导出一个场景时不带声音（混音按整段做，截取没做） |

选格式时带动其他默认：选 GIF 就把尺寸降到 480 以内、帧率降到 15 以内（GIF 每帧 256 色，大了只是文件爆炸），再提示"适合短的循环"。文件名带上和默认不同的部分（`-720p`、`-<场景>`）。

**菜单里的"GIF…"** 打开同一个对话框，格式已选 GIF、选项展开、尺寸和帧率已是 GIF 的默认；不是另一套流程，只是把埋在选项里的格式摆到菜单里。

**走服务端的作品选项一样**：含 embed 或视频层、本机有 Chrome 和 ffmpeg 时，由服务端的 Chrome 画（[export.md](./export.md) §4）。对话框选项同样是格式、尺寸、帧率、质量、范围，只是格式只有 MP4 和 GIF（ffmpeg 不写 WebM，也没有"自动"可退），并用一句话说明为什么由本机的 Chrome 画。选项交给 `POST /api/projects/:p/render`：Chrome 仍按作品自己的尺寸截图，缩放、抽帧率（只截需要的帧）、截取范围由服务端完成；MP4 的质量映射到 crf，截取范围不带声音。

服务端的 GIF 用 ffmpeg 的两遍调色板：`palettegen=stats_mode=diff` 对整段统计一份 256 色调色板，再用 `paletteuse`（bayer 抖动，只重画变化的矩形）上色。比 ffmpeg 默认调色板的色带少、文件也小；代价是需要先拿到整段帧，不能边截边出。浏览器路线用 gifenc，每帧各量化一份调色板（便宜，帧间可能轻微闪色）。

编码参数通过 `ExportRequest`（沙箱的 `motionExport.ts`）传进去：`width/height`、`fps`、`quality`、`from/to`、`format` 含 `gif`；`@dc/export` 的 `encodeVideo` 只多了 `quality`。取图仍是每帧 seek 再 rasterize，选小尺寸时画的还是作品本身的尺寸再缩小，所以小尺寸并不更快，只是文件更小。

**进度读数是一个固定大小的块。** 导出时顶栏里的读数（"正在导出 42% · 21 帧/秒 · 剩 33 秒 · 取消"）每出一帧就换一次数字，原来是一整句随内容变长变短的按钮：数字位数一变、文字一折行，按钮的宽高跟着跳，右边的工具全被挤动，高频刷新时观感很差。现在它是一个定宽定高的块：数字用等宽数字（`tabular-nums`），百分比和速度各占一个格子，格子按"最宽的样子"（100%、88 帧/秒 · 剩 888 秒）留位（实际文字和一份不可见的最宽文字叠在同一格里，所以中英文都不用手算宽度），不折行；底色按进度从左铺满，一眼看出走了多远。较长的说法（哪条路线、"约剩多少秒"整句）放在提示里；窄屏（<1100px）收掉速度格，只留百分比和取消。点它取消，和原来一样。考虑过的另一种做法是把读数拆成几个浮动小球，但顶栏上多几块浮动的东西比一个定宽的块更乱，且和"浮动栏只留工具"（[top-bar.md](./top-bar.md)）冲突。

## 5. PDF：服务端 Chrome 一键，没有时回到打印窗口

编辑器自己排好版（幻灯片一页一张、`@page` 取幻灯片尺寸；文档按 A4），把整页 HTML 交给服务端的 `POST /api/pdf`；服务端用本机的 Chrome（和精确视频渲染同一个，`findChrome`、同一个调试管道）打印成 PDF 返回，编辑器直接保存。选了这条路的原因：

- 用户要的是一个文件，不是"在打印窗口里再选一次另存为"。
- 版式由编辑器的 HTML 决定，和导出 HTML、PNG 是同一份标记，三种格式看起来一样。
- 没有新依赖：Chrome 本来就是精确视频渲染要的，没有它就保持原来的打印窗口，菜单里写明。

没选的：浏览器里用 jsPDF / pdf-lib 画（文字变成图片或要自己排版，中文字体要内嵌，质量和体积都差）。页面里的图片路径是绝对地址，服务端按请求的来源补 `<base>`，网页字体由 Chrome 自己取（在没有网络的机器上会落到后备字体）。

## 6. 状态条（六种类型）

原来右上栏里有一块"● 已同步"文字，占宽、说的是常态。现在是一个**历史图标，角上一个状态点**（绿：已保存；蓝：保存中；红：已断开），只有不正常时才多一个词（"保存中…""已断开"）。图标说明点一下做什么（打开改动记录），点说明现在怎么样，常态下栏里不多一个字。提示文字用整句说明（"所有改动都已保存到项目文件。打开改动记录"）。共用部件 `SyncStatus`。现在六种类型的顶栏都是同一个：`SyncStatus` 放在项目名旁（[top-bar.md](./top-bar.md)），看板、文档、动效原来的圆点和"日志""History"文字按钮都换成了它。

- 记住上次的视频选项（现在每次从默认开始）。
