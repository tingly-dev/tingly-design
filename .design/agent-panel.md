# 请求栏的布局：不挤舞台、能收起、看得见历史和对话上下文

状态：**已实施**（浮动的运行卡片、固定高度的动效槽位、收成药丸、请求历史、"新对话 / 接着"标记）。"还开着的问题"一节是没做的。

运行卡片本身的内容见 [agent-feedback.md](./agent-feedback.md)；这里只讲它放在哪里、怎么收、怎么翻、上下文是不是新的。

## 1. 问题

三个反馈其实是同一个面板的三个毛病：

| 反馈 | 用户在问 | 原来的样子 |
|---|---|---|
| 窗体随 agent 执行不断变动 | 我在看的东西为什么在动？ | 动效的请求栏在页面流里，排在时间轴下面；运行卡片出现、步骤变多、输入框长高，都在把舞台往上挤。其他类型的请求栏是浮在画布上的，不挤，但卡片会盖住内容且和请求栏连成一块 |
| 输入框不好直接收起、展开 | 我现在不想要它，能让开吗？ | 没有收起；CSS 里留着 `.prompt.collapsed` 但没人用 |
| 看不见历史，分不清是不是新上下文 | 它记得我刚才说的吗？我之前问过什么？ | 只显示最近一次运行；每次 Claude Code 请求其实都是全新的 `claude -p`，快速 AI 也不带历史，但界面上没有任何地方这么说 |

## 2. 决定

六种类型用同一个面板（`PromptBar` 和 `AskClaude` 共用 `AgentBar.tsx` 的部件，第 3 条：一件事一个说法；跨类型功能只做一次）。

**位置：请求栏高度固定，其余都浮在它上面。** 运行卡片和历史列表是请求栏的绝对定位子元素，贴着栏的上沿向上展开，最高 `min(60vh, 380px)`，更长的在里面滚动。栏本身的高度只由头部和输入框决定。动效的槽位（`.mprompt`）因此是固定高度，栏和卡片盖在舞台上而不是挤它；输入框长高也是向上盖，不推时间轴。

**收起：栏头右端一个按钮，收成药丸。** 药丸停在栏原来的位置，一个图标加一句话（"让 AI 修改" / "Claude Code 正在处理…" / "已完成" / "没能完成"），点一下展开。收起时一次运行照常进行，结果在药丸上可见，所以收起不等于看不到（第 10 条：完成不等于锁死）。状态存在 `localStorage`，各类型共用，刷新后保持。动效收起时槽位也跟着缩，把舞台还给用户。没有加快捷键：药丸本身就是直接入口，快捷键要和六种类型各自的按键表协调，以后需要再加。

**历史：栏头一个按钮，列表替换卡片位置。** 本次编辑器会话里发出的每条请求（快速 AI 和 Claude Code，手写 jQuery 不算），最新在上：状态、请求原文、时间、交给了谁，Claude Code 的还标"新对话"或"接着上次"。点一行把请求放回输入框（第 11 条：下一步的物件交到手上）。

**上下文：栏头一个标记，说下一条请求从哪里开始。**

- 快速 AI：标"每次从头开始"（不可点）。它只看当前文件和最近的改动，这是事实，不是开关。
- Claude Code：有可接的对话时标"接着：<上一条请求>"，点一下改成"新对话"，再点回来；没有时标"新对话"（不可点）。标记只对下一条请求有效，发出后回到默认。

"接着"是真的接：服务端把 Claude Code 报告的 `session_id` 随事件告诉编辑器，下一条请求带 `resume`，服务端用 `--resume` 启动。默认是接着上一次**成功完成**的运行（智能默认而不是开关，第 6 条）：来回改同一件东西是最常见的用法，要从头开始的人点一下标记。快速 AI 交给 Claude Code 的请求不接，因为那一条的上下文本来就是快速 AI 拼的。

## 3. 考虑过、没选的

- **像 Tingly Box 的 desk 那样把对话停靠在侧边**：对话和历史会有固定位置，但吃掉舞台的宽度，动效和幻灯片最需要宽度。浮在底部的栏加可收起，在画布类型上已经够用。是否给长对话一个可停靠的模式，见"还开着的问题"。
- **运行卡片留在栏里、只让动效例外地浮起来**：两套布局，以后每个类型还要想自己属于哪套。统一浮起，行为一致。
- **默认新对话，让用户自己点"接着"**：和现状最接近，但把"接着"变成每次都要做的动作；而用户反馈的恰恰是想看到它是不是接着的。
- **历史存在服务端、刷新后还在**：journal 已有文件级记录；请求历史只是编辑器会话内的清单，没有第二份持久状态要维护。

## 4. 跨类型

画布、幻灯片、动效走 `PromptBar`；设计系统、看板、文档走 `AskClaude`，多出来的只是栏头一行。矩阵见 [project-kinds.md](./project-kinds.md) 的"请求栏面板"一行。

## 5. 还开着的问题

- **把一条回答留作画布上的便签**（#45 的后半）：和动效的批注（#44）重叠，等批注的形态定了再做。
- **可停靠的对话模式**：长对话需要固定位置时再考虑；要和 Tingly Box 的 desk 对齐，可能值得抽成共用的 UI 包。
- **历史不跨刷新**：刷新或换项目后清空；"接着"依赖的 session 也只在本次会话内已知。
- **`--resume` 失败**（Claude Code 清掉了旧会话）会显示为一次失败的运行，用户点"新对话"重发即可；还没有自动回退。
