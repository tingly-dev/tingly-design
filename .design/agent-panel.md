# 请求栏的布局：不挡舞台、不用点开收起、看得见历史和对话上下文

状态：**已实施**（底部栏为默认，卡片平时一行；可移到右侧，右侧是自动隐藏；运行卡片、请求历史、"新对话 / 接着"标记；项目的 Claude Code 对话由服务端保存）。"还开着的问题"一节是没做的。方案：右侧自动隐藏取消，改为一直打开的左侧列（已有左列的类型用页签），面板里是能回头读的对话记录，见 [chat-panel.md](./chat-panel.md)。

运行卡片本身的内容见 [agent-feedback.md](./agent-feedback.md)；这里只讲它放在哪里、怎么收、怎么翻、上下文是不是新的。

## 1. 问题

三个反馈其实是同一个面板的三个毛病：

| 反馈 | 用户在问 | 原来的样子 |
| 窗体随 agent 执行不断变动 | 我在看的东西为什么在动？ | 动效的请求栏在页面流里，排在时间轴下面；运行卡片出现、步骤变多、输入框长高，都在把舞台往上挤。其他类型的请求栏是浮在画布上的，不挤，但卡片会盖住内容且和请求栏连成一块 |
| 输入框不好直接收起、展开 | 我现在不想要它，能让开吗？ | 没有收起；CSS 里留着 `.prompt.collapsed` 但没人用 |
| 运行卡片和答案盖住刚改完的东西，又缩不得（信息多就大，大了就挡）；收起展开是全有或全无 | 我怎么一边看结果一边读它说了什么？ | 浮动的卡片最高占视口一半，盖在被改的画板、时间轴、指标卡上；只能关掉（答案没了）或整栏收起 |
| 看不见历史，分不清是不是新上下文 | 它记得我刚才说的吗？我之前问过什么？ | 只显示最近一次运行；每次 Claude Code 请求其实都是全新的 `claude -p`，快速 AI 也不带历史，但界面上没有任何地方这么说 |

## 2. 决定

六种类型用同一个面板（`PromptBar` 和 `AskClaude` 共用 `AgentBar.tsx` 的部件，第 3 条：一件事一个说法；跨类型功能只做一次）。

**位置：两处，由人选，默认在底部。**

- **底部（默认）**：原来的浮动栏，居中浮在舞台下沿，一直看得见输入框。运行卡片贴着栏的上沿，但平时只有一行（在做什么、怎么结束的、撤销）；鼠标移到栏上或光标在输入框里时才展开成完整卡片（请求回显、步骤、答案、改了哪些文件），点一下画面或移开就又收成一行。卡片只在人主动靠过去的时候才盖住舞台。
- **右侧**：栏头的"移到右侧"把同一个面板挪到右缘，之后"移到底部"挪回来。右侧的面板平时藏在屏幕右缘，只露一个小标签，图标显示 Claude 在跑、跑完还是失败；鼠标移到标签上，面板从右边滑出（临时盖在舞台和检查器上，不改变任何布局）；移开、点一下画面、按 Esc 就收回。

窗口窄于 1000 px 时放不下右侧，总是在底部。底部的栏还能收成药丸（栏头的收起按钮），药丸留在原位，运行状态照样看得见。

两处的"自动收起"是同一个意思，只是收的东西不同：底部收的是卡片（栏本身要留着输入），右侧收的是整个面板（输入框也在里面）。内容两处相同：栏头（作用范围、上下文标记、交给谁、历史、移动、钉住）、运行卡片或历史、输入框。底部时运行卡片和历史是栏的绝对定位子元素，向上展开，最高 `min(60vh, 380px)`，动效的槽位（`.mprompt`）固定高度；右侧时这些都不存在，面板占满高度，卡片和历史是它的正常内容，随面板滚动。

右侧自动隐藏的规则：

- **移上来才开，而且要停一下**：面板在鼠标进入标签约 0.12 秒后滑出，离开约 0.35 秒后收回，鼠标掠过画布右缘不会误触。隐藏时面板不接收鼠标事件，只有标签接收，所以它不会挡住右边的检查器。
- **光标在输入框里就保持打开**：键盘焦点在面板里时（`:has(:focus-visible)`）不收；点一下面板里的按钮不算，鼠标移开仍然收回。
- **点一下画面就收**：画板、幻灯片、场景都是 iframe，点击到不了编辑器的文档，所以用"选中项变了"和窗口失焦来判断，再加编辑器文档里的指针按下。底部栏的卡片也用同一个判断收成一行。
- **Ctrl/⌘ J** 把光标放进输入框（右侧隐藏时先打开，底部收成药丸时先展开）；输入框里按 Esc 放手。
- **运行结果不强行弹出**：跑的时候右侧面板不会因为状态变化自己打开，标签上的图标说明状态；打开才看到答案。底部的卡片一行始终可见。

位置记在本机（`dc.barMode`），各类型共用。右侧时面板挂在 `<body>` 上（portal），不在任何类型自己的布局里，所以六种类型一份实现。

**收起：** 右侧由自动隐藏取代了"点按钮收起"；底部保留药丸，状态存在 `localStorage`，刷新后保持。

**历史：栏头一个按钮，列表替换卡片位置。** 本次编辑器会话里发出的每条请求（快速 AI 和 Claude Code，手写 jQuery 不算），最新在上：状态、请求原文、时间、交给了谁，Claude Code 的还标"新对话"或"接着上次"。点一行把请求放回输入框（第 11 条：下一步的物件交到手上）。

**上下文：栏头一个标记，说下一条请求从哪里开始。**

- 快速 AI：标"每次从头开始"（不可点）。它只看当前文件和最近的改动，这是事实，不是开关。
- Claude Code：有可接的对话时标"接着：<上一条请求>"，点一下改成"新对话"，再点回来；没有时标"新对话"（不可点）。标记只对下一条请求有效，发出后回到默认。

"接着"是真的接，而且记在服务端（见下一节）：默认接着这个项目上一次的 Claude Code 对话（智能默认而不是开关，第 6 条）。来回改同一件东西是最常见的用法，要从头开始的人点一下标记。快速 AI 交给 Claude Code 的请求不接，因为那一条的上下文本来就是快速 AI 拼的。

**项目的对话由服务端保存，不是页面。**

问题：会话号原来只在编辑器页面的内存里（随事件传给页面、下一条请求再带回来）。刷新、换项目、在另一个窗口打开、用命令行或 MCP 发请求，都不知道有一段对话可接，于是每次都是新的 `claude -p`，上下文从头来；只有"成功完成"的运行才算可接，被停掉或超时的那一次（会话其实已经有了）也丢了；`--resume` 指向一个 Claude Code 已清掉的会话则直接失败。

决定：

- 会话号一出现（Claude Code 的第一条消息就带着）就写进项目文件夹的 `.claude-session.json`：`{ session, prompt, at }`。结果是完成、被停还是出错都不影响，因为对话已经在 Claude Code 那边存了。这个文件和 `.journal.jsonl`、`.runs.json` 一样属于这台机器：不提交、不进 .zip。
- 请求的默认就是接着它。请求里 `resume`（给定会话）优先，`fresh`（开新的）次之，其余接项目的。所以编辑器、`tingly-design prompt`、MCP 的 `prompt` 三条路是同一个规则，在任何窗口里都接得上；要新的就 `fresh`（栏头标记、`--new`、MCP 的 `new`）。
- 编辑器打开项目时问服务端要这段对话来显示"接着：…"标记，之后由运行事件更新；标记只管下一条请求。
- Claude Code 已经不认识这个会话（被清理了）：不让人看到一次失败再手动重发，服务端发现"找不到对话"且这次什么都没跑，就忘掉它、同一条请求改为新对话重试一次，运行记录里标成"新对话"。
- 一个项目一段对话。不按类型分，也不按画板 / 幻灯片分：上下文是"这个项目里我们在聊什么"，指向哪个文件已经随请求带过去。

## 3. 考虑过、没选的

- **一直钉在侧边、让出舞台宽度（像 Tingly Box 的 desk）**：对话有固定位置，但吃掉舞台的宽度，动效和幻灯片最需要宽度，1280 宽的窗口连同右侧检查器只剩约 600 px，画布上方的工具条会挤在一起；而最常见的用法是发一句、看一眼结果。试过一版，去掉了：右侧只做临时盖上去的自动隐藏，不占宽度。
- **只留浮在底部的栏，不动卡片**：原来的方案。运行卡片最高占视口一半，正好盖在刚被改的位置上（画布的画板、动效的时间轴、看板的指标卡）；信息要多就得大，大了就挡住。底部因此保留为默认（输入框一直在手边，最自然），但卡片平时只留一行；要从根上不占舞台，就给一个右侧的位置。
- **点击收起 / 点击展开的按钮**：全有或全无，每次都是一个要做的动作；改成由鼠标位置和焦点决定。
- **运行卡片留在栏里、只让动效例外地浮起来**：两套布局，以后每个类型还要想自己属于哪套。统一浮起，行为一致。
- **默认新对话，让用户自己点"接着"**：和现状最接近，但把"接着"变成每次都要做的动作；而用户反馈的恰恰是想看到它是不是接着的。
- **历史存在服务端、刷新后还在**：journal 已有文件级记录；请求历史只是编辑器会话内的清单，没有第二份持久状态要维护。（只有会话号需要跨刷新，所以只存它。）
- **会话号留在编辑器里，换窗口 / 刷新时让页面补上**：编辑器是唯一入口时够用，命令行和 MCP 一加入就各有一份，并且被停掉的运行带不进来；改成服务端一份。
- **默认新对话，CLI 和 MCP 保持"显式 `--continue` 才接"**：不改变现有调用的行为，但同一个项目里编辑器接着、命令行从头，用户会觉得"为什么这次不记得"；统一成同一个默认。
- **每个文件一段对话**：上下文跟着文件走听起来精确，但"把整个页面换成深色"这类请求跨文件，拆开后哪一段都不完整。

## 4. 跨类型

六种类型的栏是同一个 `RequestBar`（`RequestBar.tsx`）：运行卡片或历史、栏头、附件、输入框、发送 / 停止、提示，停靠和折叠都在这里。各类型只决定栏头写什么、请求交给谁：画布、幻灯片、动效用 `PromptBar`，栏头多了指向的元素和快速 AI / Claude Code 的切换；设计系统、看板、文档用 `AskClaude`，只交给 Claude Code。栏的外观仍按 `.prompt` 和 `.dsask` 两个 class 区分，这两套样式要等样式表按区域拆开后再合并。矩阵见 [project-kinds.md](./project-kinds.md) 的"请求栏面板"一行。

## 5. 还开着的问题

- **把一条回答留作画布上的便签**（#45 的后半）：和动效的批注（#44）重叠，等批注的形态定了再做。
- **一直钉住并留下对话记录**：已有方案——左侧一直打开的面板、记录存在服务端，见 [chat-panel.md](./chat-panel.md)；它也回答了下面"对话记录"和"请求历史不跨刷新"两条。
- **右侧作为检查器里的一个标签页**（属性 / 代码 / 微调 / 对话）：不占额外宽度，但对话和属性不能同时看，设计系统、看板、文档没有这个检查器，要各自再想办法；有人要长对话的固定位置时再考虑。
- **对话记录**：面板里仍只显示最近一次运行，更早的在历史列表里（只有请求，没有答案和步骤）。要让它真正成为对话，需要把答案和步骤存下来，并在服务端持久化。
- **和 Tingly Box 的 desk 对齐**：可能值得把对话视图抽成共用的 UI 包。
- **请求历史不跨刷新**：刷新或换项目后清空（"接着"的会话号不受影响，它在服务端）。
- **一个项目同时有几段对话**：现在只有一段，"新对话"会盖掉它。如果有人要在同一个项目里并行两件事（比如一个人改画布、另一个人改文案），再考虑给对话起名、可切换；等有人这么用了再做。
- **两个窗口同时发请求**：两条都接同一个会话号，Claude Code 各自分出一个分支，后结束的那条成为"项目的对话"。要不要串行排队，等遇到再说。
