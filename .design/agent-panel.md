# 请求栏的布局：不挡舞台、不用点开收起、看得见历史和对话上下文

状态：**已实施**（右侧边栏：边缘自动隐藏、钉住、浮动三种位置；运行卡片、请求历史、"新对话 / 接着"标记）。"还开着的问题"一节是没做的。

运行卡片本身的内容见 [agent-feedback.md](./agent-feedback.md)；这里只讲它放在哪里、怎么收、怎么翻、上下文是不是新的。

## 1. 问题

三个反馈其实是同一个面板的三个毛病：

| 反馈 | 用户在问 | 原来的样子 |
|---|---|---|
| 窗体随 agent 执行不断变动 | 我在看的东西为什么在动？ | 动效的请求栏在页面流里，排在时间轴下面；运行卡片出现、步骤变多、输入框长高，都在把舞台往上挤。其他类型的请求栏是浮在画布上的，不挤，但卡片会盖住内容且和请求栏连成一块 |
| 输入框不好直接收起、展开 | 我现在不想要它，能让开吗？ | 没有收起；CSS 里留着 `.prompt.collapsed` 但没人用 |
| 运行卡片和答案盖住刚改完的东西，又缩不得（信息多就大，大了就挡）；收起展开是全有或全无 | 我怎么一边看结果一边读它说了什么？ | 浮动的卡片最高占视口一半，盖在被改的画板、时间轴、指标卡上；只能关掉（答案没了）或整栏收起 |
| 看不见历史，分不清是不是新上下文 | 它记得我刚才说的吗？我之前问过什么？ | 只显示最近一次运行；每次 Claude Code 请求其实都是全新的 `claude -p`，快速 AI 也不带历史，但界面上没有任何地方这么说 |

## 2. 决定

六种类型用同一个面板（`PromptBar` 和 `AskClaude` 共用 `AgentBar.tsx` 的部件，第 3 条：一件事一个说法；跨类型功能只做一次）。

**位置：三种，同一份内容，由人选。**

| 位置 | 样子 | 什么时候 |
|---|---|---|
| 自动隐藏（默认） | 屏幕右缘一条小标签，中间的图标显示 Claude 在跑、跑完还是失败；鼠标移到标签上，面板从右边滑出；移开、点一下画面、按 Esc 就收回 | 宽度 ≥ 1000 px |
| 钉住 | 面板固定在右缘，编辑器让出 360 px 的宽度，不盖任何东西 | 要一直看着对话时 |
| 浮动 | 原来的底部浮动栏，收得成药丸 | 窗口窄于 1000 px 时自动采用；也可以手动选 |

面板内容三种位置相同：栏头（作用范围、上下文标记、交给谁、历史、钉住、浮动）、中间的运行卡片或历史、底部的输入框。浮动时运行卡片和历史是栏的绝对定位子元素，向上展开，最高 `min(60vh, 380px)`，动效的槽位（`.mprompt`）固定高度；停靠时这些都不存在，面板自己占满高度，卡片和历史是它的正常内容，随面板滚动。

自动隐藏的规则：

- **移上来才开，而且要停一下**：面板在鼠标进入标签约 0.12 秒后滑出，离开约 0.35 秒后收回，鼠标掠过画布右缘不会误触。隐藏时面板不接收鼠标事件，只有标签接收，所以它不会挡住右边的检查器。
- **光标在输入框里就保持打开**：键盘焦点在面板里时（`:has(:focus-visible)`）不收；点一下面板里的按钮不算，鼠标移开仍然收回。
- **点一下画面就收**：画板、幻灯片、场景都是 iframe，点击到不了编辑器的文档，所以用"选中项变了"和窗口失焦来判断，再加编辑器文档里的指针按下。
- **Ctrl/⌘ J** 把光标放进输入框（隐藏时先打开，浮动收起时先展开）；输入框里按 Esc 放手。
- **运行结果不强行弹出**：跑的时候面板不会因为状态变化自己打开，标签上的图标说明状态；打开才看到答案。这和"收起不等于看不到"（第 10 条）是同一个意思，只是入口从药丸换成了边缘标签。

位置记在本机（`dc.barMode`），各类型共用。面板挂在 `<body>` 上（portal），不在任何类型自己的布局里，所以六种类型一份实现，钉住时只靠 `.app` 的 `right` 让出宽度。

**收起：** 自动隐藏取代了"点按钮收起"这个全有或全无的动作；浮动形态保留药丸，状态存在 `localStorage`，刷新后保持。

**历史：栏头一个按钮，列表替换卡片位置。** 本次编辑器会话里发出的每条请求（快速 AI 和 Claude Code，手写 jQuery 不算），最新在上：状态、请求原文、时间、交给了谁，Claude Code 的还标"新对话"或"接着上次"。点一行把请求放回输入框（第 11 条：下一步的物件交到手上）。

**上下文：栏头一个标记，说下一条请求从哪里开始。**

- 快速 AI：标"每次从头开始"（不可点）。它只看当前文件和最近的改动，这是事实，不是开关。
- Claude Code：有可接的对话时标"接着：<上一条请求>"，点一下改成"新对话"，再点回来；没有时标"新对话"（不可点）。标记只对下一条请求有效，发出后回到默认。

"接着"是真的接：服务端把 Claude Code 报告的 `session_id` 随事件告诉编辑器，下一条请求带 `resume`，服务端用 `--resume` 启动。默认是接着上一次**成功完成**的运行（智能默认而不是开关，第 6 条）：来回改同一件东西是最常见的用法，要从头开始的人点一下标记。快速 AI 交给 Claude Code 的请求不接，因为那一条的上下文本来就是快速 AI 拼的。

## 3. 考虑过、没选的

- **一直钉在侧边（像 Tingly Box 的 desk）**：对话有固定位置，但吃掉舞台的宽度，动效和幻灯片最需要宽度；而最常见的用法是发一句、看一眼结果。所以侧边是默认的自动隐藏，钉住是人主动选的。
- **只留浮在底部的栏，再修补**：原来的方案。运行卡片最高占视口一半，正好盖在刚被改的位置上（画布的画板、动效的时间轴、看板的指标卡）；信息要多就得大，大了就挡住，没有出路，所以换成了不占舞台面积的位置。
- **点击收起 / 点击展开的按钮**：全有或全无，每次都是一个要做的动作；改成由鼠标位置和焦点决定。
- **运行卡片留在栏里、只让动效例外地浮起来**：两套布局，以后每个类型还要想自己属于哪套。统一浮起，行为一致。
- **默认新对话，让用户自己点"接着"**：和现状最接近，但把"接着"变成每次都要做的动作；而用户反馈的恰恰是想看到它是不是接着的。
- **历史存在服务端、刷新后还在**：journal 已有文件级记录；请求历史只是编辑器会话内的清单，没有第二份持久状态要维护。

## 4. 跨类型

画布、幻灯片、动效走 `PromptBar`；设计系统、看板、文档走 `AskClaude`，多出来的只是栏头一行。矩阵见 [project-kinds.md](./project-kinds.md) 的"请求栏面板"一行。

## 5. 还开着的问题

- **把一条回答留作画布上的便签**（#45 的后半）：和动效的批注（#44）重叠，等批注的形态定了再做。
- **钉住时的舞台宽度**：1280 宽的窗口钉住后，舞台连同右侧检查器只剩约 600 px，画布的上方工具条会挤在一起。可能的出路是把右栏上下分开（上检查器、下对话），或钉住时收起检查器；还没做。
- **对话记录**：面板里仍只显示最近一次运行，更早的在历史列表里（只有请求，没有答案和步骤）。要让它真正成为对话，需要把答案和步骤存下来，并在服务端持久化。
- **和 Tingly Box 的 desk 对齐**：可能值得把对话视图抽成共用的 UI 包。
- **历史不跨刷新**：刷新或换项目后清空；"接着"依赖的 session 也只在本次会话内已知。
- **`--resume` 失败**（Claude Code 清掉了旧会话）会显示为一次失败的运行，用户点"新对话"重发即可；还没有自动回退。
