# 文档的页面菜单：版式与主题

状态：**方案**（讨论中，未实施）。本文只描述现状、备选和推荐；代码、i18n 和文档界面都还没改。

## 1. 问题

文档顶栏有两个并排的页面级弹层：**版式**（Layout）和**主题**（Theme）。两者都改整份文档，也都在改字体；穿着设计系统时，版式里的字体开关不生效，却不说明原因。同时，文档没有右侧面板，"文档自己的样子"由主题卡片选择、却由版式定义，用户要在两个按钮之间拼出同一件事。问题不是"哪个按钮放左边"，而是这两个弹层该不该存在两个。

## 2. 现状（当前契约，代码和本机中文界面实测）

- 顶栏右侧顺序：字数、**版式**（`docs.app.layout`）、**主题**（`docs.theme.title`）、历史版本、导入 / 导出、评论、同步、更多（`DocsApp.tsx`）。
- **版式**（`DocsApp.tsx` 的 `Settings`，`.popmenu.settings`）：
  - 标题字体：无衬线 / 衬线（`doc.json` 的 `settings.headingFont`）
  - 正文字体：无衬线 / 衬线（`settings.bodyFont`）
  - 版面宽度：窄 / 标准 / 宽 / 通栏（`settings.width`，核心的 `DOC_WIDTH_COLUMNS` / `docColumnOf`；标准在穿着系统时取系统的 `doc-column`）
- **主题**（`DocTheme.tsx`，`.popmenu.doctheme`）：说明一句；"文档自己的样子"和每个已装主题的卡片；正在穿着哪一套；折起的"设计系统"（装入 / 移除）。文档的 `doc.json` 只存 `designSystems` 和 `theme`，颜色与字体在画的时候由 `docLook.ts` 解出。
- 六种类型里，只有文档把"作品的外观"和"页面尺寸"做成两个同级顶栏弹层；画布和幻灯片的页面级主题是右侧面板的"主题"标签页，元素级布局 / 文字 / 样式在检查器里；动效没有主题；看板和设计系统没有这一类菜单。
- 词：英文界面里文档的"版式"和检查器的"布局"都叫 Layout；中文界面是"版式"和"布局"。界面里没有一个字面叫"样式"的菜单：它目前指检查器里的文字样式，以及公众号预览顶部的状态行"样式：文档自己的样子 / 样式：WeChat"。

实测到的两个重叠：

| 情形 | 操作 | 结果 |
|---|---|---|
| 穿着 WeChat | 版式里正文字体 无衬线 → 衬线 | 计算样式前后都是 `-apple-system, …, "PingFang SC", …`，没有变化，也没有说明 |
| 穿着 Tingly Design System | 版式里正文字体 无衬线 → 衬线 | 前后都是 `Inter, Arial, sans-serif`，没有变化 |
| 不穿主题 / 穿 WeChat | 版式里宽度选"标准" | 页面宽 760 px / 805 px（WeChat 的 677 px 正文栏 + 内边距）；菜单只说"标准" |

原因是 `docLookFromSystem` 优先用系统的字体族，`[data-wears]` 的样式用 `--look-body` / `--look-head` 盖过 `data-bfont` / `data-hfont`；`docColumnOf` 在标准宽度下取系统的 `doc-column`。这两条都是有意的取值方式，问题在于界面没有把"谁说了算"说出来。

## 3. 考虑过的方案

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A · 合成一个"文档样式"弹层** | 顶栏只留一个调色板按钮；弹层按"主题 → 字体 → 页面"分组，第一组仍叫主题；主题给了字体时字体行只读并说明来源；标准宽度写出真实值 | 一个按钮回答"这份文档长什么样"；字体只有一个主人；失效控件变成解释；少一个顶栏按钮；公众号预览的"样式：…"和按钮同一个词 | 弹层更高；`docs.app.layout` / `docs.settings.*` 要并进新的 `docs.style.*`；"版式"这个词从文档里消失 |
| **B · 保留两个，改名、换序、说明依赖** | 主题在前、版式改名"页面"或"页面与字体"；主题给字体时字体行改说明；标准显示主题的真实栏宽 | 改动最小，现有弹层仍然短，e2e 结构基本不动 | 两个同级页面级按钮、靠猜分工、"自己的样子"被拆开这三件事都还在；顶栏仍多一个按钮 |
| **C · 按轴拆** | 主题管外观（含"自己的样子"的字体）；"页面"只留宽度（以后放页边距、语言） | 外观 / 版面两条轴最干净；字体永远只有一个入口 | 顶栏仍是两个按钮；"标准跟随主题正文栏"要么保留并解释，要么变成新开关（多一个开关）；改名和迁移比 A 多 |
| **D · 主题留在顶栏，页宽进编辑栏，字体归主题** | 顶栏只留主题；格式栏右端加一个紧凑的"页宽"选择（窄 / 标准 / 宽 / 通栏）；标题 / 正文字体放进主题弹层卡片下，穿主题时只读显示主题给出的字体 | 每个设置贴近它改的东西：页宽贴着页面，外观和字体在主题；顶栏少一个按钮；字体只有一个主人；不再有"版式 / 布局"同词 | 主题弹层更高；格式栏多一个控件，窄窗口本来就会换行（实测 700 px 已折成多行）；`docs.app.layout` / `docs.settings.*` 要重组 |

没有选"移到右侧面板"：文档刻意没有右侧面板，评论占用侧栏；为两个低频设置新造一个面板，是把"选模式再进入"又加回来。

## 4. 推荐

推荐 **D**（在用户指出"主题的位置没问题、宽度这些配置合到编辑栏"之后）：主题留在顶栏不动；页宽进格式栏；字体归主题。

```
顶栏      字数  [主题]  历史版本  导入 / 导出  …            ← 不再有"版式"
编辑栏    ↶ ↷ │ 正文 ▾ │ B I S │ 列表 引用 │ 表格 图片 ― │  页宽 标准 ▾
主题      [文档自己的样子] [WeChat] …   正在穿着 WeChat
          字体   标题 PingFang SC / 正文 PingFang SC（来自主题，只读）
          ▸ 设计系统（装入 / 移除）
```

- **页宽在编辑栏**：它改的是眼前的页面，放在"正文 / 加粗 / 列表"这一条的右端、用分隔线和块级格式隔开；打开时显示当前值（如"页宽 标准"），四个选项。编辑栏本来就是这类页面设置的落点，顶栏则回到项目级动作。
- **字体在主题**：主题自己的说明已经承诺"颜色、字体和圆角"；"文档自己的样子"这张卡片也应该能改自己的字体。穿着主题时字体行只读，写出来自哪套主题，不再出现按了没反应的开关。
- **顶栏少一个按钮**：版式按钮消失，主题位置不变。窄窗口下顶栏少 30 px；格式栏本来 `flex-wrap: wrap`，700 px 时已经折行，新增的页宽控件放到第一行右端（`margin-left:auto`），窄时才折到下一行。

理由对应 [ux-principles.md](./ux-principles.md)：设置贴近它作用的表面（#12）；按用户的问题分区（#1，"这一页多宽"在页面边，"这份文档什么样子"在主题）；一个词一个意思（#3，"版式 / 布局"的碰撞消失，"字体"只在主题）；具体值而不是别名（#5，页宽显示当前值，标准写出真实栏宽）；减少视觉噪声（#9，顶栏少一个常驻图标）。

如果用户希望**字体也留在编辑栏**，D 可以退成"编辑栏里的一个'页面'弹层"：页宽 + 标题 / 正文字体仍在格式栏右端打开，主题只负责颜色和圆角；那样需要保留"主题给字体时只读"的状态，否则又会回到按了没反应。

若只想先修"切了没反应"，**B 的第一步**（穿着主题时把字体行改成说明、标准写出真实宽度）可以先行，再决定是否走 D。

## 5. 和六种类型、窄屏、双语、明暗

- **六种类型**：只动文档。画布、幻灯片、动效的元素级布局 / 样式仍在检查器；画布和幻灯片的页面级主题仍是右栏"主题"标签；动效依旧没有主题。按 D 拆开后文档更接近"外观是一件事、页面几何是另一件事"，但不要求和其它类型长成同一张脸——文档没有右侧面板是既定选择（[cross-kind-consistency.md](./cross-kind-consistency.md) §P5 曾决定版式弹层不动，本文重新讨论版式的去向）。
- **窄屏**：`top-bar.md` §4 记录 900 px 以下中段不折叠。实测 700 px 时标题已让位，两个 30 px 按钮并排占中段；D 让顶栏少一个按钮。编辑栏本来就 `flex-wrap: wrap`，实测 700 px 时已折成多行；页宽控件放在第一行右端，窄时才折行，不会把块级格式挤走。
- **双语**：新增的键放在 `docs.page.*`（页宽）和 `docs.theme.font*`（字体），英文和中文一起写；"主题"作为顶栏按钮和弹层标题保留；编辑栏里的页宽用"页宽 / Page width"，不再出现"版式 / Layout"。
- **明暗**：弹层用编辑器 token，和现有 `.popmenu` 一致；卡片颜色仍由主题自己的值画。两种外观都要截图核对。

## 6. 还开着的问题

1. **字体放哪**：按 D 放主题（推荐，主题已经承诺字体，也能消掉失效开关）；还是也留在编辑栏的"页面"弹层里？
2. **页宽的形态**：编辑栏右端一个显示当前值的下拉（`页宽 标准 ▾`，推荐，窄屏最省地方），还是四个段平铺、或一个图标打开小弹层？
3. "标准"宽度继续跟随已穿主题的 `doc-column`（现状，D 里把真实值写出来），还是固定成文档自己的 677 px，把"跟随主题"做成另一件事？
4. 是否先按 B 修掉失效的字体控件，再等 D 的完整实现。
5. 画布 / 幻灯片是否也要一个"页宽 / 页面"式的入口，还是保持检查器 + 主题标签——这会影响跨类型的一致性目标，但不在本次改动内。
