# 文档的页面设置：页宽与字体

状态：**已实施**（文档顶栏、格式栏和主题弹层；e2e 在 `docs`、`doc_theme`、`export_menu`）。本文描述现在的契约、考虑过的方案和还开着的问题。

## 1. 问题

文档顶栏原来有两个并排的页面级弹层：**版式**（Layout）和**主题**（Theme）。两者都改整份文档，也都在改字体；穿着设计系统时，版式里的字体开关不生效，却不说明原因。同时，文档没有右侧面板，"文档自己的样子"由主题卡片选择、却由版式定义，用户要在两个按钮之间拼出同一件事。问题不是"哪个按钮放左边"，而是页面宽度、字体和外观各该归谁。

## 2. 现在的位置

```
顶栏      字数  [主题]  历史版本  导入 / 导出  …              ← 没有"版式"
编辑栏    ↶ ↷ │ 正文 ▾ │ B I S │ 列表 引用 │ 表格 图片 ― │  页宽 标准 · 677 px ▾
主题弹层  [文档自己的样子] [WeChat] …   正在穿着 WeChat
          字体   标题 PingFang SC / 正文 PingFang SC（来自主题，只读）
          ▸ 设计系统（装入 / 移除）
```

- **页宽在格式栏**：格式栏右端、与块级格式用分隔线隔开，一个显示当前值的下拉（窄 / 标准 / 宽 / 通栏）。它写 `doc.json` 的 `settings.width`，和以前是同一个字段、同一组取值。标准选项写出真实正文栏：`docColumnOf('standard', look.column)`，不穿主题或主题没有 `doc-column` 时 677 px，穿着有 `doc-column` 的系统时用系统的栏宽（WeChat 677 px）。下拉用 `docs.page.width`，选项 `docs.page.narrow` / `standardPx` / `wide` / `full`；`DocsApp.tsx` 的 `Toolbar`，`data-page-width`。
- **字体在主题**：主题弹层卡片下面一组"字体"，`DocTheme.tsx` 的 `ThemeFonts`。没有穿主题（或穿的主题不给字体）时，标题 / 正文各一组无衬线 / 衬线，写 `settings.headingFont` / `settings.bodyFont`；穿着给字体的主题时，这一行只读，显示主题实际用的第一个字体名（跳过 `-apple-system`、`system-ui` 这类系统别名），并说明"要自己选，先回到文档自己的样子"。判断"主题给字体"用 `dsGlance(tokens, theme).headingFont` / `.bodyFont`；两个可以各自只读。主题自己的说明早就写着"颜色、字体和圆角"，字体从此归它。
- **顶栏只剩主题**：`docs.app.layout` 和 `Settings` 弹层删除，`LayoutCols` 图标随之删除；主题按钮的位置、卡片和装入流程不变。
- **宽度和原值的关系不变**：`docColumnOf`、`DOC_WIDTH_COLUMNS`、导出和 PNG 的视口仍读 `settings.width` 和 `look.column`；微信公众号的文章仍用平台栏宽，预览里的"宽度不会带过去"改用 `docs.page.*` 的词。
- **i18n**：`docs.page.*`（页宽和标准 px）与 `docs.theme.fonts` / `headingFont` / `bodyFont` / `sans` / `serif` / `fontsHint`；`docs.settings.*` 和 `docs.app.layout` 删除，英文和中文一起改。

## 3. 考虑过的方案

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A · 合成一个"文档样式"弹层 | 顶栏只留一个调色板按钮；弹层按"主题 → 字体 → 页面"分组 | 一个按钮回答"这份文档长什么样"；字体只有一个主人 | 弹层很高；页宽放进"外观"里，离页面远 |
| B · 保留两个，改名、换序、说明依赖 | 主题在前、版式改名"页面"或"页面与字体"；主题给字体时字体行改说明 | 改动最小 | 两个同级页面级按钮、靠猜分工、"自己的样子"被拆开都没解决 |
| C · 按轴拆 | 主题管外观（含字体），"页面"只留宽度 | 两条轴干净 | 顶栏仍是两个按钮；改名和迁移 |
| **D · 选中的方案** | 主题留在顶栏；页宽进格式栏；字体归主题 | 每个设置贴近它改的东西；顶栏少一个按钮；字体只有一个主人；不再有"版式 / 布局"同词；失效开关变成只读说明 | 主题弹层更高；格式栏多一个控件，窄窗口会换行 |

## 4. 为什么是 D

对应 [ux-principles.md](./ux-principles.md)：设置贴近它作用的表面（#12，"这一页多宽"在页面边，"这份文档什么样子"在主题）；按用户的问题分区（#1）；一个词一个意思（#3，"版式 / 布局"的碰撞消失，"字体"只在主题）；具体值而不是别名（#5，页宽显示当前值和标准的真实 px，只读字体显示 PingFang SC 而不是 `-apple-system`）；减少视觉噪声（#9，顶栏少一个常驻图标）。

## 5. 和六种类型、窄屏、双语、明暗

- **六种类型**：只动文档。画布、幻灯片、动效的元素级布局 / 样式仍在检查器；画布和幻灯片的页面级主题仍是右栏"主题"标签；动效依旧没有主题。文档没有右侧面板是既定选择（[cross-kind-consistency.md](./cross-kind-consistency.md) §P5）。
- **窄屏**：顶栏少一个按钮。格式栏本来就 `flex-wrap: wrap`，页宽那一组放在第一行右端（`margin-left: auto`），窄时折到下一行；实测 700 px 时格式栏已折成多行，新增组不会把块级格式挤走。
- **双语**：英文 `Page width` / `Standard · 677 px` / `Fonts` / `Faces come from …`，中文 `页宽` / `标准 · 677 px` / `字体` / `字体来自 …`。
- **明暗**：页宽下拉和字体组用编辑器 token，和现有格式栏、主题弹层一致；主题卡片的颜色仍由主题自己的值画。

## 6. 还开着的问题

1. 画布 / 幻灯片没有页宽入口，主题仍在检查器；是否也要一个"页宽 / 页面"式的入口，不在本次改动内。
2. 一个主题只给标题或只给正文字体时，另一行仍可编辑（按 `dsGlance` 的 `headingFont` / `bodyFont` 分别判断）；这种半只读状态是否要合并成一条说明。
3. "标准"继续跟随已穿主题的 `doc-column`（现在如此，下拉写出真实 px），还是固定成文档自己的 677 px、把"跟随主题"另做。
4. 格式栏在 700 px 以下折行后，页宽控件会落到下一行；是否值得在更窄时收成一个图标。
