# 文档导出为 Word

状态：**已实施**。入口在 [export-menu.md](./export-menu.md) 的文档一行；文本来源和取舍沿用 [docs-markdown.md](./docs-markdown.md)。

## 1. 问题

上游 Docs 能导出 Word、Google Docs 和 Notion。这里只有 PDF、Markdown、HTML、PNG。要把一份文档交给不用本工具的人（客户、同事、评审），对方多半要一个 Word 文件：能改、能批注、能打印，也能在自己的工具里接着用。

## 2. 决定

- **Word 做成原生文件，在浏览器里生成，不依赖服务。** `@dc/export/docx` 的 `markdownToDocx` 读 Markdown（用 `marked`，编辑器本来就有它），把每种块和行内样式写成 Word 对应的元素：标题（`Heading1–6`，能进导航窗格）、段落、粗体 / 斜体 / 删除线 / 行内代码 / 链接、高亮和文字颜色、真编号的有序和无序列表（每个有序列表从自己的起点开始）、任务列表、引用、代码块、表格（表头行、对齐）、分隔线、图片。同一份文本得到同样的字节（zip 时间固定）。
- **输入是导出 Markdown 的同一份文本**（`docToMarkdown`），不另写一条从编辑器文档走的路：文档标题成 `#`、标签页成节、标题层级理顺、`==高亮==` 已写成 `<mark>`，这些在 Markdown 导出里已经定过，Word 只是换一种写法。两个导出因此不会各自漂移。
- **文档的外观跟着走**：标题和正文字体（无衬线 / 衬线）、语言（中文文档设东亚字体和语言）、A4 版面（和 PDF 一致）；文字颜色用 core 的名字表里的浅色值（Word 是白底）。
- **图片**：PNG / JPEG / GIF 原样放进去，按像素尺寸（96 dpi）排，超过版心宽度就等比缩小。SVG（项目里的图示常是 SVG）Word 靠不住，编辑器先在页面里画成 2 倍的 PNG，按原尺寸排。读不到或画不出的图留成方括号里的说明文字，提示里说有几张。
- **整篇一项**，不做“当前标签页”变体：要发出去的是整份文档；只要一个标签页的文字，用 Markdown。菜单项的说明里写明“Google 文档从 Drive 打开 .docx”。
- **命令行** `export --as docx` 跑菜单的同一项。

## 3. Google Docs 和 Notion：为什么不直连

两者的写入都要登录、授权、一个能调用它们 API 的宿主；本工具单机运行，没有这样的宿主，做出来也是一个没人能用的按钮。而它们本身已经有入口：Google 文档能直接打开 .docx（传到 Drive 即可），Notion 能贴 Markdown。所以：

- Google Docs：导出 Word，文档指南里写明。
- Notion（以及 GitHub、聊天）：菜单里的“复制为 Markdown（当前标签页）”，一步放进剪贴板；浏览器不让写剪贴板时改为下载 .md，提示里说明，不安静失败。图片只留文件路径（剪贴板放不了文件）。
- 等有了宿主（嵌在 Tingly Box 里时可能有），再考虑直连。

## 4. 没做 / 还开着

- **会自己画的代码块**（Mermaid、KaTeX、CSV）：Word 里留成代码文字。Mermaid 画出的 SVG 用 `foreignObject` 放文字，转成 PNG 要靠浏览器自己的 SVG 渲染，各浏览器的结果不保证一致，没有试过；价值也不够大，先不做。想要图的人用 PDF 或 PNG。
- **表格里的合并单元格、嵌套表格、数学公式对象**：Markdown 没有，不是丢的。
- **评论**不导出，同 Markdown。
- **Word 里的评审留痕（修订、批注）** 不写：导出的是成品。
- **验证**：生成器的单元测试看包的结构和每种元素；渲染用 LibreOffice 转 PDF 看过（标题、列表、表格、引用、代码、中文、图片）；真 Word 没有验过，已知 Word 对元素顺序严格，所以段落和表格属性按 schema 的顺序写。
