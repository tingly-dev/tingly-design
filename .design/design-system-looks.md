# 设计系统的起点：风格（looks）

状态：**已实施**（颜色、字体、圆角、阴影，以及一组组件和封面）；DESIGN.md / tokens.css 导入是**方案**，见 §6；和原版的还原度怎么量、差在哪见 §5。调研在 `.research/opendesign.md` 第 3 部分。

## 1. 要解决的问题

新建设计系统只有一个小的中性起点，用户要从空白开始自己填颜色、字体和圆角。OpenDesign 有 151 个品牌设计系统和 html-ppt 的 36 个主题，用户一上来就能挑一个"感觉对"的再改。我们要的是同样的"更快用起来"，但不照搬它的整套库。

## 2. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 拿什么 | 只拿 html-ppt 的 36 个 CSS 主题（MIT，© 2026 lewis） | 它们是统一的 `:root` 变量，几乎就是 `tokens.json`；许可明确。151 个品牌包是第三方品牌的描述，授权和商标没核实，不内置 |
| 怎么进来 | `scripts/import-looks.mjs` 从主题文件生成 `packages/core/src/looks.data.ts`（只存数值），`looks.ts` 把它变成 `tokens.json` | 不搬它的代码；重新生成就能跟上游 |
| 一个风格带什么 | 颜色（一套主题，亮或暗）、字体族（sans、display，以及 serif、mono）和要托管的字体（serif、mono 只在主题用到时托管）、圆角、阴影；文字样式和间距用通用的；外加 `components/` 下的一组组件和封面（§4） | 原主题的变量只有这些；它的"性格"（粗描边、硬阴影、渐变字、发光）在主题自己的 CSS 规则里，靠组件带过来 |
| 阴影里的颜色 | 原主题的 `var(--accent)` 换成我们的颜色名 | `shadow` 允许 `var(--颜色名)`，阴影跟着主题走 |
| 分组 | 干净明亮、编辑出版、大胆活泼、科技感、编辑器配色，各风格只属于一组（`import-looks.mjs` 里的 `GROUPS`） | 36 个平铺没法挑；按"感觉"分，用户问的是"我要什么感觉" |
| 在哪里选 | 新建对话框选"设计系统"后出现"从一个风格开始"：左边是分组（空白在最前，默认），右边是该组的风格，每个用自己的页面色、文字色、强调色和字体画一个小样；命令行 `new design-system --look <id>`，MCP `open` 的 `look` | 和新建画布选尺寸是同一种交互；空白是默认，不多问一步 |
| 名字 | 风格保留原始英文名（`ds.look.<id>`，中文直接复用英文定义）；分组仍按界面语言显示（`ds.lookGroup.<group>`），测试查不能缺、不能多 | 名字标识来源，不随语言改名 |
| 许可 | 生成的 README 写明来源和 MIT 版权行 | MIT 要求保留 |
| 直接装入 | 新建画布、幻灯片和面板的装入入口共用 `DesignSystemPicker`；项目系统照常列出，36 个模板放在默认收起的“内置”里，展开后按感觉分组，选中后收起。即使没有项目系统也可选 | 不先建一个设计系统，不一次铺开全部模板 |
| 副本与来源 | `POST …/design-systems` 接受 `{from}` 或 `{look}`，二者互斥。内置模板直接生成 tokens，复制到 `ds/look-<id>/tokens.json`，来源记 `builtin:<id>`，幻灯片同样注册托管字体；重复装入替换同一条记录，移除走现有接口 | 不增加项目文件夹，之后的 token 使用、归档和移除沿用现有流程 |
| 之后 | 建好就是用户自己的系统，不保留和原风格的链接 | 风格是起点；要换风格就新建 |

## 3. 取舍

- 不另存一份"风格"文件夹：36 个风格以数据形式在核心里，不增加 36 个示例项目。
- 数值取自原主题；只拿变量的话，bauhaus 和 minimal-white 在我们这里几乎分不出来（#226）。所以组件把主题自己的规则也带过来。

## 4. 组件

| 问题 | 决定 | 为什么 |
|---|---|---|
| 哪些组件 | html-ppt 自己有的：Title（展示字体标题，可带一段渐变字）、Kicker（眉题，`quiet` 更淡）、Card（`soft` / `outline` / `accent`）、Pill（`accent`）、Divider（`accent`），分在"文字""容器""标签"三组 | 只搬原版真有设计的东西；按钮、输入框原版没有，凭空画就不是这个风格了 |
| 样式从哪来 | 生成器读 base.css（排版、卡片、标签、分隔线的规则和默认变量）和主题文件里 `:root` 之外的规则，类名改成 `lk-*`，变量名改成我们的颜色名，规则里写死的颜色若等于主题的某个颜色就换成那个 token（按属性挑：背景先找 surface，文字先找 ink，描边先找 line），存进 `looks.data.ts` 的 `css` / `vars`；主题给 `.slide` 的规则改到 `.lk-page`（我们的"一页"，封面就是一页）；翻页、页眉页脚、备注、进度条、悬停这些 deck 本身的规则丢掉 | 主题的性格就在这些规则里；改名避免和用户的类撞上 |
| 落到哪 | `lookKit()` 写出 `components/bundle.css`（风格变量、base 规则、主题规则）、`bundle.js`（不用 React，每个组件返回一个元素，文字只当文字放）、`index.d.ts`、每个组件的 README 和预览、`Cover/preview.html` | 就是设计系统已有的组件格式，组件页和封面不用改。安装到画布或幻灯片只带 tokens 和字体，和其他设计系统一样，组件留在设计系统里 |
| 封面 | 原版演示页的样子：眉题、标题、导语、三张卡片（色板、渐变指标、强调卡片）、一排标签 | 打开设计系统第一眼就是原版的效果 |
| 文案 | 预览和 README 的字在 `starter.lookKit.*`，用新建者的语言写 | 和其他起始文案一样 |
| 组件之后 | 和其他设计系统的组件一样，用户可以改；`bundle.css` 里的变量和规则也是用户的 | 风格是起点 |

## 5. 还原度：带什么规则，怎么量，哪里故意不同

**带过来的规则和原因**：

| 原版的规则 | 我们的处理 | 为什么 |
|---|---|---|
| 主题写在 `.slide`、`.slide::before` 上的（swiss-grid 的网格线、news-broadcast 的左侧红条、retro-tv 的扫描线、japanese-minimal 和 pitch-deck-vc 的留白） | 改名为 `.lk-page`，一页的外观；base.css 里 deck 定位用的 `.slide`、`.slide.is-*`、`.slide-number` 不带 | 这些是风格的一部分，不是翻页机制 |
| base.css 的 `*{box-sizing:border-box}` | 只给 `lk-` 元素和一页、预览里的元素 | 尺寸要和原版一样，又不能改到用户自己的元素 |
| base.css 的裸 `h3`、`h4` | 只在 `.lk-page`、组件预览和 `.lk-card` 里生效（`:where()`，不抬高优先级） | 卡片小标题要和原版同样大小，但不该改写用户页面里的标题 |
| 字体变量互相引用（`--font-display: var(--font-sans)`） | 生成时解开 | tokens.json 的字体栈不能是 `var()` |
| 规则和渐变里写死的颜色 | 等于主题某个颜色的换成那个 token，按用途挑（背景先找 surface，文字先找 ink，描边先找 line，渐变先找 accent） | 改 token 时整个风格跟着变 |
| 封面的留白 | 封面固定 56px 64px，不用主题按 1920px 幻灯片定的留白 | 封面卡片只有约 960px 宽 |

**怎么量**：`scripts/audit-looks.py <html-ppt 目录>`（要开着 `pnpm dev`）。它从每个风格新建一个系统，把 html-ppt 演示稿的前两页原样换成 `lk-` 类名，只加载这个系统的 `tokens.css` 和 `components/bundle.css`，和原版同尺寸（1920×1080）各截一张，逐像素算平均差（0–255）。另外再算一遍"把页面盖上一层纯色"后的差，也就是原版 deck 的画法。

**现在的结果**：30 个风格两页的平均差都不超过 1，余下是字体抗锯齿。

**故意不同的 6 个：aurora、vaporwave、y2k-chrome、glassmorphism、cyberpunk-neon、retro-tv（平均差 14–35）**。这 6 个主题把招牌效果画在 `body` 的背景上：极光光晕、蒸汽波落日、铬金属反光、玻璃背后的色块、霓虹和复古电视的暗角。html-ppt 自己的 deck 外层 `.deck{background:var(--bg)}` 是一块纯色，把这些背景整个盖住了，所以原版演示稿里看不到它们。把我们的页面也盖上纯色后，平均差降到 0.1–2.9，说明其余部分一致。我们让背景露出来（YZ 选的）：这是主题作者要的效果，也是"一眼看出风格"要的东西；代价是和原版演示稿的截图不同。

**不带过来的**：动画（html-ppt 另有一套 `anim-*`，属于动效，不属于设计系统的外观）、卡片悬停（`card-hover`）、页眉页脚和页码（deck 的部件）。

## 6. 还开着的问题

- 概览的小样（`Specimen`）只用 tokens 画，描边粗细、渐变字、发光在那里看不到；它下面就是真实的封面，所以留着它做浅色 | 深色的对照。启动页卡片已经改画封面，见 [design-system-glance.md](./design-system-glance.md)。
- **导入 DESIGN.md / tokens.css**：用户自己带来的文件转成 `tokens.json`，说明文字进 README；不内置品牌包。
- 风格的名字目前直接沿用原主题名；`catppuccin`、`dracula` 等编辑器配色是别人的配色方案，名字只用于标明出处。
