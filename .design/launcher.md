# 启动页：项目卡片、分组与列表视图

状态：**已实施**。测试是 `e2e/launcher.py`。

## 1. 要解决的问题

一列标题加一个类型下拉框的起始页，五种类型混在一起、看不出里面是什么，新建时要先想好类型。启动页要回答的是用户此刻的三个问题：**我上次在做什么、我有哪些东西、我要新建什么**。

## 2. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 一个项目怎么呈现 | 卡片：标题、类型、一个"有多大"的数（几个画板、几页、几个组件、几个数据集、几个标签页）、修改时间、预览 | 一个数比一串元数据好扫 |
| 预览 | 画布和幻灯片：在沙箱运行时里**实时渲染**打开的画板 / 封面（只读，滚到视口附近 200 px 才加载）；设计系统：有封面就实时画封面（带组件样式），没有就用它自己的颜色、字体和圆角画样张，下面是字体和色板（见 [design-system-glance.md](./design-system-glance.md)）；看板：数据集标题；文档：标签页大纲和第一段 | 实时渲染最像"打开后看到的"；其余三种的内容不是一张图，画摘要更有信息量 |
| 预览太大 | 源码超过 200 KB 只画画板位置的缩略图（`MAX_PREVIEW_SOURCE`） | 启动页不能因为一个大项目卡住 |
| 卡片数据从哪来 | 服务端 `GET /api/projects` 返回 `ProjectCard`，由 `packages/core/src/launcher.ts` `projectCard` 按类型算 | 前端不必为每张卡片读一堆文件 |
| 找项目 | 全部 / 每种类型的标签（带数量）、搜索（标题、文件夹、类型、分组；`/` 聚焦，Enter 打开第一个）、按最近或名称排序、方向键在卡片间移动 | |
| 项目多了怎么办 | 分组、列表视图、改标题，见 §3 | |
| 回到上次 | "继续上次的"链接和"最近打开"标记，记在浏览器 `localStorage`（最多 20 个） | 最常见的动作放最前；这是每个浏览器自己的便利，不需要服务端 |
| 新建 | "新建项目"菜单里选类型，对话框里填标题（对话框里也能换类型） | 不先问"哪种类型"再给空白表单，类型和例子在对话框里摆出来 |
| 新建对话框 | 类型是一排小标签，只展开选中那种的一句简介；标题可以不填；文件夹是一个预填好的字段（`projects/…`），跟着标题自动起名，人一点进去或输入就停下跟随——写名字放在 `projects/`，写完整路径就建到那里 | 文件夹不该是第二个必填项：预填、可改、可不碰。但它得一眼可见、可直接输入，因为同一个字段收完整路径，藏在一个链接后面就没人发现 |
| 新建画布、幻灯片、动效时的尺寸 | 共用标题下面的分类选择器：屏幕、演示、社交与封面、网页广告、打印、更多比例、自定义；分类在左，具体名称、像素值和比例小样在右，选中值的用途在下面。`BOARD_SIZES` 是共用表；宽高各为 1–7680。画布默认 1200×760，幻灯片默认 1920×1080，动效记上次值和“你的尺寸”。详情见“统一尺寸选择：当前契约” | 同一件事用同一个控件；选尺寸不是创建的必经步骤，默认值可直接创建 |
| 新建设计系统时的起点 | 选了"设计系统"，标题下面左边是分组（空白、干净明亮、编辑出版、大胆活泼、科技感、编辑器配色），右边是该组的风格，每个用自己的颜色和字体画小样；空白是默认 | 见 [design-system-looks.md](./design-system-looks.md) |
| 新建时的可选项 | 标题下面按类型多一块"起步选项（可跳过）"，都不填也能直接创建：画布是设计系统，幻灯片是设计系统，看板是一个数据文件（CSV、TSV、JSON，放进 `data/` 并建好数据源）；画布、幻灯片、动效共用标题下面的尺寸分类选择器，见下述尺寸契约。设计系统（类型）和文档没有要先问的事，不显示这一块。选了设计系统就在创建后装进去，出错时项目照样建好，用提示说明哪一步没成 | 第 6 条：这些选择原先只能进项目以后再做，起始页已经写好了，agent 也是从那个起点开始的；第 2 条：同一块、同一个位置，不为每种类型各做一个向导。设计系统只有画布和幻灯片能装（`install` 只收这两种），动效、看板、文档要不要支持是另一件事，没有一起做 |
| 文件夹名从哪来 | 跟着标题走；标题里没有字母或数字（中文标题）时用类型名；已被占用时顺延 `-2`、`-3`，不报错 | 原先中文标题直接被拒绝，要人去想一个英文文件夹名。自动生成的名字不该让人解决冲突；只有人自己改的名字才校验并提示 |
| 窄屏 | 手机宽度不横向滚动 | |

## 3. 分组、列表视图、在启动页上改项目

问题：项目一多，大卡片一屏只有两排，"新建"区又占掉顶部；系统给的类型分类之外，人没有自己的归类；改个标题还得先打开项目。

| 问题 | 决定 | 为什么 |
|---|---|---|
| 分组是文件夹、标签还是别的 | **单层分组，一个项目至多属于一个分组**，只是启动页上的归类，磁盘上仍是平的 `projects/<name>/` | 磁盘文件夹会让 `?p=`、委托给 Claude Code 的路径、宿主的 `tingly-design:open`、`uploads/` 引用全部按"平的项目名"设计的东西失效。多标签最灵活，但每个项目都要管一组标签，"项目太多"的难处是找和整理，标签把整理变重了 |
| 分组存在哪 | `projects/.groups.json`（项目目录之外，服务端读写，`{ 文件夹名: 分组名 }`） | 写进每个项目自己的索引要改六种格式的解析器，还会算作一次编辑，把项目的"最近修改"顶到最前，"最近"排序就乱了。代价：把项目文件夹拷走，分组不跟着走。分组是"我怎么整理工作区"，不是项目本身的属性 |
| 类型和分组 | 两条独立的轴：类型标签页不变，分组是另一条轴 | ux-principles 第 4 条。不把两者混成一个列表 |
| 没有分组时 | 界面和以前一样，没有分组栏位、没有空状态 | 第 6 条。第一次把项目放进分组之后才出现分组标题 |
| 怎么建分组、怎么删 | "移到分组"菜单里选已有的，或直接输入新名字回车；分组里最后一个项目被移走，分组自动消失。没有"管理分组"页 | 第 2 条。分组是项目的属性，不是要单独维护的对象 |
| 分组怎么显示 | 有分组时，"全部项目"按分组分段，每段一个可折叠的标题（名字、数量），没分组的放最后；段按段里最近改过的项目排，按名称排序时按名字。折叠状态记在 `localStorage`。搜索时拉平，不分段，列表里多出"分组"列，卡片上写分组名 | 正在做的分组总在最上面；搜索要的是命中，不是结构 |
| 新装时的示例 | 第一次种下示例时，`seedSamples` 同时写好 `projects/.groups.json`，把每个示例放进默认分组 `tingly-design`；示例本身不带任何点文件（日志、运行记录、Claude Code 会话、对话记录都属于这台机器），分组文件是种下时现生成的，不是仓库里提交的一份 | 新用户自己的项目不会和示例混在一起，示例一眼能整体折起来。不提交 `.groups.json`：开发时 `projects/` 就是用户自己的工作区，提交的分组会把启动页变成分段，还会被测试清理掉；分组是整理方式，不是示例的属性。示例里的会话文件不随包发布：含本机路径和个人对话 |
| 词 | 叫"分组"（Group），不叫"文件夹" | 第 3 条。"文件夹"已经指 `projects/<name>`（新建对话框的位置字段） |
| 卡片和列表 | 工具栏一个分段控件切换，记在 `localStorage`，默认卡片。列表一行一个项目：类型图标和标题、`projects/<name>`（等宽，真实值）、分组（仅搜索时）、内容量、修改时间；点"名称""修改时间"列头排序；**没有实时预览** | 32 个项目卡片一屏看不完；列表一屏看十几个，也不用为每一行起一个 iframe。预览是卡片的事 |
| 控件放哪 | 页头只放"这是谁、我要新建、外观和语言"；搜索、排序、卡片/列表切换放在项目列表自己的标题行（"全部项目"）右边 | 这几个控件作用在下面那个列表上，放在页头离它太远；页头回答"我要新建什么"，列表标题行回答"我要找哪个" |
| 新建入口 | 只有页头的"新建项目"按钮，点开是一个菜单：六种类型，分隔线，然后“导入 HTML 或 SVG…”、“导入 PowerPoint（.pptx）…”、“导入 Markdown（.md）…”、“导入项目包（.zip）…”以及可用时的“打开文件夹…”；每一项前面是和首页磁贴同一套的类型色小图标块（图标底色加类型色），所以菜单里一眼分得出类型，不是一列灰图标。没有整行的新建磁贴 | 一整行七个磁贴大多数时候只是为了点"新建项目"而占的位置；菜单一次点击就到类型。最初的磁贴是为了新用户一眼看到类型和例子，但新建对话框里同样有类型和例子，两处重复。按某个类型筛选时，列表末尾仍有该类型的新建磁贴，因为这时位置已经说明了意图 |
| 改项目 | 每张卡片和每行末尾有一个常显的"⋯"（灰色小按钮），菜单里是"重命名"和"移到分组"。"⋯"是卡片的兄弟元素，不在卡片这个按钮里面 | 整理动作要一眼找得到：最初只在悬停时显示，结果人根本不知道可以分组，也没人会想到右键。代价是每张卡多一个小图标，选了可见而不是少一点噪声（第 9 条让步于可发现性）。按钮嵌按钮是无效的 HTML，键盘和读屏会乱 |
| 重命名 | 只改标题，不改文件夹名；`PATCH /api/projects/:p` 按类型改对应索引文件的 `title`（`INDEX_FILE`），走写回：进日志、编辑器里开着的项目会同步看到新标题 | 文件夹是实现细节（见新建对话框）；改文件夹名会让 `?p=` 和引用失效 |
| 移到分组的撤销 | 提示条上有"撤销" | 第 10 条。整理应该可以随手试 |

没做的：删除项目（需要回收站和撤销，另议）、多选批量移动、拖拽到分组标题。编辑器里的项目菜单（`ProjectMenu`）还是按最近排，不按分组。

## 4. 和其他功能的关系

- **离开项目**：进了编辑器之后不必回启动页才能换项目，见下面"项目菜单"。
- 外观（主题）和语言是启动页上两个相邻的按钮。语言按钮直接写出当前语言，原先藏在外观菜单里，换语言的人找不到。
- logo 是 GitHub 主页的链接（新标签页打开）。启动页底部有两个安静的文字链接：反馈问题（指向新建 issue 的选择页，所以仓库有 issue 表单时会先看到表单）和在 GitHub 上点星。它们是页脚，不是横幅，没有计数、没有弹窗、不会因为"用了多少次"而出现。

- 外观菜单（主题）只放在启动页，见 [theming](../docs/zh/theming.md)。
- 导入表格（`.csv`、`.tsv`）是第四个直接动作，也认拖放：文件建成一个新看板，原文件放进 `data/` 并建好数据源，与新建对话框里的“数据文件”选项走同一段 `applyNewOptions`；不弹确认，因为一个表只可能是看板的数据，名字取自文件名。`.json` 不认拖放，因为单个 JSON 文件也可能是别的东西，要用 JSON 起步就在新建对话框里选。
- 导入 PowerPoint、Markdown、项目包和表格是四个直接动作，各自打开只筛选该格式的文件选择器（Markdown 同时接受 `.md` 和 `.markdown`；项目包接受 Tingly Design 和 Claude Design 的 `.zip`）。提示分别说明新建幻灯片、新建文档和打开项目包，不把三种意图藏在“导入项目”下，也不再加格式选择对话框。`chooseProjectArchive(format)` 仅限定 picker 的 accept，仍共用 `importProjectFile` 和服务端内容检测；拖放识别不变。
- 导入 HTML / SVG 的入口在启动页（`ImportDialog`），导入结果是一个新画布，见 [import-external-material.md](./import-external-material.md)。
- 打开项目文件夹之外的项目、把新项目建到任意位置："新建项目"菜单最后一项"打开文件夹…"，新建对话框的位置字段也收完整路径，见 [project-folders.md](./project-folders.md)。
- 嵌入时宿主可以用 `tingly-design:open` 直接打开项目，跳过启动页，见 [embedding](../docs/zh/embedding.md)。

## 5. 项目菜单：编辑器里的出口

每种类型的编辑器都有同一个控件 `ProjectMenu`，在共用顶栏（[top-bar.md](./top-bar.md)）的最左：一个直达启动页的"首页"按钮，和旁边一个菜单。菜单里是：全部项目、其他项目（和启动页同样的排序，最近打开的在前，最多 8 个）、新建项目（和启动页是同一个对话框，默认类型是当前项目的类型）、AI 模型设置。反馈问题和点星不在这个菜单里，在顶栏最右的"更多"（⋯）菜单里。

| 取舍 | 决定 | 为什么 |
|---|---|---|
| 回首页是一次点击还是两次 | 首页是单独的按钮，不藏在菜单里 | "回首页很难"是最初的抱怨；菜单是给"去别的项目"用的 |
| 项目名要不要放进这个控件 | 不放 | 各类型的标题已经是可以重命名的控件，一个控件两种含义（改名 / 切换）会互相抢点击 |
| 在哪里 | 共用顶栏的最左，六种类型都是窗口左上角同一个位置 | 以前没有共用的栏，组件共用、位置各自；现在栏也共用 |
| 反馈入口放哪 | 顶栏最右"更多"（⋯）菜单的头两行；不做悬浮按钮，也不放进项目菜单 | 项目菜单是"去别的项目"，混在一起没人找得到；顶栏上一个固定位置，低频入口不占常驻图标 |
| 项目列表什么时候取 | 打开菜单时才取 | 不为一个多数时候用不到的列表在每次进入编辑器时多发一次请求 |

## 6. 加一种类型时

启动页是最容易漏的地方：`kindOf` 认不出的目录不会出现在列表里，也不报错。要动的是 `ProjectPreview`、`projectCard` 和 `INDEX_FILE`（core，重命名要知道标题在哪个文件）、`KINDS` 和图标（`launcher/kinds.tsx`）、`Preview`（`launcher/Preview.tsx`）、`POST /api/projects` 的白名单（server），完整清单见 [project-kinds.md](./project-kinds.md) §2。新类型的编辑器也要用 `TopBar`（它自带 `ProjectMenu`）。动效类型最初就是这样：格式和示例都写好了，启动页却看不到。

## 统一尺寸选择：当前契约

状态：已实施。

画布、幻灯片、动效的新建对话框共用 `BoardSizePicker` 和核心 `BOARD_SIZES`：左列分类，右列具体名称、比例形状和宽高，下面说明用途；自定义仍是 1–7680 像素。三套独立控件会让人重复学习，也容易让某一类型漏掉新尺寸，所以不按类型维护预设。分类新增“更多比例”，覆盖 3:2、2:3、2:1、1:2、21:9、2.39:1、16:10 等。默认值直接可创建，不增加确认步骤。

平台尺寸按人找尺寸的方式分组：通用的图文与视频（1:1、4:5、3:4、9:16、16:9、链接卡片）、微信（公众号头条封面 900×383、次图 200×200、引导图 900×500，视频号封面横版 1080×608 与竖版 1080×1260）、国内平台（抖音、微博、B 站）、海外平台（Instagram、X、LinkedIn、Facebook、Pinterest、YouTube）。原来一个“社交与封面”塞了 20 多个，找视频号要从头扫一遍。入表的条件是有公开数字：一个平台只有一篇博客提到、或数字互相矛盾的（快手、知乎、朋友圈封面、B 站竖版封面）不收，调研和未收的原因见 `.research/size-presets.md`；一个像素尺寸只对应一个预设（尺寸选择器靠它反查名字），两个平台共用像素时说明里并写（1080×608 既是视频号也是抖音的横版封面）。已有预设 id 不改，只改分组和文案，命令行 `--size wechat` 与动效格式名照旧可用。

动效属性面板里的“添加尺寸”和命令行（`new --size`、`new -i`）也读这份表、用这个选择器，不另维护预设。画布和幻灯片的属性面板（共用的 `SizeRows`）同样列出“你的尺寸”：面板里敲一个非预设的宽高就记入，每个 × 都能移除。画布默认 1200×760；幻灯片默认 1920×1080；动效默认上次创建的尺寸，首次为 1920×1080，并在“你的尺寸”中保留、移除用过的自定义值。切换类型分别保留尺寸，不把某一种类型的未完成输入带入另一种。

幻灯片把尺寸写进 `deck.json` 的可选 `size: [w,h]`。缺省或无效时 `deckSize` 返回 1920×1080，兼容旧作品。新封面和新增页按尺寸缩放起步排版；编辑舞台、缩略图、启动页预览、放映、PNG、HTML 和 PDF 都使用这个尺寸，AI 的大纲也带实际宽高。只让选择器变样而仍写出固定横版会违背选择本身。设计系统继续选风格，看板继续可导入数据，文档没有额外起步参数。
