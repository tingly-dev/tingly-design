# 启动页：按类型分组的项目卡片

状态：**已实施**。测试是 `e2e/launcher.py`。

## 1. 要解决的问题

一列标题加一个类型下拉框的起始页，五种类型混在一起、看不出里面是什么，新建时要先想好类型。启动页要回答的是用户此刻的三个问题：**我上次在做什么、我有哪些东西、我要新建什么**。

## 2. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 一个项目怎么呈现 | 卡片：标题、类型、一个"有多大"的数（几个画板、几页、几个组件、几个数据集、几个标签页）、修改时间、预览 | 一个数比一串元数据好扫 |
| 预览 | 画布和幻灯片：在沙箱运行时里**实时渲染**打开的画板 / 封面（只读，滚到视口附近 200 px 才加载）；设计系统：用它自己的颜色、字体和圆角画的样张 + 色板 + 数量（见 [design-system-glance.md](./design-system-glance.md)）；看板：数据集标题；文档：标签页大纲和第一段 | 实时渲染最像"打开后看到的"；其余三种的内容不是一张图，画摘要更有信息量 |
| 预览太大 | 源码超过 200 KB 只画画板位置的缩略图（`MAX_PREVIEW_SOURCE`） | 启动页不能因为一个大项目卡住 |
| 卡片数据从哪来 | 服务端 `GET /api/projects` 返回 `ProjectCard`，由 `packages/core/src/launcher.ts` `projectCard` 按类型算 | 前端不必为每张卡片读一堆文件 |
| 找项目 | 全部 / 每种类型的标签（带数量）、搜索（`/` 聚焦，Enter 打开第一个）、按最近或名称排序、方向键在卡片间移动 | |
| 回到上次 | "继续上次的"链接和"最近打开"标记，记在浏览器 `localStorage`（最多 20 个） | 最常见的动作放最前；这是每个浏览器自己的便利，不需要服务端 |
| 新建 | 每种类型一个新建块，或对话框里选类型、填标题，文件夹名从标题生成；名字被占用或不合法在创建前就提示 | 不先问"哪种类型"再给空白表单，类型和例子一起摆出来 |
| 窄屏 | 手机宽度不横向滚动 | |

## 3. 和其他功能的关系

- 外观菜单（主题）只放在启动页，见 [theming](../docs/zh/theming.md)。
- 导入 HTML / SVG 的入口在启动页（`ImportDialog`），导入结果是一个新画布，见 [import-external-material.md](./import-external-material.md)。
- 嵌入时宿主可以用 `tingly-design:open` 直接打开项目，跳过启动页，见 [embedding](../docs/zh/embedding.md)。

## 4. 加一种类型时

启动页是最容易漏的地方：`kindOf` 认不出的目录不会出现在列表里，也不报错。要动的是 `ProjectPreview` 和 `projectCard`（core）、`KINDS`、图标和 `Preview`（`Launcher.tsx`）、`POST /api/projects` 的白名单（server），完整清单见 [project-kinds.md](./project-kinds.md) §2。动效类型最初就是这样：格式和示例都写好了，启动页却看不到。
