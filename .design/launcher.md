# 启动页：按类型分组的项目卡片

状态：**已实施**。测试是 `e2e/launcher.py`。

## 1. 要解决的问题

一列标题加一个类型下拉框的起始页，五种类型混在一起、看不出里面是什么，新建时要先想好类型。启动页要回答的是用户此刻的三个问题：**我上次在做什么、我有哪些东西、我要新建什么**。

## 2. 决定

| 问题 | 决定 | 为什么 |
|---|---|---|
| 一个项目怎么呈现 | 卡片：标题、类型、一个"有多大"的数（几个画板、几页、几个组件、几个数据集、几个标签页）、修改时间、预览 | 一个数比一串元数据好扫 |
| 预览 | 画布和幻灯片：在沙箱运行时里**实时渲染**打开的画板 / 封面（只读，滚到视口附近 200 px 才加载）；设计系统：用它自己的颜色、字体和圆角画的样张 + 色板 + 数量（见 [design-system-glance.md](./design-system-glance.md)）；看板：数据集标题；文档：标签页大纲和第一段 | 实时渲染最像"打开后看到的"；其余三种的内容不是一张图，画摘要更有信息量 |
| 预览太大 | 源码超过 200 KB 只画画板位置的缩略图（`MAX_PREVIEW_SOURCE`） | 启动页不能因为一个大项目卡住 |
| 卡片数据从哪来 | 服务端 `GET /api/projects` 返回 `ProjectCard`，由 `packages/core/src/launcher.ts` `projectCard` 按类型算 | 前端不必为每张卡片读一堆文件 |
| 找项目 | 全部 / 每种类型的标签（带数量）、搜索（`/` 聚焦，Enter 打开第一个）、按最近或名称排序、方向键在卡片间移动 | |
| 回到上次 | "继续上次的"链接和"最近打开"标记，记在浏览器 `localStorage`（最多 20 个） | 最常见的动作放最前；这是每个浏览器自己的便利，不需要服务端 |
| 新建 | 每种类型一个新建块，或对话框里选类型、填标题 | 不先问"哪种类型"再给空白表单，类型和例子一起摆出来 |
| 新建对话框 | 类型是一排小标签，只展开选中那种的一句简介；标题可以不填；文件夹名只是一行安静的路径（`projects/…`），点"改文件夹"才出现输入框 | 文件夹名是实现细节，不该和标题并排成两个必填项。六块带简介的大方块把整个对话框撑满，主角（标题）反而被挤到下面 |
| 新建动效时的尺寸 | 选了"动效"，标题下面多一排尺寸（按形状命名的预设，带按比例的小方块和像素值，选中时写出适合的平台），可以自定义；默认是上次用的，自定义的记在"你的尺寸"里。细节见 [motion-editing.md](./motion-editing.md) §3.7 | 动效的第一个问题就是给谁看，竖的还是横的；要在新建时回答，而不是建出一个 16:9 再去面板里改 |
| 文件夹名从哪来 | 跟着标题走；标题里没有字母或数字（中文标题）时用类型名；已被占用时顺延 `-2`、`-3`，不报错 | 原先中文标题直接被拒绝，要人去想一个英文文件夹名。自动生成的名字不该让人解决冲突；只有人自己改的名字才校验并提示 |
| 窄屏 | 手机宽度不横向滚动 | |

## 3. 和其他功能的关系

- **离开项目**：进了编辑器之后不必回启动页才能换项目，见下面"项目菜单"。
- 外观（主题）和语言是启动页上两个相邻的按钮。语言按钮直接写出当前语言，原先藏在外观菜单里，换语言的人找不到。
- logo 是 GitHub 主页的链接（新标签页打开）。启动页底部有两个安静的文字链接：反馈问题（指向新建 issue 的选择页，所以仓库有 issue 表单时会先看到表单）和在 GitHub 上点星。它们是页脚，不是横幅，没有计数、没有弹窗、不会因为"用了多少次"而出现。

- 外观菜单（主题）只放在启动页，见 [theming](../docs/zh/theming.md)。
- 导入 HTML / SVG 的入口在启动页（`ImportDialog`），导入结果是一个新画布，见 [import-external-material.md](./import-external-material.md)。
- 嵌入时宿主可以用 `tingly-design:open` 直接打开项目，跳过启动页，见 [embedding](../docs/zh/embedding.md)。

## 4. 项目菜单：编辑器里的出口

每种类型的编辑器都有同一个控件 `ProjectMenu`，在共用顶栏（[top-bar.md](./top-bar.md)）的最左：一个直达启动页的"首页"按钮，和旁边一个菜单。菜单里是：全部项目、其他项目（和启动页同样的排序，最近打开的在前，最多 8 个）、新建项目（和启动页是同一个对话框，默认类型是当前项目的类型）、AI 模型设置。反馈问题和点星不在菜单里，是顶栏最右的两个图标。

| 取舍 | 决定 | 为什么 |
|---|---|---|
| 回首页是一次点击还是两次 | 首页是单独的按钮，不藏在菜单里 | "回首页很难"是最初的抱怨；菜单是给"去别的项目"用的 |
| 项目名要不要放进这个控件 | 不放 | 各类型的标题已经是可以重命名的控件，一个控件两种含义（改名 / 切换）会互相抢点击 |
| 在哪里 | 共用顶栏的最左，六种类型都是窗口左上角同一个位置 | 以前没有共用的栏，组件共用、位置各自；现在栏也共用 |
| 反馈入口放哪 | 顶栏最右的两个安静图标（反馈问题、点星），悬停说明；不做悬浮按钮，也不放进菜单 | 藏在菜单第二层的入口没人看见；顶栏图标一直在、不带文字和颜色，不是噪声 |
| 项目列表什么时候取 | 打开菜单时才取 | 不为一个多数时候用不到的列表在每次进入编辑器时多发一次请求 |

## 5. 加一种类型时

启动页是最容易漏的地方：`kindOf` 认不出的目录不会出现在列表里，也不报错。要动的是 `ProjectPreview` 和 `projectCard`（core）、`KINDS`、图标和 `Preview`（`Launcher.tsx`）、`POST /api/projects` 的白名单（server），完整清单见 [project-kinds.md](./project-kinds.md) §2。新类型的编辑器也要用 `TopBar`（它自带 `ProjectMenu`）。动效类型最初就是这样：格式和示例都写好了，启动页却看不到。
