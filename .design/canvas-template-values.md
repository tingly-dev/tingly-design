# 画布的模板值：集中看、集中改

状态：**方案**（尚未实施）。现状是"一次只能看一块画板的 Tweaks"，见 §1；§2 以后是提案。

## 1. 要解决的问题

画板是模板：`{{heading}}` 这样的洞，加上 `data-props` 里声明的值（颜色、文字、开关、数字）。一个画布里常有十几块画板共用同一套值的写法（一组封面、一组海报、一套组件稿）。要回答的问题是"这个画布里到底有哪些可调的值，现在各是什么"，现在只能：

- 选中一块画板，切到 Tweaks，看这一块。要看另一块，再选再看。
- 没有任何地方能一眼看到全部。想核对"每块封面的标题是不是都改了"得点十几次。
- 值只在 Tweaks 里能改，而 Tweaks 只在选中画板时出现；什么都没选时，右侧面板只有画布名和设计系统，这是最空的一个状态。

现状（已实施的部分）：Tweaks 列出画板里每个带 `default` 的值，没写 `editor` 的按默认值显示成文本、开关或数字；整段文字就是一个文本值的 `{{name}}` 可以在画板上原地改，改的是这个值的默认值。仍然只读：夹在其他文字里的洞（`Hello {{name}}!`）和 `<sc-for>` 里的项，它们要靠 Tweaks 里的值去改。

## 2. 考虑过的方案

| 方案 | 好处 | 问题 |
|---|---|---|
| A. 右侧面板再加第四个页签"模板值" | 位置固定，好找 | 页签已经是"属性 / 代码 / Tweaks"三种看同一选中对象的方式；第四个是另一个范围（整个画布），混在一排里会让人分不清"这个页签看的是谁"，也是一个要选的模式 |
| B. 什么都没选时，右侧面板直接列出整个画布的模板值，按画板分组 | 范围一致：什么都没选 = 画布本身；与画布名、设计系统装入同在一处；不增加模式 | 选中画板后看不到别的画板的值（这时本来就在看那一块） |
| C. 把值放进图层树，画板下面挂值的叶子 | 结构和值在同一棵树里 | 图层树表达的是"元素的包含关系"，值不是元素；树会变得很长，隐藏、锁定这些树上的操作对值没有意义 |
| D. 单独的表格视图（一行一块画板，一列一个值，像电子表格） | 同名值一眼对齐，适合成批的封面 | 比其他方案大得多，要新的视图和导航；第一版用不到 |

## 3. 决定（建议）

选 **B**，D 留作以后。

理由：问题的单位是"整个画布"，而面板里"什么都没选"正好是画布级的位置；不加页签、不加模式，是同一份数据（`data-props`）的另一个范围。Tweaks 页签保持不变：选中一块画板仍然看这一块，两处用同一个字段组件和同一条写回路径，所以行为一致，撤销、改动记录也一致。

## 4. 具体样子

什么都没选时，在"画布"一节下面加一节"模板值"：

- 按画板在画布上的顺序分组；组头是画板的名字和值的个数，可折叠；没有声明任何值的画板不出现。
- 一行一个值：名字、当前默认值，用的就是 Tweaks 里的 `TweakField`（颜色是取色，文字是输入框，开关、数字同理）。改动写回对应画板的 `data-props` 里的 `default`，记为人的改动，可撤销。
- 点组头：选中那块画板并滚到它（在画布上看到这块画板），之后面板自然回到这块的属性和 Tweaks。
- 值超过一屏时（比如 30 个以上）顶部出现一个按名字过滤的输入框；不超过就不放，少一点杂物。
- 空状态（画布里没有一块画板声明值）用一句话教人怎么声明：在画板的 `data-props` 里写 `"heading":{"default":"…"}`，并说明之后它会出现在这里；这是产品内的说明，不是空白。
- `$time`、`$preview` 这类以 `$` 开头的保留项不列出（`boardTweaks` 已经过滤）。
- 文案放 `packages/i18n` 的 `panel` 区域，中英同写。

## 5. 数据与代码

- core 增加一个纯函数：给画布和各画板的源码，返回"画板 → 值的列表"（沿用 `boardTweaks`，不重复判断编辑器类型）。它是纯数据，可以单测，也是命令行以后要列出模板值时的来源。
- 编辑器：`RightPanel` 的"什么都没选"分支加一个 `TemplateValues` 组件；字段组件、写回（`setPropDefault`）都复用已有的。
- 读取每块画板的源码是现成的（画板文件已经在 store 里）。

## 6. 跨类型

只做画布。幻灯片和动效通过 `<x-embed data-props>` 覆盖画板的值，那是"某一个嵌入元素"的值，选中该元素时在属性面板里已有（`BoardEmbedProps`），没有"整份稿子的值"这个问题；设计系统、看板、文档没有模板值。要在跨类型矩阵里写明这是有意跳过，并写原因。

## 7. 没定的

1. 同名值（几块画板都有 `accent`）要不要能一起改。倾向第一版不做：几块画板的 `accent` 是否该相同是设计判断，一起改会误伤；以后若要，更像设计系统的 token 而不是这里的功能。
2. 脚本里读取、但 `data-props` 没声明的值。无法可靠地从脚本推断，第一版不列；更合适的做法是检查器报"这个洞没有对应的值"，让它进入声明，再出现在这里。
3. 值很多时是否需要分组之外的组织（按名字前缀等）：等真的出现再看。

## 8. 验证

- core 单测：多块画板的值汇总、保留项过滤、没有声明时为空。
- e2e：在示例画布里什么都没选时看到"模板值"，改一个值后画板上的内容变了、文件里的 `default` 变了、可以撤销；点组头选中并滚到画板。
