# 文件夹浏览与任意位置新建

状态：**方案**。落地后合并进 [project-folders.md](./project-folders.md)，本文件归档。

## 问题

1. “打开文件夹…”和新建对话框的位置只能手敲路径；浏览器拿不到本地路径，但服务端就在本机，可以替它列目录。
2. 新建对话框的位置默认显示 `projects/<名字>`，像是被固定在 `projects/` 里。要求：默认值也写成完整路径，任何位置同等对待。

## 决定

| 问题 | 决定 |
|---|---|
| 谁来浏览 | 服务端 `GET /api/browse?path=`，只列子文件夹（不列文件、隐藏文件夹），标出里面已有项目的文件夹及其类型；路径不存在时退到最近的存在的上级；空路径是家目录。`DC_LINKS=0` 时 403，与 `/api/folder` 一致 |
| 选择器 | 共用的 `FolderPicker` 对话框：上一级、当前路径（可直接改）、子文件夹列表（双击/回车进入）、“选这个文件夹”。叠在打开它的对话框之上 |
| 入口 | “打开文件夹”和新建对话框的位置字段旁各一个“浏览…”按钮 |
| 新建选中的文件夹 | 选中的是空文件夹/不存在：位置就是它；里面已有文件：位置是它下面一个以自动名字命名的子文件夹（人可再改），不让人先去判断“该选空的” |
| 默认位置 | 字段永远显示完整路径：默认是 `<项目文件夹>/<自动名字>`（家目录下写 `~/…`），跟着标题；人一点进去输入就停止跟随。没有 `projects/` 前缀标签 |
| 默认位置仍是项目文件夹里的一个名字 | 完整路径恰好是“项目文件夹的直接子文件夹”时，仍按名字创建（不登记链接、不进 `.links.json`），所以行为和以前相同，只是显示不同 |
| 宿主关了链接 | 位置回到只能写名字的老样子（带 `projects/` 前缀），没有浏览按钮 |

## 接口

`GET /api/browse?path=` → `{ path, abs, parent, sep, dirs: [{ name, kind? }], more }`；`path` 是显示形式（`~/…`），`abs` 用来继续往下走，`parent` 为 null 表示到根。`GET /api/health` 多一个 `projectsPath`（项目文件夹的显示形式，完整路径）。

## 没定的

- 不做“新建文件夹”按钮：新建对话框里直接改路径即可。
- 隐藏文件夹不显示，路径框里手写仍可到达。
