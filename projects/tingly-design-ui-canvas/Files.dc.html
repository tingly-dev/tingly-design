# Spring launch Artboards: Cover, Poster, Card …
Read only in this pass. Editing through the write-back engine is an open question.
1
A pane, not a tab
A button in the top bar next to Properties, remembered open or closed per kind, like Layers. Files and “what is selected” are two questions; one panel would make them fight for space.
2
What is listed
The same line as the archive and git: dot files (.runs.json, .claude-session.json, .transcript.jsonl, .image.json, .references.json, renders/, .history/ …) and node_modules never appear. uploads/ is content people reference, so it is a folder like any other.
3
Put on canvas, no re-upload
The picture is already in the folder: the note takes its folder path (uploads/…, assets/…) and the editor and frames serve it from there. Scaled to the view, placed in the middle, one undo step.
4
Live
The list re-reads when the folder changes: the events the editor already gets (edits, uploads, outside writes) arrive merged as the asset revision, and the pane refetches on it.
5
Copy path
Copies the folder-relative path, the value an artboard’s src wants — the artifact for the next action, not just a name.
6
Canvas only, for now
Registered in the pane table for the design kind only. The list, preview and copy are kind-neutral; “put on canvas” is the canvas step. Other kinds join with their own step, not a copy.
Open
Other kinds (a deck’s slides/, a dashboard’s data/, a system’s assets/) and what each kind’s “use it” is; editing a text file in place (needs the write-back engine); dragging a row onto an artboard; “reveal in file manager”.
