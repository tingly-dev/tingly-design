1
One form, two places
Double-click or Enter opens it beside the element; Properties carries the same Content section. Esc, selecting something else or clicking away closes it.
2
What an element holds
A picture: source (with the project’s own pictures to pick from, or an upload kept in uploads/) and alt. A link: label, address, new tab. An input: placeholder. A card: every part, in reading order. A run of text between styled words is a field of its own.
3
Plain text stays in place
Text that can be retyped is still retyped where it is drawn; a plain link’s address is in the panel’s Content section.
4
Values from the template
A value that is one text tweak edits the tweak; one fed by the script or a list row is read-only and says why.
5
Nothing to edit, or locked
Says so in a line, with where to go next, instead of staying silent.
6
Canvas, slides, motion
One runtime message and one form; the other kinds have no element selection.
Open
Does the popover need to exist next to the panel’s section, or should a double-click focus the panel instead? Lists and tables (add, remove, move a row), icon names and values from list rows come next.
