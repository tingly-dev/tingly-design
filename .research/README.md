# 调研索引

这里放调研：为一个还没做的决定收集事实，比如比较库和方案、实测性能、做验证代码。和 `.design/` 的分工：`.design/` 写已定或正在定的设计（这个子系统为什么这样做）；`.research/` 写决定之前的调查（有哪些选择、各自实测如何、倾向什么）。调研得出的决定落地时，结论写进相关的 `.design/` 说明，调研本身留在这里作依据。

维护约定：

- 标题下第一行写状态（`研究` / `验证` / `已采纳` / `已放弃`），和结论被用到哪里。
- 写事实、数据和推理，标明哪些是实测、哪些是推断；不记 PR 编号、提交和时间线。
- 验证代码放在同名目录里（`<主题>-go-spike/` 之类），附上能复现的步骤；不进产品构建。
- 新增一份调研时，在下表加一行。
