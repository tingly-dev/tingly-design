## 图 1　三层运行环境（现状）

```
┌─────────────────────────── 浏览器（JS，换不换后端都不动） ───────────────────────────┐
│ apps/editor        各类型的编辑器、启动页、提示栏                                      │
│ packages/core      格式解析和回写（canvas / deck / ds / dash / docs / motion）          │
│ packages/sandbox   画板、看板、动效运行时（opaque origin 的 iframe）                    │
│ packages/import    HTML / SVG → 画布（编辑器里的导入在这里做）                          │
└───────────────────────────────────────┬──────────────────────────────────────────────┘
                                        │ HTTP（REST + SSE）
┌───────────────────────── 服务端（Node，约 1500 行，要选的是这一层） ────────────────────┐
│ 文件和版本 · 监听和 SSE · journal · 快速 AI · 起 claude · 只读 SQLite · git            │
│ 还在用 @dc/core 做几件"懂格式"的事：新建项目、装设计系统、重写 tokens.css、启动页卡片   │
└───────────────────────────────────────┬──────────────────────────────────────────────┘
                                        │ 读写同一个 projects/ 目录
┌────────────────────── 批处理工具（重在 Chromium / ffmpeg / Dawn，不在 Node） ───────────┐
│ motion-render.mjs   Chromium 逐帧截图 → ffmpeg                                          │
│ dc-import / check   Chromium 排版、像素对比（开发和评测用，不随产品分发）                 │
│ vgpu/node           Dawn 原生模块（调研中）                                              │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 图 2　边界：谁懂格式

```
            浏览器（懂格式）                               服务端（不懂格式）
 ┌──────────────────────────────────┐            ┌──────────────────────────────────┐
 │ 新建项目：new* + stringify*        │ ─批量写入─▶ │ 一组文件 + 各自基准版本             │
 │ 装设计系统：读 tokens，改索引       │ ─批量写入─▶ │ 项目锁里一起写，对不上整组 409       │
 │ tokens.json 变了 → tokens.css      │ ──PUT────▶ │ 单文件写：基准版本 → 新版本          │
 │ 启动页卡片：读 JSON 算标题和预览     │ ◀─列目录── │ 目录、文件、资源、上传               │
 │ 编辑、回写、导入                    │ ◀──SSE──── │ 文件事件、journal、委托进度          │
 └──────────────────────────────────┘            │                                    │
                                                 │ 安全检查（Go、TS 各一份，用例共用）： │
                                                 │   路径、附件、消息、看板 SQL 绑定     │
                                                 │ 快速 AI 代理（提示 go:embed）        │
                                                 │ 起 claude（提示 go:embed）           │
                                                 │ 只读 SQLite、git commit             │
                                                 └──────────────────────────────────┘
```

- 左边任何一项都不进 Go；右边任何一项都不需要解析项目格式。
- 两份代码只出现在"安全检查"这一格：它必须在服务端做，浏览器的检查可以被绕过。

## 图 3　接进 TB：方案 A 和方案 C

```
 方案 A：Node 子进程（现行的 integration 方案）

 Wails 窗口 / 浏览器
 ┌──────────────────────────────────────┐
 │ TB 控制台 /design                     │
 │  └ iframe /apps/design/<key>/…        │
 └───────────────┬──────────────────────┘
                 ▼
 ┌──────────── TB（Go）────────────┐        ┌───── node server.mjs ─────┐
 │ 取 session → 发 key               │ spawn  │ 127.0.0.1:随机端口          │
 │ 下载包、探测 Node、看护子进程      │ ─────▶ │ 文件、SSE、快速 AI、claude  │
 │ 反向代理（key 校验、不缓冲）        │ ─────▶ │                            │
 └──────────────────────────────────┘ 代理   └────────────────────────────┘
   用户机器上要有 Node ≥ 20.11；两个进程；排错跨进程


 方案 C：Go 薄宿主（倾向）

 Wails 窗口 / 浏览器
 ┌──────────────────────────────────────┐
 │ TB 控制台 /design                     │
 │  └ iframe /apps/design/…（同源）      │
 └───────────────┬──────────────────────┘
                 ▼
 ┌──────────────────── TB（Go，一个二进制）────────────────────┐
 │ import tingly-design/host  →  挂路由 /apps/design/…           │
 │   文件、SSE、journal、快速 AI（走网关进程内路径）、claude       │
 │ go:embed 编辑器和沙箱的构建产物                                 │
 └──────────────────────────────────────────────────────────────┘
   不下载、不探测 Node、不看护、不代理


 独立运行（两种方案都有）

 A：node server.mjs        C：tingly-design（同一个 host 包 + 一个小 main）
    环境变量、TINGLY_DESIGN_READY 行、路由都保持不变
```

## 图 5　迁移步骤

```
 ① 写下契约                ② Node 变薄                 ③ 写 Go 版
 OpenAPI + SSE 事件        批量写入                    host 包 + 小 main
 e2e 定为契约测试   ──▶    懂格式的挪到浏览器    ──▶    同一套 e2e、共用用例
                           安全检查用例抽成数据文件      跑到全绿（两版并存）
 ────────── 不管选不选 C 都值得做 ──────────
                                                          │
                                                          ▼
 ⑥ 动效导出进编辑器         ⑤ 删掉 Node 服务端          ④ TB 挂路由
 Go 驱动按需下载的   ◀──    pnpm dev = go run + Vite ◀── import host 包
 Chromium + ffmpeg          bundle 产出 Go 二进制         去掉下载、探测、看护、代理
```

- 每一步都能单独发布、单独回退；②之前用户感觉不到任何变化。
- 两份服务端只在③④之间并存。
