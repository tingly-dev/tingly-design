# Slides

Choose "幻灯片" (slides) when creating a project. The sample [`?p=tingly-design-intro-slides`](http://localhost:5173/?p=tingly-design-intro-slides) is "Meet Tingly", an introduction to Tingly Box and Tingly Design; the gateway slide carries a live `<x-embed>` diagram.

Choose a size below the title when creating a deck: the same categories, concrete dimensions and Custom fields as Canvas and Motion. The default is 1920×1080; portrait, square and other ratios work through editing, presentation and export. The size is saved as `size: [width, height]` in `deck.json`; existing decks keep the default.

![Slide editor: thumbnails and sections on the left, the stage and speaker notes in the middle, layers and properties on the right](../../images/slides.png)

```
projects/<name>/
  deck.json            title, slide order, sections, typefaces
  slides/<id>.html     one file per slide: exactly one <section id="<id>">, deck size (default 1920×1080), a closed HTML/CSS subset
  assets/              uploaded images and fonts
```

- **Thumbnail strip**: grouped by section (double-click a section to edit its description); drag to reorder; right-click to add, duplicate, skip, start a section or delete. Live embeds stay still in thumbnails.
- **Stage**: the current slide, scaled to fit. Selection, double-click to retype, drag to reorder or pin, and the layers / properties / code panel (the layers with the same hide and lock on every row) all work as on the canvas, through the same minimal write-back. Speaker notes sit below the stage (written to `<aside>`).
- **Theme**: the right panel's Theme tab lists every theme of the design systems installed in this deck, plus Original look. One click puts the deck's colours and typefaces into that theme, for **All slides** or **This slide** (the choice is on the tab); the toast has Undo. Details in [Design system](./design-system.md).
- **Text boxes**: a `<div data-text>` holding paragraphs and lists is one box: a click selects the whole box (move, resize and style it once), a double-click types in the paragraph under the pointer, and `data-text="N"` sets the lists' indent in px.
- **Insert**: text, images (uploaded to `assets/`), tables, shapes (rectangle, rounded, ellipse, diamond, four arrows, line), connectors and icons.
- **Format check**: every slide is checked against the subset of the original `format.md` (unknown tags, `margin`, `z-index`, `em`, `var()`, an unpinned `<x-embed>`…). Counts show above the stage and on thumbnails, and clicking an issue selects the element. If a fast AI edit introduces a new violation, it is undone and the model is told why and asked again.
- **Present**: F5 from the start, ⇧F5 from the current slide; → / Space / click plays the slide's builds (`data-build-in`) and then advances; `fade` and `push` transitions (`magic` falls back to fade); N toggles speaker notes; F for full screen; Esc to leave.
- **Import / Export** (top right, next to Present): a PDF in one click, one page per slide (made by the Chrome on the machine running the server; with none, it opens the print dialog and you choose Save as PDF), a single HTML file (images inlined, embeds sandboxed and running, arrow keys to page), a Markdown file (the deck written as a document: the title, section and slide titles as headings, text, lists and tables, pictures by their path and alt text, speaker notes as quotes; shapes and embeds left out), or the speaker notes as text. The same menu saves this slide, or every slide, as PNG pictures at the slide's size (an embed comes out empty in a picture), copies this slide as a picture to the clipboard (“Copy as PNG”), and brings in pictures and SVGs. At the end of the same menu, “Whole project (.zip)” saves the project itself: every file, its change log and the design systems it installed, beside it; “Project files only (.zip)” leaves those two out. “Import a project package (.zip)…” in the home page's New menu opens it again (a name already taken gets `-2`), and so does a project folder you zipped yourself.
- **Importing pictures**: drop or paste pictures or SVGs into the editor and they go onto the open slide (kept in `uploads/`, like Insert image).
- **Built-in effects**: an empty embed with `data-fx` (`<x-embed data-fx="aurora" …>`) draws a moving WebGL background or light, the same sixteen as in motion pieces (see the motion guide). It stands still while you edit and in the PDF, and moves while presenting and in the downloaded HTML.
- **Importing from a project**: the Import / Export menu's "From a project…" lists the artboards of your canvases. The one you pick is copied into this deck (`uploads/<canvas>-<board>/`) and goes onto the open slide. An artboard that moves with time (an effect, marked "Moves") fills the slide behind everything and loops while presenting and in the downloaded HTML; a still one sits in the middle. Select it to set its options (they are written to the embed, the copy stays as it came), open the original, or update it from its canvas: every slide using it changes together.

Rendering follows the original's rules: a `<div>` with no `display` is a flex column; children paint in source order, with all flow content painted as one layer where the first flow child sits (so a full-bleed backdrop written first stays behind the text); `<x-embed>` runs in its own sandboxed page with no network and a different origin.

## PowerPoint (.pptx)

On the home page, choose **New project → Import PowerPoint (.pptx)…**, or drop a PPTX onto the launcher. It becomes a **new slides project**, not an attachment or an addition to the deck you have open. The command line uses the same converter: `tingly-design import talk.pptx`. A name already taken gets a free suffix. The conversion summary lists each kind of change once, with the slides and objects it touches; the original PPTX, pictures and JSON report stay under `uploads/`. Failed conversion creates no project.

Import keeps going past what it cannot read: an object it cannot convert is left out with a note naming its slide, and the rest of the deck comes in. Text and its styles (mixed sizes and fonts, spacing, autofit), bullets and numbering, placeholder and theme inheritance, preset and custom shapes, lines and connectors, solid, gradient, pattern and picture fills, shadows, groups, cropped pictures, tables with merged cells and table styles (every PowerPoint built-in style, even when the file only names it, with banded rows and columns, first and last rows and columns, double and diagonal borders, and vertical text), SmartArt, backgrounds and speaker notes become editable content. Charts are redrawn from their own data as a picture that looks like the original: bars and columns (also 3-D, drawn with a simple depth), lines, stock, areas, scatter, bubbles, pies, doughnuts, bar and pie of pie, radar, surface (as a contour map), combinations on two axes, log and date axes, number formats, data labels, trendlines and error bars, and the Office 2016 charts (waterfall, funnel, histogram and Pareto, box and whisker, treemap, sunburst); map charts show the picture saved in the file; to change the numbers, edit the chart in the original file. The deck keeps the presentation's page shape: a 4:3 deck stays 4:3, a portrait deck stays portrait. Animations are dropped with a note. Only a presentation that is damaged, unsafe (macros or ActiveX) or over the size limits is refused as a whole. Old `.ppt` and encrypted presentations are not supported.

Dropping a PPTX into an open slides project appends its pages as ordinary slides at the end of the deck — one undo removes exactly that batch, and the conversion report stays under `uploads/`.

In a slides project's **Import / Export** menu, choose **PowerPoint (.pptx)** to save the whole visible deck. Text, supported shapes and pictures become native PowerPoint objects; speaker notes stay notes. Hidden slides and hidden elements are omitted. Editing continues in the ordinary slide files; export creates a fresh package, not an update of the original PPTX.

Export measures the actual slide layout and keeps as much as it can editable: text (with letter spacing, capitals, strike-through and transparency), boxes with solid or translucent fills and rounded corners, borders (a border on one side becomes a line), list markers, PNG/JPEG pictures, and tables: a table whose cells hold only text becomes a real PowerPoint table, with its merged cells, fills, borders, padding and alignment, so it can be restyled and extended in PowerPoint (a table with pictures, icons or rotated text in its cells, or space between cells, is exported cell by cell instead). What PowerPoint has no object for (gradients, shadows, SVG and icons, embeds, rotated or clipped elements, other picture formats) is placed as a picture of that element only, at its place in the stacking order; text on top of a gradient card stays text. The result lists every element that became a picture, by slide. It does not promise identical font rendering or fully reflowable original paragraphs, and it does not embed fonts. A deck fails only when something cannot be read at all (a missing picture, a font that did not load, the time limit); then no partial presentation is downloaded. `tingly-design export talk --as pptx --out ./exports` writes the file into the `exports` directory; MCP export uses the same path. It also takes a range over the visible slides: `--slide 2`, `--slide 2-4` or `--slide 1,3-4` (positions count the visible deck from 1; a range names no hidden slide). A range export names the range in its file name.
